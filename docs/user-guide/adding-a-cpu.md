# Adding a CPU

A new CPU architecture is added by writing a **spec table** — a typed C# declaration of registers and instructions — and running the **spec importer** to generate the spec file from a curated dataset. The Roslyn source generator then produces five artifacts at build time from that table.

Source: `src/CpuEmulator.Cpus.Mos6502/Mos6502Spec.cs`, `src/CpuEmulator.Generators/`, `tools/CpuEmulator.SpecImporter/`

---

## The workflow in brief

1. **Curate a dataset** — a JSON opcode table (`mos6502-opcodes.json` is the model) listing every documented opcode with mnemonic, addressing mode, byte count, cycle count, and page-cross flag.
2. **Write a semantics map** — a JSON file (`mos6502-semantics.json` is the model) mapping each mnemonic to its micro-op expression string in the DSL vocabulary.
3. **Run the importer** — generates the C# spec file from the two data files.
4. **Write the hand-authored partial** — implement the CPU's reset, interrupt servicing, and bus wiring in a companion `partial class` file.
5. **Build** — the Roslyn generator reads the spec table and emits the five generated artifacts.

---

## The spec table (DSL)

A spec table is a static class annotated with `[CpuSpecification("arch-name")]` and two fields: `Registers` and `Instructions`.

```csharp
using CpuEmulator.Core.Specification;
using static CpuEmulator.Core.Specification.Spec;

[CpuSpecification("mos6502")]
public static class Mos6502Spec
{
    public static readonly RegisterDef[] Registers =
    [
        new("A", 8),
        new("X", 8),
        new("Y", 8),
        new("S", 8, RegisterRole.StackPointer),
        new("P", 8, RegisterRole.Status),
        new("PC", 16, RegisterRole.ProgramCounter),
    ];

    public static readonly InstructionDef[] Instructions =
    [
        Insn(0x00, "BRK", AddrMode.Implied, [Brk()]),
        Insn(0xA9, "LDA", AddrMode.Immediate, [Load(Reg.A, Operand), SetNZ(Reg.A)]),
        Insn(0xBD, "LDA", AddrMode.AbsoluteX, [Load(Reg.A, Mem), SetNZ(Reg.A)]),
        // ... 151 rows total for the 6502
    ];
}
```

`Mos6502Spec.cs` is **importer output** — generated by the tool, not hand-written. The canonical regeneration command is in the file header (see below).

## The importer

The spec importer (`tools/CpuEmulator.SpecImporter`) generates the spec table from two data files:

- **`data/mos6502-opcodes.json`** — curated 151-opcode dataset. Each row has: opcode byte, mnemonic, addressing mode, byte count, cycle count, page-cross flag, and optional provenance citation.
- **`data/mos6502-semantics.json`** — hand-authored map: mnemonic → micro-op expression string (e.g. `"LDA": "[Load(Reg.A, Operand), SetNZ(Reg.A)]"`).

### Regeneration command

```
dotnet run --project tools/CpuEmulator.SpecImporter -- \
  --dataset  tools/CpuEmulator.SpecImporter/data/mos6502-opcodes.json \
  --semantics tools/CpuEmulator.SpecImporter/data/mos6502-semantics.json \
  --out      src/CpuEmulator.Cpus.Mos6502/Mos6502Spec.cs
```

Add `--report` to print a summary of emitted rows, TODO semantics, and TODO modes.

The committed `Mos6502Spec.cs` is pinned to the tool output by the byte-equality test `RegeneratedSpecTests.Committed_Mos6502Spec_is_exactly_the_tool_output`. If the test fails, re-run the command above; do not hand-edit the spec file.

## Five generated artifacts

From one spec table the Roslyn generator emits five artifacts into `{Namespace}.{CpuName}.g.cs`:

| # | Artifact | What it does |
|---|---|---|
| ① | CPU state struct | Strongly-typed register fields (`A`, `X`, `Y`, `S`, `P`, `PC`, `_cycles`); `GetRegister`/`SetRegister` for CPU-agnostic introspection |
| ② | Tier-0 interpreter | Per-opcode methods behind a `delegate*[256]` dispatch table — zero-alloc, AOT-safe, cycle-exact (every bus transaction happens at the cycle it would on silicon) |
| ③ | IL-emission methods | Per-opcode `DynamicMethod` emitters for the M2 JIT block compiler (not used until M2) |
| ④ | Disassembler | `Disassemble(byte opcode, byte lo, byte hi) → string` — mnemonic + canonical operand text (e.g. `"LDA $E01E,X"`, `"BNE *-7"`) |
| ⑤ | Single-instruction assembler | `TryAssemble(mnemonic, operandText, out bytes, out error) → bool` — the exact inverse of ④, from the same table |

Artifacts ④ and ⑤ are the inverse pair that makes `assemble(disassemble(op)) == op-bytes` for all 151 documented 6502 opcodes (the roundtrip keystone test `AssemblerRoundtripTests`).

## Assembler operand grammar

`TryAssemble` accepts canonical operand text as produced by `Disassemble`. The hex-digit width selects the addressing mode; no silent promotion occurs.

| Operand form | Addressing mode | Operand bytes | Notes |
|---|---|---|---|
| *(empty)* | Implied, falling back to Accumulator | — | `ASL` = `ASL A`; a mnemonic never has both rows |
| `A` | Accumulator | — | |
| `#$hh` | Immediate | lo | Exactly 2 hex digits; `#$hhhh` is an error |
| `$hh` | ZeroPage | lo | Exactly 2 hex digits |
| `$hh,X` | ZeroPageX | lo | |
| `$hh,Y` | ZeroPageY | lo | |
| `$hhhh` | Absolute | lo, hi | Exactly 4 hex digits |
| `$hhhh,X` | AbsoluteX | lo, hi | |
| `$hhhh,Y` | AbsoluteY | lo, hi | |
| `($hh,X)` | IndirectX | lo | |
| `($hh),Y` | IndirectY | lo | |
| `($hhhh)` | Indirect | lo, hi | |
| `*+d` / `*-d` | Relative | offset byte | Decimal, −128..+127; raw-offset semantics (relative to the post-operand PC) |
| `$hhhh` *(branch mnemonics)* | Relative, via `MonitorEngine.TryAssembleAt` only | offset byte | Engine resolves `target − (address + length)` — NOT generated `TryAssemble` |

**Width rule:** 1- or 3-digit hex operands are errors naming the rule. Ambiguities are resolved by the spec table: a mnemonic+mode pair either exists or assembly fails.

## CPUGEN diagnostics

The generator emits structured errors at build time; specs with errors produce no generated code.

| ID | Title | Cause |
|---|---|---|
| CPUGEN001 | Missing Registers table | Spec class lacks a `Registers` field |
| CPUGEN002 | Invalid register definition | A `RegisterDef` entry is not statically analyzable |
| CPUGEN003 | Missing Instructions table | Spec class lacks an `Instructions` field |
| CPUGEN004 | Invalid instruction definition | An `Insn(...)` call is not statically analyzable |
| CPUGEN005 | Duplicate opcode | Same opcode byte appears in two `Insn` rows |
| CPUGEN006 | Unknown micro-op | A semantics expression uses an unrecognized factory name |
| CPUGEN007 | Register role violation | A register role constraint is violated (e.g. two PC-role registers) |
| CPUGEN008 | Unknown register in micro-op | A micro-op references a register name not in `Registers` |
| CPUGEN009 | Invalid spec metadata | Multiple specs generate the same CPU class name |
| CPUGEN010 | Unsupported mode/op combination | An addressing mode is incompatible with the micro-op semantics |
| CPUGEN011 | Invalid micro-op argument | A micro-op factory receives an argument of the wrong kind |

All diagnostics are errors — a spec with any CPUGEN error produces no generated artifacts and fails the build.

## The hand-written partial

The generated class is `partial`. You must provide a companion partial class implementing:

- **Bus wiring** — `ReadBus`/`WriteBus` methods that charge the cycle counter and delegate to `IAddressSpace`.
- **`Reset()`** — load PC from the reset vector, initialize S/P, clear the NMI latch.
- **`TryServiceInterrupt()`** — declared as `private partial bool` in the generated file; implement the interrupt service sequence.
- **`InterruptPending`** — declared as `public partial bool` in the generated file; implement with the same predicate `TryServiceInterrupt` gates on.

The 6502's hand-written partial is `src/CpuEmulator.Cpus.Mos6502/Mos6502Cpu.cs`. The `InterruptPending` partial property there reads:

```csharp
public partial bool InterruptPending => _nmiPending || (_irqLine && (P & 0x04) == 0);
```

A missing `partial` implementation is a build error (CS8795), not a runtime fault — the compiler enforces the seam.
