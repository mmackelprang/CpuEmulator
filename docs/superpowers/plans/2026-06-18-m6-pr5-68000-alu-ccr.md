## Objective (the ADR §8 PR-5 row — the 68000's flag long pole)

Make the 68000 **integer ALU** families emit real IL: **ADD/ADDA/ADDI/ADDQ, SUB/SUBA/SUBI/SUBQ, CMP/CMPA/CMPI,
AND/ANDI, OR/ORI, EOR/EORI**, plus **ADDX/SUBX** (the X-bit consumers). The crux is **the CCR model — XNZVC,
with the X (extend) bit DISTINCT from C**:

- **ADD/SUB set X = C** (X is an OUTPUT mirroring carry/borrow).
- **ADDX/SUBX consume X as an INPUT** (`+ (xIn?1:0)` into the carry/borrow) and have **sticky Z** (Z only clears
  on non-zero; never freshly set when result is zero — the classic ADDX bug class).
- **CMP never touches X** (X restored from the old CCR).
- **AND/OR/EOR (Logic) leave X UNTOUCHED**, force V=C=0.
- **ADDA/SUBA/CMPA (An dest) set NO CCR** (ADDA/SUBA) or full-32 Cmp CCR (CMPA).

Reuse a **shared CCR-compute helper** (the JIT analogue of the interpreter's `AluCcr.Arith`/`Logic`/`Cmp`/`ArithX`
— like the Z80's shared `EmitZ80AddSubFlags`). This is the highest-bug-density code in the 68000 JIT; the
data-axis SR comparison in `RunCaseThroughJit` is the entire safety net.

**Why PR-5 (ADR §8):** the 68000 ALU is the largest data-axis family after MOVE, and `SUBQ` alone is 40% of W2
(ADDQ/SUBQ are the counted-loop edges). It is **size L** because the CCR X-bit arm is the 68000's flag long
pole — the X-distinct-from-C asymmetry (plain ADD/SUB hard-wire `xIn:false`; only ADDX/SUBX pass the live X) is
the dominant TomHarte failure class.

## What the recon CONFIRMED (file:line — load-bearing, verified against `main` @ `555b1bd`)

### The CCR-compute oracle (the shared helpers the JIT must mirror)

The CCR is the low byte of `SR` (bits **C=0x01, V=0x02, Z=0x04, N=0x08, X=0x10**, `M68000Spec.cs:43`). Every ALU
body sets flags via a shared `AluCcr` helper, then `SR = (SR & 0xFF00) | ccrByte`. The four rules:

```csharp
// AluCcr.Arith (M68000Cpu.Alu.cs:227-255) — the load-bearing NZVCX compute. X = C is the LAST line.
internal static byte Arith(uint a, uint b, uint result, uint size, bool xIn, byte oldCcr, bool isSub)
{
    uint m = Mask(size), sb = SignBit(size);
    uint r = result & m;
    bool n = (r & sb) != 0, z = r == 0, c, v;
    if (!isSub)
    {
        ulong full = (ulong)(a & m) + (b & m) + (xIn ? 1u : 0u);
        c = (full & ~(ulong)m) != 0;                            // carry out of the size
        v = (((a ^ r) & (b ^ r)) & sb) != 0;                   // both inputs' sign differs from result's
    }
    else
    {
        ulong sub = (ulong)(b & m) + (xIn ? 1u : 0u);
        c = (ulong)(a & m) < sub;                              // borrow out
        v = (((a ^ (b & m)) & (a ^ r)) & sb) != 0;
    }
    byte ccr = (byte)(oldCcr & ~0x1F);                          // clear X N Z V C; keep the system-byte-shadow bits
    if (n) ccr |= 0x08;  if (z) ccr |= 0x04;  if (v) ccr |= 0x02;  if (c) ccr |= 0x01;
    if (c) ccr |= 0x10; else ccr &= unchecked((byte)~0x10);     // X = C  (the OUTPUT-X tail)
    return ccr;
}

// The delegates ADD/SUB pass — note xIn is HARD-WIRED false (plain ADD/SUB never read the live X):
public static byte ArithAdd(uint a, uint b, uint r, uint size, bool xIn, byte old) => Arith(a,b,r,size,false,old,isSub:false);
public static byte ArithSub(uint a, uint b, uint r, uint size, bool xIn, byte old) => Arith(a,b,r,size,false,old,isSub:true);
//   (M68000Cpu.Alu.cs:262-263) — passing the live X to a non-X op would corrupt carry/borrow (e.g. SUB.w D5,D5 must give C=X=0).

// AluCcr.Logic (M68000Cpu.Alu.cs:266-273) — N/Z from result, V=C=0, X UNTOUCHED (old & ~0x0F keeps bit 4):
//   ccr = (oldCcr & ~0x0F);  if (N) ccr |= 0x08;  if (Z) ccr |= 0x04;   // V=0, C=0, X preserved.

// AluCcr.Cmp (M68000Cpu.Alu.cs:285-290) — Arith borrow but X RESTORED from old (CMP never touches X):
//   byte arith = Arith(a, b, result, size, false, oldCcr, isSub:true);
//   return (byte)((arith & ~0x10) | (oldCcr & 0x10));          // keep the new N Z V C, restore the old X.

// AluCcr.ArithX (M68000Cpu.Alu.cs:294-303) — Arith WITH the live xIn passed through, plus STICKY Z:
internal static byte ArithX(uint a, uint b, uint result, uint size, bool xIn, byte oldCcr, bool isSub)
{
    byte ccr = Arith(a, b, result, size, xIn, oldCcr, isSub);   // xIn PASSED THROUGH (the INPUT-X path)
    uint m = Mask(size);
    bool zResult = (result & m) == 0;
    ccr = (byte)(ccr & ~0x04);                                  // clear the freshly-computed Z
    if (zResult) ccr |= (byte)(oldCcr & 0x04);                  // re-OR the OLD Z only when the result is zero (sticky)
    return ccr;
}
//   ArithXAdd/ArithXSub (M68000Cpu.Alu.cs) pass xIn through; the live X is read in the driver: xIn = (Ccr & 0x10) != 0.
```

> **The X-distinction in one sentence:** plain ADD/SUB call `Arith` with `xIn:false` and set X=C at the tail
> (X is an output); ADDX/SUBX call `ArithX` with the LIVE `xIn` (X is an input to the carry/borrow) and have
> sticky Z; CMP restores the old X (never touches it); AND/OR/EOR leave X untouched. **Getting the `xIn` source
> right per family is the dominant PR-5 correctness risk** — the data-axis SR comparison catches it.

### The ALU driver oracle (`BinaryAluExecute` — the read-A/read-B/write/CCR machine)

```csharp
// BinaryAluExecute (M68000Cpu.Alu.cs:55-139) — the structure the JIT mirrors:
uint mask = SizeMask(size);
bool xIn = (Ccr & 0x10) != 0;                                  // the live X (only ADDX/SUBX use it)
byte oldCcr = (byte)(SR & 0xFF);
// RegEa shape (the Dn <op> <ea> form):
uint dnReg = (operword >> 9) & 7u;                             // bits 11-9 = the Dn operand
bool toEa  = (operword & 0x0100u) != 0;                        // bit 8 direction: 1 = Dn op <ea> -> <ea>
if (toEa) { dest = ResolveEaDest(srcMode, srcReg, size, ext, out a); a &= mask; b = dn; }   // dest = the EA (memory)
else      { a = DataReg(dnReg) & mask; b = ReadEaOperand(...) & mask; dest = AluDest.DataRegister(dnReg); }  // dest = Dn
uint result = aluFn(a, b, xIn, size) & mask;                   // the pure op (Add/Sub/And/Or/Eor)
if (writesResult) WriteResolvedDest(dest, size, result);       // CMP has writesResult:false
SR = (ushort)((SR & 0xFF00) | ccrRule(a, b, result, size, xIn, oldCcr));   // the per-family CCR rule
```

The family registrations (`M68000Cpu.Alu.cs:323-334`) — the `(AluFn, CcrRule, writesResult)` tuple is the only
per-family difference:

| Family | AluFn | CcrRule | writesResult | X behavior |
|---|---|---|---|---|
| ADD/ADDI/ADDQ | `Alu.Add` | `ArithAdd` | true | X = C (output) |
| SUB/SUBI/SUBQ | `Alu.Sub` | `ArithSub` | true | X = C (output) |
| AND/ANDI | `Alu.And` | `Logic` | true | X untouched |
| OR/ORI | `Alu.Or` | `Logic` | true | X untouched |
| EOR/EORI | `Alu.Eor` | `Logic` | true | X untouched |
| CMP/CMPI | `Alu.Sub` | `Cmp` | **false** | X restored (untouched) |
| ADDX | `Alu.AddX` | `ArithXAdd` | true | X = INPUT + output, sticky Z |
| SUBX | `Alu.SubX` | `ArithXSub` | true | X = INPUT + output, sticky Z |

> **`ResolveEaDest`/`WriteResolvedDest` (the address-once discipline, `M68000Cpu.Alu.cs:174-203`):** when the
> dest is a memory EA (`toEa`), the EA is computed ONCE and carried in an `AluDest`, so `WriteResolvedDest` does
> NOT re-run `ComputeEa` (which would double-advance An on `(An)+`/`-(An)`). **The JIT MUST mirror this** —
> PR-4's `EmitM68kEaRead`/`EmitM68kEaWrite` already resolve each EA once; the RegEa-toEa form reads-then-writes
> the SAME memory address, so the arm must compute the dest address once, read the old value, compute the
> result, and write back to that SAME address. `.l` memory write-back is **low-word-first** (`WriteLongBusRmw`,
> `M68000Cpu.cs:218-222`) — the reverse of MOVE.l store order; PR-5 needs an `EmitStoreLongRmw` (low-word-first)
> emit helper (a small addition to PR-4's wide-bus helpers).

### The immediate / quick / address / X forms

- **Immediate forms (ADDI/SUBI/CMPI/ANDI/ORI/EORI)** ride `ImmEa` (`M68000Cpu.Alu.cs:372-383`): the immediate is
  read from the extension words; the dest is an EA. Same CCR rules.
- **Quick forms (ADDQ/SUBQ)** ride `QuickEa` via `QuickAlu` (`:386-403`): the immediate is 3 bits (1-8, 0→8)
  from bits 11-9 of the operword; the dest is an EA. **ADDQ/SUBQ on an An dest are special: they operate on the
  WHOLE An (no CCR, like ADDA/SUBA) — confirm against the QuickAlu body.**
- **ADDA/SUBA/CMPA** (`AddrAlu`, `:349-361`): An dest, `.w` source SIGN-EXTENDS to 32, op always full-32-bit;
  ADDA/SUBA set NO CCR; CMPA sets full-32 Cmp CCR. The size field (opmode bit 8) is already remapped to a real
  size index by the decoder (so the body sees `1=.w, 2=.l`).
- **ADDX/SUBX** (`XAlu`, `:481-508`): bit 3 (R/M) picks Dx-Dy (register) vs -(Ax)-(Ay) (memory predecrement).
  The memory form pairs **source Ax first, then dest Ay** (`:500-503`). `aluFn` honors `xIn`; the CCR is
  `ArithXAdd`/`ArithXSub` (sticky Z). NEGX rides the UnaryEa path with `NegXRule`.

## DECISIONS (the design forks — the X-bit handling is the load-bearing one)

### DECISION X — the shared CCR helper shape (how X-distinct-from-C is emitted)

The JIT needs the four CCR rules (`Arith`, `Logic`, `Cmp`, `ArithX`) as emit helpers. Two shapes:

- **(X1) One parametrized `EmitM68kArithCcr(ctx, a, b, result, size, xInSource, ccrVariant)`** that emits the
  full `Arith` body inline, where `xInSource ∈ {Zero, LiveX}` controls whether the carry/borrow reads the live
  X, and `ccrVariant ∈ {Arith, Cmp, ArithX}` controls the X-output tail (X=C / restore-old-X / sticky-Z). Plus a
  separate `EmitM68kLogicCcr` (N/Z, V=C=0, X untouched). **Pro:** one arithmetic helper covers ADD/SUB/CMP/ADDX/
  SUBX (the carry/borrow + V math is shared); the per-family difference is two small flags. Mirrors the
  interpreter's `Arith` + the `ArithAdd`/`ArithSub`/`ArithX` wrappers exactly. **Con:** the helper is large
  (carry, borrow, overflow, N, Z, the X tail) — but it is written ONCE and the data-axis gate verifies it.
- **(X2) Separate helpers per family** (`EmitM68kAddCcr`, `EmitM68kSubCcr`, `EmitM68kCmpCcr`, `EmitM68kAddXCcr`,
  …). **Pro:** each is small and independently readable. **Con:** duplicates the carry/borrow/overflow math 5×;
  more surface to keep in sync (the interpreter deliberately centralized this — ADR 0007's CCR-centralization
  rationale).

> **RECOMMENDATION: X1 (one parametrized arithmetic CCR helper + a separate logic helper).** Rationale: it
> mirrors the interpreter's `Arith`-with-wrappers structure one-for-one (the lowest-divergence-risk shape), it is
> the Z80 precedent (`EmitZ80AddSubFlags` is one helper parametrized by add/sub, `BlockCompiler.Z80.cs:372-402`),
> and it centralizes the highest-bug-density math so the data-axis gate verifies ONE implementation. The two
> control flags (`xInSource`, `ccrVariant`) are compile-time constants the arm passes per family — no runtime
> branch. **This is the load-bearing PR-5 decision; surface it but it does not need an owner checkpoint (it is
> the proven Z80 shape applied to the 68000 CCR).**

### DECISION DIR — the RegEa direction bit + the memory-dest RMW (address-once)

The RegEa forms have a direction bit (operword bit 8): `toEa=false` → dest is Dn (read the EA as a source);
`toEa=true` → dest is the memory EA (read-modify-write the EA, with Dn as the other operand). The memory-dest
form is the harder path: it must resolve the dest EA ONCE, read the old value, compute the result, and write
back to the SAME address (the address-once discipline — DECISION above). The JIT arm computes the dest address
into a local (`ctx.AddrLocal`), reads via `EmitM68kReadSized` from that local, computes the result, then writes
via `EmitM68kWriteSizedAt(local)` — NOT a second `EmitM68kEaWrite` (which would re-resolve and double-advance).
`.l` RMW uses the low-word-first `EmitStoreLongRmw`. **No owner decision — this is mechanical; the plan surfaces
the address-once requirement so the implementer does not double-resolve.**

### DECISION T (inherited from PR-4) — data-axis parity / coarse cycles

Per PR-4 DECISION T: `RunCaseThroughJit` asserts the DATA axis ONLY (incl. SR, where X lives) — NOT CycleCount/
prefetch. The ALU arm charges the descriptor's `BaseCycles` (the published 68000 ALU timing, from `M68kCycles`
extended in Task 1) via `EmitChargeCycles` to keep the `>= 1-cycle` budget invariant; cycle exactness is NOT
correctness-gated. So the X-bit correctness rides entirely on the SR comparison — pin the cycle table to the
published values and focus the verification on the CCR.

## Task 2 — JIT: the shared CCR-compute helpers (DECISION X1)

**Files:**
- Modify: `src/CpuEmulator.Jit/BlockCompiler.M68000.cs` (add the CCR helpers)

The parametrized arithmetic CCR helper mirrors `AluCcr.Arith` + its wrappers (the recon oracle). It takes the
operands (a, b in locals), the result (in a local), the size, and two compile-time flags: `xInSource`
(Zero | LiveX) and `ccrVariant` (Arith | Cmp | ArithX). It writes the new low byte of SR.

- [ ] **Step 1:** The X-read helper + the arithmetic CCR helper:

```csharp
    // M6 PR-5: push the live X bit (0 or 1) — (Ccr & 0x10) != 0 ? 1 : 0. Only ADDX/SUBX call this; ADD/SUB pass
    // a literal 0 (the xIn:false hard-wire, M68000Cpu.Alu.cs:262-263).
    private void EmitM68kLiveX(EmitContext ctx)
    {
        ILGenerator il = ctx.Il;
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, _m68kSR);
        il.Emit(OpCodes.Ldc_I4, 0x10); il.Emit(OpCodes.And);
        il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Cgt_Un);    // (SR & 0x10) != 0 -> 0/1
    }

    // M6 PR-5 (DECISION X1): the parametrized arithmetic CCR. Mirrors AluCcr.Arith + ArithAdd/ArithSub/Cmp/ArithX
    // (M68000Cpu.Alu.cs:227-303). aLocal/bLocal hold the masked inputs; resultLocal the masked result; size 0/1/2.
    //   xInSource: M68kXIn.Zero (plain ADD/SUB/CMP — xIn forced 0) | M68kXIn.LiveX (ADDX/SUBX — read the live X).
    //   variant:   Arith (X = C output) | Cmp (X restored from old) | ArithX (xIn input + sticky Z).
    //   isSub:     true for SUB/CMP/SUBX; false for ADD/ADDX.
    // Computes c, v, n, z exactly as the oracle, builds the new CCR byte, and writes SR = (SR & 0xFF00) | ccr.
    private void EmitM68kArithCcr(EmitContext ctx, LocalBuilder aLocal, LocalBuilder bLocal,
                                  LocalBuilder resultLocal, int size, M68kXIn xInSource, M68kCcrVariant variant,
                                  bool isSub)
    {
        ILGenerator il = ctx.Il;
        uint m = size == 0 ? 0xFFu : size == 1 ? 0xFFFFu : 0xFFFFFFFFu;
        uint sb = size == 0 ? 0x80u : size == 1 ? 0x8000u : 0x80000000u;

        // xIn (0 or 1) into a local:
        if (xInSource == M68kXIn.LiveX) EmitM68kLiveX(ctx); else il.Emit(OpCodes.Ldc_I4_0);
        il.Emit(OpCodes.Stloc, ctx.HiLocal);   // reuse HiLocal as xInLocal

        // r = result & m (already masked by the caller, but mask defensively); n = (r & sb)!=0; z = r==0.
        // c, v per the add/sub branch (use ulong math for carry/borrow — emit via long ops or a small helper).
        // ... emit the carry/borrow/overflow exactly as AluCcr.Arith (this is the large, write-once core) ...
        // Build ccr: start from (oldCcr & ~0x1F) [Arith/ArithX] or compute then mask per variant.
        //   if (n) |= 0x08; if (z) |= 0x04; if (v) |= 0x02; if (c) |= 0x01;
        //   Arith:  if (c) |= 0x10 else &= ~0x10                     (X = C)
        //   Cmp:    ccr = (ccr & ~0x10) | (oldCcr & 0x10)            (X restored)
        //   ArithX: ccr &= ~0x04; if (resultZero) ccr |= (oldCcr & 0x04)   (sticky Z; X already = C from Arith tail)
        // Finally: SR = (ushort)((SR & 0xFF00) | ccr).
    }

    private enum M68kXIn { Zero, LiveX }
    private enum M68kCcrVariant { Arith, Cmp, ArithX }
```

> **Builder note — emit the carry/borrow with ulong math.** The oracle uses `ulong` for the carry/borrow
> (`(ulong)(a&m) + (b&m) + xIn`). In IL, compute with `Conv_U8`/`Add`/`And`/`Clt` so the carry out of bit-size
> is captured (e.g. for the add: `full = (ulong)a + (ulong)b + xIn; c = (full & ~m) != 0`). The overflow `v` is
> the pure-int sign-bit formula (`((a^r) & (b^r)) & sb) != 0` for add; the sub variant per the oracle). **This
> helper is the single highest-bug-density piece — write it as a verbatim transcription of `AluCcr.Arith`, then
> let the data-axis SR comparison (Task 6) verify it against the interpreter.** Do NOT optimize the flag math;
> match the oracle bit-for-bit.

## Task 3 — JIT: the RMW low-word-first long-store helper

**Files:**
- Modify: `src/CpuEmulator.Jit/BlockCompiler.cs` (add `EmitStoreLongRmw` beside PR-4's `EmitStoreLong`)

The 68000 `.l` read-modify-write (a memory-dest ALU op) writes **low word first** (`WriteLongBusRmw`,
`M68000Cpu.cs:218-222`) — the reverse of MOVE.l's high-word-first store. The data-axis RESULT is identical (the
final memory is the same long); the order matters only for the trace (which the JIT gate ignores, T2), BUT the
emit helper should mirror the interpreter to be correct-by-construction:

```csharp
    // M6 PR-5: write a long as two .w transactions LOW WORD FIRST (the 68000 RMW write-back order, WriteLongBusRmw,
    // M68000Cpu.cs:218-222). Stack: ..., address(uint), value(uint). The DATA result equals EmitStoreLong's
    // (same final memory); only the .w order differs (trace-only, which the JIT gate ignores — PR-4 T2). Used by
    // the memory-dest ALU RMW forms.
    private void EmitStoreLongRmw(EmitContext ctx)
    {
        ILGenerator il = ctx.Il;
        il.Emit(OpCodes.Stloc, ctx.DataLocal);   // value
        il.Emit(OpCodes.Stloc, ctx.AddrLocal);   // address
        EmitMarkDirty(ctx, ctx.AddrLocal);
        // low word at addr+2 first:
        EmitLoadBus(ctx); il.Emit(OpCodes.Ldloc, ctx.AddrLocal); il.Emit(OpCodes.Ldc_I4_2); il.Emit(OpCodes.Add);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Conv_U2); il.Emit(OpCodes.Callvirt, MWrite16);
        // high word at addr:
        EmitLoadBus(ctx); il.Emit(OpCodes.Ldloc, ctx.AddrLocal);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Ldc_I4, 16); il.Emit(OpCodes.Shr_Un);
        il.Emit(OpCodes.Conv_U2); il.Emit(OpCodes.Callvirt, MWrite16);
    }
```

> **Builder note:** since the JIT gate ignores the trace (T2), `EmitStoreLong` (high-word-first) would produce
> the SAME data-axis result for an RMW. So `EmitStoreLongRmw` is optional for DATA-axis parity — but emit it
> anyway for correctness-by-construction (a later cycle-exact JIT phase would need it, and it costs nothing).
> If the implementer prefers to defer it, reuse `EmitStoreLong` for the RMW and note the trace-order divergence
> as a known, gate-invisible difference. **Recommend emitting it (low cost, future-proof).**

- [ ] **Step 2:** `EmitM68kAlu` — the driver mirroring `BinaryAluExecute`. Decode the operword (DECISION P3),
  determine the family (from `d.Mnemonic`), read A/B per the direction bit (DECISION DIR), emit the pure op,
  write the result (Dn-partial or memory-RMW-address-once), set the CCR via the shared helper:

```csharp
    // M6 PR-5: the 68000 integer-ALU emit arm. Mirrors BinaryAluExecute (M68000Cpu.Alu.cs:55-139) on the DATA
    // axis (incl. SR/X). Family = d.Mnemonic. The direction bit (operword bit 8, RegEa forms) picks Dn-dest vs
    // memory-EA-dest (RMW, address-once). Per-family CCR via EmitM68kArithCcr (Arith/Cmp/ArithX) or the reused
    // EmitM68kMoveCcr (Logic). xIn = 0 for plain ADD/SUB; live X for ADDX/SUBX.
    private void EmitM68kAlu(EmitContext ctx, ushort pc, OpcodeDescriptor d)
    {
        ILGenerator il = ctx.Il;
        ushort operword = _bus.Read16(pc);
        int size = M68kSizeFromKey(d);
        var fam = M68kAluFamily(d.Mnemonic);    // Add/Sub/And/Or/Eor/Cmp/AddX/SubX + the Imm/Quick/Addr variants

        switch (fam.Shape)
        {
            case M68kAluShape.RegEa: EmitM68kAluRegEa(ctx, pc, d, operword, size, fam); break;   // ADD/SUB/AND/OR/EOR/CMP register/EA
            case M68kAluShape.ImmEa: EmitM68kAluImmEa(ctx, pc, d, operword, size, fam); break;   // ADDI/SUBI/ANDI/ORI/EORI/CMPI
            case M68kAluShape.QuickEa: EmitM68kAluQuickEa(ctx, pc, d, operword, size, fam); break;// ADDQ/SUBQ
            case M68kAluShape.AddrEa: EmitM68kAluAddrEa(ctx, pc, d, operword, size, fam); break; // ADDA/SUBA/CMPA
            case M68kAluShape.XAlu: EmitM68kAluX(ctx, pc, d, operword, size, fam); break;        // ADDX/SUBX
        }
        EmitChargeCycles(ctx, d.BaseCycles);    // coarse cycle charge (PR-4 DECISION T)
    }
```

- [ ] **Step 3:** `EmitM68kAluRegEa` — the register/EA form with the direction bit + the memory-RMW address-once:

```csharp
    // M6 PR-5: the RegEa form (ADD/SUB/AND/OR/EOR/CMP Dn,<ea> or <ea>,Dn). Direction bit (operword & 0x100):
    //   toEa=false: dest=Dn; a=Dn, b=read(ea). result=a op b. write Dn (size-aware). CCR(a,b,result).
    //   toEa=true:  dest=ea(memory); resolve ea ONCE, a=read(ea), b=Dn. result=a op b. write-back ea (RMW).
    // CMP (writesResult:false) computes a-b for CCR but writes nothing.
    private void EmitM68kAluRegEa(EmitContext ctx, ushort pc, OpcodeDescriptor d, ushort operword, int size, M68kAluFam fam)
    {
        ILGenerator il = ctx.Il;
        int dnReg = (operword >> 9) & 7, srcMode = (operword >> 3) & 7, srcReg = operword & 7;
        bool toEa = (operword & 0x0100) != 0 && fam.HasDirection;   // CMP/AND-immediate etc. fix the direction
        int extIndex = 0;

        if (!toEa)
        {
            // a = Dn (sized), b = read(ea) (sized)
            EmitM68kEaRead(ctx, srcMode, srcReg, size, ref extIndex); il.Emit(OpCodes.Stloc, ctx.LoLocal);   // b
            EmitLoadDataRegSized(ctx, $"D{dnReg}", size); il.Emit(OpCodes.Stloc, ctx.AddrLocal);             // a (reuse AddrLocal as aLocal — confirm no clobber)
            // result = a op b
            EmitM68kAluOp(ctx, fam, ctx.AddrLocal, ctx.LoLocal, size); il.Emit(OpCodes.Stloc, ctx.SumLocal); // result
            if (fam.WritesResult) { il.Emit(OpCodes.Ldloc, ctx.SumLocal); EmitStoreDataRegSized(ctx, $"D{dnReg}", size); }
            EmitM68kFamilyCcr(ctx, fam, ctx.AddrLocal, ctx.LoLocal, ctx.SumLocal, size);
        }
        else
        {
            // memory dest: resolve ea ONCE into a local; a = read(ea); b = Dn; result = a op b; write-back (RMW)
            EmitM68kResolveEaAddr(ctx, srcMode, srcReg, size, ref extIndex);   // leaves the dest address in ctx.AddrLocal
            il.Emit(OpCodes.Ldloc, ctx.AddrLocal); EmitM68kReadSized(ctx, size); il.Emit(OpCodes.Stloc, ctx.LoLocal); // a = read(ea)
            EmitLoadDataRegSized(ctx, $"D{dnReg}", size); il.Emit(OpCodes.Stloc, ctx.HiLocal);                        // b = Dn (HiLocal reused as bLocal — CAREFUL: EmitM68kArithCcr reuses HiLocal for xIn; spill if needed)
            EmitM68kAluOp(ctx, fam, ctx.LoLocal, ctx.HiLocal, size); il.Emit(OpCodes.Stloc, ctx.SumLocal);           // result
            il.Emit(OpCodes.Ldloc, ctx.AddrLocal); il.Emit(OpCodes.Ldloc, ctx.SumLocal); EmitM68kWriteSizedRmw(ctx, size);  // write-back to the SAME ea (low-word-first for .l)
            EmitM68kFamilyCcr(ctx, fam, ctx.LoLocal, ctx.HiLocal, ctx.SumLocal, size);
        }
    }
```

> **Builder note — local allocation discipline (the X-bit trap).** `EmitM68kArithCcr` reuses `ctx.HiLocal` as
> the `xIn` local (Task 2). If the RegEa form also uses `HiLocal` for the `b` operand, the CCR helper will
> clobber it. **Allocate dedicated locals for a/b/result** (e.g. add `ctx.ALocal`/`ctx.BLocal`/`ctx.ResultLocal`
> to `EmitContext`, or carefully sequence so the CCR helper reads a/b BEFORE it computes xIn into HiLocal). The
> `ResolveEaDest`-address-once requires the dest address in a stable local (`ctx.AddrLocal`) that survives the
> read+compute+write — confirm `AddrLocal` is not clobbered by `EmitM68kReadSized`/`EmitM68kAluOp`. **This local
> juggling is the most error-prone part of PR-5; prefer dedicated `EmitContext` locals over reuse.** Surface a
> tripwire: a JIT unit test that ADDs to a memory `(An)+` dest and asserts both the memory result AND the An
> post-increment (catches a double-resolve or a clobbered address).

- [ ] **Step 4:** `EmitM68kFamilyCcr` — dispatch to the right CCR helper per family:

```csharp
    // M6 PR-5: route to the per-family CCR helper. ADD/SUB -> EmitM68kArithCcr(Arith, xIn=Zero); CMP ->
    // EmitM68kArithCcr(Cmp, xIn=Zero); ADDX/SUBX -> EmitM68kArithCcr(ArithX, xIn=LiveX); AND/OR/EOR ->
    // EmitM68kMoveCcr (the Logic rule — reused from PR-4). ADDA/SUBA -> NO CCR; CMPA -> EmitM68kArithCcr(Cmp).
    private void EmitM68kFamilyCcr(EmitContext ctx, M68kAluFam fam, LocalBuilder a, LocalBuilder b, LocalBuilder result, int size)
    {
        switch (fam.Ccr)
        {
            case M68kCcr.Arith:  EmitM68kArithCcr(ctx, a, b, result, size, M68kXIn.Zero,  M68kCcrVariant.Arith,  fam.IsSub); break;
            case M68kCcr.Cmp:    EmitM68kArithCcr(ctx, a, b, result, size, M68kXIn.Zero,  M68kCcrVariant.Cmp,    isSub: true); break;
            case M68kCcr.ArithX: EmitM68kArithCcr(ctx, a, b, result, size, M68kXIn.LiveX, M68kCcrVariant.ArithX, fam.IsSub); break;
            case M68kCcr.Logic:  EmitM68kMoveCcr(ctx, result, size); break;   // V=C=0, X untouched (reused)
            case M68kCcr.None:   break;                                       // ADDA/SUBA set no CCR
        }
    }
```

> **Builder note — ADDX/SUBX (the X-INPUT family, the highest-risk arm).** The `-(Ax),-(Ay)` form predecrements
> BOTH address registers (source Ax first, then dest Ay, `M68000Cpu.Alu.cs:500-503`), reads both via the sized

> sticky-Z is the other trap: Z is only re-set from the OLD Z when the result is zero — never freshly set. The
> data-axis SR comparison (Task 6) over the ADDX/SUBX corpus is the gate; the corpus stresses exactly the
