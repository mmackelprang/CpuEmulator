## 0. The one-paragraph close-state M5 is driving toward

The 8086/8088 EXECUTES the real-mode integer ISA: a NEW byte-granular variable-length prefix-stacking decode
front-end (`EmitX86DecodeWalk`, the third decode arm beside the 6502/Z80 byte walk and the 68000 field walk)
feeds the *unchanged* opaque-key / computed-length / `DecodeResult` back-end; a NEW `EmitX86Ea` + a
segment-resolution layer forms `(seg<<4)+offset & 0xFFFFF` over the *unchanged* flat 20-bit little-endian
`AddressSpace`; the hand-written `M8086Cpu` partial runs the MOV / ALU / shift-rotate-stack /
control-strings-interrupts families, gated **TomHarte-green on the `SingleStepTests/8088` `v2/*.json.gz`
`regs`+`ram` final state (the DATA axis)**; the 8088 prefetch-queue + per-clock `cycles` trace + cycle count
(the TIMING axis) land in a separate LATE sub-milestone; and the 8086 runs through the generic JIT as
all-fallback (tier parity, zero JIT-assembly change). **Every 6502 / Z80 / 68000 artifact stays
byte-identical at every step** (their `RegeneratedSpecTests` guard + their TomHarte/ZEX gates), because the
8086 work is opt-in via a new decode-structure variant and gated to the x86 path in the generator.

## 1. CRITICAL SCHEDULING CONSTRAINT — do not start M5 until `CpuEmitter.cs` is free

**M5's generator work edits `src/CpuEmulator.Generators/CpuEmitter.cs`** — the same file the in-flight 68000
timing work is rewriting:

- **PR #47 (`feat/m4-5d-2b-cycle-timing`, "M4.5d-2b (partial): the deferred-refill seam + 13 families
  cycle-exact") is OPEN** at plan time. It reworks the FieldGrammar `Step` cycle-charge + the bus-transaction
  model in `CpuEmitter.cs` (per `2026-06-16-m4-5d-2-timing-prefetch.md` §4 T5, "this touches the generator's
  FieldGrammar Step emit, `CpuEmitter.cs:231`").
- M4.5d-2a (PR #44) already merged the stateful prefetch-queue rewrite; 2b is the remaining timing PR.

**Binding rule:** M5.1 (the first M5 code PR) starts only AFTER PR #47 (and any 2b follow-on splitting IPL/
address-error per that plan's DD1) has merged to `main` and `CpuEmitter.cs` is no longer under active
rewrite. Rationale: the 8086 adds `EmitX86DecodeWalk` *beside* the two existing decode arms and adds an x86
Step arm; both touch the same emitter regions (the `EmitDecodeWalk` router at `CpuEmitter.cs:4014`, the Step
emit, the keyed-descriptor table). Landing M5 generator work concurrently with the 2b rewrite guarantees a
merge conflict in the highest-risk file in the repo and risks a silent cross-arm regression.

**Contention-minimizing sequencing baked into this plan:** the EARLY M5 tasks deliberately touch
`CpuEmitter.cs` as little as possible —
- **M5.1 (state)** edits the *dataset/spec* path and the hand-written partial, NOT the emitter (per ADR 0005,
  the state half is near-total reuse; the register-file + FLAGS land via the spec, not new emitter code).
- **M5.2 (decode front-end)** is the FIRST heavy `CpuEmitter.cs` PR — and is therefore the natural gate: it
  cannot proceed until 2b frees the file, and it lands the new arm in isolation against a synthetic fixture
  (no real 8086 dataset depends on it yet), exactly the M4.3a discipline.
- This ordering means the only hard `CpuEmitter.cs` collision risk (M5.2) is the one explicitly fenced behind
  the 2b merge.

> If the owner wants M5 prep to begin before 2b merges, the only safe pre-work is the **NON-emitter** slices:
> the M5.4 importer-arm + dataset scaffolding (a new `tools/` arm, disjoint from `CpuEmitter.cs`) and the
> M8088 loader (test infrastructure, disjoint from `CpuEmitter.cs`). Those can be developed on a branch off a
> pre-2b main and rebased; flagged in §9 Q5. The DEFAULT plan keeps the documented dependency order.

## 3. The DATA-axis vs TIMING-axis separation (binding — ADR 0006 Decision 6, the M4.5a lesson-learned)

The plan separates the two axes from the START and never makes a timing artifact a blocking precondition for a
correctness PR (the M4.5a gate-scoping fix, generalized to M5):

- **DATA / correctness axis (early, primary; M5.5a–d gate on it).** After each instruction, the final
  register file (merged-sparse) + final RAM match the vector's `final`, with `flags` masked by
  `metadata.json`. Needs: decode front-end, ModR/M+EA+segmentation, op bodies, flag computation. Does NOT need
  the per-clock `cycles` trace, the cycle count, or the prefetch `queue` final state.
- **TIMING axis (late, separate; M5.5e).** The 8088 BIU prefetch-queue model (to assert `queue`), the
  11-element per-clock `cycles` bus-trace diff, the cycle count. Genuinely harder than the 68000's
  (per-clock pin states, not per-bus-cycle tuples). Its own sub-milestone, AFTER the correctness axis is green
  across the integer ISA. **It is NOT a precondition for any of M5.5a–d.**

Concretely: the M8088 runner ships with a **data-axis mode** (diffs `regs`-merged + `ram`, masks `flags`,
IGNORES `cycles`/`queue`) so a correct MOV/ALU body goes green without the timing machinery existing — exactly
how the 680x0 runner's `timingAxis:false` default works (`M68000TomHarteRunner.cs:67-72`).

### M5.3 — ModR/M EA + segmentation

**Branch:** `feat/m5-3-x86-ea-segmentation`. **Files:** `src/CpuEmulator.Generators/CpuEmitter.cs`
(`EmitX86Ea`); `src/CpuEmulator.Cpus.M8086/M8086Cpu.Ea.cs` (the segment-resolution helper + the EA-operand

`tests/CpuEmulator.Tests/Generators/M8086EaTests.cs` (synthetic + unit).

**`EmitX86Ea` (the new EA emitter; the contract):** a small `switch` on `(mod, r/m)` producing
`base(BX/BP/none) + index(SI/DI/none) + disp(0/8/16)`, **wrapped at 16 bits BEFORE the segment shift** (the
segment-relative wrap quirk: `[BX+SI]` whose 16-bit sum exceeds `0xFFFF` wraps within the segment, it does NOT
carry into the segment base). Reuses the base+signed-displacement seam of `EmitZ80IndexedEa` (`:2279`). NO
write-back side effect (the 8086 has no `(An)+`/`-(An)` — string ops step `SI`/`DI` in the string-op body,
driven by `DF`, NOT in the EA layer). The 16-bit `(mod,r/m)` offset table:

| `mod=00/01/10`, `r/m` | base+index | default segment |
|---|---|---|
| 000 | `[BX+SI]` | DS |
| 001 | `[BX+DI]` | DS |
| 010 | `[BP+SI]` | **SS** (uses BP) |
| 011 | `[BP+DI]` | **SS** (uses BP) |
| 100 | `[SI]` | DS |
| 101 | `[DI]` | DS |
| 110 | `[BP]` (but `mod=00,r/m=110` ⇒ `disp16` direct) | **SS** (uses BP) / DS for the disp16-direct |
| 111 | `[BX]` | DS |

**The segment-resolution layer (in the partial, NOT the bus — ADR 0005 Decision 2(A)).** The physical address
is formed in the partial:

```csharp
    /// <summary>Form the 20-bit physical address from a segment register and a 16-bit offset (ADR 0005 D2).
    /// physical = (seg << 4) + offset, masked to 20 bits. The offset has ALREADY wrapped at 16 bits in the EA
    /// computation (the segment-relative wrap quirk); this only does the shift + the 20-bit mask.</summary>
    private static uint Physical(ushort segment, ushort offset)
        => (uint)(((segment << 4) + offset) & 0xFFFFF);
```

The default-segment-per-mode rule (code fetch ⇒ CS never overridable; stack/BP-based ⇒ SS; general data ⇒ DS;
string `ES:DI` destination ⇒ ES not overridable, source `SI` ⇒ DS overridable) is **data carried on the
resolved EA descriptor**; the segment-override prefix (consumed by `EmitX86DecodeWalk` in M5.2) is threaded to
this layer as "use this segment instead of the default." The `reg`-as-register-vs-extension dual role is a
`regIsExtension` flag per opcode (data, not a code branch).

**The bus is UNCHANGED.** No `IAddressSpace` change; the flat 20-bit LE `AddressSpace` is the physical bus.
The 8088 two-byte-cycle 16-bit access falls out of the LE wide-method composition (`Read16` = two `Read8`) for
free — the byte-bus trace the vectors record.

**Per-task gate (M5.3):** synthetic + unit proofs green (each `(mod,r/m)` form's offset; the
`mod=00,r/m=110`⇒disp16 exception; the 16-bit-wrap on a near-`0xFFFF` `[BX+SI]`; `Physical` for a few
seg:offset pairs incl. a 20-bit-wrap case like `seg=0xFFFF,offset=0xFFFF` → `0xFFFEF`; the BP⇒SS default; the
override replacing the default). `RegeneratedSpecTests` green (the EA emitter is gated to the x86 path; the

sequence (`FLAGS`, then `CS`, then `IP`) + the `IF`/`TF` clear (partial policy); `IRET` pops `IP`,`CS`,`FLAGS`.
Note the **`IF` polarity is opposite the 6502 `I`** (8086 `IF=1` ENABLES) — partial policy, the `Flag` name
`I` is reused. The synchronous `INT n`/`INT3`/`INTO`/divide-error vectors are fallback-class ops
(`NeedsFallback`+`EndsBlock`, the BRK precedent) — automatic since the 8086 is all-fallback in M5. The
`TF`-driven single-step (post-instruction trap, vector 1) is a TIMING-adjacent post-step — DISCLOSE+defer the
`cycles`-coupled bits to M5.5e; the no-wait-state 8088 set does NOT exercise `TF`/async interrupts (fixtures
README), so the data-axis gate does not require them. **Gate:** the control/string/IN-OUT/INT opcode files
data-axis green; synthetic tests (the `REP`/`CX`/`DF` loop; the `INT n` push+vector sequence; far `CALL`/`RET`
seg:offset); byte-identity guard; an honest per-family deferral list if any class resists (never faked green).

**M5.5 honest close-state:** the 8086 EXECUTES the real-mode integer ISA, DATA-axis green across the
`SingleStepTests/8088` `regs`+`ram` final state (merged-sparse, flags-masked); the `queue`/`cycles` timing
axis is parsed-but-not-asserted (M5.5e); any disclosed per-class deferral is listed, not faked.
6502/Z80/68000 byte-identical.

## 6. The 8088 vector-gate approach (summary)

- **Source:** `SingleStepTests/8088` `v2/*.json.gz` — GZIP-compressed, OPCODE-HEX-keyed (`00.json.gz`,
  `88.json.gz`, `A4.json.gz`), 324 files, 10,000 cases each. Fetched by the EXISTING
  `tools/get-test-vectors-8088.ps1` → cache `<cache>/8088/v2`. Schema PINNED (ADR 0006 Decision 5 RESOLVED +
  `tests/.../TomHarte/fixtures/README.md`); a 2-real-case parse-proof fixture already committed.
- **Two gate modes (the lesson-learned baked in):**
  - **DATA / correctness (M5.5a–d, the primary gate):** after `Step`, the final register file (MERGE the
    sparse `final.regs` over `initial.regs`) + the final RAM match; `flags` is ANDed with the per-opcode
    `metadata.json` `flags-mask` before comparison. IGNORES `cycles`/`queue`.
  - **TIMING (M5.5e, the late gate):** the 4-byte prefetch `queue` final state + the 11-element per-clock
    `cycles` trace + the cycle count.
- **Loader divergences from the 680x0 loader (the three PINNED):** hex-keyed resolver (reuse the 6502/Z80
  `TomHarteVectors` shape, keep the `GZipStream`); merge-sparse-`final` (not replace); AND the `flags-mask`.
- **Discipline (every prior CPU's TomHarte gate):** skip-when-absent attribute (`M8088TomHarteTheory`/`-Fact`,
  mirroring `M68000TomHarteTheoryAttribute`); the heavy sweep runs under `-c Release` with vectors fetched
  first; the per-file split (one file == one Fact == one collection) so files distribute across cores (the
  `2026-06-16-parallelize-tomharte-sweep.md` precedent); an honest per-class deferral list, never faked green.

## 7. Byte-identity invariant (the every-stage regression guard)

At EVERY task's gate, run `dotnet test --filter "FullyQualifiedName~RegeneratedSpecTests"` (the 6502/Z80/68000
byte-identity guard) PLUS the full 6502/Z80/68000 suites. The 8086 work is additive and opt-in:
- the new `Flag` members (M5.1) are unreferenced by the other specs;
- the new `X86DecodeStructure` variant (M5.2) is absent on 6502/Z80/68000, so their decode walks are untouched;
- `EmitX86DecodeWalk`/`EmitX86Ea` (M5.2/M5.3) are inside the x86-path branch in `CpuEmitter.cs`;
- the x86 importer arm (M5.4) is disjoint from the opcode-row + field-grammar arms;
- the M8086 spec/project + the M8088 loader are net-new.

A change to any of the above that perturbs a 6502/Z80/68000 `.g.cs` is a regression — the guard catches it.
(The one explicit care item: when M5.2 retires/supersedes the synthetic ModR/M placeholder, confirm the
synthetic-CPU test that exercises it is migrated or kept as the degenerate proof — no SHIPPED CPU declares
`ModRmOpcodes`, so no real spec moves.)

## 8. The merge-gate definition (every stage)

A stage's PR merges only when ALL hold (the M4.5x merge-gate, generalized):
1. **Full suite green** under `dotnet test` (the synthetic/unit tests for the stage + everything prior).
2. **6502 / Z80 / 68000 byte-identical** — `RegeneratedSpecTests` green + their full suites + their
   TomHarte/ZEX gates unaffected (the additive/opt-in invariant, §7).
3. **`dotnet build --no-incremental -warnaserror` clean.**
4. **The stage's own gate** (per §5): M5.1 = state round-trip; M5.2 = the synthetic variable-length-decode
   fixture; M5.3 = the EA/segmentation synthetic+unit proofs; M5.4 = the regen guard + the cross-source diff +
   the loader parse-proof; M5.5a–d = the family's 8088 DATA-axis files green under `-c Release` with vectors
   present (executed count shown; honest deferral list if any); M5.5e = the TIMING axis green (its own plan);
   M5.6 = JIT data-axis tier parity == interpreter data-axis sweep.
5. **Pre-merge review** pointed at the stage's highest-risk surface (M5.2's variable-length walk; M5.3's
   segment-wrap; M5.5b's flag/BCD subtleties).
6. **Branch per stage → PR** (the global CLAUDE.md branch policy; implementation never lands straight to main).
7. **Honesty** (the M4.5x discipline): any instruction-class whose data-axis state resists reconciliation is
   DISCLOSED + deferred per-class, never faked green; the timing axis (M5.5e) is explicitly NOT a precondition
   for M5.5a–d.

## 9. Open questions for the owner

These are genuine forks the plan does NOT silently resolve (the early tasks proceed on the recommended default;
each is settle-able just-in-time without blocking):

1. **Segment-register role (ADR 0005 Decision 1 / open Q1).** `CS/DS/ES/SS` as `General` (recommended,
   following the 68000 `USP`/`SSP`-stay-in-the-partial precedent) vs a new `SegmentRegister` role.
   *Default taken: `General`.* Revisit at M5.1-T2 only if the disassembler/monitor needs the tag to render
   `CS:` prefixes — unlikely.

2. **Auxiliary-carry flag name (ADR 0005 Decision 3 / open Q2).** Reuse `H` for AF (recommended — semantically
   identical to the BCD half-carry) vs add a dedicated `Af` member. *Default taken: `H`.* One-line additive
   either way; the BCD op bodies (M5.5b — `DAA`/`AAA`) are the only consumers, so settle whichever reads
   cleaner there with the real bodies in hand.

3. **`SP` register role (ADR 0005 Decision 1 / open Q3).** `SP` as `RegisterRole.StackPointer` (recommended —
   the 8086 has one SP, the natural tag) vs `General`. *Default taken: `StackPointer`.* Confirm at M5.1-T2 the
   generated `Step`/monitor actually consumes the role for the 8086 — if not, `General` is harmless.

4. **Where the state-only spec is authored first (M5.1 fork).** Hand-author `M8086Spec.cs` state-only in M5.1
   (recommended — decouples M5.1 from the M5.4 importer arm; M5.4 regenerates it and the regen guard pins it,
   exactly as M4.1's 68000 spec preceded the M4.4a importer) vs build the x86 importer arm first and generate
   even the state-only spec. *Default taken: hand-author in M5.1; the regen guard is added in M5.4.* Confirms
   the M4.1→M4.4a precedent applies.

5. **Pre-2b parallelism (the §1 scheduling fork).** The DEFAULT plan starts M5.1 only after PR #47 (M4.5d-2b)
   merges and frees `CpuEmitter.cs`. If the owner wants to overlap, the ONLY `CpuEmitter.cs`-disjoint pre-work
   is the M5.4 importer arm + the M8088 loader (test/tooling, no emitter edit) on a branch off pre-2b main,
   rebased after 2b. *Default taken: keep the documented order (no overlap).* The owner decides whether the
   overlap is worth the rebase.

6. **The exact `X86DecodeStructure` variant record shape (ADR 0006 §4 item 1 — explicitly just-in-time).** The
   prefix-role map + the per-opcode has-ModR/M / immediate-length / group metadata fields settle when M5.2/M5.4
   have real 8086 opcode-table rows in hand from the extraction. The COMMITMENT is firm (a new byte-granular
   variable-length arm, real ModR/M length, prefix stacking, opaque key reused); only the record's field
   names/shape are open. *No default needed before M5.2 implementation.*

7. **Whether `REP`-string + the BCD `AAM`/`AAD` immediate-base byte need an operand-model extension (ADR 0006
   §4 item 2).** Depends on the operand model after M5.3. The `REP` loop is the Z80-block-op precedent (a
   `CX`-counted one-instruction loop); the BCD immediate-base is a small operand. *Default taken: no extension
   anticipated; finalize at M5.5b/M5.5d with the real bodies.*

## 10. Risk

**M5.2 (the x86 decode front-end) is the highest-risk M5 abstraction** — the most input-dependent length math
of the four CPUs (prefixes × ModR/M × `w`/`s` × opcode-group), the symmetric analogue of the 68000's field
walk (the highest-risk M4 abstraction). **Mitigation:** ship the SHAPE + the synthetic variable-length-decode
fixture BEFORE any 8086 dataset depends on it (the M4.3a/M3.1b discipline), and gate it behind the §1 2b merge
so it never collides with the in-flight `CpuEmitter.cs` rewrite. **M5.5b (ALU/BCD/flags)** is the densest
correctness pocket (parity = low-byte even-parity, aux-carry, the BCD adjusts) — TomHarte-caught, bounded by
synthetic flag-edge unit tests before the sweep. **M5.5e (timing)** is genuinely harder than the 68000's
(per-clock pin states) — which is exactly why it is sequenced LATE and separate, never a precondition for the
correctness axis.
