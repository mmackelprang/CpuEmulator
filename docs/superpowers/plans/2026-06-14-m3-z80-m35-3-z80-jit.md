**Goal:** make the M2 6502-shaped `BlockCompiler`/`JittedCpu`/`BlockDelegate` GENERIC over the CPU type +
register file + keyed decode (ADR Decision 7, J1/J2/J3), drive the complete Z80 interpreter through that
generic compiler with EVERY Z80 op as an interpreter fallback first, and prove tier parity (the Z80
TomHarte sweep AND ZEXALL run THROUGH the JIT produce byte-identical final state to the interpreter) — all
WITHOUT regressing the 6502 JIT (byte-identical 6502 artifacts + the existing 6502 JIT tier-parity gate stay
green). No Z80 IL is emitted in 5-3a; that is 5-3b.

**Architecture:** The JIT today is, by construction (J1/J2/J3 in ADR §Decision-7), *a 6502 JIT wearing a
generic descriptor table*. The descriptor **table** is already CPU-agnostic (`OpcodeDescriptor`,
`JitDescriptorsByKey`, the generated `DescriptorFor(uint)` + structured decode walk all exist and the Z80
already emits them as well-formed fallback rows); the **compiler that consumes it** is not — it is typed to
`Mos6502Cpu` end to end. 5-3a generalizes the compiler. The de-risking spine (ADR §Risks, scoped-plan §PR
breakdown) is **all-fallback first**: a Z80 block in which every op emits an `inner.Step()` callout is
trivially tier-identical (it *is* the interpreter), so it proves the generic COMPILER works — the
discovery walk, the keyed `DescriptorFor`, the per-CPU `BlockDelegate`, the data-driven register file, the
cycle/budget/dirty/chain machinery, the dispatcher — before any Z80 IL exists. The intermediate is itself a
shippable PR.

**Tech Stack:** C# .NET 10, `System.Reflection.Emit` (`DynamicMethod` + `ILGenerator`), the Roslyn source
generator (`CpuEmulator.Generators`), `CpuEmulator.Jit`, xUnit + the SingleStepTests/z80 vectors + the
ZEXDOC/ZEXALL CP/M `.com` harness (M3.5-2).

### J2 — the register file (`FA/FP/FPC` baked; the operand path is already data)

`BlockCompiler.cs:52-54` bakes `FA/FP/FPC` to `typeof(Mos6502Cpu).GetField`. The OPERAND registers already
resolve by name through `_regFields` (`BlockCompiler.cs:43,88-91` — the M3.1a J2 partial). `EmitHelpers.cs:85`
has a `FieldInfoIndex { X, Y }` enum + `EmitLoadRegByte` that maps to `"X"`/`"Y"` by NAME through `RegField`
— so the indexed-mode register path is already data-driven; only the `FieldInfoIndex` enum NAME is
6502-flavored (a cosmetic finding, not a blocker, since the Z80 indexed-mode arms are 5-3b). For 5-3a the
register file is NOT exercised by any emitted Z80 op (everything falls back), so J2's only 5-3a obligation
is: the per-CPU register map (`_regFields`) must build successfully against the Z80's 36-entry `Registers`
table (`Z80Spec.cs:21-58` — A/F/B/C/D/E/H/L, the alt set A_…L_, I/R, IXh/IXl/IYh/IYl, WZ/SP/PC, and the
16-bit pair-views AF/BC/DE/HL/AF_/BC_/DE_/HL_/IX/IY). CONFIRM each name maps to a field on `Z80Cpu` (the
8-bit halves + I/R are fields; the 16-bit pairs are PROPERTIES — see the risk below).

### J3 — keyed-descriptor consumption (mostly DONE; `Discover` is the work)

The generated keyed table + resolver ALREADY EXIST for the Z80: `JitDescriptorsByKey` (a
`Dictionary<uint, OpcodeDescriptor>`, `CpuEmitter.cs:3523`), the structured `Decode(IFetchStream)` walk
(`CpuEmitter.cs:3861-3942` — handles prefix/compound DDCB-4-byte/sub-field/ModR/M), and
`DescriptorFor(uint)` (`CpuEmitter.cs:3949-3951`, dictionary lookup → `Undefined` sentinel). `BlockCompiler.Discover`
(`BlockCompiler.cs:101-115`) already advances PC by the walk's COMPUTED `r.Length` (not a static field), and
`PagesSpanned` (`:177-185`) already uses the computed length — so the compound DDCB 4-byte length (ADR J8
note, §Risks) is handled the moment `Discover` calls the Z80's `Decode`/`DescriptorFor`. J3's 5-3a work is
PURELY: route `Discover` through the per-CPU decode seam (J1 item 4) instead of the literal `Mos6502Cpu.`
statics. The Z80's `EndsBlock` classification is already correct (every Z80 class is a fallback →
`NeedsFallback` + `EndsBlock`, `CpuEmitter.cs:3661,3692`), so a Z80 block ends after the first op in 5-3a
(one fallback Step per block) — which is FINE for parity (it is exactly the interpreter, one op at a time).

### The tier-parity gate (the load-bearing 5-3a deliverable)

The 6502 precedent is exact and is the TEMPLATE:
- `Mos6502JitTomHarteTests.cs` — the per-opcode sampled sweep through `RunCaseThroughJit` (`TomHarteRunner.cs:86`).
- `KlausJitFunctionalTests.cs` — the heavy-workload run-to-trap with an EXACT cycle anchor.
- `RunCaseThroughJit` (`TomHarteRunner.cs:86-136`) — builds a `Mos6502Cpu` + `AddressSpace`, wraps in
  `JittedCpu`, drives `Run` with a one-instruction budget, diffs registers + RAM + cycle count.

5-3a mirrors this for the Z80: a `RunZ80CaseThroughJit` that builds a `Z80Cpu`, wraps in `JittedCpu<Z80Cpu>`,
drives `Run`, and diffs the FULL Z80 state (all registers + F's X/Y + WZ + Q + IM + RAM + cycle count) — the
same diff `Z80TomHarteRunner.RunCase` already does for the interpreter (`Z80TomHarteRunner.cs:24+`). Because
every Z80 op falls back to `inner.Step()`, the JIT result IS the interpreter result — so a green sweep proves
the generic compiler runs the Z80 faithfully. Plus ZEXALL through `JittedCpu<Z80Cpu>.Run` (the integration
parity proof; reuse the M3.5-2 `CpmBdosHost`).

### What 5-3a does NOT do
- Emit ANY Z80 IL (that is 5-3b). Every Z80 op is a fallback. The `FallbackEmitCount` for any Z80 block ==
  the op count.
- Touch the interrupt servicing policy (M3.5-1, already merged) or the ZEXALL harness build (M3.5-2, merged).
- Optimize anything (D9 — the post-M3 boundary; no register allocation, no Z80-specific block/chain tuning).

```csharp
// src/CpuEmulator.Core/Jit/IJitTarget.cs
using System.Reflection;

namespace CpuEmulator.Core.Jit;

/// <summary>The per-CPU static seam the generic block compiler resolves its CPU-specific reflection +
/// decode through (J1). Lets <c>BlockCompiler&lt;TCpu&gt;</c> stay generic while still emitting DIRECT
/// field access against the concrete CPU type (the baked-<see cref="FieldInfo"/> speed premise — NOT an
/// <c>ICpuCore</c>-virtual rewrite). AOT-clean: carries reflection handles + a decode delegate, never
/// <c>Reflection.Emit</c> (that is the JIT assembly's job). One generated implementation per CPU
/// (CpuEmitter emits <c>JitTarget</c>); a CPU with no DecodeStructure (6502) and one with (Z80) both fit.</summary>
public interface IJitTarget
{
    /// <summary>The concrete interpreter CPU type — the emitted block's first parameter type.</summary>
    System.Type CpuType { get; }

    /// <summary>The status/flags register field (6502 "P", Z80 "F"), resolved by name on the CPU type —
    /// the data-driven replacement for the baked <c>FP</c>.</summary>
    FieldInfo StatusField { get; }

    /// <summary>The program-counter field ("PC"), resolved by name — the baked <c>FPC</c> replacement.</summary>
    FieldInfo ProgramCounterField { get; }

    /// <summary>The accumulator field (6502 "A", Z80 "A") — the baked <c>FA</c> replacement. The 6502
    /// ALU/decimal arms reference it directly; Z80 emitted arms (5-3b) resolve their own targets via the
    /// operand register map, so this is the 6502-convention handle the shared arms use.</summary>
    FieldInfo AccumulatorField { get; }

    /// <summary>The interpreter <c>Step()</c> — the fallback callout target.</summary>
    MethodInfo StepMethod { get; }

    /// <summary>The internal <c>AdvanceCycles(long)</c> — the cycle-charge target (skipVisibility reaches it).</summary>
    MethodInfo AdvanceCyclesMethod { get; }

    /// <summary>The <c>CycleCount</c> getter — the fallback's consumed-cycle delta math.</summary>
    MethodInfo CycleCountGetter { get; }

    /// <summary>The <c>InterruptPending</c> getter — the chain-edge interrupt sample.</summary>
    MethodInfo InterruptPendingGetter { get; }

    /// <summary>Run the generated decode walk from a fetch stream (the J3 seam): returns the key + the
    /// COMPUTED length. Wraps the static <c>Decode</c> so the compiler never names a concrete CPU type.</summary>
    DecodeResult Decode(IFetchStream stream);

    /// <summary>Resolve an operation-key to its descriptor (the keyed table for a structured CPU; the
    /// dense [256] array for the 6502). Wraps the static <c>DescriptorFor</c>.</summary>
    OpcodeDescriptor DescriptorFor(uint operationKey);

    /// <summary>The CPU's declared register names — the operand register map (<c>_regFields</c>) is built
    /// from these (J2). The 6502 names A/X/Y/S/P/PC; the Z80 names its full 36-entry file.</summary>
    System.Collections.Generic.IReadOnlyList<string> RegisterNames { get; }
}
```

## 5-3b — Promote the hot Z80 ops to emitted IL (SCOPED OUTLINE — detail just-in-time)

> **Why outlined, not detailed:** the literal IL for each Z80 op (the per-arm `ILGenerator` sequence) depends

> 5-3a all-fallback ZEXALL run (which ops dominate the 46-billion-T-state run). Writing the IL now would
> guess both. Detail this with `superpowers:writing-plans` immediately before the 5-3b Builder run, using
> the 5-3a close-state's J-findings + a ZEXALL op-frequency profile.

**Goal (D7):** flip the HOT straight-line Z80 ops from `NeedsFallback` to emitted IL, re-prove tier parity.

**The emit-vs-fallback split (D7 recommendation — confirm against the 5-3a profile):**

- **EMIT (hot, straight-line, register-shape):** 8-bit `LD r,r'`/`LD r,n`/`LD r,(HL)`/`LD (HL),r` (the
  `Transfer`/`Load`/`Store` kinds — the single densest block, opcodes 0x40–0x7F); 8-bit ALU `ADD/ADC/SUB/
  SBC/AND/OR/XOR/CP A,r`/`A,n`/`A,(HL)` (`Add8`..`Cp8`); `INC r`/`DEC r` (`IncReg`/`DecReg`); 16-bit `INC rr`/
  `DEC rr`/`ADD HL,rr` (`Inc16`/`Dec16`/`Add16`); `LD rr,nn` (`Load16`); the common control flow — `JR`/`JR
  cc`/`DJNZ` (`RelJump`/`RelJumpIf`/`Djnz` — DJNZ is the hottest loop primitive, ADR J9), `JP nn`/`JP cc,nn`
  (`JumpAbs`/`JumpIf`), `CALL nn`/`CALL cc`/`RET`/`RET cc` (`CallAbs`/`CallIf`/`Ret`/`RetCc`), `RST n`
  (`Rst` — static vector, chainable, ADR J9). These carry the Z80 flag model (S/Z/Y/H/X/P/N/C) — the IL
  must set ALL eight flags + Q + WZ bit-for-bit (the interpreter is the oracle; mirror its body).
- **FALL BACK (irregular — stays interpreter):** the ED block ops (`LDIR`/`CPIR`/`OTIR` self-repeat loops —
  `EdBlock`); `DAA` (a different algorithm from the 6502 decimal arm — ADR J7, the 6502 `BlockCompiler.Decimal.cs`
  is DEAD CODE for the Z80); `EX (SP),HL`/`EXX`/`EX DE,HL`/`EX AF,AF'` (`ExSpHl`/`Exx`/`ExDeHl`/`ExAfAf`);
  I/O (`IN`/`OUT`/`EdIn`/`EdOut` — the Port class, the Io-bus callout); the (IX+d)/(IY+d) indexed ops
  (`DdFdLdIndexed`/`DdFdAluIndexed`/`DdFdIncDecIndexed`/`DdFdStoreImmIndexed`); the DDCB/FDCB compound ops

## Risks (5-3a-specific)

- **J1 is the largest single JIT change.** Mitigated by all-fallback-first (no Z80 IL) + the per-task 6502
  regression gate. If the generic refactor (Tasks 2–5) proves larger than one working session, it is itself
  shippable as a 6502-only-still-green intermediate (the 6502 runs through `BlockCompiler<Mos6502Cpu>`, no
  Z80 yet) before the Z80 factory/sweep lands.
- **The 6502 byte-identity guard + the generated `JitTarget` member (Task 6).** `EmitJitTarget` ADDS a
  member to the 6502 `.g.cs` — the byte-identity baseline MUST be regenerated and the delta confirmed
  additive (no change to any existing 6502 emission). This is the one place the "every 6502 artifact
  byte-identical" invariant needs a deliberate baseline update (additive-only). Flag for the user's review.
- **`IMonitorSupport` on the Z80 (Task 8).** If the Z80 does not implement `IMonitorSupport`, the
  `JittedCpu<TCpu>` constraint relaxes to `ICpuCore` only + a runtime `is IMonitorSupport` guard. Confirm at
  Task 8; it does not block parity (the diff uses `ICpuCore` only).
- **The `_regFields` pair-view skip (J2).** The Z80's 16-bit pair-views are field-less properties; the 5-3a
  map skips them (no emitted op needs them). If a future check assumes every `RegisterName` maps to a field,
  it breaks — the skip is deliberate and pinned (Task 7). 5-3b owns the 16-bit register emit path.
- **ZEX-through-JIT wall-clock (Task 10).** All-fallback adds dispatcher/budget overhead per op over the
  ~130s interpreter ZEX run. Budget the full run generously (env-gated, not on every CI run — the M3.5-2
  precedent). The smoke (ZEXDOC wiring) is the CI gate; the full ZEXALL-through-JIT is the pre-merge gate.

## NEW decisions/risks flagged for the Coordinator (beyond D7/D9)

- **(NEW-1) The J1 generalization shape — `IJitTarget` seam vs `ICpuCore`-virtual.** This plan CHOSE a
  per-CPU `IJitTarget` static seam + generic `BlockCompiler<TCpu>` (preserving the baked-`FieldInfo`
  direct-field emit, the JIT's speed premise) over an `ICpuCore`-virtual rewrite (which would lose direct
  field access). This is a genuine architecture choice the ADR left open ("generic over `ICpuCore` OR a
  generated per-CPU state type" — Decision-7 J1). **Recommend the `IJitTarget` seam (chosen here); confirm
  before the 5-3a Builder run.** It is the minimal change that keeps the emit model intact.
- **(NEW-2) The 6502 `.g.cs` byte-identity baseline gains a `JitTarget` member (additive).** The
  "byte-identical 6502 artifact" invariant needs a one-time additive baseline update (Task 6). **Recommend:
  accept the additive delta, confirm it touches no existing 6502 emission.** Flag because it is the first
  deliberate change to the 6502 generated baseline since the JIT landed.
- **(NEW-3) Task sequencing is not the task NUMBER order.** The buildable order is Task 1 (Z80 stub) → Task 6
  (generated targets) → Tasks 2–5 (generic refactor + 6502 call sites) → Tasks 8–10 (Z80 gate). The numbers
  are review units. **No decision needed — but the Builder must follow the buildable order, not the numeric
  order; called out in Tasks 2/5/6.**
- **(UNRESOLVED) J1's genericity scope spans 6+ files but is mechanical.** It is larger than a typical PR in
  line-count but LOW semantic risk (type-parameter threading + handle-to-instance + a generated seam), and
  the all-fallback intermediate de-risks it. **Assessment: 5-3a is ONE PR** (the generic refactor + the Z80
  bring-up + the parity gate are one coherent "the Z80 runs through the JIT" story). If the refactor alone
  proves session-spanning, the 6502-still-green intermediate (Risks above) is the natural split point — but
  do not pre-split; let the Builder split only if forced.
