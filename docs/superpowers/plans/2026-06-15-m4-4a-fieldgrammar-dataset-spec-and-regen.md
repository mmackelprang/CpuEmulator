# M4.4a: The 68000 FieldGrammar Dataset + the Importer FieldGrammar Arm + the Real `M68000Spec.cs` (regen-guarded)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax
> for tracking. This is the FIRST of the two M4.4 slices (a = the FieldGrammar dataset + the importer arm
> that ingests it + the real, generator-clean `M68000Spec.cs` + the byte-identity regen guard; b = the gzip
> mnemonic-keyed TomHarte loader + its parse proof). Land M4.4a, then M4.4b. M4.5 (the op BODIES) depends
> on both.

**Goal:** make the 68000 spec REAL — retire the M4.1 guarded hand-write (`M68000Spec.cs`, zero instruction
patterns, `TODO(M4.4)`) and replace it with a `M68000Spec.cs` GENERATED by the importer from a
**FieldGrammar dataset** (a compact per-family table that the importer EXPANDS into the `FieldGrammar.Ops`
rows the M4.3a/M4.3b decode+EA substrate already consumes), then lock it with an `M68000RegeneratedSpecTests`
byte-identity guard exactly like the 6502/Z80 have. After M4.4a the 68000 **DECODES real instructions**
(`Decode(IFetchStream)` resolves real `(operation, size)` keys for MOVE / the ALU families / shift-rotate /
bit ops / MOVEQ-ADDQ-SUBQ / Bcc-BSR-JMP-JSR / the system ops, and `DescriptorFor` resolves them) but
**executes NOTHING** — every descriptor is a decode-only stub with NO op body (the MOVE/ALU/shift emit arms
are M4.5). This is the honest close-state: real decode + a populated `FieldGrammar`, no live semantics.

**Architecture:** The importer today (`tools/CpuEmulator.SpecImporter/`) is **opcode-row-based**:
`OpcodeDataset.Parse` reads a flat `[{opcode:"0xNN", mnemonic, mode, bytes, cycles, …}]` array (a single-byte
hex regex + 6502/Z80 byte-count rules), `SpecFileEmitter.Emit` walks those rows and emits `Insn(...)` /
`// TODO` lines + an optional `DecodeStructure`. It **explicitly rejects an empty dataset** (`OpcodeDataset.cs:160-161`,
the guard the M4.1 plan's Decision D4 hit — the 68000's zero opcode-rows could not go through it). The 68000
is field-encoded and extraordinarily regular, so M4.4a adds a **SECOND importer arm** that ingests a NEW
dataset SHAPE — a `FieldGrammar` dataset (`data/m68000-fieldgrammar.json`): a compact list of instruction
FAMILIES, each `(mask, match, operation, sizeShift, sizeWidth, sizeEncoding, eaShift, legalEa)`, that the
importer's `FieldGrammarEmitter` writes out as a `public static readonly FieldGrammar Decode68k = new(...)`
declaration the M4.3a generator already wires (`CpuEmitter.cs:3972 EmitFieldDecodeWalk`). The two existing
6502/Z80 opcode-row datasets + their emitter + their regen guards are **untouched** (the FieldGrammar arm is
a disjoint pipeline selected by a new `--field-grammar` CLI flag); the 6502/Z80 `RegeneratedSpecTests` stay
green byte-for-byte.

**Tech Stack:** C# (.NET 10), the console spec importer (`CpuEmulator.SpecImporter`), the Roslyn incremental
source generator (`CpuEmulator.Generators` — UNCHANGED by M4.4a; M4.3a/M4.3b already taught it the
`FieldGrammar` → `Decode`/`ComputeEa` emit), and xUnit. The SingleStepTests/680x0 TomHarte gate is M4.4b
(the loader) + M4.5 (the green sweep) — **out of scope here**.

## Scope

**IN scope (the dataset + the importer arm + the real spec + the regen guard; the 68000 DECODES, executes nothing):**

1. **The FieldGrammar dataset (`data/m68000-fieldgrammar.json`).** A compact, hand-authored, provenance-cited
   table of instruction FAMILIES — one entry per `(mask, match, operation, size-field, ea-field, legal-EA-
   category)` — covering the families ADR 0004 §3 names: `MOVE`/`MOVEA` (incl. the `01/11/10` size outlier +
   two-EA length), the integer ALU families (`ADD`/`ADDA`/`SUB`/`SUBA`/`AND`/`OR`/`EOR`/`CMP`/`CMPA`), the
   immediate ALU (`ADDI`/`SUBI`/`ANDI`/`ORI`/`EORI`/`CMPI`), the quick forms (`MOVEQ`/`ADDQ`/`SUBQ`), the
   shift/rotate (`ASL`/`ASR`/`LSL`/`LSR`/`ROL`/`ROR`/`ROXL`/`ROXR`, register + memory forms), the bit ops
   (`BTST`/`BCHG`/`BCLR`/`BSET`), the program-control (`Bcc`/`BSR`/`BRA`/`DBcc`/`JMP`/`JSR`/`RTS`/`RTE`/`RTR`),
   the address/misc (`LEA`/`PEA`/`LINK`/`UNLK`/`MOVEM`/`MOVEP`/`SWAP`/`EXT`/`TST`/`CLR`/`NEG`/`NOT`/`TAS`/
   `Scc`/`NBCD`/`PEA`), the multiply/divide/BCD (`MULU`/`MULS`/`DIVU`/`DIVS`/`ABCD`/`SBCD`/`ADDX`/`SUBX`), and
   the system ops (`TRAP`/`TRAPV`/`CHK`/`ILLEGAL`/`RESET`/`NOP`/`STOP`/`ANDI/EORI/ORI to CCR/SR`/`MOVE to/from
   SR/CCR`/`MOVE USP`). **Each entry is a FAMILY, not a single legal word** — the `(mask, match)` selects the
   family; the `size`/`EA` fields + the M4.3a `ExtensionWordCount` fan it out across sizes × EA-modes ×
   registers at decode time. This is the "derive from a compact family table" decision (see Decision D1).
2. **The importer FieldGrammar arm.** A NEW `FieldGrammarDataset` loader (parses + validates the family JSON:
   `(Match & ~Mask) == 0`, `SizeShift + SizeWidth <= 16`, `sizeEncoding ∈ {Standard, Move}`, `legalEa` is a
   known `EaCategory`, no two families with overlapping `(mask, match)` that could double-match an operword —
   the importer's analog of the 6502 byte-count rules) and a NEW `FieldGrammarEmitter` (emits the spec source:
   the auto-generated header, the `Registers` table + `FlagLayout` from a small `m68000-fieldgrammar-config.json`,
   and the `public static readonly FieldGrammar Decode68k = new(FetchUnit.Word, [ FieldOp(...) , … ]);`
   declaration). Wired into `SpecImportEngine` + `Program.cs` behind a `--field-grammar` flag so the existing
   `--dataset/--semantics` opcode-row path is byte-identical.
3. **The real `M68000Spec.cs`.** Regenerated by the importer (the M4.1 hand-write + its `TODO(M4.4)` retired);
   carries the M4.1 `Registers`/`FlagLayout` (byte-identical state model — D2 below) PLUS the populated
   `Decode68k` FieldGrammar and an EMPTY `Instructions = []` (no op bodies — those are M4.5). The generated
   `Decode(IFetchStream)` resolves real `(operation, size)` keys; `DescriptorFor` returns the Undefined
   stub for each (no descriptor rows yet — M4.5 fills them).
4. **The `M68000RegeneratedSpecTests` byte-identity guard.** Mirrors `RegeneratedSpecTests` (6502) + the Z80
   regen guard: asserts the committed `M68000Spec.cs` is exactly the tool output (line-ending normalized),
   plus a family-count assertion (the dataset's family count, pinned). This makes the spec dataset-driven, not
   hand-edited.
5. **A decode smoke proof.** A focused test that loads the REAL `M68000Spec.cs` decode through
   `GeneratorTestHost` (or a direct reference to the compiled `M68000Cpu.Decode`) and asserts a representative
   operword (e.g. `ADD.w D0,(A0)` = `0xD050`) decodes to a NON-Undefined-shaped key with the right computed
   length — proving the family table actually decodes real instructions, not just compiles.

### RECON FINDINGS that refine the ADR's sketch (the code WINS — flagged)

> Discovered during write-time recon by reading the source. The implementer MUST re-confirm each at Task 0.
> ADR 0004 §4 left the EXACT dataset shape + ingest mechanism "just-in-time"; these settle it against the
> live M4.3a/M4.3b seams and are the reconciliation flags the Coordinator asked for.

- **F1 — the FieldGrammar shape is FIXED by M4.3a; the dataset must match it 1:1.** The `FieldOp` record is
  `(ushort Mask, ushort Match, string Operation, int SizeShift, int SizeWidth, SizeEncoding SizeEncoding, int
  EaShift, EaCategory LegalEa)` and the generator's `s_fieldOps` table + the `Decode` walk read EXACTLY these
  fields. So the dataset's per-family record is this 8-tuple; the importer's job is parse → validate → emit
  `FieldOp(Mask: 0x…, Match: 0x…, Operation: "…", SizeShift: …, SizeWidth: …, SizeEncoding: SizeEncoding.…,
  EaShift: …, LegalEa: EaCategory.…)`. **No new generator field is needed for the regular families.** The
  outliers (MOVE two-EA, MOVEQ/branch with NO size/EA field) are handled by how the family fills these fields
  (see F3/F4), NOT by new fields.
- **F2 — `Operation` is an opaque label in M4.3a; the key is `(opIndex, size)`, NOT the string.** The
  generated key is `(1u<<24)|(opIndex<<8)|size` where `opIndex` = the family's POSITION in `Decode68k.Ops`
  (`CpuEmitter.cs:4087` packs `{i}u`). So `Operation` is documentation/disassembly only in M4.4a; the
  descriptor lookup (M4.5) will key on `(opIndex, size)`. **Consequence:** the dataset's family ORDER is
  load-bearing for the key — the regen guard pins it, and M4.5's descriptor rows must use the same order. The
  importer emits families in dataset order (stable). Record this: family order = key identity.
- **F3 — the MOVE size outlier rides `SizeEncoding.Move`, already in the carrier (C4 from M4.3a).** MOVE/MOVEA
  encode size in bits 13-12 as `01=b, 11=w, 10=l` (NOT the standard `00/01/10`); `MapSize(bits, enc=1)`
  (`CpuEmitter.cs:4144-4146`) already maps `1→b, 3→w, 2→l`. So the MOVE family's dataset row sets
  `sizeEncoding: "Move"`, `sizeShift: 12`, `sizeWidth: 2`. **No new mechanism — the M4.3a carrier was built
  expressly for this.** The MOVE family's `mask/match` is `0xC000 / 0x0000` (bits 15-14 = `00`), and the
  destination is the SECOND EA field (bits 11-6, mode then register SWAPPED vs the standard layout — see F4).
- **F4 — MOVE's TWO EA fields + the swapped destination layout is the ONE shape the single-`EaShift`
  `FieldOp` cannot fully express; it needs a decode decision (D5 below).** The standard families have ONE
  6-bit EA at bits 5-0 (`EaShift: 0`). MOVE has a SOURCE EA at bits 5-0 AND a DESTINATION EA at bits 11-6
  with mode/register **swapped** (dest register = bits 11-9, dest mode = bits 8-6). The M4.3a
  `ExtensionWordCount` is single-EA; MOVE's true length is the SUM of both EAs' extension words. **M4.3a's
  own plan (C5) flagged this exact deferral: "the two-EA MOVE sum is an M4.4 grammar concern."** This is the
  load-bearing M4.4a decision — resolved as D5 (the dataset declares MOVE with the SOURCE EA at `EaShift: 0`
  so the source-EA extension words decode; the DESTINATION EA's extension-word contribution + the
  swapped-field destination decode is recorded as an M4.5 descriptor-side concern, because M4.4a only needs
  the length to be RIGHT for the common single-or-no-destination-extension cases and the descriptor that reads
  the destination EA is M4.5 anyway). **CONFIRM at Task 0 whether `ExtensionWordCount` is reachable per-EA;
  if the two-EA length is wrong for `MOVE.l #imm,abs.l` (1+2 source + 2 dest), flag the Coordinator —
  the fix is a generator change (a two-EA `FieldOp` arm), which is OUT of M4.4a scope.** (See Risks.)
- **F5 — the no-size / no-EA families (MOVEQ, Bcc, BRA, BSR, NOP, RTS, …) fill the size/EA fields with
  inert values.** MOVEQ has its data in bits 7-0 and NO size field (it is always `.l`); Bcc/BRA/BSR have an
  8-bit displacement in bits 7-0 (or a following word for `.w`), a condition in bits 11-8, NO standard EA.
  These families set `sizeShift/sizeWidth` to a region that maps to a fixed size (e.g. `sizeWidth: 0` →
  `sizeBits = 0` → `MapSize(0, Standard) = b`; the family's "size" is then ignored by M4.5's body), and set
  `eaShift` to a value whose 6 bits decode to mode 0/1 (`ExtensionWordCount = 0`, no spurious extension-word
  consumption). **CONFIRM `sizeWidth: 0` is safe:** `(1 << 0) - 1 = 0`, so `sizeBits = 0`, `MapSize(0,*) = 0`
  (`.b`) — fine; the body (M4.5) does not consult size for these. **The branch displacement length** (Bcc.w
  reads one following word; Bcc.b does not) is, like MOVE, NOT expressible by the single-EA
  `ExtensionWordCount` — so for the `.w`/`.l` branch forms the COMPUTED length is short by 1-2 words. Record
  this as the SAME class of deferral as F4 (D5): the branch displacement decode + its length contribution is
  an M4.5 descriptor concern; M4.4a's branch families decode the operword + condition (the key) correctly, and
  the displacement-word length is M4.5. **Flag to the Coordinator with F4.**

```csharp
using System.IO;
using System.Text.Json;
using System.Text.Json.Serialization;

namespace CpuEmulator.SpecImporter;

/// <summary>
/// The spec-config half of the FieldGrammar importer arm: architecture/namespace/specClassName +
/// the register file + flag layout. The 68000 has NO per-mnemonic semantics map (op bodies are M4.5),
/// so this carries ONLY the state model the emitter writes verbatim. Reuses RegisterConfig/FlagBitConfig
/// from SemanticsMap so the emitted Registers/FlagLayout shape matches the opcode-row arm byte-for-byte.
/// </summary>
public sealed class FieldGrammarConfig
{
    public string Architecture  { get; init; } = "";
    public string Namespace     { get; init; } = "";
    public string SpecClassName { get; init; } = "";
    public RegisterConfig[] Registers { get; init; } = [];
    public FlagBitConfig[]  Flags     { get; init; } = [];

    private static readonly JsonSerializerOptions JsonOptions = new()
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
        PropertyNameCaseInsensitive = true,
    };

    [JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]
    private sealed class Dto
    {
        public string Architecture  { get; set; } = "";
        public string Namespace     { get; set; } = "";
        public string SpecClassName { get; set; } = "";
        public RegisterDto[] Registers { get; set; } = [];
        public FlagDto[]     Flags     { get; set; } = [];
    }

    [JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]
    private sealed class RegisterDto
    {
        public string  Name { get; set; } = "";
        public int     Bits { get; set; }
        public string  Role { get; set; } = "";
    }

    [JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]
    private sealed class FlagDto
    {
        public string Name { get; set; } = "";
        public int    Bit  { get; set; }
    }

    public static FieldGrammarConfig Load(string path) => Parse(File.ReadAllText(path));

    public static FieldGrammarConfig Parse(string json)
    {
        Dto? dto;
        try { dto = JsonSerializer.Deserialize<Dto>(json, JsonOptions); }
        catch (JsonException ex)
        {
            throw new InvalidDataException($"FieldGrammar config JSON is malformed: {ex.Message}", ex);
        }
        if (dto is null) throw new InvalidDataException("FieldGrammar config is null.");
        if (string.IsNullOrWhiteSpace(dto.Architecture))
            throw new InvalidDataException("FieldGrammar config: 'architecture' must be non-empty.");
        if (string.IsNullOrWhiteSpace(dto.Namespace))
            throw new InvalidDataException("FieldGrammar config: 'namespace' must be non-empty.");
        if (string.IsNullOrWhiteSpace(dto.SpecClassName))
            throw new InvalidDataException("FieldGrammar config: 'specClassName' must be non-empty.");
        if (dto.Registers.Length == 0)
            throw new InvalidDataException("FieldGrammar config: 'registers' must be non-empty.");

        return new FieldGrammarConfig
        {
            Architecture  = dto.Architecture,
            Namespace     = dto.Namespace,
            SpecClassName = dto.SpecClassName,
            Registers     = [.. System.Linq.Enumerable.Select(dto.Registers,
                                r => new RegisterConfig(r.Name, r.Bits, r.Role))],
            Flags         = [.. System.Linq.Enumerable.Select(dto.Flags,
                                f => new FlagBitConfig(f.Name, f.Bit))],
        };
    }
}
```

```csharp
using System.IO;
using System.Text.Json;
using System.Text.Json.Serialization;

namespace CpuEmulator.SpecImporter;

/// <summary>
/// One instruction-FAMILY row of the 68000 FieldGrammar dataset — the importer's analog of OpcodeEntry,
/// but field-encoded: a (mask, match) selects the family; size/EA fields fan it out across sizes × EA-modes
/// × registers at decode time (the M4.3a ExtensionWordCount / MapSize do the fan-out). Field names + types
/// match the FieldOp record (DecodeStructure.cs) 1:1 — the emitter writes FieldOp(Mask: .., Match: .., …).
/// </summary>
public sealed record FieldGrammarFamily(
    ushort Mask, ushort Match, string Operation,
    int SizeShift, int SizeWidth, string SizeEncoding,
    int EaShift, string LegalEa, string? Source = null);

public static class FieldGrammarDataset
{
    private static readonly HashSet<string> KnownSizeEncodings = new(StringComparer.Ordinal)
        { "Standard", "Move" };

    // Mirrors the EaCategory enum (DecodeStructure.cs). SYNC HAZARD: if EaCategory gains members, add here.
    private static readonly HashSet<string> KnownEaCategories = new(StringComparer.Ordinal)
        { "DataAddressing", "MemoryAlterable", "DataAlterable", "Control", "Alterable", "All" };

    private static readonly JsonSerializerOptions JsonOptions = new()
    {
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
        PropertyNameCaseInsensitive = true,
    };

    [JsonUnmappedMemberHandling(JsonUnmappedMemberHandling.Disallow)]
    private sealed class Dto
    {
        public string? Operation { get; set; }
        public string? Mask { get; set; }
        public string? Match { get; set; }
        public int?    SizeShift { get; set; }
        public int?    SizeWidth { get; set; }
        public string? SizeEncoding { get; set; }
        public int?    EaShift { get; set; }
        public string? LegalEa { get; set; }
        public string? Source { get; set; }
    }

    public static FieldGrammarFamily[] Load(string path) => Parse(File.ReadAllText(path));

    public static FieldGrammarFamily[] Parse(string json)
    {
        Dto[]? dtos;
        try { dtos = JsonSerializer.Deserialize<Dto[]>(json, JsonOptions); }
        catch (JsonException ex)
        {
            throw new InvalidDataException($"FieldGrammar dataset JSON is malformed: {ex.Message}", ex);
        }
        if (dtos is null || dtos.Length == 0)
            throw new InvalidDataException("FieldGrammar dataset is empty.");

        var families = new FieldGrammarFamily[dtos.Length];
        var seenMatch = new HashSet<(ushort, ushort)>();
        for (int i = 0; i < dtos.Length; i++)
        {
            var d = dtos[i];
            var ctx = $"family {i} ({d.Operation ?? "?"})";
            if (string.IsNullOrWhiteSpace(d.Operation))
                throw new InvalidDataException($"Missing 'operation' at {ctx}.");
            if (d.Mask is null) throw new InvalidDataException($"Missing 'mask' at {ctx}.");
            if (d.Match is null) throw new InvalidDataException($"Missing 'match' at {ctx}.");
            if (d.SizeShift is null) throw new InvalidDataException($"Missing 'sizeShift' at {ctx}.");
            if (d.SizeWidth is null) throw new InvalidDataException($"Missing 'sizeWidth' at {ctx}.");
            if (d.SizeEncoding is null) throw new InvalidDataException($"Missing 'sizeEncoding' at {ctx}.");
            if (d.EaShift is null) throw new InvalidDataException($"Missing 'eaShift' at {ctx}.");
            if (d.LegalEa is null) throw new InvalidDataException($"Missing 'legalEa' at {ctx}.");

            ushort mask = ParseHex16(d.Mask, $"mask at {ctx}");
            ushort match = ParseHex16(d.Match, $"match at {ctx}");
            if ((match & ~mask) != 0)
                throw new InvalidDataException(
                    $"'match' {d.Match} has bits outside 'mask' {d.Mask} at {ctx} (unreachable family).");
            if (d.SizeWidth.Value < 0 || d.SizeShift.Value < 0 ||
                d.SizeShift.Value + d.SizeWidth.Value > 16)
                throw new InvalidDataException(
                    $"size field [shift {d.SizeShift}, width {d.SizeWidth}] out of bounds at {ctx} " +
                    "(shift + width must be 0..16).");
            if (d.EaShift.Value < 0 || d.EaShift.Value > 10)
                throw new InvalidDataException($"eaShift {d.EaShift} out of bounds (0..10) at {ctx}.");
            if (!KnownSizeEncodings.Contains(d.SizeEncoding))
                throw new InvalidDataException(
                    $"Unknown sizeEncoding '{d.SizeEncoding}' at {ctx}: expected Standard or Move.");
            if (!KnownEaCategories.Contains(d.LegalEa))
                throw new InvalidDataException(
                    $"Unknown legalEa '{d.LegalEa}' at {ctx}: expected one of " +
                    $"{string.Join(", ", KnownEaCategories)}.");
            // No two families may share an identical (mask, match) — the decode walk takes the FIRST hit,
            // so a duplicate is dead (and almost certainly an authoring error).
            if (!seenMatch.Add((mask, match)))
                throw new InvalidDataException(
                    $"Duplicate (mask {d.Mask}, match {d.Match}) at {ctx}: a second family can never fire.");

            families[i] = new FieldGrammarFamily(
                mask, match, d.Operation,
                d.SizeShift.Value, d.SizeWidth.Value, d.SizeEncoding,
                d.EaShift.Value, d.LegalEa, d.Source);
        }
        return families;
    }

    private static ushort ParseHex16(string text, string what)
    {
        if (text.StartsWith("0x", StringComparison.OrdinalIgnoreCase) &&
            ushort.TryParse(text.AsSpan(2), System.Globalization.NumberStyles.HexNumber, null, out var v))
            return v;
        throw new InvalidDataException($"{what}: expected '0xNNNN' (16-bit hex), got '{text}'.");
    }
}
```

```csharp
/// <summary>A report from the FieldGrammar emitter (the arm's analog of ImportReport).</summary>
public sealed record FieldGrammarReport(int Families)
{
    public override string ToString() => $"families={Families}";
}

/// <summary>
/// Emits a complete spec-class source file from a FieldGrammar dataset + config. The spec declares the
/// 68000 state model (Registers + FlagLayout) AND a populated FieldGrammar (Decode68k) the M4.3a generator
/// expands into the Decode(IFetchStream) field-decode walk. Instructions is EMPTY — the op BODIES are M4.5.
/// Family order in the dataset is preserved (the (opIndex, size) key identity — F2).
/// </summary>
public static class FieldGrammarEmitter
{
    public static (string Source, FieldGrammarReport Report) Emit(
        FieldGrammarFamily[] families,

        string               datasetPath = "data/m68000-fieldgrammar.json",
        string               outputPath  = "src/CpuEmulator.Cpus.M68000/M68000Spec.cs")
```

### Decisions (the Coordinator-facing record)

- **D1 — derive-from-a-compact-family-table (NOT author every legal word).** The dataset is ~60-75 FAMILY
  rows; the M4.3a `ExtensionWordCount`/`MapSize`/`ComputeEa` substrate fans each family out across sizes ×
  14 EA-modes × 8 registers at DECODE time. Authoring the rows directly (vs an algorithmic family generator)
  is chosen because the M4.3a `FieldOp` shape IS the compact representation — the importer just validates +
  re-emits it; no second algorithm is needed. This is the smallest correct surface and keeps the dataset
  human-auditable against the M68000PRM.
- **D2 — the generated spec's Registers/FlagLayout are byte-identical to the M4.1 hand-write** (driven by
  `m68000-fieldgrammar-config.json`), so the M4.1 `M68000Cpu` partial + the M4.1 state tests are unaffected;
  only the header changes + `Decode68k` is added.
- **D5 (the load-bearing one) — the MOVE two-EA length + the branch-displacement length are M4.5 descriptor
  concerns, NOT M4.4a.** The M4.3a `ExtensionWordCount` is single-EA; MOVE's true length is source-EA +
  dest-EA extension words, and Bcc.w/.l read a following displacement word. M4.4a's families decode the
  operword + the key correctly (the family matches; the source EA's extension words decode for length), and
  the dest-EA/displacement length contribution is deferred to M4.5 (which adds the descriptor rows + bodies
  that read those words anyway). **This is flagged to the Coordinator below as the primary new risk.**
