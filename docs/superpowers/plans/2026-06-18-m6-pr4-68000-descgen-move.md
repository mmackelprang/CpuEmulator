## Objective (the ADR §8 PR-4 row — the 68000's structural unlock)

Make the 68000 **MOVE / MOVEA / MOVEQ** family emit real IL instead of falling back to `inner.Step`. Unlike the
Z80/8086 (whose descriptor tables were populated-but-forced-fallback — a gate-flip), **the 68000's
`JitDescriptorsByKey` is literally EMPTY** (`= new() { };`, 0 rows, `M68000Cpu.g.cs:624-626`), because the 68000
spec carries `InstructionDef[] Instructions = []` (`M68000Spec.cs:133`) — the descriptor-emit `foreach`
(`CpuEmitter.cs:4075`) iterates **zero times**. So PR-4 has FIVE halves, the first of which is genuinely new:

1. **Generator side — NET-NEW descriptor-row generation** (`CpuEmitter.cs` + `M68000Spec.cs` / the importer):
   populate the 68000's `JitDescriptorsByKey` with MOVE/MOVEA/MOVEQ rows whose `OperationKey` matches the
   decode walk's `(1u << 24) | (opIndex << 8) | size` packing (`CpuEmitter.cs:4971`). This requires (1a) the
   descriptor ROWS to exist (DECISION P — where the EA-mode matrix is encoded), (1b) a **68000 cycle branch** in
   `JitBaseCycles`/`ComputeCycles` so the generator does not hit the throwing default (`CpuEmitter.cs:1073`),
   and (1c) a **68000 JIT classification** (`ClassifyForJit`) so a MOVE row gets a real `JitOpClass` + correct
   `EndsBlock`/`NeedsFallback`.
2. **JIT side — the wide-bus emit helpers** (`BlockCompiler.cs`): big-endian `LoadWordFromBus` / `LoadLongFromBus`
   / `EmitStoreWord` / `EmitStoreLong` (the JIT has BYTE-ONLY bus helpers today — a hard GAP).
3. **JIT side — the 32-bit register emit helpers** (`BlockCompiler.cs`): `EmitLoadReg32` / `EmitStoreReg32` +
   size-aware `.b`/`.w`/`.l` register read/write (preserve upper bits on narrow writes — the GAP analogue of
   PR-0's `EmitLoadReg16`).
4. **JIT side — the EA-mode resolver + A7 banking** (`BlockCompiler.M68000.cs`): `EmitM68kEaRead` /
   `EmitM68kEaWrite` over the 68000's 12 EA modes (the hardest part — MOVE has an EA on BOTH source and dest),
   with the `-(A7)`/`(A7)`/`(A7)+` S-bit (USP/SSP) banking branch emitted inline (A7 is a banked PROPERTY, not a
   field).
5. **JIT side — the MOVE/MOVEQ emit arm** (`BlockCompiler.M68000.cs`): `EmitM68kMove` — resolve source EA, read
   the operand, resolve dest EA, write the operand, set the MOVE CCR (N/Z, V=C=0, X unaffected), charge cycles
   (DECISION T — the simple "budget floor" model, NOT the prefetch-queue trace).

**Why PR-4 is "the big one" (ADR §8):** it is the only net-new descriptor GENERATOR change in the whole M6 arc
(the Z80/8086 are gate-flips). It also builds ALL the shared 68000 JIT infrastructure (wide bus, 32-bit
registers, the EA matrix, A7 banking) that PR-5 (ALU) and PR-6 (shifts/branch) reuse. MOVE is the right first
family: it is the single largest 68000 family by ISA + the W1 hot op (§6), and like the Z80 LD (PR-1) it touches
flags only lightly (N/Z, V=C=0, X untouched) — so PR-4 proves the net-new descriptor path + the EA matrix +
the wide-bus emit **without** paying the full CCR-X-bit tax (that is PR-5).

### The MOVE / MOVEQ oracle (the interpreter bodies the IL must match byte-identically, DATA axis)

All from the hand-written 68000 partials (the oracle — NOT generated). `size` is the index `0=.b/1=.w/2=.l`;
`srcMode`/`srcReg` are the operword's low-6 EA field (`mode=(ea>>3)&7`, `reg=ea&7`).

```csharp
// MOVE  (M68000Cpu.Move.cs:78-88) — dest mode/reg are SWAPPED in bits 11-6 (the .b/.w/.l MOVE encoding quirk):
uint dstReg  = (operword >> 9) & 7u;   // dest register = bits 11-9
uint dstMode = (operword >> 6) & 7u;   // dest MODE = bits 8-6  (NOTE: mode field is bits 8-6, reg is 11-9 — reversed vs source)
uint value = ReadEaOperand(srcMode, srcReg, size, r.ExtensionWords);                                  // source
WriteEaOperand(dstMode, dstReg, size, value, DestExtensionWords(r.ExtensionWords, srcMode, srcReg, size));
SetMoveCcr(value, size);                                                                              // N/Z from value; V=C=0; X preserved

// SetMoveCcr (M68000Cpu.Move.cs:64-75): N = (value & signbit(size)) != 0; Z = (value & mask(size)) == 0;
//   ccr = (oldCcr & ~0x0F);  if (N) ccr |= 0x08;  if (Z) ccr |= 0x04;  // V(0x02)=0, C(0x01)=0, X(0x10) UNTOUCHED.

// MOVEA  (M68000Cpu.Move.cs:113-120) — dest is An, WHOLE 32-bit write, .w SIGN-EXTENDS to 32, sets NO CCR:
uint value = ReadEaOperand(srcMode, srcReg, size, r.ExtensionWords);
uint extended = size == 1u ? unchecked((uint)(int)(short)(ushort)value) : value;  // .w sign-extend; .l as-is (MOVEA has no .b)
SetAreg(dstReg, extended);                                                         // whole An; NO CCR

// MOVEQ  (M68000Cpu.SystemMisc.cs:20-26) — imm8 sign-extended to .l into Dn; Logic CCR (N/Z, V=C=0, X untouched):
uint dn = (operword >> 9) & 7u;
uint result = unchecked((uint)(int)(sbyte)(byte)(operword & 0xFFu));   // sign-extend imm8 -> .l
SetDataRegPartial(dn, result, 2u);                                     // size 2 = full 32-bit write
SR = (ushort)((SR & 0xFF00) | AluCcr.Logic(0, 0, result, 2u, false, (byte)(SR & 0xFF)));
```

### The CCR model (the X-bit lives here, but MOVE leaves X UNTOUCHED — the PR-4 simplification)

- The CCR is the **low byte of the 16-bit `SR` field** (a generated `public ushort SR;`). Bits (`M68000Spec.cs:43`):
  **C=0x01, V=0x02, Z=0x04, N=0x08, X=0x10** (S=0x2000 in the system byte). Accessor `Ccr` (`M68000Cpu.cs:49-53`):
  `get => (byte)(SR & 0xFF); set => SR = (ushort)((SR & 0xFF00) | value);`.
- **MOVE/MOVEQ touch N/Z, force V=C=0, and leave X UNTOUCHED** (the `oldCcr & ~0x0F` mask keeps bit 4). So the
  PR-4 emit arm sets the CCR by: `SR = (ushort)((SR & 0xFFF0) | (N?8:0) | (Z?4:0));` — a single, simple CCR write.
  **MOVEA sets NO CCR at all.** **The full X-bit machinery (ADDX/SUBX, X=C for ADD/SUB) is PR-5, not PR-4.**

### The EA resolver oracle (`ComputeEa` — GENERATED today, but the JIT must emit its own IL version)

`ComputeEa` is emitted by the generator (`CpuEmitter.cs:5362-5400`, method `EmitM68kEa`) and runs in the
INTERPRETER. Verbatim (the C# it emits — the JIT IL must reproduce this address math):

```csharp
private uint ComputeEa(uint eaMode, uint eaReg, uint size, ExtensionWords ext, bool pureEa)
{
    uint mag = size == 0u ? 1u : size == 1u ? 2u : 4u;             // .b/.w/.l magnitude
    if (eaReg == 7u && eaMode is 3u or 4u && mag == 1u) mag = 2u;  // A7 ±2 (stack word-align on byte (A7)+/-(A7))
    switch (eaMode)
    {
        case 0u: return 0u;                                                              // Dn — register direct (no addr)
        case 1u: return Areg(eaReg);                                                     // An — register direct (no addr)
        case 2u: return Areg(eaReg);                                                     // (An)
        case 3u: { uint ea = Areg(eaReg); if (!pureEa) SetAreg(eaReg, ea + mag); return ea; }  // (An)+  — POST-increment
        case 4u: { uint ea = Areg(eaReg) - mag; if (!pureEa) SetAreg(eaReg, ea); return ea; }  // -(An)  — PRE-decrement
        case 5u: return unchecked(Areg(eaReg) + (uint)(short)ext[0]);                    // d16(An)
        case 6u: return ComputeBriefIndex(Areg(eaReg), ext[0]);                          // d8(An,Xn)
        case 7u: return eaReg switch
        {
            0u => (uint)(short)ext[0],                                                   // abs.W
            1u => ((uint)ext[0] << 16) | ext[1],                                         // abs.L (two words, high first)
            2u => unchecked(PcForEa + (uint)(short)ext[0]),                              // d16(PC)
            3u => ComputeBriefIndex(PcForEa, ext[0]),                                    // d8(PC,Xn)
            4u => 0u,                                                                    // #imm — no address
            _ => 0u,
        };
        default: return 0u;
    }
}
```

> **The `pureEa` flag is load-bearing.** `false` performs the `(An)+`/`-(An)` write-back (mutates An); `true`
> (LEA/PEA/JMP/JSR) computes the address WITHOUT mutating. **Calling EA-compute twice for one operand
> double-advances An** — the interpreter solves this with the `ResolveEaDest`/`WriteResolvedDest` "address-once"
> discipline (`M68000Cpu.Alu.cs:174-203`). **The JIT MUST mirror this: resolve each EA exactly ONCE, stash the
> address in a local, and reuse it for the access.** For MOVE specifically: source EA is read once; dest EA is
> resolved once and written once — but `(An)+`/`-(An)` on each side mutates An, and the dest's extension words
> follow the source's in the combined buffer (`DestExtensionWords`, `M68000Cpu.Move.cs:94-111`).
> `Areg`/`SetAreg` (`CpuEmitter.cs` generated) read/write An with the A7-banking applied for reg 7.
> `#imm` (mode 7 reg 4) is read from the extension words in `ReadEaOperand` (`M68000Cpu.Move.cs:29`), NOT via an
> address. `ComputeBriefIndex` (`CpuEmitter.cs:5420-5427`): bit15=An-vs-Dn index, bit11=.w(sign-ext)-vs-.l,
> bits14-12=index reg, low byte=signed disp8.

### The timing / cycle model — and why the JIT parity gate sidesteps it (DECISION T — THE big simplification)

| # | Fact | Evidence |
|---|---|---|
| T1 | The interpreter's cycle model is a **stateful 2-word prefetch queue** (`M68000FetchStream`, `Core/Jit/M68000FetchStream.cs`) owned across Steps, with **deferred + leading refills** threaded through each op body (`Refill()`/`LeadRefills()`, `M68000Cpu.cs:121-145`) + per-EA-mode idle clocks (`EaCalcIdle`, `:179-183`) + `WordAccessCycles = 4` per word access. This is the M4.5d-2b cycle-exact model. **Reproducing this in emitted IL is genuinely hard** (the queue is stateful across instructions; the refill interleave is per-instruction-class). | `M68000Cpu.cs:100-222`; `M68000FetchStream.cs` |
| T2 | **BUT the JIT parity gate is the DATA axis ONLY.** `RunCaseThroughJit` (`M68000TomHarteRunner.cs:250-314`) seeds the case, runs EXACTLY ONE instruction through Tier-1 with a **1-cycle budget**, then compares ONLY D0–D7, A0–A6, USP, SSP, SR, RAM. **It does NOT compare `CycleCount`, `final.pc`, or `final.prefetch`** (verified `:303-313` — there is no `CycleCount` / `FinalPrefetch` check). The comment is explicit: "the JIT data-axis gate asserts regs/SR/RAM, NOT the per-transaction trace; trace-equivalence is the interpreter axis" (`:270-271`). | `M68000TomHarteRunner.cs:250-314` |
| T3 | The JIT budget loop relies on a **`>= 1 cycle per instruction` invariant** (`:288-293`): the 1-cycle budget runs exactly one block because every 68000 instruction charges `>= 1` cycle, driving `budget <= 0` and exiting the loop. So an emitted MOVE MUST charge `>= 1` cycle (else the loop runs a runaway second instruction). | `M68000TomHarteRunner.cs:280-295` |

> **DECISION T (the load-bearing PR-4 simplification — surfaced for the owner): emit a CORRECT-BUT-COARSE cycle
> charge, NOT the prefetch-queue trace.** Because the JIT parity gate asserts only the data axis (T2), and only
> requires `>= 1 cycle per instruction` (T3), the emitted MOVE charges the descriptor's `BaseCycles` (the
> standard MOVE timing: 4 clocks + EA costs, from the 68000 timing table — a static per-(srcMode,dstMode,size)
> constant the generator computes in DECISION C) via `EmitChargeCycles(ctx, n)`. **It does NOT model the
> prefetch queue, the deferred/leading refills, or the per-transaction trace.** This is the SAME stance ADR 0008
> §6 took for M4.6: "M4.6 needs the functional exception model (M4.5d-1) but is agnostic to the prefetch/timing
> axis (M4.5d-2) — the JIT parity gate is the data axis." **The emitted 68000 cycles/sec will therefore be
> approximate (coarse), exactly as the baseline already caveats (OQ4 — the cycles/sec column stays timing-axis-
> caveated; guest-MIPS is the headline).** If the owner later wants cycle-exact emitted 68000 timing, that is a
> separate, large piece of work (emitting the stateful queue) — explicitly OUT of scope for the M6 emit arc.
> **Owner: confirm DECISION T (coarse cycle charge, data-axis parity only) is the accepted M6 bar for the
> 68000.**

## DECISIONS (the design forks — DECISION P is the owner checkpoint)

### DECISION P — how the dual-EA matrix is encoded (the descriptor-shape fork — THE owner checkpoint)

MOVE has an EA on BOTH source and dest, but `OpcodeDescriptor.Mode` is a SINGLE field (G4). Three options:

- **(P1) Extend `JitMode` with the 12 68000 modes AND add a second mode field to `OpcodeDescriptor`** (e.g.
  `JitMode DestMode`). A descriptor record-shape change — touches `OpcodeDescriptor.cs` (a Core type every CPU's
  descriptor uses) + the generator's literal emit + every CPU's table regeneration. **Pro:** explicit, typed.
  **Con:** the highest blast-radius option — it changes the shared `OpcodeDescriptor` record, forcing a
  regeneration of ALL four CPUs' tables (the empty-diff regression gate must then prove the OTHER CPUs' rows are
  byte-identical despite the new field defaulting). High risk against the regression gate.
- **(P2) Encode the EA matrix in the `Ops` array.** `JitOp(Kind, RegA, RegB, FlagBit, BoolArg)` already carries
  4 fields. A 68000 MOVE descriptor carries `Ops = [ JitOp("MoveSrc", …, FlagBit=srcMode, …), JitOp("MoveDst",
  …, FlagBit=dstMode, …) ]` — source-EA and dest-EA as encoded `JitOp` entries, keeping `OpcodeDescriptor.Mode`
  as a coarse class marker. **No record-shape change** (the `Ops` array is already `ImmutableArray<JitOp>`, any
  length). Matches the J2 "operand detail is DATA in Ops" philosophy ADR 0011 §1.2 names. **Pro:** zero shared-
  type change → the empty-diff regression gate is trivial (the other CPUs' rows are untouched). **Con:** the
  mode/reg are packed into `FlagBit` (a `byte`) — fits (mode 0-7, reg 0-7 → a 6-bit field), but it is a slightly
  unnatural use of `FlagBit`.
- **(P3) Resolve EA at emit time from the raw opcode word** (like the Z80 flow arms read targets from `_bus` at
  compile time). The 68000 EA mode/register fields live in fixed bit positions of the operword; the emit arm
  decodes them from the operword the descriptor carries (or re-reads from `_bus` at the block PC). The generated
  `s_fieldOps` table (`M68000Cpu.g.cs:649-652`) already extracts the EA-field bit positions. **Pro:** the
  descriptor carries the LEAST (just enough to route to `EmitM68kMove`); the emit arm does the bit-extraction
  the decoder already knows how to do. **Con:** duplicates a slice of the decode logic into the emit arm; the
  emit arm needs the operword, which it reads from `_bus.Read16((ushort)pc)` at compile time (the operword is a
  code-stream constant — exactly how the Z80 flow arms read their targets).

> **RECOMMENDATION: P3 (emit-time operword decode), with P2 as the fallback if P3's bit-extraction proves
> fiddly.** Rationale: (a) P3 has **zero shared-type blast radius** — `OpcodeDescriptor` and `JitMode` are
> untouched, so the empty-diff regression gate against 6502/Z80/8086 is trivially clean (DECISION R); (b) the
> operword IS a compile-time constant the emit arm can read from `_bus` exactly as the proven Z80 flow arms read
> their 16-bit targets (`BlockCompiler.Z80.cs`); (c) the EA-field bit positions are FIXED and small (src
> mode=bits 5-3, src reg=bits 2-0; dest reg=bits 11-9, dest mode=bits 8-6 — the MOVE quirk), so the extraction
> is ~6 lines, not a re-implementation of the decoder; (d) the descriptor then carries only a coarse `Mnemonic`
> + a single `JitOpClass` (a new `M68000Move`) + `BaseCycles` + `EndsBlock=false` — the minimal row. **This is
> the single biggest design decision in PR-4 and the one to relay to the owner before any building.** It sets
> the descriptor shape for the WHOLE 68000 emit arc (PR-5/PR-6 inherit it). **Owner: confirm P3 (emit-time
> operword decode) vs P2 (Ops-encoded matrix) vs P1 (descriptor-shape change).**

### DECISION C — how the 68000 cycle model is reproduced in IL (the generator cycle branch + the coarse charge)

Per DECISION T, the emit arm charges a COARSE-but-correct `BaseCycles` (NOT the prefetch trace). The generator
must compute that `BaseCycles` for each MOVE row (G E6: `ComputeCycles` throws on 68000 modes today). Two halves:

- **(C-gen) A 68000 cycle function in the generator.** Add `M68kCycles(srcMode, dstMode, size)` to `CpuEmitter.cs`
  (mirroring `Z80Cycles`, `CpuEmitter.cs:1081`), returning the standard MOVE timing from the 68000 table:
  MOVE is `4 + srcEaCost + dstEaCost` clocks (e.g. `MOVE.w Dn,Dn` = 4; `MOVE.w (An),Dn` = 8; `MOVE.l (An),(An)`
  = 20). The exact table is the published 68000 MOVE timing (byte/word vs long differ; the EA cost is per-mode).
  `JitBaseCycles` (`CpuEmitter.cs:4175`) gets a `if (model is 68000 && Mnemonic is "MOVE"/"MOVEA"/"MOVEQ") return
  M68kMoveCycles(...)` branch BEFORE the `ComputeCycles` fallthrough — so the 68000 rows never hit the throwing
  default. Gated on a 68000-only signal (the model's FieldGrammar-ness or the mnemonic set), so 6502/Z80/8086
  are provably unreachable (R2).
- **(C-jit) The emit arm charges it.** `EmitM68kMove` calls `EmitChargeCycles(ctx, d.BaseCycles)` (the batch
  helper PR-1 added, `BlockCompiler.cs:500-517`). **No per-access charge** (unlike the Z80, where each
  `LoadByteFromBus` charges 1) — the 68000 wide-bus emit helpers (Task 2) charge 0 (the data axis doesn't read
  cycles, T2), and the whole `BaseCycles` is charged once at the end. This keeps the `>= 1 cycle` invariant (T3)
  and is data-axis-transparent.

> **Note: because the JIT parity gate does NOT compare CycleCount (T2), the exact MOVE timing table value is NOT
> correctness-gated in PR-4.** A wrong `BaseCycles` would only show up in the (caveated, coarse) arc-end
> benchmark, not in the TomHarte-through-JIT parity. So the cycle table can be the standard published MOVE
> timing without per-case verification — a real simplification. (The Z80 had to nail cycles because the Z80 JIT
> parity gate DID compare cycles; the 68000's does not.) **Pin the cycle table to the published 68000 values and
> move on; do not over-invest in cycle exactness the gate cannot see.**

### DECISION A7 — A7 banking in the emitted EA resolver (G3)

`(An)`/`(An)+`/`-(An)`/`d16(An)`/`d8(An,Xn)` with `An == A7` (reg 7) must use the BANKED A7 (`SupervisorMode ?
SSP : USP`), and the byte forms word-align (`mag = 2` for `(A7)+`/`-(A7)` at `.b`, `ComputeEa` `pureEa` block).
A7 is NOT a field (G3) — `RegField("A7")` throws. The emit arm must, for `An` reads/writes where `reg == 7`,
emit the S-bit branch: `((SR >> 13) & 1) != 0 ? Ldfld SSP : Ldfld USP` (and the symmetric store). **Recommended:
a shared helper `EmitLoadAreg(ctx, reg)` / `EmitStoreAreg(ctx, reg)` that, for `reg < 7`, does `RegField($"A{reg}")`,
and for `reg == 7`, emits the S-bit branch over USP/SSP.** This helper is reused by PR-5 (ALU EA) and PR-6 (the
`-(A7)` stack push of BSR/JSR), so it belongs in the shared `BlockCompiler.M68000.cs` infrastructure. The
S-bit is `(SR >> 13) & 1` (S=0x2000). Mirror the `A7` property body (`M68000Cpu.cs:60-64`) exactly.

    // ComputeCycles/JitBaseCycles today (CpuEmitter.cs:1073 throws on a 68000 mode). Keyed on the 68000-only

    // (DECISION T2), this value is NOT correctness-gated — pin it to the standard table and move on.
    private static int M68kMoveCycles(int srcMode, int srcReg, int dstMode, int dstReg, int size)
    {

        int dst = M68kEaCost(dstMode, dstReg, isLong, isSource: false);

    {

        2 or 3 => isLong ? 8 : 4,                 // (An) / (An)+
        4      => isLong ? 10 : 6,                // -(An)  (the extra predecrement clock)

            1 => isLong ? 16 : 12,                // abs.L
            2 => isLong ? 12 : 8,                 // d16(PC)
            3 => isLong ? 14 : 10,                // d8(PC,Xn)
            4 => isLong ? 8 : 4,                  // #imm
            _ => 0,
        },
        _ => 0,
    };

    // .b: reg = (reg & ~0xFF)   | (value & 0xFF);

        il.Emit(OpCodes.Ldc_I4, unchecked((int)mask)); il.Emit(OpCodes.And);        // value & mask
        il.Emit(OpCodes.Or);
        il.Emit(OpCodes.Stfld, _regWide32Fields[name]);        // reg = (old & ~mask) | (value & mask)
    }

- [ ] **Step 2:** `EmitM68kEaRead(ctx, eaMode, eaReg, size, extWordIndex)` — the 12-mode read switch. For Dn/An
  (modes 0/1) the operand is the register; for memory modes, compute the EA (address-once), then read via the
  sized bus helper. The extension words are read from the code stream at the instruction's operand bytes (the
  emit arm knows the operand layout — like the Z80 absolute-EA read, `BlockCompiler.Z80.cs:301-312`):

```csharp
    // M6 PR-4: read an EA operand (sized). Leaves the operand on the stack (.b/.w/.l masked). Resolves the EA
    // EXACTLY ONCE (the address-once discipline) into ctx.AddrLocal, then reads. (An)+/-(An) mutate An.
    private void EmitM68kEaRead(EmitContext ctx, int eaMode, int eaReg, int size, ref int extIndex)
    {
        ILGenerator il = ctx.Il;
        switch (eaMode)
        {
            case 0: EmitLoadDataRegSized(ctx, $"D{eaReg}", size); return;     // Dn
            case 1: EmitLoadDataRegSized(ctx, $"A{eaReg}", size); return;     // An (rare as a source; .w sign-ext handled by caller for MOVEA dest)
            case 2:                                                            // (An)
                EmitLoadAreg(ctx, eaReg); EmitM68kReadSized(ctx, size); return;
            case 3:                                                            // (An)+ : ea=An; An += mag
                EmitLoadAreg(ctx, eaReg); il.Emit(OpCodes.Stloc, ctx.AddrLocal);
                EmitAdvanceAreg(ctx, eaReg, +M68kMag(eaReg, eaMode, size));
                il.Emit(OpCodes.Ldloc, ctx.AddrLocal); EmitM68kReadSized(ctx, size); return;
            case 4:                                                            // -(An) : An -= mag; ea = An
                EmitAdvanceAreg(ctx, eaReg, -M68kMag(eaReg, eaMode, size));
                EmitLoadAreg(ctx, eaReg); EmitM68kReadSized(ctx, size); return;
            case 5:                                                            // d16(An)
                EmitLoadAreg(ctx, eaReg); EmitAddSignedExtWord(ctx, ref extIndex); EmitM68kReadSized(ctx, size); return;
            case 6:                                                            // d8(An,Xn)
                EmitM68kBriefIndex(ctx, eaReg, isPc: false, ref extIndex); EmitM68kReadSized(ctx, size); return;
            case 7:
                switch (eaReg)
                {
                    case 0: EmitSignExtWordAsAddr(ctx, ref extIndex); EmitM68kReadSized(ctx, size); return;   // abs.W
                    case 1: EmitAbsLongAddr(ctx, ref extIndex); EmitM68kReadSized(ctx, size); return;          // abs.L
                    case 2: EmitPcRelD16(ctx, ref extIndex); EmitM68kReadSized(ctx, size); return;             // d16(PC)
                    case 3: EmitM68kBriefIndex(ctx, 0, isPc: true, ref extIndex); EmitM68kReadSized(ctx, size); return;  // d8(PC,Xn)
                    case 4: EmitImmOperand(ctx, size, ref extIndex); return;                                   // #imm (from ext words)
                }
                break;
        }
        throw new EmulationException($"EmitM68kEaRead: unhandled EA mode {eaMode}/{eaReg}");
    }
```

> The `ref int extIndex` threads the per-operand extension-word position so source and dest don't collide (the
> dest's ext words follow the source's — `DestExtensionWords`, `M68000Cpu.Move.cs:94-111`). **Confirm whether the

- [ ] **Step 3:** `EmitM68kMove` — the arm (DECISION P3: decode the operword at compile time):

```csharp
    // M6 PR-4: the 68000 MOVE/MOVEA emit arm. Decodes the operword's EA matrix at emit time (DECISION P3),
    // resolves+reads the source EA, resolves+writes the dest EA (the MOVE bits-11-6 mode/reg SWAP quirk),
    // sets the MOVE CCR (N/Z, V=C=0, X untouched; MOVEA sets none), charges BaseCycles. Mirrors MoveExecute
    // (M68000Cpu.Move.cs:78-120) on the DATA axis. NO prefetch-queue / trace (DECISION T).
    private void EmitM68kMove(EmitContext ctx, ushort pc, OpcodeDescriptor d)
    {
        ILGenerator il = ctx.Il;
        ushort operword = _bus.Read16(pc);                       // the operword is a code-stream constant
        int size = M68kSizeFromKey(d);                           // 0/1/2 from the descriptor key
        int srcMode = (operword >> 3) & 7, srcReg = operword & 7;
        int dstReg = (operword >> 9) & 7, dstMode = (operword >> 6) & 7;   // NOTE the swap: mode=8-6, reg=11-9
        bool isMovea = dstMode == 1;                             // MOVE to An = MOVEA (no CCR; whole An; .w sign-ext)

        int extIndex = 0;
        // 1) read the source operand (sized) -> stash in a local (so the dest-EA resolution has a clean stack)
        EmitM68kEaRead(ctx, srcMode, srcReg, size, ref extIndex);
        il.Emit(OpCodes.Stloc, ctx.SumLocal);                    // value

        // 2) set the MOVE CCR from `value` (MOVEA sets none) — N/Z, V=C=0, X untouched
        if (!isMovea) EmitM68kMoveCcr(ctx, ctx.SumLocal, size);

        // 3) write the dest. MOVEA -> whole An (.w sign-extend); MOVE -> size-aware EA write.
        if (isMovea)
        {
            il.Emit(OpCodes.Ldloc, ctx.SumLocal);
            if (size == 1) { il.Emit(OpCodes.Conv_I2); il.Emit(OpCodes.Conv_I4); }   // .w sign-extend to 32
            EmitStoreReg32(ctx, $"A{dstReg}");                   // whole An (banking handled if dstReg==7? No — An direct write uses An field; A7 direct is rare/illegal as MOVEA dest. Confirm.)
        }
        else
        {
            il.Emit(OpCodes.Ldloc, ctx.SumLocal);
            EmitM68kEaWrite(ctx, dstMode, dstReg, size, ref extIndex);   // size-aware; memory or Dn
        }

        // 4) charge the (coarse) BaseCycles (DECISION C-jit / T) — keeps the >= 1-cycle budget invariant (T3)
        EmitChargeCycles(ctx, d.BaseCycles);
    }

    // M6 PR-4: the MOVE CCR — N = (value & signbit(size)) != 0; Z = (value & mask(size)) == 0; V=C=0; X untouched.
    // SR = (SR & 0xFFF0) | (N?0x08:0) | (Z?0x04:0).  (SetMoveCcr oracle, M68000Cpu.Move.cs:64-75.)
    private void EmitM68kMoveCcr(EmitContext ctx, LocalBuilder valueLocal, int size)
    {
        ILGenerator il = ctx.Il;
        uint mask = size == 0 ? 0xFFu : size == 1 ? 0xFFFFu : 0xFFFFFFFFu;
        uint signbit = size == 0 ? 0x80u : size == 1 ? 0x8000u : 0x80000000u;
        // compute the new low byte into ctx.DataLocal: keep SR high bits + X(0x10); set N(0x08)/Z(0x04).
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, _m68kSR);
        il.Emit(OpCodes.Ldc_I4, unchecked((int)0xFFF0)); il.Emit(OpCodes.And);      // SR & 0xFFF0 (clear N Z V C; keep X + system byte)
        // | (N?8:0):
        il.Emit(OpCodes.Ldloc, valueLocal); il.Emit(OpCodes.Ldc_I4, unchecked((int)signbit)); il.Emit(OpCodes.And);
        var noN = il.DefineLabel(); var afterN = il.DefineLabel();
        il.Emit(OpCodes.Brfalse, noN); il.Emit(OpCodes.Ldc_I4, 0x08); il.Emit(OpCodes.Or); il.Emit(OpCodes.Br, afterN);
        il.MarkLabel(noN); il.MarkLabel(afterN);
        // | (Z?4:0):
        il.Emit(OpCodes.Ldloc, valueLocal); il.Emit(OpCodes.Ldc_I4, unchecked((int)mask)); il.Emit(OpCodes.And);
        var nz = il.DefineLabel(); var afterZ = il.DefineLabel();
        il.Emit(OpCodes.Brtrue, nz); il.Emit(OpCodes.Ldc_I4, 0x04); il.Emit(OpCodes.Or); il.Emit(OpCodes.Br, afterZ);
        il.MarkLabel(nz); il.MarkLabel(afterZ);
        il.Emit(OpCodes.Conv_U2);
        il.Emit(OpCodes.Stloc, ctx.DataLocal);
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Stfld, _m68kSR);
    }
```

> **Builder note — the CCR helper's stack discipline.** The `EmitM68kMoveCcr` above OR-s the N/Z terms onto the

## BLOCKER (Builder, found in pre-merge review + verification) — 68000 emit arm is DEAD at runtime

**Status: ⚠️ DEAD-ARM BLOCKER RESOLVED by PR-4a (the arm now DISPATCHES — `M68kMoveEmitSelections > 0`), but
the now-REAL parity gate surfaced a SECOND, deeper blocker: the MOVE EA helpers emit incorrect IL. Still do NOT
merge. See "## RESOLUTION + NEW BLOCKER (PR-4a)" at the end of this section.**

**Original status (now historical): 🚫 BLOCKED — do NOT merge. The PR-4 emit arm does not execute; the parity
gate is vacuous.**

### The defect
`BlockCompiler.Discover` (`src/CpuEmulator.Jit/BlockCompiler.cs:293`) unconditionally builds a **byte-granular**
`BusFetchStream` (`UnitBytes == 1`; `NextUnit()` → `_bus.Read8`). The 6502/Z80/8086 decoders read bytes, so this
works for them. But the **68000's generated `Decode()` is word-granular**: `uint operword = stream.NextUnit();`
(`M68000Cpu.g.cs:748`) expects a 16-bit big-endian word (`M68000FetchStream`, `UnitBytes == 2`). Fed a byte stream,
`Decode` reads only the operword's **high byte** (e.g. `0x32` from `MOVE.w D0,(A1)+` = `0x32C0`), mis-matches the
field-op table, and `DescriptorFor` returns `OpcodeDescriptor.Undefined` (`NeedsFallback=true`). So **every 68000
block — MOVE/MOVEA/MOVEQ included — falls back to `inner.Step()` at RUNTIME.** `EmitM68kMove` is never dispatched.

### How it was proven
A compile-time arm-selection counter in `EmitM68kMove` recorded **0 selections** across **847 executed MOVE.w
corpus cases** (all "parity-green") + the synthetic guard block. Reverting the PR-4 review fix (the
`M68kValueLocal` clobber) left the full `M68000JitMoveFamilyTests` UAT=full sweep (~33k cases) **byte-identical
green** — impossible if the emit arm ran. The "green" parity gates are **interpreter-vs-interpreter**
(tier-1 degrades to `inner.Step`), NOT tier-0-vs-tier-1 of the emitted IL.

### Consequence for PR-4
- The descriptor GENERATION (Task 1: the 8 net-new keyed rows), the wide-bus helpers, the 32-bit register
  helpers, the EA resolver, the A7 banking, and the MOVE/MOVEA/MOVEQ emit arm are all PRESENT and STATICALLY
  reviewed as correct (and the review-fix `M68kStoreStageLocal` is the right fix for the dest-`(An)+`/`-(An)`
  operand-clobber, even though that path is currently unreachable).
- BUT PR-4's load-bearing merge precondition — **actual emitted-IL MOVE data-axis parity, byte-identical
  tier-0-vs-tier-1** — is **NOT met**. The emit arm does not run.
- `FallbackEmitCount` (a COMPILE-time count) drops as claimed, but that is decoupled from runtime dispatch:
  the compile path and the runtime `Discover` both mis-decode identically, so the block is still a runtime
  fallback. (The descriptor-state unit tests pass because they call `DescriptorFor(key)` with the CORRECT
  precomputed key, bypassing the byte-stream decode.)

### The blocking fix (out of PR-4 scope — net-new, needs Planner/Architect)
`BlockCompiler.Discover` must feed the 68000 a **word-granular** fetch stream (honor `IFetchStream.UnitBytes` /
construct `M68000FetchStream` for the 68000 target). This is a generic-compiler change touching the discovery
walk for ALL CPUs (or a per-`_target` fetch-stream factory seam on `IJitTarget`), with its own correctness +
empty-diff implications. It was NOT in the PR-4 plan's recon (the plan assumed keyed `DescriptorFor` dispatch
would suffice once rows existed; the recon missed that `Discover` re-runs the decode walk through a byte stream).
Once that lands, the PR-4 emit arm + the (currently vacuous) parity gates become real and load-bearing.
