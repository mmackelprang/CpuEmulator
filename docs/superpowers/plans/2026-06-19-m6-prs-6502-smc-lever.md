# M6 PR-S — the 6502 SMC / recompile-cost lever (the W1 Klaus 0.00× hole)

> **Status:** PLANNED (2026-06-19). The co-equal M6 lever (ADR 0011 §3.4 / §7 OQ3 / §8 PR-S). Unlike the
> emit PRs (PR-1…PR-6, PR-B/C/D — which add *what* the JIT emits), PR-S is a **JIT-performance policy
> lever**: the 6502 already emits IL, but on the SMC-heavy W1 (Klaus) the JIT runs at ~**0.00×** of the
> reference (slower than its own interpreter) because the block cache is **invalidated + recompiled faster
> than it executes** — every self-modifying store evicts the hot block and the very next dispatch
> recompiles it, so `Compile()` runs per instruction and never amortizes. PR-S adds a **recompile-cost cap
> with interpreter-fallback cooldown**: a block PC that thrashes (recompiles past a cap) stops re-JITing
> and runs via the interpreter oracle for a cooldown window. **This is a policy change — when to re-JIT vs
> interpret — never a change to what is correct.**
>
> **Dependencies:** NONE. PR-S touches `BlockCache.cs` / `JittedCpu.cs` / `JitOptions.cs` (JIT runtime +
> options) + new tests + a bench instrumentation surface — a **different file set from every emit PR** (no
> `CpuEmitter.cs`, no `BlockCompiler.*` emit arms). Orthogonal to the entire emit arc; lands any time.
> Main @ `efcdd94` (the M6 emit arc complete: Z80 + 68000 + 8086 all emit).

---

## 1. The problem — the exact thrash site (file:line, traced)

The dispatcher loop is `JittedCpu.Run` (`src/CpuEmulator.Jit/JittedCpu.cs:117-147`). Each iteration of the
`while (cycleBudget > 0)` loop, in order:

```
JittedCpu.cs:140   _cache.InvalidateIfDirty();        // SMC: evict every block on a dirtied page
JittedCpu.cs:141   CompiledBlock<TCpu> block = _cache.GetOrCompile((ushort)_inner.GetRegister(_pcName), _compiler);
JittedCpu.cs:142   RunChain(block, ref cycleBudget);  // run the block + follow its chain edges
```

On a self-modifying store to a code page, the emitted RAM store calls `dirty.Mark(page)`
(`BlockCompiler.cs:180`, `DirtyMap.Mark`), and one of two things ends the running block:

- the **intra-block SMC guard** (`EmitSmcGuard`, `BlockCompiler.cs:702-725`) exits `BlockExit.Recompile`
  when the store hit one of the block's own `SpannedPages` — `RunChain` returns to the dispatcher
  (`JittedCpu.cs:171`); or
- the **chain-edge `dirty.Any` gate** (gate (3) in `EmitChainOrExit`, `BlockCompiler.cs:1402-1405`) breaks
  the chain when *any* page is dirty, forcing a dispatcher round-trip.

Either way the next loop iteration runs `InvalidateIfDirty()` (`BlockCache.cs:66-77`) → per-page `Evict`
(`BlockCache.cs:96-104`) → drops the block from `_blocks` + `_blocksByPage` + severs its chain links — and
then **line 141 immediately recompiles the same PC** via `GetOrCompile` → `compiler.Compile(pc)`
(`BlockCache.cs:33-45`; `BlockCompiler.Compile`, `BlockCompiler.cs:443-476`: `Discover` the run + emit a
fresh `DynamicMethod`).

**Klaus's pathology** (ADR 0011 §1.1 fact 2; §6 6502 W1 table): the functional test writes test-vector
bytes into code-adjacent pages on nearly every iteration (PHP/PLP/PLA/CMP flag-save-restore pattern — 16.2%
PHP, 15.7% CMP, 8.7% PLA). So the hot block is evicted-and-recompiled **per dispatch**. `Compile()` (a
`Discover` walk + a `DynamicMethod` IL emit + `CreateDelegate`) costs far more than the interpreter's own
`Step()` dispatch — so a JIT that recompiles every instruction is strictly slower than just interpreting.
That is the measured 0.00× (466 K cycles/sec JIT vs 178 M cycles/sec interpreter).

**The key observation that makes the lever safe + cheap:** the cost being burned is the **`Compile()` per
dispatch**, NOT the block's *execution*. The fallback valve (`EmitFallbackStep` → `inner.Step`,
`BlockCompiler.cs:1452-1474`) is *already* the byte-exact interpreter oracle the differential fuzzer proves
parity against. So the lever is: **detect a PC whose block recompiles too often, and for a cooldown window
run that PC through the interpreter instead of recompiling** — trading the per-dispatch `Compile()` cost
for the interpreter's `Step()` cost (which is what the interpreter pays anyway, and which on Klaus is
*faster* than recompiling). No correctness surface moves: the interpreter is the oracle.

## 2. Design decisions

### DECISION S-1: the lever is (a) a recompile-cost cap with interpreter cooldown — NOT (b) finer invalidation

ADR 0011 §7 OQ3 names three candidates. The evaluation against **correctness-safety × W1 payoff**:

- **(a) Recompile-cost cap / thrash detection (CHOSEN).** Track a per-PC recompile counter; once a PC's
  block has been recompiled more than a cap within a window, mark that PC "SMC-hot" and, instead of
  recompiling, **run the instruction(s) at that PC through `inner.Step` for a cooldown of N dispatches**,
  then let it try the JIT again. This is a pure **policy** change confined to the dispatcher + cache
  bookkeeping (`JittedCpu.Run` / `BlockCache`). **It touches NOTHING about what is invalidated or what is
  correct** — the cooldown path is the same `inner.Step` oracle the fallback valve and the differential
  fuzzer already exercise. Payoff is direct: it eliminates the per-dispatch `Compile()` that *is* the
  0.00×. Highest safety × payoff.

- **(b) Finer-grained invalidation (REJECTED as the lever).** Invalidation is **already page-precise**
  (`InvalidateIfDirty` evicts only blocks on dirtied pages via `_blocksByPage`, `BlockCache.cs:72`).
  Going finer (per-block byte-range checks, or the ADR §3.4 "per-block checksum" candidate) (1) does NOT
  help Klaus — Klaus genuinely writes *into the executing block's own page*, so a finer grain still evicts
  the hot block; and (2) adds re-validation cost to the **correctness-critical hot path**, the single
  highest-risk area in the JIT, for uncertain W1 gain. Wrong risk/payoff ratio.

- **(c) Hybrid (a)+(b) (REJECTED for M6).** (b)'s marginal Klaus value is ~0 (writes hit code pages), so
  stacking (b)'s correctness-path change on top of (a) doubles the risk for little extra W1 payoff. The
  *other* (b)-shaped lever — **per-bank block specialization** keyed on `(PC, bankState)` (ADR 0009 OQ3) —
  targets a **different** workload (bank-switching mappers, not SMC) and stays a named follow-on, out of
  PR-S scope (no bank-switching machine exists yet).

**Chosen: (a).** Correctness-safety: maximal (routes SMC-hot PCs through the existing oracle). W1 payoff:
removes the per-dispatch `Compile()` that causes 0.00×. This is ADR 0011 §7 OQ3's recommended candidate (a)
and §8 PR-S's stated likely lever.

### DECISION S-2: track recompiles per-PC in the cache, cooldown in the dispatcher

The recompile counter lives where recompiles happen — `BlockCache`. `GetOrCompile` is the one place a
block is (re)compiled (`BlockCache.cs:33-45`), and `Evict` is the one place a block is dropped
(`BlockCache.cs:96-104`). So:

- a per-PC `Dictionary<ushort,int> _recompiles` increments when `GetOrCompile` compiles a PC that was
  **previously evicted** (a *re*compile, not a first compile);
- a per-PC `Dictionary<ushort,int> _cooldown` holds the remaining dispatch count for a PC currently in
  interpreter-cooldown;
- the cache exposes `bool ShouldInterpret(ushort pc)` (true while a PC is SMC-hot + cooling) and
  `void NoteDispatched(ushort pc)` (decrements the cooldown), plus committed test-seam counters
  (`SmcHotPcCount`, `TotalRecompiles`).

The dispatcher (`JittedCpu.Run`) consults `ShouldInterpret(pc)` **before** `GetOrCompile`: if true, it runs
ONE `inner.Step` (the same shape as the existing `InterruptPending` / `Halted` fast paths,
`JittedCpu.cs:121-139`) and `NoteDispatched(pc)` instead of compiling. This keeps `BlockCache` owning the
*policy state* and `JittedCpu` owning the *dispatch decision* — the existing separation.

### DECISION S-3: the cap is a `JitOptions` knob, default ON, with a disable for differential isolation

The cap + cooldown window are `JitOptions` fields (the established pattern — `DisableChaining`,
`BlockLengthCap`). Defaults chosen so emit-only workloads (W2/W3, which never SMC) are **byte-identical**
to today (their PCs never recompile, so the counter never trips). `DisableSmcLever` (default false) turns
the lever fully off — required so the differential fuzzer can run BOTH with-lever and without-lever and
prove the lever is parity-transparent (mirrors how the fuzzer runs chaining on AND off, `DifferentialFuzzTests.cs:42-43`).

### DECISION S-4: correctness invariant — cooldown re-arms on a clean run, and a cooling PC still honors SMC

Two correctness subtleties the cooldown must preserve, both kept by routing through the existing machinery:

1. **A cooling PC's interpreter Step still self-modifies + dirty-marks correctly.** `inner.Step` does its
   own `WriteBus` → `dirty.Mark` through the bus (the interpreter is the oracle), so an SMC store made
   *during* cooldown still marks its page; the next dispatch's `InvalidateIfDirty` still evicts any stale
   compiled neighbor. Cooldown changes *which tier runs the PC*, not whether SMC is observed.

2. **Cooldown is bounded + self-healing.** After the cooldown window expires the PC is allowed to JIT again
   (the counter resets on the next successful, non-re-evicted run — see Task 2's `GetOrCompile`). A PC that
   was hot during a warmup burst but then stabilizes returns to full JIT speed; a PC that stays hot keeps
   cycling cheaply through the interpreter. There is no permanent "give up" that could strand a PC the
   workload later runs hot-and-stable.

## 3. The defaults (tunable; the directional W1 gate confirms them)

```
SmcRecompileCap     = 16    // a PC recompiled > 16 times (re-evicted-then-recompiled) is SMC-hot
SmcCooldownDispatches = 256 // run the SMC-hot PC via the interpreter for 256 dispatches, then retry JIT
```

Rationale: the cap is high enough that a normal warmup (a block compiled once, maybe re-compiled a handful
of times as nearby pages settle) never trips, but low enough that Klaus's per-dispatch thrash trips within
the first few hundred cycles. The cooldown is long enough to amortize away the `Compile()` cost over many
interpreted instructions, short enough that a PC that stops being hot recovers quickly. **These are starting
values; Task 5's directional W1 check confirms recompile-count drops sharply and W1 moves off 0.00× — if it
does not, the plan's tuning note (Task 5) says to lower the cap / lengthen the cooldown and re-run.** They
are `JitOptions` fields, so tuning is a one-line change, never a recompile of the policy.

```csharp
internal sealed class BlockCache<TCpu>(int pageCount, JitOptions opts) where TCpu : class
{
    private readonly int _pageCount = pageCount;
    private readonly JitOptions _opts = opts;
    private readonly System.Collections.Generic.Dictionary<ushort, CompiledBlock<TCpu>> _blocks = new();
    private readonly System.Collections.Generic.Dictionary<int, System.Collections.Generic.List<CompiledBlock<TCpu>>> _blocksByPage = new();
    public DirtyMap Dirty { get; } = new(pageCount);

    // M6 PR-S: the SMC/recompile-cost lever state. _recompiles[pc] counts how many times the block at
    // pc has been EVICTED-then-recompiled (a first compile is not a recompile). When it exceeds the
    // cap, the PC is SMC-hot: _cooldown[pc] is set to the cooldown window and ShouldInterpret(pc)
    // returns true until the window drains (the dispatcher runs inner.Step for it instead of compiling).
    private readonly System.Collections.Generic.Dictionary<ushort, int> _recompiles = new();
    private readonly System.Collections.Generic.Dictionary<ushort, int> _cooldown = new();
    // M6 PR-S: committed instrumentation (the §3.4 "quantify first" asserted artifact). TotalRecompiles
    // is every evict-then-recompile across the run; TotalEvictions is every block drop; SmcHotPcCount is
    // how many distinct PCs ever tripped the cap. A test asserts the lever drops TotalRecompiles sharply
    // on an SMC-thrash program (the recompile-count-drop gate).
    public long TotalRecompiles { get; private set; }
    public long TotalEvictions { get; private set; }
    public int SmcHotPcCount => _everHotPcs.Count;
    private readonly System.Collections.Generic.HashSet<ushort> _everHotPcs = new();

    public ChainTable<TCpu> Chains { get; } = new();

    /// <summary>M6 PR-S: should the dispatcher run this PC through the interpreter (because it is
    /// SMC-hot and in its cooldown window) instead of compiling it? False when the lever is disabled.</summary>
    public bool ShouldInterpret(ushort pc) =>
        !_opts.DisableSmcLever && _cooldown.TryGetValue(pc, out int n) && n > 0;

    /// <summary>M6 PR-S: account one interpreter-dispatch of an SMC-hot PC — decrement its cooldown.
    /// When the window drains the entry is removed, so the next dispatch retries the JIT (self-healing:
    /// a PC that stopped being hot returns to full JIT speed; a still-hot PC re-trips the cap cheaply).</summary>
    public void NoteInterpretedDispatch(ushort pc)
    {
        if (_cooldown.TryGetValue(pc, out int n))
        {
            if (n <= 1) { _cooldown.Remove(pc); _recompiles.Remove(pc); }   // window drained: re-arm the JIT
            else _cooldown[pc] = n - 1;
        }
    }

    public CompiledBlock<TCpu> GetOrCompile(ushort pc, BlockCompiler<TCpu> compiler)
    {
        if (_blocks.TryGetValue(pc, out var hit)) return hit;
        // A miss here is either a first compile or a recompile (the block was evicted). Count the
        // recompile + arm the cooldown if this PC has now thrashed past the cap.
        if (_recompiles.TryGetValue(pc, out int prior))
        {
            int now = prior + 1;
            _recompiles[pc] = now;
            TotalRecompiles++;
            if (!_opts.DisableSmcLever && now > _opts.SmcRecompileCap)
            {
                _cooldown[pc] = _opts.SmcCooldownDispatches;   // SMC-hot: cool down via the interpreter
                _everHotPcs.Add(pc);
            }
        }
        CompiledBlock<TCpu> block = compiler.Compile(pc);
        _blocks[pc] = block;
        foreach (int page in block.SpannedPages)
        {
            if (!_blocksByPage.TryGetValue(page, out var list))
                _blocksByPage[page] = list = [];
            list.Add(block);
        }
        return block;
    }
```

In `Evict`, record that the PC has been evicted (so the *next* `GetOrCompile` of it counts as a recompile)
and bump the eviction counter. Add at the top of `Evict` (`BlockCache.cs:96`, before `_blocks.Remove`):

```csharp
    private void Evict(CompiledBlock<TCpu> block)
    {
        TotalEvictions++;
        // M6 PR-S: seed the recompile counter so the NEXT GetOrCompile of this PC is counted as a
        // recompile (a first-ever compile of a never-evicted PC is not). Use a sentinel 0 entry; the
        // recompile increment in GetOrCompile turns the first post-evict compile into count 1.
        if (!_recompiles.ContainsKey(block.EntryPc))
            _recompiles[block.EntryPc] = 0;
        _blocks.Remove(block.EntryPc);
        foreach (int page in block.SpannedPages)
            if (_blocksByPage.TryGetValue(page, out var list))
                list.Remove(block);
        Chains.Sever(block.EntryPc);
        Chains.Forget(block);
    }
```

`FlushAll` must also clear the new state (the per-worker reuse reset must be byte-equivalent to a fresh
cache — `BlockCache.cs:84-90`):

```csharp

    {
        _blocks.Clear();
        _blocksByPage.Clear();
        Chains.Clear();
        Dirty.Clear();
        _recompiles.Clear();    // M6 PR-S: reset the lever state on reuse
        _cooldown.Clear();
```

**Note for the implementer (DECISION S-2 detail):** the sentinel-0 seed in `Evict` means a PC's first
recompile lands at count 1, its 16th at count 16, and the 17th evict-then-recompile (count 17 > cap 16)

recompiles."

### Task 5 — the recompile-count-drop instrumentation gate (committed, asserted)

**New file:** `tests/CpuEmulator.Tests/Jit/SmcRecompileLeverTests.cs`

This is the §3.4 "instrument recompile/eviction counts as a committed, asserted artifact" deliverable. It
drives the SMC seed-class on a tiny synthetic thrash program and proves (a) parity to the interpreter holds
WITH the lever on, (b) the lever drops the recompile count sharply vs lever-off, and (c) the lever marks at
least one PC SMC-hot on a thrashing program.

```csharp
using CpuEmulator.Core;
using CpuEmulator.Cpus.Mos6502;
using CpuEmulator.Jit;

namespace CpuEmulator.Tests.Jit;

/// <summary>M6 PR-S — the SMC/recompile-cost lever. The lever is a PERFORMANCE policy: a block PC that
/// recompiles past the cap (the self-modifying-code thrash signature) runs via the interpreter oracle
/// for a cooldown window instead of recompiling every dispatch. These pins prove (1) the lever is
/// parity-transparent (the interpreter is the oracle, so the result is byte-identical with the lever ON
/// or OFF), (2) the lever sharply DROPS the recompile count on a thrashing program (the W1 fix's
/// mechanism, asserted as a committed artifact — ADR 0011 §3.4), and (3) it actually trips (marks a PC
/// SMC-hot) on a thrasher.</summary>
public class SmcRecompileLeverTests
{
    private static AddressSpace NewRamSpace()
    {
        var space = new AddressSpace(AddressSpaceKind.Program, addressBits: 16);
        space.MapMemory(0x0000, new byte[0x10000], writable: true);
        return space;
    }

    private static void Poke(AddressSpace space, ushort at, params byte[] bytes)
    {
        for (int i = 0; i < bytes.Length; i++)
            space.Write8((uint)(at + i), bytes[i]);
    }

    /// <summary>A tight self-modifying loop at $0200: it stores a (harmless, self-consistent) opcode
    /// byte INTO its own code page every iteration, then loops — the per-dispatch thrash signature.
    /// LDX #count seeds the loop trip; each pass: STA $0203 (patch a NOP-class byte onto this very
    /// page → dirty-mark → SMC guard → evict+recompile), DEX, BNE back, then JMP-self to park.</summary>
    private static (Mos6502Cpu Cpu, JittedCpu<Mos6502Cpu> Jit) NewThrasher(JitOptions opts, byte trips)
    {
        var space = NewRamSpace();
        // $0200: LDX #trips
        // $0202: LDA #$EA           (NOP opcode value — patching it in is self-consistent)
        // $0204: STA $0207          (store onto THIS page $02 — the SMC thrash; $0207 is the NOP slot)
        // $0207: EA (NOP)           (the patched-every-pass byte)
        // $0208: DEX
        // $0209: BNE $0202          (loop — recompiles the block each pass)
        // $020B: JMP $020B          (park)
        Poke(space, 0x0200, 0xA2, trips, 0xA9, 0xEA, 0x8D, 0x07, 0x02, 0xEA,
                            0xCA, 0xD0, 0xF7, 0x4C, 0x0B, 0x02);
        var cpu = new Mos6502Cpu(space, UndefinedOpcodePolicy.Nop) { PC = 0x0200, S = 0xFD, P = 0x34 };
        return (cpu, new JittedCpu<Mos6502Cpu>(cpu, Mos6502Cpu.JitTarget, space, options: opts));
    }

    private static void DriveToPark(Mos6502Cpu cpu, JittedCpu<Mos6502Cpu> jit)
    {
        while (cpu.CycleCount < 5_000_000)
        {
            ushort before = cpu.PC;
            long budget = 64;
            jit.Run(ref budget);
            if (cpu.PC == before) return;   // JMP-self park
        }
    }

    [Fact]
    public void Lever_on_and_off_reach_the_same_state_and_cycles()
    {
        // Parity: the lever changes the tier a hot PC runs on, NOT the result. On the SAME thrasher,
        // lever-on and lever-off must agree on final A/X/P/PC + cycles (the interpreter is the oracle).
        var (onCpu, onJit) = NewThrasher(new JitOptions(), trips: 200);
        var (offCpu, offJit) = NewThrasher(new JitOptions { DisableSmcLever = true }, trips: 200);
        DriveToPark(onCpu, onJit);
        DriveToPark(offCpu, offJit);
        Assert.Equal(offCpu.A, onCpu.A);
        Assert.Equal(offCpu.X, onCpu.X);
        Assert.Equal(offCpu.P, onCpu.P);
        Assert.Equal(offCpu.PC, onCpu.PC);
        Assert.Equal(offCpu.CycleCount, onCpu.CycleCount);
    }

    [Fact]
    public void Lever_drops_the_recompile_count_sharply_on_a_thrasher()
    {
        // THE COMMITTED ARTIFACT (ADR 0011 §3.4): on an SMC-thrash program, the lever-ON recompile
        // count is far below the lever-OFF count — the mechanism behind the W1 fix, asserted.
        var (offCpu, offJit) = NewThrasher(new JitOptions { DisableSmcLever = true }, trips: 200);
        DriveToPark(offCpu, offJit);
        long off = offJit.TotalRecompiles;

        var (onCpu, onJit) = NewThrasher(new JitOptions(), trips: 200);
        DriveToPark(onCpu, onJit);
        long on = onJit.TotalRecompiles;

        // Lever-off recompiles ~once per loop trip (the thrash); lever-on caps recompiles then runs the
        // interpreter, so its recompile count is a small fraction. Assert a sharp drop (>= 4x fewer) and
        // that lever-off actually thrashed (so the comparison is non-vacuous).
        Assert.True(off > 50, $"lever-off should thrash (recompile per trip); got {off}");
        Assert.True(on * 4 < off, $"lever-on recompiles {on} should be <<  lever-off {off} (sharp drop)");
    }

    [Fact]
    public void Lever_marks_a_thrashing_pc_smc_hot()
    {
        // Non-vacuity: the lever actually trips on a thrasher (>= 1 PC marked SMC-hot), so the drop
        // above is the lever firing, not an artifact of a short run.
        var (cpu, jit) = NewThrasher(new JitOptions(), trips: 200);
        DriveToPark(cpu, jit);
        Assert.True(jit.SmcHotPcCount >= 1, "the thrasher should mark at least one PC SMC-hot");
    }

    [Fact]
    public void Non_smc_program_never_trips_the_lever()
    {
        // A non-self-modifying loop (stores to a DATA page, not code) must never trip the lever — its
        // block compiles once and runs; the recompile counter stays 0, the byte-identical-W2/W3 guard.
        var space = NewRamSpace();
        // $0200: LDX #200 / LDA #$01 / STA $4000 (DATA page, no SMC) / DEX / BNE $0202 / JMP-self
        Poke(space, 0x0200, 0xA2, 0xC8, 0xA9, 0x01, 0x8D, 0x00, 0x40, 0xCA, 0xD0, 0xF8, 0x4C, 0x0A, 0x02);
        var cpu = new Mos6502Cpu(space, UndefinedOpcodePolicy.Nop) { PC = 0x0200, S = 0xFD, P = 0x34 };
        var jit = new JittedCpu<Mos6502Cpu>(cpu, Mos6502Cpu.JitTarget, space);
        DriveToPark(cpu, jit);
        Assert.Equal(0, jit.SmcHotPcCount);
        Assert.Equal(0L, jit.TotalRecompiles);
    }
}
```

### Task 6 — the bounded, directional W1 (Klaus) check (the lever-works gate)

**New file:** `tests/CpuEmulator.Tests/Klaus/KlausSmcLeverDirectionalTests.cs`

PR-S's entire deliverable IS the W1 perf fix, so per the prompt this PR carries a **bounded, directional W1
check** (the full W1/W2/W3 capture stays for the arc-end benchmark). This runs a **bounded** Klaus window
(NOT the full 96M-cycle run — that is the headline pin's job) under the JIT with the lever ON vs OFF and
asserts (a) the lever-on recompile count over the window is sharply below lever-off (the thrash collapses)
and (b) the lever-on wall-clock is no worse — a directional "the lever works" gate, foreground + bounded.
It gates on the Klaus binary being present (the `[KlausJitFact]` skip idiom, like `KlausJitFunctionalTests`).

```csharp
using CpuEmulator.Core;
using CpuEmulator.Cpus.Mos6502;
using CpuEmulator.Jit;
using Xunit.Abstractions;

namespace CpuEmulator.Tests.Klaus;

/// <summary>M6 PR-S — the BOUNDED, DIRECTIONAL W1 (Klaus) check (ADR 0011 §3.4 / the PR-S benchmark
/// exception). The full W1/W2/W3 throughput capture is the arc-end benchmark's job; this is the
/// directional confirmation that the SMC/recompile-cost lever WORKS on the actual SMC-heavy workload:
/// over a BOUNDED Klaus window, the lever-ON recompile count collapses vs lever-OFF (the per-dispatch
/// thrash the lever exists to kill), and the lever-ON wall-clock is no worse. Bounded (a few-million-
/// cycle window, not the 96M headline run) + foreground. Skips when the Klaus binary is absent.</summary>
public class KlausSmcLeverDirectionalTests(ITestOutputHelper output)
{
    private const ushort StartAddress = 0x0400;
    private const long Window = 5_000_000;   // bounded: ~5M cycles, a few seconds — NOT the full 96M run

    private static (Mos6502Cpu Cpu, JittedCpu<Mos6502Cpu> Jit) NewKlausJit(byte[] image, JitOptions opts)
    {
        var space = new AddressSpace(AddressSpaceKind.Program, addressBits: 16);
        space.MapMemory(0x0000, (byte[])image.Clone(), writable: true);   // Klaus self-modifies RAM
        var cpu = new Mos6502Cpu(space) { PC = StartAddress, S = 0xFD, P = 0x34 };
        return (cpu, new JittedCpu<Mos6502Cpu>(cpu, Mos6502Cpu.JitTarget, space, options: opts));
    }

    private static (long Recompiles, long Evictions, int HotPcs, double Seconds) RunWindow(byte[] image, JitOptions opts)
    {
        var (cpu, jit) = NewKlausJit(image, opts);
        var sw = System.Diagnostics.Stopwatch.StartNew();
        while (cpu.CycleCount < Window)
        {
            long budget = System.Math.Min(2_000_000, Window - cpu.CycleCount);
            jit.Run(ref budget);
        }
        sw.Stop();
        return (jit.TotalRecompiles, jit.TotalEvictions, jit.SmcHotPcCount, sw.Elapsed.TotalSeconds);
    }

    [KlausJitFact]
    public void Lever_collapses_Klaus_recompiles_over_a_bounded_window()
    {
        byte[] image = File.ReadAllBytes(KlausVectors.TryGetBinaryPath()!);
        Assert.Equal(0x10000, image.Length);

        var off = RunWindow(image, new JitOptions { DisableSmcLever = true });  // pre-PR-S thrash
        var on  = RunWindow(image, new JitOptions());                            // lever ON (the fix)

        output.WriteLine($"Klaus[{Window} cyc]  lever OFF: recompiles={off.Recompiles:N0} " +
                         $"evictions={off.Evictions:N0} {off.Seconds:F2}s");
        output.WriteLine($"Klaus[{Window} cyc]  lever ON : recompiles={on.Recompiles:N0} " +
                         $"evictions={on.Evictions:N0} hotPCs={on.HotPcs} {on.Seconds:F2}s");

        // DIRECTIONAL gate 1: Klaus thrashes WITHOUT the lever (recompiles dominate the window).
        Assert.True(off.Recompiles > 1000,
            $"Klaus should thrash without the lever; recompiles={off.Recompiles}");
        // DIRECTIONAL gate 2: the lever SHARPLY drops recompiles (the W1 0.00× mechanism removed).
        Assert.True(on.Recompiles * 4 < off.Recompiles,
            $"lever ON recompiles {on.Recompiles} should be << OFF {off.Recompiles}");
        // DIRECTIONAL gate 3: the lever actually fired on Klaus (>= 1 SMC-hot PC).
        Assert.True(on.HotPcs >= 1, "the lever should mark >= 1 Klaus PC SMC-hot");
        // DIRECTIONAL gate 4: lever-ON wall-clock is no worse than lever-OFF over the window (the whole
        // point — recompiling less is faster). A generous 1.5x slack absorbs machine noise on a bounded
        // window; the headline magnitude lives in the arc-end full-W1 capture, not this pin.
        Assert.True(on.Seconds <= off.Seconds * 1.5,
            $"lever ON {on.Seconds:F2}s should not be slower than OFF {off.Seconds:F2}s");
    }
}
```

**Tuning note (DECISION S-3 / §3):** if gate 2 or gate 4 fails with the default cap=16 / cooldown=256, the
defaults are too loose for Klaus's thrash density — **lower `SmcRecompileCap` (e.g. 8) and/or lengthen
`SmcCooldownDispatches` (e.g. 1024)** in `JitOptions` (Task 1) and re-run. The defaults are a starting
estimate; this gate is exactly the instrument that confirms them. Do NOT loosen the assertions to pass —
