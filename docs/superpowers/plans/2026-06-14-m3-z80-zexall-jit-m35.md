# M3.5: ZEXALL + Interrupt Servicing + the Z80 through the JIT — Scoped Plan

> **For agentic workers:** this is a SCOPED plan — the finish-line, PR breakdown, dependencies, and known
> quirks/risks are pinned, but the deepest task-by-task literal code is to be DETAILED JUST-IN-TIME before
> each sub-PR's Builder run. This is DELIBERATE: the JIT-genericity literal code (which DD/FD/DDCB ops are
> hot enough to emit vs. fall back) genuinely depends on running M3.4e's interpreter under ZEXALL, and the
> interrupt-servicing detail depends on whether M3.4e's decode changes touched the `Step` fetch path. Use
> superpowers:writing-plans to expand each sub-PR immediately before building it. Depth template:
> `docs/superpowers/plans/2026-06-14-m3-z80-ed-core.md`.

**Goal:** finish the Z80 — implement interrupt SERVICING (IM 0/1/2 + NMI, IFF1/IFF2, the EI-delay, the HALT
wake), wire the ZEXALL/ZEXDOC exhaustive exerciser as the integration gate, and drive the Z80 through the
JIT (making `BlockCompiler` generic over the CPU type / register file / decode structure — ADR 0001
Decision 7, J1/J2/J3), emitting the hot ops and falling back for the irregular ones, with the enumerated
Decision-7 findings as the headline artifact.

**Architecture:** by M3.5 the Z80 interpreter is complete across every plane (base + CB + ED + DD + FD +
DDCB + FDCB, all TomHarte-green — PRs through M3.4e). M3.5 is the LAST milestone of M3: it does NOT add
opcodes; it adds (1) the interrupt POLICY the partial's `TryServiceInterrupt`/`InterruptPending` stub
(`Z80Cpu.cs:78,124`, currently `=> false`), (2) an integration-tier behavioral gate (ZEXALL, the Z80 analog
of the 6502's Klaus suite), and (3) the JIT-genericity work that turns the 6502-shaped `BlockCompiler` into
a framework compiler (the whole reason the Z80 is M3 — ADR §1.1, Decision 7). The cross-architecture JIT
OPTIMIZATION is a SEPARATE post-M3 milestone (gated behind M4 68000 + M5 8086 per the 2026-06-13 human
checkpoint) — NOT part of M3.5.

**Tech Stack:** as the predecessor plans (C# .NET 10, the Roslyn generator, `CpuEmulator.Jit`, xUnit + the
SingleStepTests/z80 vectors; ZEXALL is a separate CP/M `.com` artifact).

## Scope

**IN scope (the three coupled deliverables):**

1. **Interrupt SERVICING** (M3.5-1): implement `TryServiceInterrupt()` + `InterruptPending` for
   IM 0 (device opcode, usually RST n), IM 1 (fixed RST 38h → 0x0038), IM 2 (vectored: `I<<8 |
   device-byte` → table pointer → PC), NMI (fixed 0x0066, saves IFF1→IFF2, clears IFF1, RETN restores), the
   IFF1/IFF2 latches with `EI`'s one-instruction delay, and the HALT wake (clear `_halted` on a serviced
   interrupt).
2. **ZEXALL/ZEXDOC** (M3.5-2): the exhaustive exerciser — a minimal CP/M BDOS stub (console out) + the
   `.com` loaded at 0x0100, run to completion, the per-test CRCs compared to the known-good set. ZEXDOC
   (documented flags) + ZEXALL (all flags incl. X/Y) — both run; ZEXALL is the strict gate.
3. **Z80 through the JIT** (M3.5-3): the ADR Decision 7 J1/J2/J3 generic-compiler work + emit the hot
   straight-line Z80 ops + fall back for the irregular ones + tier parity (the differential fuzzer + the
   TomHarte sweep through the JIT, as M2-ii did for the 6502) + the enumerated findings doc.

**OUT of scope (separate / post-M3):**

- **The cross-architecture JIT OPTIMIZATION** (register allocation, block chaining, inlining tuned across
  architectures) — POST-M3, gated behind M4 68000 + M5 8086 (the 2026-06-13 human checkpoint). M3.5 makes
  the compiler GENERIC; it does not OPTIMIZE it. The JIT may remain slower-than-Tier-0 (the accepted
  trade-off in the checkpoint).
- **Full Z80 JIT emission** (block-op loops in IL, DAA in IL, (IX+d)/DDCB in IL) — D7 below; the
  recommendation is hot-ops-only + fallbacks for M3.5, with the fallback list enumerated.
- **The optional M3.6 host/monitor demo** — separate (ADR Decision 8).

> **The honest one-liner for M3.5's close-state (target):** the Z80 is complete — every documented +
> undocumented opcode TomHarte-green (through M3.4e); interrupt servicing works for IM 0/1/2 + NMI with a
> dedicated interrupt UAT; ZEXALL passes (the integration proof); and the Z80 runs through a JIT now generic
> over the CPU type / register file / decode structure, with the hot ops emitted and the irregular ones as
> proven fallbacks (the ADR Decision-7 findings enumerated). The cross-arch JIT optimization is a separate
> post-M3 milestone.

## Ground truth — the seams M3.5 touches (CONFIRMED by recon)

- **The interrupt seam is the hand-written partial — already shaped for this.** `Z80Cpu.cs`:
  `public partial bool InterruptPending => false;` (`:78`), `private partial bool TryServiceInterrupt()
  => false;` (`:124`), `SetIrqLine(bool)`/`SetNmiLine(bool)` stubs (`:74-75`), the `_iff1`/`_iff2` latches +
  `Iff1`/`Iff2` properties (`:27-35`), the `Im` field (`:47`), the `_halted` latch + `Halted` partial +
  `DoHalt()` + `IdleCycle()` (`:23,82,114,117`). ADR Decision 5 (option A) keeps this seam — M3.5-1 fills
  the stubs in the partial; the generated `Step` already calls `TryServiceInterrupt()` before the fetch and
  the JIT already samples `InterruptPending` at block boundaries. **This is the seam the ADR predicted
  "should survive Z80 unchanged" — M3.5-1 confirms or refutes it (a positive finding either way).**
- **The HALT machinery exists.** `_halted` + `Halted` + the generated Step's idle-on-halt path
  (`IdleCycle()`) are wired (M3.3 skeleton). M3.5-1 adds the WAKE (servicing clears `_halted`); the busy-
  spin avoidance in `Run` is the ADR risk-Q8 watch-item.
- **The JIT is still 6502-shaped (J1/J2/J3 — the work).** `src/CpuEmulator.Jit/BlockCompiler.cs:16`:
  `private readonly Mos6502Cpu _cpu;` (J1 — typed to the concrete 6502 type); the ctor + the
  `Mos6502Cpu.Decode(stream)` / `Mos6502Cpu.DescriptorFor(...)` calls (`:107-108`) name the 6502 statics;
  the register `FieldInfo`s `FA`/`FP`/`FPC` are baked to `typeof(Mos6502Cpu).GetField(...)` (`:52-54`, J2)
  while operand registers already go through `_regFields` (the M3.1a partial data-drive). **J3 is partly
  done:** the structured CPU already emits `JitDescriptorsByKey` (a `Dictionary<uint, OpcodeDescriptor>`,
  `CpuEmitter.cs:3002`) rather than the 6502's 256-slot array (`:2978`) — so the per-page/keyed descriptor
  table exists; what remains is making `BlockCompiler` CONSUME it generically (today it calls the 6502's
  `DescriptorFor`).
- **The JIT classification glue is in the emitter.** `ClassifyForJit` (`CpuEmitter.cs:~3116`),
  `JitBaseCycles` (`~:3072`), `JitOpLiteral` (`~:3174`) — these already classify the Z80 classes (the CB/ED
  ops were added as JIT fallbacks). M3.5-3 promotes the hot ones to emitted and keeps the rest fallback.
- **The tier-parity gate exists for the 6502.** The differential fuzzer + the TomHarte sweep through the
  JIT (M2-ii). M3.5-3 runs the SAME gate through the Z80 — the JIT must produce byte-identical final state
  to the interpreter across the TomHarte vectors (the ones whose ops are JIT-emitted; the fallback ops route
  through the interpreter and are trivially identical).
- **ZEXALL is NOT in the vector cache.** `~/.cache/cpuemulator/vectors/z80/v1/` holds only SingleStepTests
  (base/cb/dd/ed/fd/ddcb/fdcb). ZEXALL/ZEXDOC are a separate `.com` binary + the expected CRC list —
  M3.5-2 fetches/embeds them (D6).

## PR breakdown (3 sub-PRs)

### M3.5-1 — Interrupt servicing (IM 0/1/2 + NMI + IFF1/IFF2 + EI-delay + HALT wake)

> **DETAILED — full execution-ready plan:**
> `docs/superpowers/plans/2026-06-14-m3-z80-m35-1-interrupt-servicing.md` (2026-06-14). That plan pins the
> seam recon (the generated `Step` already calls `TryServiceInterrupt()` first + idles on `Halted` after —
> the HALT wake needs NO generated change, refuting risk-Q8 for the interpreter), the cycle/R/IFF/WZ rules
> (NMI 11T / IM0 13T / IM1 13T / IM2 19T; R+1; NMI saves IFF1→IFF2; maskable ack clears both), the
> deterministic interrupt UAT (D5), and the ONE enumerated generator delta (the `Ei`-body partial hook
> `OnInterruptEnable()` for the EI one-instruction delay — the seam itself survives `Core`/dispatcher
> unchanged, confirming the ADR Decision-5 hypothesis).
>
> **Detailed + implemented:** see `docs/superpowers/plans/2026-06-14-m3-z80-m35-1-interrupt-servicing.md`
> (PR pending). Close-state: IM 0/1/2 + NMI + IFF1/IFF2 + EI-delay + HALT-wake serviced; interrupt UAT green
> (IM0/IM1/IM2/NMI + RETN restore + EI-delay + EI/DI asymmetry + NMI-in-EI-shadow + DI-mask + HALT-wake +
> NMI-over-IRQ priority, 17 cases + 1 synthetic generator-routing test);
> the ADR Decision-5 seam survived `Core`/dispatcher unchanged — the one enumerated generator delta is the
> `Ei`-body partial hook `OnInterruptEnable()` (structured-only, so the 6502 `.g.cs` is byte-identical).
> The EI-delay resolves both oracles: `OnInterruptEnable()` sets IFF1/IFF2 immediately (so `fb.json`'s
> final iff1=1 stays green) AND opens a one-instruction `_eiPending` no-service window (so the UAT's
> one-instruction delay holds). The whole Z80 TomHarte sweep stays green (servicing returns false when
> nothing is pending). Cycle/IFF rules are reference-derived (no servicing vector oracle); ZEXALL = M3.5-2,
> JIT = M3.5-3.

**Goal:** implement the Z80 interrupt POLICY in the partial. ADR Decision 5 option A — no Core/generator
change (the seam was built CPU-agnostic in M1); only `Z80Cpu.cs` (the partial) + the test gate.
(Refinement from the detailed plan: the ONE generator touch is the `Ei` micro-op body → `OnInterruptEnable()`
partial hook, so the partial owns the EI-delay latch. The seam, the dispatcher, and the 6502 are unchanged.)

**What to implement (the partial):**
- `InterruptPending` → `_nmiPending || (_irqLine && _iff1)` (NMI is non-maskable; INT is gated by IFF1).
- `TryServiceInterrupt()`:
  - **NMI:** push PC, IFF2 := IFF1, IFF1 := 0, PC := 0x0066, clear `_halted`, charge the cycles. RETN later
    restores IFF1 := IFF2.
  - **IM 0:** the device supplies an opcode on the data bus (usually `RST n`) — execute it. (The TomHarte
    vectors do NOT cover servicing; the gate is the interrupt UAT + ZEXALL. Model the common RST-n case;
    the device-byte source is the interrupt-acknowledge bus cycle, ADR Decision 2/5.)
  - **IM 1:** push PC, PC := 0x0038 (a fixed RST 38h), clear `_halted`.
  - **IM 2:** read the device byte, form `addr = (I << 8) | (deviceByte & 0xFE)`, read the 16-bit vector
    from `addr`, push PC, PC := vector, clear `_halted`. WZ := vector (the IM2 MEMPTR rule — confirm).
  - all maskable forms: IFF1 := IFF2 := 0 (interrupts disabled on acknowledge).
- **The EI one-instruction delay:** `EI` sets a "just-enabled" latch so an interrupt is NOT serviced until
  AFTER the instruction following EI (a documented Z80 quirk; the 6502 has the analogous CLI/SEI delay,
  design spec §6). The `ei` field is already in the TomHarte case schema (`Z80TomHarteCase.cs` `int Ei`) —
  CONFIRM whether the base/CB/ED EI/DI ops already maintain it; if EI/DI were modeled in M3.4a as
  IFF1/IFF2 writes WITHOUT the delay latch, M3.5-1 adds the latch.
- **The HALT wake:** servicing clears `_halted`; the `Run` loop must not busy-spin while halted (ADR
  risk-Q8). Confirm the generated `Run`'s halt path; if it busy-spins, that is an enumerated generator
  change.

**The TEST gate (D5):** a dedicated interrupt UAT — assert PC/SP/IFF1/IFF2/WZ/RAM after an injected
IRQ/NMI in each IM mode (deterministic, hand-constructed; the SingleStepTests vectors cannot cover
servicing). ZEXALL (M3.5-2) is the integration confirmation.

**Tasks (just-in-time):** the UAT harness (inject a line, step, assert) + one task per IM mode + NMI + the
EI-delay + the HALT wake. **GATE:** the interrupt UAT green + base/CB/ED/DD/FD still green (servicing must
not change non-interrupt single-step behavior — `TryServiceInterrupt` returns false when nothing pending,
so the TomHarte sweeps are unaffected).

**Estimated size:** medium. The seam exists; this is policy in the partial + a new UAT.

### M3.5-2 — ZEXALL/ZEXDOC integration harness

**Goal:** run the exhaustive exerciser as the Z80 integration gate (the Klaus analog).

**What to build:**
- A minimal CP/M BDOS stub: intercept `CALL 0x0005` (BDOS entry), implement function 2 (console out, char
  in E) and function 9 (print `$`-terminated string at DE); RET. Load the ZEXALL `.com` at 0x0100, set PC
  := 0x0100, SP := a high address, run to a termination condition (a jump to 0x0000 / a WBOOT).
- Capture the console output; ZEXALL prints each test's name + `OK` or `ERROR <crc> <expected>`. Assert
  every test prints `OK` (no `ERROR`).
- Run BOTH ZEXDOC (documented flags) and ZEXALL (all flags incl. X/Y). ZEXALL is the strict gate (D8).

**The artifact (D6):** ZEXALL/ZEXDOC `.com` files — fetch into the test fixtures (a `tools/get-zexall.ps1`
analog to `get-test-vectors-z80.ps1`, or embed the binaries as test resources with a provenance note).
The CP/M host shape: a TEST fixture (`ZexallHarness`) for M3.5, NOT a real `CpuEmulator.Hosts.CpmZ80`
machine (YAGNI — promote to a real host only if M3.6 is greenlit, D6).

**Note on coupling to M3.5-1:** ZEXALL itself does NOT use interrupts (it is a pure-computation exerciser),
so the FULL ZEXALL pass does NOT strictly depend on M3.5-1 — it depends on the interpreter being complete
(M3.4e). M3.5-2 can therefore proceed in PARALLEL with M3.5-1 after M3.4e. (If a ZEXALL sub-test does
exercise an interrupt path, it needs M3.5-1 — confirm at the harness build.)

**Tasks (just-in-time):** the BDOS stub + the `.com` loader + the output-capture/CRC assertion + the ZEXDOC
then ZEXALL runs. **GATE:** ZEXALL all-`OK`. This is the Z80's "TomHarte said each instruction is right;
ZEXALL says they compose right" proof.

**Estimated size:** medium. The harness is small; debugging any ZEXALL failure is where the time goes (but
if M3.4e's TomHarte sweeps are truly green, ZEXALL should largely pass — the value is catching composition
bugs the single-step vectors miss, e.g. a flag-after-flag interaction).

### M3.5-3 — Z80 through the JIT + the genericity findings

**Goal:** the ADR Decision 7 deliverable — make `BlockCompiler` generic, drive the Z80 through it, prove
tier parity, enumerate the findings.

**The genericity work (J1/J2/J3):**
- **J1** — `BlockCompiler` generic over the CPU type. Today `private readonly Mos6502Cpu _cpu;`
  (`:16`) + the `Mos6502Cpu.Decode`/`DescriptorFor` calls (`:107-108`) + `BlockDelegate(Mos6502Cpu, ...)`
  (`CompiledBlock.cs:49`). Make the compiler resolve the CPU type from the spec (a generated per-CPU
  `JittedCpu` or a generic-over-`ICpuCore` compiler). **Largest JIT change.**
- **J2** — the register file data-driven. A/P/PC are baked `FieldInfo`s (`:52-54`); the Z80's ~14+
  registers (halves + pairs + alt set + I/R + IX/IY) must ALL resolve from the spec's `Registers` table by
  name (the `_regFields` path already does this for operand regs — extend it to cover the whole file).
- **J3** — decode per-page. The structured CPU already emits `JitDescriptorsByKey` (`CpuEmitter.cs:3002`);
  make `BlockCompiler.Discover` consume it (call the generated keyed `DescriptorFor`, advance PC by the
  decode walk's total length, not a single `d.Length`). The compound DDCB/FDCB length (prefix + CB +
  displacement + opcode = 4) must be handled in `Discover`.

**The emit/fallback split (D7):** emit the hot straight-line Z80 ops (8/16-bit LD/ALU, register-indirect,
relative jumps, the `(IX+d)` loads/stores if D4 allowed them in M3.4e); FALL BACK for the irregular ones
(the ED block ops — self-repeating loops; DAA; EX (SP),HL; I/O; DDCB/FDCB; interrupt servicing). The
fallback seam is proven (ADC/SBC were fallbacks in M2-i, promoted in M2-ii). Enumerate the fallback list +
why in the findings doc.

**The tier-parity gate:** the differential fuzzer + the TomHarte sweep THROUGH the JIT — the JITted Z80
must produce byte-identical final state to the interpreter across the vectors (the JIT-emitted ops directly;
the fallback ops route through the interpreter, trivially identical). Plus ZEXALL through the JIT (the
integration parity proof).

**The findings doc (the headline artifact):** the ADR Decision 7 table (J1–J10) filled in with what the
Z80 actually forced — "the JIT assumed 6502 here; the Z80 made it data." This is the INPUT to the post-M3
cross-arch optimization milestone.

**Tasks (just-in-time):** J1 (generic compiler) + J2 (data-driven register file) + J3 (decode consumption)
+ the per-family emit promotion + the tier-parity sweep + the findings doc. **GATE:** the Z80 TomHarte
sweep through the JIT green (tier parity) + ZEXALL through the JIT green + the 6502 JIT un-regressed (J1/J2
must not break the 6502's JIT — the byte-identity + the 6502 JIT TomHarte sweep are the guard).

**Estimated size:** large (J1 is the biggest single JIT change in the project). Likely splits: e.g. 5-3a
(J1/J2/J3 generic compiler, Z80 all-fallback first — prove the Z80 runs through the JIT via fallbacks with
tier parity) then 5-3b (promote the hot ops to emitted IL + re-prove parity) then 5-3c (the findings doc).
The "all-fallback first" intermediate is the safety valve — it proves the generic COMPILER works before any
Z80 IL is emitted.

## Risks

- **J1 is the largest single JIT change in the project.** The "all-fallback first" intermediate (5-3a)
  de-risks it — prove the generic compiler runs the Z80 (everything as interpreter fallbacks, tier-trivially
  parity) BEFORE emitting any Z80 IL. If J1 proves larger than expected, that intermediate is itself a
  shippable PR.
- **The 6502 JIT must not regress.** J1/J2 touch the compiler the 6502 uses. The guard is the 6502 JIT
  TomHarte sweep (both tiers) + the byte-identity `RegeneratedSpecTests` — run after every J1/J2 task.
- **ZEXALL provenance.** ZEXALL/ZEXDOC are well-known public-domain Z80 test binaries, but confirm the
  source + license before embedding (D6).
- **The interrupt UAT is hand-constructed** (no oracle vectors). Cross-check the expected PC/SP/IFF against
  a reference Z80 emulator's documented servicing behavior + the Zilog manual (ADR Decision 5 cites the
  IM-mode mechanics).
- **Decode length in `Discover` for DDCB.** The compound form is 4 bytes; `Discover` must advance PC
  correctly or the block walk corrupts. This depends on M3.4e-1's decode-walk shape (another reason to
  detail 5-3 after M3.4e lands).
