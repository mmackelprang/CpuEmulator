# Piece #2 — 68000 + 8086 Reset + Reference Boards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the 68000 and 8086 cores' `Reset()` (currently no-op stubs) to functionally-correct initial state, then instantiate the existing `ReferenceSbc(CpuKind)` recipe for both CPUs so each boots a ROM and runs a tiny program to a verifiable `OK\r` UART result on both execution tiers.

**Architecture:** The `BoardSpec` model + `ReferenceSbc` recipe + `BoardMachineFactory` shipped in piece #1 (on `main`). The recipe and the `CpuCoreFactory` currently **throw** for `M68000`/`I8086` because their cores have no real reset. This plan: (1) fills in each core's `Reset()` — the 68000 reads its initial SSP/PC from the long-vectors at `$000000`/`$000004` through the wide big-endian bus and sets SR to supervisor/mask-7/trace-off; the 8086 jams `CS=FFFF, IP=0000, DS=ES=SS=0000, FLAGS=0`; (2) extends `ReferenceSbc.Build` + `CpuCoreFactory` to instantiate both cores (interpreter + JIT tiers), placing ROM where each CPU *boots* (68000 → ROM **low** carrying the `$0`/`$4` vectors + program; 8086 → ROM **high** carrying the `FFFF0` entry, like the 6502's high reset vector); (3) proves it with reset unit tests (asserting the exact landed register state from crafted vector bytes) and per-CPU board boot+run smokes on both tiers. Reset is **not** cycle-gated — functionally-correct initial state is the bar (no TomHarte reset vectors exist).

**Tech Stack:** C# / .NET 10, xUnit (`[Fact]`/`[Theory]`/`[InlineData]`), the existing `CpuEmulator.Core` (`AddressSpace`, `Machine`, `IAddressSpace`), `CpuEmulator.Machines` (`BoardSpec`, `ReferenceSbc`, `BoardMachineFactory`, `CpuCoreFactory`, `CpuKind`), `CpuEmulator.Peripherals` (`SimpleUart`, `IntervalTimer`), `CpuEmulator.Jit` (`JittedCpu<TCpu>`), and the generated per-CPU `JitTarget` statics.

## Resolved design decisions (grounded in the current tree)

These were resolved during recon; they bind every task below.

1. **`CpuKind` enum value for the 8086 is `I8086`, not `M8086`.** The concrete core class is `M8086Cpu` (namespace `CpuEmulator.Cpus.M8086`). The recipe/factory switch arms must say `CpuKind.I8086`; tests cast `machine.Cpu` to `M8086Cpu`. The 68000 is `CpuKind.M68000` → `M68000Cpu` (namespace `CpuEmulator.Cpus.M68000`).

2. **How `Reset()` reads the bus on each core:**
   - **68000:** uses the existing **private** `ReadLongBus(uint)` helper (`src/CpuEmulator.Cpus.M68000/M68000Cpu.cs:199`), which is big-endian (high word first via two `_bus.Read16` calls). `Reset()` lives in the same partial class as `ReadLongBus`, so it calls it directly — no new bus plumbing. `IAddressSpace` exposes `Read16`; there is no `Read32`. The cycle charge from `ReadLongBus` (4 clocks/word) is informational only — reset is not cycle-gated.
   - **8086:** **no bus read** — reset is a pure register jam (`CS=FFFF, IP=0000, DS=ES=SS=0000, FLAGS=0`). The boot entry is the physical address `(CS<<4)+IP = (0xFFFF<<4)+0 = 0xFFFF0`.

3. **68000 SR on reset = `0x2700`.** S-bit is bit 13 (`SrSupervisorBit = 1 << 13 = 0x2000`, already declared at `M68000Cpu.cs:22`; confirmed by `M68000Spec.Flags` naming `S` at bit 13). Interrupt mask is bits 10-8 → mask 7 = `0x0700`. Trace is bit 15 (cleared). CCR low byte cleared. So `SR = 0x2000 | 0x0700 = 0x2700`. After setting `SR` with S=1, `A7` aliases `SSP` (the banking view at `M68000Cpu.cs:60`), so the loaded SSP is reachable as the supervisor stack.

4. **ROM placement per CPU (the critical nuance):**
   - **Z80 (piece #1, the template):** boots at PC=0 → runs from **RAM low**; ROM unused by the boot.
   - **68000:** reads its reset vectors at `$000000` (SSP) and `$000004` (PC) → ROM must be **low**, covering at least `$0`–`$7` (the two long vectors) AND the boot program (PC points into ROM). RAM goes **high**.
   - **8086:** boots at physical `0xFFFF0` → ROM must be **high**, covering `0xFFFF0` to the top of the 20-bit space, carrying the boot program at the entry. RAM goes **low** (like the 6502's high reset vector).
   The reset entry/vectors land in ROM via the ROM image bytes the recipe builds (Task 9/12 craft them); `ResetConfig.VectorPatches` from piece #1 is available if a board prefers to poke vectors into a blank ROM, but these recipes embed the vectors directly in the built ROM image (simpler, and the smoke tests assert the landed state).

5. **JIT factory shape per CPU:** both cores are von Neumann with memory-mapped I/O and **no `IoBus`** accessor (confirmed: `M8086Cpu.Jit.cs:14-17` documents the absence; the 68000 likewise has no I/O space). So both JIT arms use the 2-bus-less `JittedCpu<TCpu>` shape: `new JittedCpu<M68000Cpu>(new M68000Cpu(bus), M68000Cpu.JitTarget, bus)` — exactly like the 6502 arm (`CpuCoreFactory.cs:45`), NOT the Z80's 3-arg-with-IoBus shape. Both `JitTarget` statics exist (generated: `M68000Cpu.JitTarget`, `M8086Cpu.JitTarget`).

6. **`CpuCoreFactoryTests.Unsupported_kind_on_a_runnable_tier_throws` (`CpuCoreFactoryTests.cs:32-38`) currently asserts `CpuKind.M68000` THROWS on the interpreter tier.** Piece #2 makes the 68000 buildable, so that test must be **repurposed** to a kind that is still unsupported — there is none after this plan (all four CPUs build). The test is replaced by positive build tests for the 68000/8086 (Task 7). The negative-path coverage shifts to "an unknown/garbage `ExecutionTier` throws", which the factory already guards (`CpuCoreFactory.cs:22`).

## A note on the tiny boot programs (un-fakeable smoke payloads)

Each board smoke runs a real machine-code program assembled by hand into the ROM image, mirroring the Z80 template (`ReferenceSbcZ80Tests.cs`), which hand-assembles bytes and writes them into the boot region. The UART DATA register is at the recipe's `UartBase` and transmit is captured by `uart.OnTransmit = b => tx.Append((char)b)` (recon item 6: `SimpleUart.Write` offset 0 → `OnTransmit`). The MMIO convention per CPU is defined in the recipe (Task 8); the test reads those same constants by hard-coding the documented addresses the recipe maps. Below each task gives the **exact bytes + their assembly listing**, so the engineer pastes them verbatim.

The 68000 program writes a **byte** to the UART DATA register with `MOVE.B Dn,(xxx).L` (the simplest absolute-long store the core already executes — confirmed: `MoveExecute` is a live op-body, generated dispatch index 22). The 8086 program writes a byte with `MOV [disp16],AL` via `MOV AL,imm8` then a `MOV moffs,AL` (opcode `0xA2`, in the live MOV table — generated dispatch shows `0xA2 MOV`).

```csharp
using CpuEmulator.Core;
using CpuEmulator.Cpus.M68000;
using Xunit;

namespace CpuEmulator.Tests.Cpus;

/// <summary>Piece #2 — the 68000 functional reset (no TomHarte reset vector exists, so this is the
/// reset-state gate). Reset loads the initial SSP from the long at $000000 and the initial PC from the
/// long at $000004 (read big-endian through the bus), and sets SR to supervisor (S=1), interrupt mask 7,
/// trace off (SR=0x2700). Not cycle-gated — functionally-correct landed state is the bar.</summary>
public class M68000ResetTests
{
    // A 24-bit (16 MB) program space with the low 64 KiB mapped, so the $0/$4 vectors land in memory.
    private static M68000Cpu NewCpuWithVectors(uint ssp, uint pc)
    {
        var bus = new AddressSpace(AddressSpaceKind.Program, 24);
        bus.MapMemory(0, new byte[0x10000], writable: true);
        // The reset vectors are LONGS, big-endian (high byte first), at $0 (SSP) and $4 (PC).
        bus.Write16(0x0000, (ushort)(ssp >> 16));
        bus.Write16(0x0002, (ushort)ssp);
        bus.Write16(0x0004, (ushort)(pc >> 16));
        bus.Write16(0x0006, (ushort)pc);
        return new M68000Cpu(bus);
    }

    [Fact]
    public void Reset_loads_SSP_from_the_long_at_0()
    {
        var cpu = NewCpuWithVectors(ssp: 0x0000_8000, pc: 0x0000_0400);
        cpu.Reset();
        Assert.Equal(0x0000_8000u, cpu.SSP);
    }

    [Fact]
    public void Reset_loads_PC_from_the_long_at_4()
    {
        var cpu = NewCpuWithVectors(ssp: 0x0000_8000, pc: 0x0000_0400);
        cpu.Reset();
        Assert.Equal(0x0000_0400u, cpu.PC);
    }

    [Fact]
    public void Reset_enters_supervisor_with_mask_7_and_trace_off()
    {
        var cpu = NewCpuWithVectors(ssp: 0x0000_8000, pc: 0x0000_0400);
        cpu.Reset();
        Assert.Equal((ushort)0x2700, cpu.SR);   // S(13)=1, mask(10-8)=7, trace(15)=0, CCR=0
        Assert.True(cpu.SupervisorMode);          // the S-bit banking view agrees
    }

    [Fact]
    public void Reset_A7_aliases_the_loaded_SSP_in_supervisor_mode()
    {
        // After reset (supervisor), A7 is the SSP bank, so it reads the loaded supervisor stack pointer.
        var cpu = NewCpuWithVectors(ssp: 0x0000_8000, pc: 0x0000_0400);
        cpu.Reset();
        Assert.Equal(0x0000_8000u, cpu.A7);
    }

    [Fact]
    public void Reset_reads_full_32bit_vectors_big_endian()
    {
        // A full 32-bit vector value proves the long read is wide + big-endian (not truncated to 16 bits).
        var cpu = NewCpuWithVectors(ssp: 0x00AB_CDE0, pc: 0x0012_3456);
        cpu.Reset();
        Assert.Equal(0x00AB_CDE0u, cpu.SSP);
        Assert.Equal(0x0012_3456u, cpu.PC);
    }
}
```

```csharp
/// A memory-mapped UART + interval timer at fixed MMIO addresses, both IRQs wired to the CPU's maskable
/// interrupt, scaled to each CPU's address width — with the ROM placed where each CPU BOOTS:
/// <list type="bullet">
///   <item>6502/Z80 (16-bit): RAM low, MMIO at $C000, ROM high at $E000 (the 6502 reads $FFFC there; the
///         Z80 runs from RAM at $0).</item>
///   <item>68000 (24-bit): ROM LOW at $0 (carrying the reset vectors at $0/$4 + the boot program), MMIO,
///         then RAM high — the 68000 fetches its SSP/PC vectors from low memory.</item>
///   <item>8086 (20-bit): RAM low, MMIO, ROM HIGH ending at $100000 (covering the 0xFFFF0 reset entry) —
///         like the 6502's high reset vector.</item>
/// </list>
/// Reset is not cycle-gated (no TomHarte reset vectors exist); functionally-correct landed state is the bar.</summary>

    private const uint TimerBase68k = 0x01_0100;      // timer at $010100
```

```csharp
        var rom = new byte[0x1_0000];   // 64 KiB high ROM (recipe-required size)

        int p = (int)(ResetEntryPhysical - RomBase);   // image offset of the entry = 0xFFF0
        // MOV AX,0xA000 ; MOV DS,AX  — point DS at the UART segment (physical 0xA0000).
        rom[p++] = 0xB8; rom[p++] = 0x00; rom[p++] = 0xA0;   // MOV AX,0xA000
        rom[p++] = 0x8E; rom[p++] = 0xD8;                    // MOV DS,AX
        // For each byte: MOV AL,imm8 ; MOV [0x0000],AL  (DS:0000 = physical 0xA0000 = UART DATA).
        foreach (byte ch in new byte[] { (byte)'O', (byte)'K', (byte)'\r' })
        {
            rom[p++] = 0xB0; rom[p++] = ch;                  // MOV AL,ch
            rom[p++] = 0xA2; rom[p++] = 0x00; rom[p++] = 0x00; // MOV [0x0000],AL
        }
        rom[p++] = 0xF4;                                     // HLT

        // The 8086 reset entry (0xFFFF0) is only 16 bytes below the top; the program above fits in those
        // 16 bytes only if short. It is 3+2 + 3*(2+3) + 1 = 21 bytes, which would run off the top of ROM.
        // So instead place the program at the START of ROM ($F0000) and put a NEAR/FAR jump at the entry.
        // (See Step 3 — the test author resolves the entry-vs-length layout during the failing-test diagnosis.)
        return rom;
    }

    private static string RunBoot(ExecutionTier tier)
    {
        var uart = new SimpleUart();
        var timer = new IntervalTimer();
        var tx = new StringBuilder();
        uart.OnTransmit = b => tx.Append((char)b);

        BoardSpec spec = ReferenceSbc.Build(CpuKind.I8086, uart, timer, BuildRom());
        Machine machine = BoardMachineFactory.Build(spec, tier);

        machine.Reset();            // 8086: CS=FFFF, IP=0, DS=ES=SS=0, FLAGS=0
        machine.Run(2000);          // ample budget; HLT ends progress within it
        return tx.ToString();
    }

    [Fact]
    public void I8086_board_boots_and_prints_OK_on_the_interpreter()
    {
        Assert.Equal("OK\r", RunBoot(ExecutionTier.Interpreter));
    }

    [Fact]
    public void I8086_board_boots_and_prints_OK_on_the_jit()
    {
        Assert.Equal("OK\r", RunBoot(ExecutionTier.Jit));
    }
}
```
