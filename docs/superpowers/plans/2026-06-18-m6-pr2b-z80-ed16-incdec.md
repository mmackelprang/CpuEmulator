## Objective (PR-2's DECISION E, made concrete)

PR-2 emitted the base-plane Z80 ALU (8-bit ADD/ADC/SUB/SBC/AND/OR/XOR/CP, 8-bit INC/DEC, and **base-plane**
`ADD HL,rr`) and explicitly DEFERRED two 16-bit sub-families (DECISION E). PR-2b ships both:

1. **ED-plane `ADC HL,rr` / `SBC HL,rr`** (`Z80EdOp` / `EdAdcSbc16`, KeyShape `PrefixedOpcode`, 15 T) — the
   **first emitted ED-prefixed family**. The 16-bit flag word is S/Z/Y/H/X/P_V/N/C computed on the 16-bit
   result (carry from bit 15, half-carry from bit 11), WZ = HL+1 (pre-op), Q = F. This is a **different gate
   path** than the base plane: the row is `KeyShape.PrefixedOpcode` with `Prefix == 0xED`, which PR-1/PR-2's
   `IsEmittableZ80Family` rejects outright (`KeyShape != OpcodeByte || Prefix != -1`). PR-2b opens a narrow
   ED-plane lane in the gate AND teaches the JIT's two-byte-footprint plumbing about an emitted ED row.

2. **16-bit `INC rr` / `DEC rr`** (`Inc16` / `Dec16`, base-plane `Z80Alu`, 6 T) — **flagless**: they touch NO
   flag bits and set `Q = 0`. Trivial 16-bit +1/−1 over a pair-view. They are base-plane (the easy gate path)
   and need only the no-flag Q=0 path PR-1 already built (`EmitZ80ClearQ`).

**Why these two in one PR.** PR-2's DECISION E grouped them as the "follow-up": they are the two 16-bit ALU
sub-families left after PR-2's flag long pole. `ADC/SBC HL,rr` reuses PR-2's 16-bit flag shape almost verbatim
(it is the `ADD HL,rr` flag word with the full S/Z/P/V recomputed instead of preserved); `INC16/DEC16` is the
trivial no-flag bookend. Both are small; bundling them keeps the ED-plane gate work (the one genuinely new
mechanism) in a single reviewable unit alongside its natural sibling.

**Why PR-2b is NOT in the §6 hot path (and why we ship it anyway).** Neither family is in the Z80 §6 top-8 for
any workload (ED ADC/SBC HL,rr and INC16/DEC16 are tail ops). The throughput payoff is ~nil. The reason to ship
is **block-fragmentation reduction + ED-plane proof**: today every ED-prefixed op is a fallback that ENDS the
block (`endsBlock=true`), so a hot loop containing one `ADC HL,DE` (common in 16-bit arithmetic) fragments. More
importantly, PR-2b **proves the ED-prefixed gate path** that PR-3 does NOT need but a future ED-family PR (block
ops stay fallback by §2, but e.g. ED I/O might not) could reuse. It is a low-risk, high-confidence consolidation
PR — exactly the kind that benefits from the oracle gate carrying all the correctness weight.

## What the recon CONFIRMED (file:line — load-bearing, verified against `main` @ `851de3b`)

### Family 1 — ED ADC/SBC HL,rr (the ED-plane gate path)

- **Descriptor shape.** The rows are `InstructionClass.Z80EdOp`, op-kind `EdAdcSbc16`, `KeyShape.PrefixedOpcode`
  (`Prefix == 0xED`), `JitOpClass.Register` (the JIT dispatch class — `ClassifyForJit`'s `Z80EdOp → "Register"`
  mapping, `CpuEmitter.cs:4349-4354`). `JitOp.Args` carry `[0]="ADC"|"SBC"` and `[1]=pair` ("BC"/"DE"/"HL"/"SP")
  — verified in the importer (`Z80EdSemantics.cs:43`: `[EdAdcSbc16("{ADC|SBC}","{RpSp[p]}")]`). The eight ED
  opcodes: `ED4A`=ADC HL,BC, `ED5A`=ADC HL,DE, `ED6A`=ADC HL,HL, `ED7A`=ADC HL,SP; `ED42`=SBC HL,BC,
  `ED52`=SBC HL,DE, `ED62`=SBC HL,HL, `ED72`=SBC HL,SP.
- **The `JitOp` slot wiring is EMPTY today.** `JitOpLiteral`'s `EdAdcSbc16` case (`CpuEmitter.cs:4429`) is in the
  "JIT fallback; slots unused" group — it leaves `RegA`/`RegB`/`flagBit`/`boolArg` at their defaults, so the
  descriptor row carries `Ops = [ JitOp("EdAdcSbc16", "", "", 0, false) ]` (no operand info). **This is a
  generator change PR-2b MUST make**: to emit from the descriptor, the arm needs the addend pair and the
  add/sub sense in the `JitOp`. PR-2b moves `EdAdcSbc16` out of the "slots unused" group and populates
  `RegB` = the addend pair, `boolArg` = (op == "SBC"). (RegA is implicitly "HL".) **This is the load-bearing
  ED-plane gate-path detail the prompt flagged** — see DECISION F.
- **Base cycles ALREADY CORRECT (no `JitBaseCycles` fix).** `Z80Cycles` carries
  `(Z80EdOp, "EdAdcSbc16", _) => 15` (`CpuEmitter.cs:1125`), routed via `JitBaseCycles`'s `Z80EdOp` →
  `Z80Cycles` branch (`:4198-4204`). So `BaseCycles == 15` is correct in the committed table; PR-2b's gate
  change flips ONLY `NeedsFallback`/`EndsBlock`, NOT `BaseCycles`.
- **`Z80WritesFlags` already returns true for `EdAdcSbc16`** (`CpuEmitter.cs:1005`), so the interpreter sets
  `Q = F`. The emit arm mirrors with `EmitZ80SetQFromF`.
- **The interpreter oracle** (`EmitZ80EdAdcSbc16`, `CpuEmitter.cs:3458-3495`; the 16-bit flag word
  `EmitZ80Ed16FlagWord`, `:3499-3512`). Verbatim (the IL must match this byte-for-byte):

```csharp
// EdAdcSbc16 — ADC HL,rr (sub=false) / SBC HL,rr (sub=true). pair = BC/DE/HL/SP.
WZ = unchecked((ushort)(HL + 1));            // MEMPTR — BEFORE the add/sub (pre-op HL)
int hl  = HL;
int rr  = <pair>;                            // BC / DE / HL / SP
int cin = ((F & 0x01) != 0 ? 1 : 0);         // C = bit0
// ADC:
int full = hl + rr + cin;
int half = (hl & 0x0FFF) + (rr & 0x0FFF) + cin;
ushort res16 = unchecked((ushort)full);
int ov   = (~(hl ^ rr) & (hl ^ full) & 0x8000);
// SBC:
//   int full = hl - rr - cin;
//   int half = (hl & 0x0FFF) - (rr & 0x0FFF) - cin;
//   ushort res16 = unchecked((ushort)full);
//   int ov   = ((hl ^ rr) & (hl ^ full) & 0x8000);
F = unchecked((byte)(
      ((res16 & 0x8000) != 0 ? 0x80 : 0x00)              // S — result bit15
    | (res16 == 0          ? 0x40 : 0x00)                // Z — full 16-bit zero
    | (((res16 >> 8) & 0x20) != 0 ? 0x20 : 0x00)         // Y — result HIGH byte bit5
    | (<halfBit> ? 0x10 : 0x00)                          // H — (half & 0x1000) != 0  (bit-11 carry/borrow)
    | (((res16 >> 8) & 0x08) != 0 ? 0x08 : 0x00)         // X — result HIGH byte bit3
    | (<ov != 0> ? 0x04 : 0x00)                          // P/V — 16-bit overflow
    | (sub ? 0x02 : 0x00)                                // N — SBC: 0x02 ; ADC: 0x00
    | (<carry> ? 0x01 : 0x00)));                         // C — ADC: full > 0xFFFF ; SBC: full < 0
HL = res16;
_cycles += 15 - 2;                                       // 15 T total; the body charged 2 (see cycle note)
Q = F;
```

> **CRITICAL — the `15 - 2` residual.** The interpreter charges `_cycles += 13` for ED ADC/SBC HL,rr
> (`CpuEmitter.cs:3494`: `_cycles += {15 - 2}`). The `- 2` is NOT two bus accesses — ED ADC/SBC HL,rr does NO
> memory access (it is register-only). The `2` is **the ED prefix's TWO opcode-fetch cycles** (the 0xED byte +
> the 0x4A.. byte): the interpreter's Step charges 1 fetch per opcode byte, and a prefixed op fetches 2 bytes.
> So in the JIT, **`EmitInstruction` must charge 2 fetch cycles for an emitted ED row, not 1** — see DECISION G
> (the R-refresh + two-fetch wrinkle). The emit arm then charges the residual `13` to reach 15.

### Family 2 — INC16 / DEC16 (the flagless base-plane bookend)

- **Descriptor shape.** Base-plane `InstructionClass.Z80Alu`, op-kind `Inc16` (`0x03`=INC BC, `0x13`=INC DE,
  `0x23`=INC HL, `0x33`=INC SP) / `Dec16` (`0x0B`=DEC BC, `0x1B`=DEC DE, `0x2B`=DEC HL, `0x3B`=DEC SP),
  `JitOpClass.Register`. `JitOp.RegA` = the target pair (verified — `JitOpLiteral`'s `Inc16`/`Dec16` case is in
  the `regA = Quote(op.Args[0])` group at `CpuEmitter.cs:4401-4409`, so `RegA` IS populated, e.g. `"BC"`).
- **Base cycles ALREADY CORRECT.** `Z80Cycles` carries `(Z80Alu, "Inc16", _) => 6` and `(Z80Alu, "Dec16", _) => 6`
  (`CpuEmitter.cs:1085-1086`). So `BaseCycles == 6`; the gate flips only `NeedsFallback`/`EndsBlock`.
- **Flagless + Q=0.** `Z80WritesFlags(Z80Alu, …)` returns false for `Inc16`/`Dec16` (`CpuEmitter.cs:998`:
  `kind is not ("Inc16" or "Dec16")`), so the interpreter sets `Q = 0` and touches NO flag bit. The emit arm
  uses PR-1's `EmitZ80ClearQ` (NOT `EmitZ80SetQFromF`).
- **The interpreter oracle** (`EmitZ80IncDec16`, `CpuEmitter.cs:2365-2373`). Verbatim:

```csharp
// Inc16 (delta=+1) / Dec16 (delta=-1). target = the pair-view (e.g. "BC").
<target> = unchecked((ushort)(<target> + 1));            // DEC: - 1
_cycles += (6 - 1);                                      // internalT = total(6) - 1 fetch = 5
// NO flag write. Q = 0 (the trailing Z80 Q lifecycle).
```

> Base-plane single-byte fetch (1 cycle), no memory access, so the residual is `6 - 1 = 5`. The arm charges 5.

### The gate's two force-points (PR-1/PR-2 mechanism — PR-2b extends `IsEmittableZ80Family` for BOTH planes)

`IsEmittableZ80Family(insn)` (`CpuEmitter.cs:4244-4285`) is consulted in `KeyedDescriptorLiteral` (`:4140`,
un-forces fallback) AND `ClassifyForJit` (`:4326`, un-forces the z80 block-ending force). Today it returns false
for both PR-2b families: the **first line** `if (insn.KeyShape != KeyShape.OpcodeByte || insn.Prefix != -1)
return false;` rejects the ED rows (PrefixedOpcode, Prefix=0xED), and `Inc16`/`Dec16` fall through to
`return false` (PR-2 deliberately omitted them). PR-2b adds an **ED-plane lane** (a narrow exception to the
base-plane-only guard, admitting ONLY `EdAdcSbc16`) and the two base-plane `Inc16`/`Dec16` kinds.

### The footprint plumbing (`Z80EmitOperandBytes` — the ED two-byte-key wrinkle)

`Z80EmitOperandBytes` (`BlockCompiler.cs:204-224`) corrects the discovery walk's PC footprint for emitted Z80
rows. Today it handles `LD` (PR-1) and the ALU kinds (PR-2). **Neither PR-2b family reads a PC operand byte**
(ED ADC/SBC HL,rr and INC16/DEC16 are register-only), so their PC-operand footprint is 0. BUT — the ED row's
**opcode-key length is 2** (prefix + opcode), which the decode walk's `r.Length` already accounts for
(`KeyShape.PrefixedOpcode => 2` fixed-length, `CpuEmitter.cs:4150`). So `Z80EmitOperandBytes` returns 0 for
both families and the walk length is correct (ED = `r.Length`(2) + 0; INC16 = `r.Length`(1) + 0).
**Confirm this** (DECISION G's footprint half): the only ED-specific risk is the cycle count (two fetches), not
the byte footprint — the byte footprint is already right.

## DECISIONS (surfaced for the owner — see the report-back)

- **DECISION F — populate the `EdAdcSbc16` `JitOp` slots (REQUIRED, the ED gate-path crux).** Today the
  descriptor row carries no operand info (the kind is in the "slots unused" group). The emit arm CANNOT recover
  the addend pair from the opcode cleanly across the eight ED opcodes without a table, and the add/sub sense is
  likewise not in a slot. **PR-2b moves `EdAdcSbc16` out of `JitOpLiteral`'s "slots unused" group and populates
  `RegB` = the addend pair (`op.Args[1]`) and `boolArg` = (`op.Args[0] == "SBC"`).** This is a **descriptor data
  change** — it alters the generated Z80 `JitOp(...)` literal for the eight ED rows (adds `RegB`/`boolArg`),
  which the regression gate must scope: it touches ONLY the eight ED rows, and ONLY the previously-empty slots
  (no 6502/68000 row has an `EdAdcSbc16` op-kind, so their tables are provably untouched). **Alternative
  considered:** an opcode→pair table in the JIT arm (`Z80Ed16Pair(opcode)`, mirroring PR-2's `Z80AluSource`),
  leaving the descriptor untouched. **Recommendation: populate the slots (DECISION F).** Rationale: it keeps the
  arm descriptor-driven (Decision 2's discipline — the `Ops` carry the operand), matches how PR-2's `Add16`
  carries `RegA`/`RegB`, and the regression gate cleanly proves the change is ED-only. The opcode-table
  alternative is a fine fallback if the owner prefers zero descriptor-data change. **Owner's call.**

- **DECISION G — the ED two-fetch cycle charge (REQUIRED for correctness).** An emitted ED row must charge **2
  opcode-fetch cycles** (prefix + opcode), not the 1 that `EmitInstruction` charges today
  (`BlockCompiler.cs:343`, `EmitChargeOneCycle`). Two clean options:
  - **(G1) Pass the key-byte count into the fetch charge.** `EmitInstruction` already computes
    `EmitZ80RefreshR(ctx, 1)` with a hard-coded `keyBytes=1`; PR-1's comment says "PR-2+ that emit prefixed rows
    pass the prefix-byte count." PR-2b is that PR. Make `EmitInstruction` compute `keyBytes` from the descriptor
    (`d.Length`-derived or `KeyShape`-derived: 2 for a PrefixedOpcode emitted row, 1 otherwise) and charge
    `keyBytes` fetch cycles (a second `EmitChargeOneCycle`, or `EmitChargeCycles(ctx, keyBytes)`), AND pass the
    same `keyBytes` to `EmitZ80RefreshR` (the R refresh also bumps per opcode byte — the interpreter bumps R
    twice for a prefixed op; **verify** against `OnInstructionFetched`). The ED arm then charges residual `13`.
  - **(G2) Charge the extra fetch inside the ED arm.** Leave `EmitInstruction` at 1 fetch; the `EmitZ80EdAdcSbc16`
    arm charges `1` (the second fetch) up front, then residual `13` → total `1 (EmitInstruction) + 1 + 13 = 15`.
    The R-refresh still needs the second bump.
  - **Recommendation: G1** (it is the mechanism PR-1 explicitly deferred to "PR-2+", and it is the right home for
    every future prefixed emit — the ED arm should not own block-scaffold cycle accounting). **The R-refresh
    second bump is the subtle half — confirm the interpreter bumps R per opcode byte for ED rows (it does for the
    standard Z80: the ED prefix increments R, then the ED opcode increments R again).** If the existing R model
    differs, match it exactly (the TomHarte gate checks R). **Owner: G1 (recommended) or G2?**

> **Why this is the ONLY genuinely new mechanism in PR-2b.** INC16/DEC16 is pure base-plane reuse. ED ADC/SBC
> HL,rr's flag word is PR-2's `ADD HL,rr` shape with S/Z/P recomputed (a small helper variant). The two-fetch
> charge (DECISION G) + the descriptor-slot population (DECISION F) are the ED-plane's one-time cost — exactly
> the "open the ED lane" work the prompt asked the plan to address.

```csharp

    // iff its (plane, op-kind) is in the proven-emittable set, each with a matching emit branch in
    // BlockCompiler.Z80.cs. The whitelist and the arms MUST stay in lockstep: the arm's default throws if the
    // gate admits a kind with no branch.
    //
    // EXCLUSIONS (all stay JIT fallback — by §2, not yet armed):
    //   • Non-base-plane rows EXCEPT the single ED ADC/SBC HL,rr lane below: the ED LD A,I/A,R, the ED block
    //     ops, EVERY DD/FD-indexed ALU/LD, the CB/DDCB planes.
    //   • 0xF9 LD SP,HL (16-bit Register/Transfer) — no 8-bit arm (PR-1 exclusion, retained).
    // Extended family-by-family in PR-3+.
    private static bool IsEmittableZ80Family(InstructionModel insn)
    {
        string kind = insn.Ops.Length > 0 ? insn.Ops[0].Kind : string.Empty;

        // ── M6 PR-2b: the ED-plane ADC/SBC HL,rr lane (the FIRST emitted prefixed family) ──
        // PrefixedOpcode with the ED prefix, op-kind EdAdcSbc16 (the eight ED4A.../ED42... rows). This is the
        // ONLY prefixed row PR-2b admits — the base-plane guard below would otherwise reject it. EmitZ80Alu
        // routes EdAdcSbc16 to EmitZ80EdAdcSbc16. Its descriptor slots are populated by Task 2 (RegB=pair,
        // boolArg=SBC), and EmitInstruction charges the 2-byte ED fetch (Task 3 / DECISION G).
        if (insn.KeyShape == KeyShape.PrefixedOpcode && insn.Prefix == 0xED && kind == "EdAdcSbc16")
            return true;

        // Base plane only (from here down) — exclude ED / DD / FD prefixed forms.
        if (insn.KeyShape != KeyShape.OpcodeByte || insn.Prefix != -1) return false;
        if (insn.Opcode == 0xF9) return false;                  // LD SP,HL (16-bit transfer) — no 8-bit arm.

        // ── M6 PR-1: the LD family ──
        if (insn.Mnemonic == "LD")
        {
            bool ldModeOk = insn.Mode is "Register" or "Immediate" or "RegisterIndirect"
                                       or "ExtendedAddress" or "ImmediateExtended";
            if (!ldModeOk) return false;
            if (kind is "EdLdIaRa") return false;               // belt-and-suspenders (base-plane-excluded already)
            return true;
        }

        // ── M6 PR-2: the 8-bit ALU + INC/DEC + 16-bit-ADD family ──
        // ── M6 PR-2b: + the no-flag 16-bit Inc16/Dec16 (INC rr / DEC rr, Q=0) ──
        if (kind is "Add8" or "Adc8" or "Sub8" or "Sbc8" or "And8" or "Or8" or "Xor8" or "Cp8"
                  or "IncReg" or "DecReg" or "IncMem8" or "DecMem8"
                  or "Add16"
                  or "Inc16" or "Dec16")                        // PR-2b: the flagless 16-bit pair INC/DEC
            return true;

        return false;
    }
```

- [ ] **Step 2:** `EmitZ80EdAdcSbc16` — WZ=HL+1, the 16-bit add/sub, the recomputed 16-bit flag word, `HL=res16`,
  `Q = F`, residual 13. The sense is `op.BoolArg` (true=SBC), the pair is `op.RegB` (Task 2 populated these):

```csharp
    /// <summary>M6 PR-2b: ED ADC HL,rr / SBC HL,rr (prefixed, 15 T). Mirrors EmitZ80EdAdcSbc16 (the oracle)
    /// one-for-one: WZ = HL+1 (pre-op), the 16-bit add/sub with carry-in, the full SZ5H3PNC F word RECOMPUTED on
    /// the 16-bit result (S=bit15, Z=full16-zero, Y/X from the high byte, H from bit-11 carry, P/V 16-bit
    /// overflow, N per op, C from bit 16), HL = res16, Q = F. The pair is op.RegB; the sense is op.BoolArg
    /// (true = SBC). The 2-byte ED fetch is charged by EmitInstruction (DECISION G); this arm charges the
    /// residual 13 (15 − 2 fetches). NO bus access.</summary>
    private void EmitZ80EdAdcSbc16(EmitContext ctx, OpcodeDescriptor d, JitOp op)
    {
        ILGenerator il = ctx.Il;
        bool subtract = op.BoolArg;                   // true = SBC

        // WZ = (ushort)(HL + 1)  — MEMPTR, set BEFORE the add/sub (oracle pre-op HL).
        EmitLoadReg16(ctx, "HL"); il.Emit(OpCodes.Ldc_I4_1); il.Emit(OpCodes.Add);
        EmitZ80SetWZ(ctx);                            // PR-1 helper

        // hl → NibLocal (int), rr → DataLocal (int), cin (int) staged into the sum.
        EmitLoadReg16(ctx, "HL");      il.Emit(OpCodes.Stloc, ctx.NibLocal);
        EmitLoadReg16(ctx, op.RegB);   il.Emit(OpCodes.Stloc, ctx.DataLocal);

        // full = hl ± rr ± cin → SumLocal (SIGNED int)
        il.Emit(OpCodes.Ldloc, ctx.NibLocal); il.Emit(OpCodes.Ldloc, ctx.DataLocal);
        il.Emit(subtract ? OpCodes.Sub : OpCodes.Add);
        EmitZ80CarryIn(ctx, carryIn: true, subtract);     // ± (F & 0x01) — PR-2 helper
        il.Emit(OpCodes.Stloc, ctx.SumLocal);
        // half = (hl & 0x0FFF) ± (rr & 0x0FFF) ± cin → TmpInt (SIGNED int)
        il.Emit(OpCodes.Ldloc, ctx.NibLocal); il.Emit(OpCodes.Ldc_I4, 0x0FFF); il.Emit(OpCodes.And);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Ldc_I4, 0x0FFF); il.Emit(OpCodes.And);
        il.Emit(subtract ? OpCodes.Sub : OpCodes.Add);
        EmitZ80CarryIn(ctx, carryIn: true, subtract);
        il.Emit(OpCodes.Stloc, ctx.TmpInt);
        // res16 = (ushort)full → LoLocal (int 0..0xFFFF)
        il.Emit(OpCodes.Ldloc, ctx.SumLocal); il.Emit(OpCodes.Ldc_I4, 0xFFFF); il.Emit(OpCodes.And);
        il.Emit(OpCodes.Stloc, ctx.LoLocal);

        EmitZ80Ed16Flags(ctx, subtract);              // the 16-bit flag word → F

        // HL = res16
        il.Emit(OpCodes.Ldloc, ctx.LoLocal);
        EmitStoreReg16(ctx, "HL");
        EmitZ80SetQFromF(ctx);                        // Q = F (PR-2 helper)
        EmitChargeCycles(ctx, 13);                    // 15 T = 2 fetches (EmitInstruction) + residual 13
    }
```

> **Builder note — `EmitZ80CarryIn` reuse.** PR-2's `EmitZ80CarryIn(ctx, carryIn, subtract)` pushes
> `± (cpu.F & 0x01)` and adds/subs it. ED ADC/SBC ALWAYS has a carry-in (there is no plain "ADD HL,rr 16-bit
> with carry" — the base `ADD HL,rr` is PR-2's `Add16`, NO carry-in; the ED forms are ALWAYS ADC/SBC), so pass
> `carryIn: true`. Confirm the cin is read from the OLD F (before this op's F write) — the staging reads
> `cpu.F & 1` during the sum/half computation, BEFORE `EmitZ80Ed16Flags` writes F. (The oracle reads cin first,
> computes, writes F last — same order.)

- [ ] **Step 3:** `EmitZ80Ed16Flags` — the 16-bit ADC/SBC flag word (a sibling of PR-2's `EmitZ80AddSubFlags`,
  but on the 16-bit result with S/Z/P recomputed and H/C from the 16-bit boundaries). Reads `ctx.NibLocal=hl`,
  `ctx.DataLocal=rr`, `ctx.SumLocal=full` (signed), `ctx.TmpInt=half` (signed), `ctx.LoLocal=res16`:

```csharp
    /// <summary>M6 PR-2b: the ED ADC/SBC HL,rr 16-bit F flag word. Mirrors EmitZ80Ed16FlagWord one-for-one.
    /// Pre-staged: ctx.NibLocal=hl, ctx.DataLocal=rr (int); ctx.SumLocal=full (SIGNED int); ctx.TmpInt=half
    /// (SIGNED int); ctx.LoLocal=res16 (int 0..0xFFFF). subtract: false=ADC (N=0, ov=~(hl^rr)&(hl^full),
    /// C=full>0xFFFF), true=SBC (N=1, ov=(hl^rr)&(hl^full), C=full<0). All bits recomputed (no preservation).</summary>
    private void EmitZ80Ed16Flags(EmitContext ctx, bool subtract)
    {
        ILGenerator il = ctx.Il;
        // S: ((res16 & 0x8000) != 0) ? 0x80 : 0
        EmitSelectMask(ctx, () => { il.Emit(OpCodes.Ldloc, ctx.LoLocal); il.Emit(OpCodes.Ldc_I4, 0x8000); il.Emit(OpCodes.And); il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Cgt_Un); }, 0x80);
        // Z: (res16 == 0) ? 0x40 : 0
        EmitSelectMask(ctx, () => { il.Emit(OpCodes.Ldloc, ctx.LoLocal); il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Ceq); }, 0x40); il.Emit(OpCodes.Or);
        // Y: ((res16 >> 8) & 0x20)   — high byte bit5 lines up with the Y flag bit
        il.Emit(OpCodes.Ldloc, ctx.LoLocal); il.Emit(OpCodes.Ldc_I4_8); il.Emit(OpCodes.Shr_Un); il.Emit(OpCodes.Ldc_I4, 0x20); il.Emit(OpCodes.And); il.Emit(OpCodes.Or);
        // H: ((half & 0x1000) != 0) ? 0x10 : 0   — bit-11 carry/borrow
        EmitSelectMask(ctx, () => { il.Emit(OpCodes.Ldloc, ctx.TmpInt); il.Emit(OpCodes.Ldc_I4, 0x1000); il.Emit(OpCodes.And); il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Cgt_Un); }, 0x10); il.Emit(OpCodes.Or);
        // X: ((res16 >> 8) & 0x08)   — high byte bit3 lines up with the X flag bit
        il.Emit(OpCodes.Ldloc, ctx.LoLocal); il.Emit(OpCodes.Ldc_I4_8); il.Emit(OpCodes.Shr_Un); il.Emit(OpCodes.Ldc_I4, 0x08); il.Emit(OpCodes.And); il.Emit(OpCodes.Or);
        // P/V: 16-bit overflow → 0x04. ov = (subtract ? (hl^rr) : ~(hl^rr)) & (hl^full) & 0x8000.
        il.Emit(OpCodes.Ldloc, ctx.NibLocal); il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Xor);   // hl^rr
        if (!subtract) { il.Emit(OpCodes.Ldc_I4_M1); il.Emit(OpCodes.Xor); }                                  // ~(hl^rr)
        il.Emit(OpCodes.Ldloc, ctx.NibLocal); il.Emit(OpCodes.Ldloc, ctx.SumLocal); il.Emit(OpCodes.Xor);     // hl^full
        il.Emit(OpCodes.And);
        il.Emit(OpCodes.Ldc_I4, 0x8000); il.Emit(OpCodes.And);
        il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Cgt_Un);                                                   // ov != 0 → 1/0
        il.Emit(OpCodes.Ldc_I4, 0x04); il.Emit(OpCodes.Mul); il.Emit(OpCodes.Or);                             // * 0x04
        // N: subtract ? 0x02 : 0
        if (subtract) { il.Emit(OpCodes.Ldc_I4, 0x02); il.Emit(OpCodes.Or); }
        // C: subtract ? (full < 0) : (full > 0xFFFF) → 0x01
        il.Emit(OpCodes.Ldloc, ctx.SumLocal);
        if (subtract) { il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Clt); }
        else          { il.Emit(OpCodes.Ldc_I4, 0xFFFF); il.Emit(OpCodes.Cgt); }
        il.Emit(OpCodes.Ldc_I4_1); il.Emit(OpCodes.And); il.Emit(OpCodes.Or);
        EmitStoreF(ctx);                                  // Conv_U1 + Stfld _z80F (PR-2 helper)
    }
```

> **Builder note — the bit-alignment gift, re-checked for 16-bit.** S=bit15 of res16 does NOT line up with the
> F's S flag (bit7), so S needs an explicit `Cgt_Un` select (unlike the 8-bit ADD/SUB where `res & 0x80` IS the
> S contribution). Y/X DO line up because they come from the **high byte** (`res16 >> 8`), so `(res16 >> 8) &
> 0x20` IS the Y contribution and `(res16 >> 8) & 0x08` IS the X contribution — same alignment as the 8-bit
> case, just sourced from the high byte. Cross-check every bit against `EmitZ80Ed16FlagWord`
> (`CpuEmitter.cs:3499-3512`); the TomHarte sweep (Task 7) proves it exhaustively. **`ctx.TmpInt` collision:**
> `half` lives in `ctx.TmpInt`; `EmitStoreF` reuses `ctx.TmpInt` as staging AFTER the H term reads it (H is the
> 4th OR term, before `EmitStoreF`) — same ordering as PR-2's `EmitZ80AddSubFlags`, confirmed safe.

## Design decisions surfaced for the owner (Coordinator) — confirm before / during implementation

- **DECISION F — populate the `EdAdcSbc16` descriptor slots vs an in-arm opcode→pair table (RECOMMENDED:
  populate).** The ED rows carry no operand info today (the kind is in `JitOpLiteral`'s "slots unused" group). To
  emit descriptor-driven, PR-2b populates `RegB` (pair) + `boolArg` (SBC). **Alternative:** a `Z80Ed16Pair(opcode)`
  table in the arm (zero descriptor change). **Recommendation: populate** — keeps the arm descriptor-driven
  (Decision 2's discipline; matches PR-2's `Add16`), and the regression gate cleanly proves the change is ED-only
  (no 6502/68000 row carries `EdAdcSbc16`). **Owner's call: populate the slots, or keep the descriptor untouched
  and table-drive in the arm?**
- **DECISION G — the ED two-fetch cycle charge + R-refresh (RECOMMENDED: G1 — generalize in `EmitInstruction`).**
  An emitted ED row fetches 2 opcode bytes, so it charges 2 fetch cycles and bumps R twice. **G1:** compute
  `keyBytes` (2 for an emitted prefixed row, 1 otherwise) in `EmitInstruction` and pass it to both the fetch
  charge and `EmitZ80RefreshR` — the mechanism PR-1 explicitly deferred to "PR-2+", and the right home for every
  future prefixed emit. **G2:** charge the second fetch inside the ED arm. **Recommendation: G1.** **The R-refresh
  second bump is the subtle half — the plan flags that the implementer MUST confirm the interpreter's
  `OnInstructionFetched` bumps R per opcode byte for ED rows (it does on the standard Z80), and that the
  `(R + keyBytes) & 0x7F` single-bump math matches the interpreter's post-state R (the TomHarte gate checks R).**
  **Owner's call: G1 (recommended) or G2?**
- **Bundling (RESOLVED in this plan, owner can split):** PR-2b ships BOTH the ED ADC/SBC HL,rr family and the
  flagless INC16/DEC16 in one PR (PR-2's DECISION E grouped them as "the follow-up"). They are independent and
  small; if the owner prefers, INC16/DEC16 (trivial, base-plane, no new mechanism) could fold into PR-3's no-flag
  work and PR-2b could be ED-only. **Recommendation: keep them together** — INC16/DEC16 is the natural no-flag
  bookend to the 16-bit ALU, and PR-3 is already a large control-flow PR.
