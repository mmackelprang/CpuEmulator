## Objective (the ADR §8 PR-6 row — closes the 68000 for M6)

Make the 68000 **shift/rotate** + **control-flow** families emit real IL:

- **Shifts/rotates:** ASL/ASR, LSL/LSR, ROL/ROR, ROXL/ROXR — register-count form (count from Dn%64 or imm 1-8)
  and memory form (count = 1, `.w`, the EA target). The CCR: ASL/ASR/LSL/LSR set C=X=last-bit-out (count>0),
  count-0 preserves X + clears C, ASL also sets V; ROL/ROR set C=last-bit, X UNTOUCHED, V=0; ROXL/ROXR rotate
  THROUGH X (the last bit out becomes both C and X). **The X involvement is the shift family's wrinkle** (the
  PR-5 CCR helpers + new shift-specific rules).
- **Control flow (block-ending):** Bcc (conditional), BRA, BSR (push return PC), **DBcc (the decrement-and-branch
  loop primitive)**, JMP, JSR (push return PC), RTS (pop PC). These are control-flow / block-ending — the same
  static-vs-dynamic chaining problem the Z80 PR-3 solved (Bcc/BRA = JR/JP, BSR/JSR = CALL, RTS = RET, DBcc = the
  DJNZ analogue).
- **Stays FALLBACK by design (§2 + the exception tail):** TRAP/TRAPV/CHK/ILLEGAL/RTE (exception-capable),
  MOVEM/MULU/MULS/DIVU/DIVS (microcoded/multi-cycle), BSR/Bcc to dynamic targets, LINK/UNLK (rare), and any
  68000 op not in the emit set. The fallback valve keeps these exactly the oracle.

**Why PR-6 (ADR §8):** it completes the 68000 emit at the §6 cumulative-~100% line (MOVE + ALU + shifts +
branch/call/return cover essentially all executed instructions). **It is where 68000 blocks finally span
multiple instructions and chain** (§3.1) — until the hot branches emit, every 68000 control-flow op is a
fallback that ends the block after one instruction. The load-bearing content is the **DBcc block-ending +
counter-decrement handling** (DECISION D) and the static-vs-dynamic chaining (DECISION C, mirroring PR-3's
DECISION I). Size M — it reuses PR-3's proven control-flow shape + PR-4/PR-5's 68000 infrastructure.

## What the recon CONFIRMED (file:line — load-bearing, verified against `main` @ `555b1bd`)

### The shift/rotate oracle (`ShiftRotateExecute` — the per-bit loop + the X handling)

All shifts run through `ShiftRotateExecute` (`M68000Cpu.Shift.cs:83-157`) — NOT `BinaryAluExecute` (shifts need
explicit `lastBitOut` + `msbChanged` CCR inputs). The per-bit loop with the X threading:

```csharp
// The per-bit core (M68000Cpu.Shift.cs:112-133) — captures lastBitOut, tracks msbChanged (ASL's V):
case ShiftKind.Asl: case ShiftKind.Lsl:
    lastBitOut = (v & sb) != 0; v = (v << 1) & mask; break;
case ShiftKind.Asr:  // (arithmetic right — preserve the sign bit)
    lastBitOut = (v & 1u) != 0; v = (v >> 1) | (v & sb); break;
case ShiftKind.Lsr:
    lastBitOut = (v & 1u) != 0; v = v >> 1; break;
case ShiftKind.Rol:
    lastBitOut = (v & sb) != 0; v = ((v << 1) | (lastBitOut ? 1u : 0u)) & mask; break;
case ShiftKind.Ror:
    { bool lo = (v & 1u) != 0; v = ((v >> 1) | (lo ? sb : 0u)) & mask; lastBitOut = lo; } break;
case ShiftKind.Roxl:
    lastBitOut = (v & sb) != 0; v = ((v << 1) | (xIn ? 1u : 0u)) & mask; xIn = lastBitOut; break;   // X feeds IN; last bit -> new X
default: // Roxr
    { bool lo = (v & 1u) != 0; v = ((v >> 1) | (xIn ? sb : 0u)) & mask; lastBitOut = lo; xIn = lo; } break;

// Count handling (M68000Cpu.Shift.cs:90-107): register form — bit 5 selects Dn%64 (register) vs imm 1-8
//   (bits 11-9, 0->8); memory form — count is implicitly 1, .w only, the EA is the RMW target.
// For ASL/ASR/LSL/LSR, count > width forces lastBitOut = false (C/X cleared, :140-142); rotates wrap, uncapped.
```

The shift CCR rules (selected by kind, `M68000Cpu.Shift.cs:148-155`):

```csharp
// ShiftCcr.Shift (ASL/ASR/LSL/LSR, M68000Cpu.Shift.cs:30-46): N/Z from result; C = X = lastBitOut (count>0);
//   count 0 -> C=0, X UNCHANGED; ASL ALSO sets V = msbChanged (the MSB changed during the shift).
// ShiftCcr.Rotate (ROL/ROR, :49-55): N/Z from result; C = lastBitOut; X UNTOUCHED; V=0.
// ShiftCcr.RotateX (ROXL/ROXR, :58-66): N/Z from result; rotate THROUGH X — the last bit out becomes BOTH C and
//   X; count 0 -> C = current X, X unchanged.
```

> **The shift X-distinction (the family wrinkle):** ASL/ASR/LSL/LSR set C=X=last-bit (count>0), but count-0
> leaves X UNCHANGED (a subtle edge); ROL/ROR leave X UNTOUCHED entirely; ROXL/ROXR rotate THROUGH X (X is both
> an input — fed into the rotate — and an output — the last bit out). **ROXL/ROXR are the hardest shift arm**
> (X-as-input-and-output, like ADDX/SUBX in PR-5). ASL's V (`msbChanged`) is the other subtlety. The data-axis
> SR comparison gates all of this.

### The control-flow oracle (the block-ending ops — mirror PR-3's shape)

```csharp
// Bcc/BRA/BSR (M68000Cpu.Control.cs:18-41) — condition field bits 11-8 sub-dispatches:
uint cc = (operword >> 8) & 0xFu;
uint disp8 = operword & 0xFFu;
int disp = disp8 == 0x00u ? (short)r.ExtensionWords[0]    // Bcc.w (16-bit disp word; disp8==0 selects it)
                          : (sbyte)(byte)disp8;           // Bcc.b (0xFF = -1 is a NORMAL .b disp on the 68000)
uint target = unchecked(PcForEa + (uint)disp);            // branchBase = operword address + 2
if (cc == 0x1u) { uint sp = A7 - 4u; A7 = sp; WriteLongBus(sp, PC); PC = target; return; }   // BSR: push return PC, branch
if (cc == 0x0u || EvaluateCondition(cc, (byte)(SR & 0xFF))) PC = target;                       // BRA or taken Bcc
// not-taken: PC already past the instruction (fall through)

// DBcc (M68000Cpu.Control.cs:45-61) — the loop primitive. CONDITION TRUE -> fall through (NO decrement):
if (EvaluateCondition(cc, (byte)(SR & 0xFF))) return;     // condition true: fall through, no decrement
ushort counter = (ushort)(DataReg(dn) & 0xFFFFu);
counter = (ushort)(counter - 1);                          // decrement Dn.w (the LOW 16 bits only)
SetDataRegPartial(dn, counter, 1u);                       // .w partial write (upper word preserved)
if (counter != 0xFFFFu) PC = unchecked(PcForEa + (uint)disp);   // branch UNLESS it ran out (-1 terminates, NOT 0)

// JMP / JSR (M68000Cpu.Control.cs:64-75) — control EA (pureEa: true, never dereferenced):
uint ea = ComputeEa(srcMode, srcReg, 2u, r.ExtensionWords, pureEa: true);
uint sp = A7 - 4u; A7 = sp; WriteLongBus(sp, PC);         // JSR only: push the return PC
PC = ea;

// RTS (M68000Cpu.Control.cs:78-...) — pop PC from (A7)+:
uint sp = A7; uint ret = ReadLongBus(sp); A7 = sp + 4u; PC = ret;
```

`EvaluateCondition` (`M68000Cpu.Scc.cs:13-35`) is the shared 16-condition table (T/F/HI/LS/CC/CS/NE/EQ/VC/VS/PL/
MI/GE/LT/GT/LE) — the JIT arm calls it or emits the equivalent condition test from the CCR bits.

> **The DBcc off-by-one (the classic bug, vector-pinned):** DBcc decrements **only on condition FALSE**, tests/
> decrements **Dn's LOW 16 bits only** (upper word preserved), and **terminates at -1 (0xFFFF), NOT 0** — so a
> DBcc with Dn.w == 0 decrements to 0xFFFF and BRANCHES (one more iteration); a DBcc with Dn.w == 1 decrements to
> 0 and BRANCHES; only Dn.w == 0 already (→ 0xFFFF) on the LAST decrement falls through. This is the load-bearing
> DBcc semantic — pin it against the DBcc vectors.

### The control-flow ops are block-ending (the chaining + `EndsBlock` problem)

These ops set PC non-sequentially → they END the basic block (like the Z80 PR-3 flow ops). The generated Step
detects `FormalPc != PC` and reseeds the prefetch queue (`CpuEmitter.cs:345-364`); for the JIT, the emitted arm
self-terminates with `EmitChainOrExit` (static target) or `EmitNormalExit` (dynamic target). **Bcc-not-taken
and DBcc-fall-through fall through sequentially (do NOT end the block in spirit, but the descriptor marks them
EndsBlock=true and the not-taken/fall-through edge chains to `pc + length` — exactly the Z80 PR-3 two-edge
shape).**

## DECISIONS (the design forks — DBcc block-ending is the load-bearing one)

### DECISION C — static-vs-dynamic chaining (mirror PR-3's DECISION I)

Every PR-6 control-flow op keeps `EndsBlock=true` when emitted. The composition with chaining (the proven Z80
PR-3 / 6502 pattern):

- **STATIC target → `EmitChainOrExit(ctx, staticTargetPc)`** (chainable; the target is a compile-time constant
  read from the code stream at compile time):
  - **Bcc / BRA:** `staticTargetPc = (pc + 2) + (sbyte)disp8` (or `(pc+2) + (short)extWord` for Bcc.w) — chain
    to it (the taken edge); Bcc's not-taken edge chains to `pc + length` (the fall-through).
  - **BSR:** `staticTargetPc = (pc + 2) + disp` — chain to the call entry (the return PC is dynamic-on-the-stack,
    but the entry is static, exactly like 6502 JSR / Z80 CALL).
  - **JSR / JMP with a STATIC ea** (abs.W/abs.L/d16(PC) — compile-time constant): chain to the ea. **JMP/JSR with
    a DYNAMIC ea** ((An)/(An,Xn) — runtime register) → `EmitNormalExit`.
  - **DBcc:** `staticTargetPc = (pc + 2) + disp` — chain to it (the branch-taken edge); the fall-through (counter
    ran out OR condition true) chains to `pc + length`.
- **DYNAMIC target → `EmitNormalExit(ctx)`** (NOT chainable):
  - **RTS:** PC = popped — dynamic; exit to the dispatcher (exactly like 6502 RTS / Z80 RET).
  - **JMP/JSR (An)/(An,Xn):** runtime target — exit.

> **No owner decision on C — it is the proven PR-3 / 6502 pattern.** The plan surfaces the static-vs-dynamic
> split so the implementer applies it correctly. The one judgement call: **JMP/JSR with a register-indirect ea
> ((An)) is DYNAMIC → `EmitNormalExit`; with an absolute/PC-relative ea it is STATIC → chain.** Decode the ea
> mode at compile time (DECISION P3) and branch on static-vs-dynamic.

### DECISION D — the DBcc block-ending + counter decrement (the load-bearing PR-6 decision)

DBcc is the hot counted-loop branch and the trickiest emit. It is BLOCK-ENDING (it sets PC non-sequentially on
the taken edge), but it also DECREMENTS Dn.w (a data-axis side-effect) and has THREE outcomes:

1. **Condition TRUE** → fall through, NO decrement (PC = `pc + length`, Dn unchanged).
2. **Condition FALSE, counter (Dn.w) decrements to != -1** → branch (PC = target, Dn.w decremented).
3. **Condition FALSE, counter decrements to -1 (was 0)** → fall through (PC = `pc + length`, Dn.w = 0xFFFF).

The emit shape (mirroring the oracle exactly):

```
EmitM68kDBcc:
  // 1) test the condition (from cc bits 11-8). If TRUE -> jump to FALL_THROUGH (no decrement).
  EmitM68kCondition(cc)        // pushes 0/1 from the CCR
  Brtrue fallThroughLabel
  // 2) condition FALSE: decrement Dn.w (low 16, preserve upper word)
  counter = (DataReg(dn) & 0xFFFF) - 1
  SetDataRegPartial(dn, counter & 0xFFFF, size=.w)
  // 3) if counter (the post-decrement low word) != 0xFFFF -> branch to target; else fall through.
  (counter & 0xFFFF) == 0xFFFF ? branch to fallThrough : branch to TARGET
  branchTakenLabel:
    PC = target;  EmitChargeCycles(ctx, takenCycles);  EmitChainOrExit(ctx, staticTargetPc)   // STATIC target -> chain
  fallThroughLabel:
    PC = pc + length;  EmitChargeCycles(ctx, fallThroughCycles);  EmitChainOrExit(ctx, pc + length)   // STATIC fall-through -> chain
```

> **The DBcc decisions (surfaced — D is load-bearing but the resolution is mechanical, mirroring the oracle):**
> (a) **the decrement is `.w` partial** (`SetDataRegPartial(dn, _, 1u)` — preserve Dn's upper word) — use PR-4's
> `EmitStoreDataRegSized(ctx, $"D{dn}", size=1)`; (b) **the terminate-at-`-1` (0xFFFF), NOT 0** — the post-
> decrement test is `(counter & 0xFFFF) != 0xFFFF` for the BRANCH-taken edge; (c) **condition-TRUE falls through
> WITHOUT decrementing** — the condition test gates the whole decrement block; (d) **BOTH outgoing edges are
> STATIC** (the branch target and the fall-through `pc+length` are compile-time constants) → BOTH chain via
> `EmitChainOrExit`. **The data-axis gate verifies Dn.w + the landed PC** for every DBcc vector — the off-by-one
> surfaces as a red test. **No owner checkpoint needed; the plan pins the exact three-outcome shape so the
> implementer transcribes the oracle correctly.** This is the 68000 analogue of PR-3's DJNZ (DECISION I/J/K),
> with the 68000's condition-TRUE-falls-through twist (DJNZ has no condition — it always decrements).

### DECISION A7-PUSH — BSR/JSR push to `-(A7)` (reuse PR-4's A7 banking)

BSR/JSR push the return PC to `-(A7)` (a long write, `A7 -= 4; WriteLongBus(A7, PC)`). RTS pops from `(A7)+`.
These reuse PR-4's `EmitLoadAreg`/`EmitStoreAreg` (the A7 S-bit banking) + PR-4's `EmitStoreLong`/`LoadLongFromBus`.
The push is: `EmitLoadAreg(7); ldc 4; sub; dup -> EmitStoreAreg(7); [the new A7 as the address] EmitLoadPC; EmitStoreLong`.
**Mirror the BSR/JSR oracle (`M68000Cpu.Control.cs`) exactly — the return PC is the PC AFTER the instruction
(past the operword + ext words).** The SMC backstop: BSR/JSR push via `EmitStoreLong` (marks dirty); they end
the block and self-terminate with `EmitChainOrExit`, whose `dirty.Any` gate routes a self-modifying push to the
dispatcher — so a BSR/JSR pushing onto its own code page is caught by the chain-edge SMC backstop (the same
PR-3 reasoning — no intra-block `mayWriteRam` entry needed for the block-ending flow ops; only the shift
memory-RMW form needs `mayWriteRam`).

### DECISION T (inherited) — data-axis parity / coarse cycles; the `>= 1-cycle` floor on transfers

Per PR-4 DECISION T: the JIT gate is the data axis (incl. the landed PC — a register). The control-flow arm
charges the descriptor's `BaseCycles` (coarse) via `EmitChargeCycles`. **CRITICAL (the runaway trap):** a taken
control transfer must charge `>= 1` cycle, or the 1-cycle-budget `RunCaseThroughJit` loop runs a runaway second
instruction (the exact ~10h-hang the interpreter's generated Step guards against — `M68000TomHarteRunner.cs:288-293`).
So the emitted Bcc/BRA/BSR/DBcc/JMP/JSR/RTS MUST each charge `>= 1` cycle (their `BaseCycles` is `>= 10`, so this
is automatic — but verify the taken edge charges before `EmitChainOrExit`, not after).

```csharp
    // M6 PR-6: the 68000 shift/rotate arm. Mirrors ShiftRotateExecute (M68000Cpu.Shift.cs:83-157) on the DATA
    // axis (incl. SR/X). Kind from d.Mnemonic + direction; count from Dn%64 (register) / imm 1-8 / memory=1.
    // CCR: ShiftCcr.Shift (ASL/ASR/LSL/LSR: C=X=lastBit, count0 keeps X, ASL sets V) / .Rotate (ROL/ROR: C=lastBit,
    // X untouched) / .RotateX (ROXL/ROXR: rotate THROUGH X). The memory form is a .w RMW (address-once).
    private void EmitM68kShift(EmitContext ctx, ushort pc, OpcodeDescriptor d)
    {
        ILGenerator il = ctx.Il;
        ushort operword = _bus.Read16(pc);
        var kind = M68kShiftKind(d.Mnemonic, operword);   // Asl/Asr/Lsl/Lsr/Rol/Ror/Roxl/Roxr
        bool memoryForm = M68kShiftIsMemoryForm(operword);
        int size = memoryForm ? 1 : M68kSizeFromKey(d);   // memory form is .w

        // 1) read the value (Dn register low byte/word/long, or the memory EA RMW)
        // 2) read the count (Dn%64 / imm 1-8 / 1 for memory)
        // 3) emit the shift/rotate + capture lastBitOut (+ msbChanged for ASL); for ROXL/ROXR thread the live X
        // 4) write the result (Dn size-aware partial, or memory RMW write-back)
        // 5) set the CCR via the kind's rule (EmitM68kShiftCcr / EmitM68kRotateCcr / EmitM68kRotateXCcr)
        // 6) EmitChargeCycles(ctx, d.BaseCycles)
        // ... (the per-kind IL — see the per-kind notes below) ...
    }
```

> **Builder note — closed-form vs loop.** For a constant count (imm 1-8) the shift is a single IL `Shl`/`Shr_Un`
> (+ the sign-fill for ASR) and the last-bit-out is `(value >> (width - count)) & 1` (left) or `(value >>
> (count - 1)) & 1` (right) — closed-form, no loop. For a RUNTIME count (Dn%64), either emit a runtime loop
> (simplest, matches the oracle's per-bit loop exactly — and runtime count is rarer in the hot path) OR a
> closed-form with masked shifts. **Recommend: closed-form for the imm/memory(count=1) forms (the hot path), and
> a runtime loop for the Dn%64 register-count form** (correctness over speed for the rare runtime-count case;
> the loop transcribes the oracle's per-bit body verbatim, so it is the lowest-risk). The ROXL/ROXR through-X
> rotate is inherently per-bit (X feeds in each iteration) — emit the runtime loop for ROXL/ROXR with a runtime
> count, closed-form only for count=1. **The data-axis SR comparison gates the last-bit-out / X / V exactness.**

> **Builder note — the shift CCR helpers.** Three small helpers, each transcribing its oracle rule:
> - `EmitM68kShiftCcr(result, lastBitOut, msbChanged, count, size)` — N/Z from result; if count>0: C=X=lastBit;
>   if count==0: C=0, X UNCHANGED (read+keep the old X); ASL also OR-s V=msbChanged. (`ShiftCcr.Shift`.)
> - `EmitM68kRotateCcr(result, lastBitOut, size)` — N/Z; C=lastBit; X UNTOUCHED; V=0. (`ShiftCcr.Rotate`.)
> - `EmitM68kRotateXCcr(result, lastBitOut, count, size)` — N/Z; C=X=lastBit; count0: C=current X, X unchanged.
>   (`ShiftCcr.RotateX`.) Reuse the N/Z computation from PR-5's CCR helpers; the C/X/V differences are the
>   per-kind tail. The count==0 edge (X unchanged, C cleared/=X) is the subtle one — pin against the count-0
>   shift vectors.

- [ ] **Step 5:** **DBcc — the three-outcome shape (DECISION D — the load-bearing piece):**

```csharp
    // M6 PR-6 (DECISION D): DBcc — the decrement-and-branch loop primitive. Three outcomes:
    //   (1) condition TRUE  -> fall through, NO decrement.
    //   (2) condition FALSE, Dn.w-- != 0xFFFF -> branch (PC = target).
    //   (3) condition FALSE, Dn.w-- == 0xFFFF (was 0) -> fall through (Dn.w = 0xFFFF).
    // Dn.w is the LOW 16 bits (upper word preserved); terminates at -1 (0xFFFF), NOT 0. Both edges are STATIC -> chain.
    private void EmitM68kDBcc(EmitContext ctx, ushort pc, OpcodeDescriptor d, int length, int cc, int dn, uint target)
    {
        ILGenerator il = ctx.Il;
        var fallThrough = il.DefineLabel();
        var branchTaken = il.DefineLabel();

        // (1) if condition TRUE -> fall through (no decrement)
        EmitM68kCondition(ctx, cc);
        il.Emit(OpCodes.Brtrue, fallThrough);

        // (2/3) condition FALSE: counter = (Dn.w) - 1; write Dn.w (preserve upper word)
        EmitLoadDataRegSized(ctx, $"D{dn}", 1);          // Dn.w (low 16) on stack
        il.Emit(OpCodes.Ldc_I4_1); il.Emit(OpCodes.Sub);
        il.Emit(OpCodes.Ldc_I4, 0xFFFF); il.Emit(OpCodes.And);   // counter = (Dn.w - 1) & 0xFFFF
        il.Emit(OpCodes.Dup); il.Emit(OpCodes.Stloc, ctx.DataLocal);
        EmitStoreDataRegSized(ctx, $"D{dn}", 1);         // Dn.w = counter (upper word preserved)
        // if counter == 0xFFFF -> fall through; else branch
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Ldc_I4, 0xFFFF); il.Emit(OpCodes.Ceq);
        il.Emit(OpCodes.Brtrue, fallThrough);

        il.MarkLabel(branchTaken);
        EmitSetPc(ctx, target);                          // PC = target (compile-time constant)
        EmitChargeCycles(ctx, d.BaseCycles);             // taken cycles (>= 1 — DECISION T)
        EmitChainOrExit(ctx, (ushort)target);            // STATIC -> chain

        il.MarkLabel(fallThrough);
        EmitSetPc(ctx, (uint)(pc + length));             // PC = next instruction
        EmitChargeCycles(ctx, d.BaseCycles);             // fall-through cycles (>= 1)
        EmitChainOrExit(ctx, (ushort)(pc + length));     // STATIC -> chain
    }
```

> **Builder note — the DBcc parity traps (pin against the DBcc vectors):** (a) the decrement is `.w` PARTIAL —
> `EmitStoreDataRegSized(ctx, $"D{dn}", 1)` preserves Dn's upper 16 bits (a full-32 write would corrupt them);
> (b) the terminate is at **0xFFFF (-1), NOT 0** — the test is `counter == 0xFFFF`; (c) condition-TRUE falls
> through WITHOUT touching Dn — the `Brtrue, fallThrough` BEFORE the decrement is load-bearing; (d) both edges
> charge `>= 1` cycle BEFORE `EmitChainOrExit` (DECISION T — avoid the runaway). The `EmitSetPc` helper writes
> the 32-bit PC field. The data-axis gate verifies Dn.w + the landed PC for every DBcc vector — the off-by-one
> surfaces as a red test, not a runaway loop.
