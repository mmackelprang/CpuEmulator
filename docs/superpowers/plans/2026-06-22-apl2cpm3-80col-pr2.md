# Plan — V80-2: CP/M 3.1 reaches `A>` on the 40-column console (close the Z80-entry handoff)

> **Arc:** apl2cpm3 CP/M 3.1 on the SoftCard + Videx — the 80-column CP/M sub-arc (ADR 0018). **PR 2 of 3.**
> **Depends on:** V80-1 (the configurable slot + the `Apl2Cpm3` loader must be merged first).
> **Grounded against:** `main` @ `7dacd6d` + the merged V80-1 (the slot-4 `SoftCardBoard.Spec(... controlPortBase: ControlPortBaseSlot4)` and `Apl2Cpm3.LoadBootDisk`). Re-ground all literal code against the *then-current* main when this PR is taken.
> **ADR:** ADR 0018 Decision 3 (the Z80-entry-handoff residual — a bring-up item, not pre-designed) + Decision 4 (the 40-col gate) + Decision 2 (the existing skew holds) + Open Questions 1-2. **Reuses the ADR 0017 per-instruction yield + the slot-4 handshake unchanged.**
> **Queue row:** **V80-2** (THE 40-col milestone).

## Why this PR

With V80-1 merged, the slot fix is live: building the SoftCard board at slot 4 over apl2cpm3 Disk 1 makes the
Z80 activate and the CPMLDR load to `$1100+` (ADR 0018 §1.2, live-verified). But the boot does **not** reach
`A>`: the Z80 NOP-slides from its `$0000` reset PC (= 6502 `$1000` via translation branch 1) because the
**entry vector to the loaded CPMLDR is absent** (ADR 0018 §1.2 "the residual"). This PR closes that residual
**by live triage against the running disk** — the same evidence-backed, instruction-stepped bring-up that
closed 2.2's `$1010` bridge (ADR 0017 Decision 4 / CPM-4, which turned out to be a no-op once fixes 1-3
landed). The arbiter is decoded `A>` on screen.

**This is an irreducible bring-up PR.** ADR 0018 Decision 3 is explicit: the exact stub/PC behaviour is
disk/loader data closed at build time against the oracle, **not** pre-designed here. So this plan specifies
**the triage method, the ordered hypotheses, the seam each hypothesis touches, the escalation trigger, and
the final un-fakeable gate** — but it does NOT pre-write the fix (there may be none beyond the slot, or it
may be a small handshake-timing item). The Builder runs the triage, lands whatever the live disk requires,
and finishes with the gate below.

**Definition of done:** the live apl2cpm3 Disk 1 boots to **CP/M 3.1 `A>`** on the 40-col Apple console
(`$0400` text page): the decoded-text gate asserts the `A>` CCP prompt + a CP/M-3 sign-on substring
(`CP/M V3.0` / `DIGITAL RESEARCH`) + `CoprocessorActive`. The gate is `[Apl2Cpm3Fact]` (skip-with-note absent).
A human-visible `A>` PNG is captured via `tools/BootProbe`. **This is milestone 1.**

1. **Red:** un-skip the V80-1 `Cpm3_boots_to_the_A_prompt_on_the_interpreter_40col` gate body to the full

## Task 1 — Live triage: localize the Z80-entry-handoff residual (throwaway probe, reverted)

### What the ADR already established (do NOT re-derive)

- The slot-4 handshake fires: the Z80 activates on the single `$C400` write (~2.4 M cycles); the CPMLDR
  loads (the `CP/M V3.0` sign-on lands at `$1C3E`; RAM `$1100-$23FF` populated). ADR 0018 §1.2.
- The Z80 resets to `PC=$0000` (= 6502 `$1000`), which is **all zeros**, so it NOP-slides
  (`$005B → $0068 → … → $00F7 → $0003 → …`, wrapping, never reaching `$1100+`). Confirmed stuck to 100 M
  cycles. ADR 0018 §1.2.
- Only **one** control-port toggle was observed (the Z80 never handed control back). ADR 0018 §5 OQ1.

### The ordered hypotheses (ADR 0018 Decision 3 — confirm/falsify live, in this order)

Build a throwaway `BootProbe` mode (or a temporary xunit `[Fact(Skip-removed)]`) over the slot-4 apl2cpm3
board, instruction-step the boot, and answer each in order:

**H1 (the likely crux) — the entry vector at the Z80 reset address.** Step the 6502's start-Z80 routine
(track-0 `STA $C400` at offset `$DBA`, followed by `RTS` — ADR 0018 §1.2, verified `8D 00 C4` present on the
staged disk) and the boot2/CPMLDR stages. Determine:
- Does any 6502 (or Z80) stage write a `JP <loader>` stub at physical `$1000` (the Z80's `$0000`) **before**
  the Z80 is released? Dump physical `$1000-$1010` at the moment of the `$C400` write. If it is all zeros at
  release, the loader expects the Z80 to start *somewhere else* (not `$0000`) OR a later stage should write
  the stub.
- Is the loader's intended Z80 entry point derivable from the loaded image (e.g. the `CP/M V3.0 Loader` block
  at `$1100+` has a known entry — dump `$1100-$1120` and disassemble as Z80)? CP/M-3 `CPMLDR` conventionally
  begins execution at the load address top; confirm the real bytes.

**H2 — a later boot2/CPMLDR stage writes the stub after the first toggle (a multi-round-trip handshake).** If
H1 shows the stub *would* be written by a 6502 stage that only runs after the Z80 hands control back, then
the residual is the **handback** not firing. Verify the Z80→6502 handback path: the Z80's write to its
`$E400` (translation branch 5 → physical `$C400`) must toggle the control port back. Step the Z80's
NOP-slide and confirm it never reaches an `$E400` write (consistent with the single-toggle observation →
points back to H1: the Z80 is lost before it can hand back).

### Triage deliverable

A localized finding: *which* of H1/H2 holds, *what* address the entry vector should carry, and *whether* our
seams (the slot-4 handshake + the ADR 0017 per-instruction yield + the `SoftCardTranslation` branch 1
`$1000→$0000` mapping) already service it once the stub is present. Record the instruction-step evidence in
the PR body (the ADR-0017-Decision-4 discipline). **Revert the probe before the PR** — it is a throwaway, like
the ADR's own trace.

> **Grounding note:** the Z80 PC is read via `z80.GetRegister("PC")` (the shipped pattern, used live in
> `SoftCardBoardTests.Cpm_boot_runs_the_z80_bios_at_Axxx_stably_*` at line 305). Physical RAM is read via
> `machine.Space(AddressSpaceKind.Program).Read8(addr)`. Both are already available — no new instrumentation
> API.

## Task 2 — Land the minimal change the triage identifies (the bring-up)

**This task's exact content is determined by Task 1** (ADR 0018 Decision 3 forbids pre-designing it). The
scoped, bounded outcomes — in order of likelihood:

### Outcome (1) — no production change needed (the V80-1 slot fix + the shipped seams are sufficient)

Mirrors CPM-4's actual outcome (the `$1010` bridge was a no-op once CPM-1-3 landed). If the triage shows the
6502 boot *does* write the `JP <loader>` stub at `$1000` and our slot-4 handshake + per-instruction yield
already round-trip correctly, the Z80 enters the loader and reaches `A>` with **no further production change**.
Then V80-2 is **test-only** (Task 3 + Task 4). This is the cleanest outcome and the one to hope for.

### Outcome (2) — a bounded handshake/timing item in the dual-CPU run loop

If the triage shows the handback (`$E400`→`$C400`) or the slice cadence is one stage short for CP/M-3's
longer loader (more Z80↔6502 round-trips than 2.2), the fix is confined to the **`RunDualCpu` branch** (the
ADR 0017 Decision 3 per-instruction yield seam) — e.g. ensuring the yield fires symmetrically on the slot-4
write. The single-CPU `RunSingleCpu` path stays byte-for-byte unchanged (the load-bearing regression gate,
exactly as CPM-3 enforced). The Builder writes the failing synthetic dual-CPU yield test first (mirror
`DualCpuYieldTests`), lands the change, confirms green.

### Outcome (3) — the Z80-core reset PC (ESCALATE — Decision 6, judged unlikely)

If, and only if, the triage shows apl2cpm3 depends on the SoftCard latching a **non-`$0000` Z80 start PC**
(not a stub the loader writes), that touches the Z80-core `Reset()` → `PC=$0000` path / the dual-CPU handoff
model. **The Builder STOPS and reports to the owner** (ADR 0018 Decision 6 / Open Question 1). Do NOT change
the Z80 core reset semantics without owner sign-off — it is cross-cutting beyond this PR. The ADR judges this
unlikely (the more probable cause is the loader writing a `JP` stub), but it is flagged so it is not a silent
surprise.

> **The plan does not pre-commit to an outcome.** The Builder lands whichever the live disk requires, records
> the evidence + the chosen outcome in the PR body (the CPM-4 PR-body precedent), and — for outcome (2) —
> adds the synthetic regression test that FAILS pre-fix / PASSES post-fix.

## Task 3 — The un-fakeable 40-col `A>` gate (replace the V80-1 skip)

### 3a. Fill in the skipped gate body

Edit `tests/CpuEmulator.Tests/Apple2/Apl2Cpm3BootTests.cs` — replace the V80-1 named-skip with the live
asserting gate (gated by `[Apl2Cpm3Fact]`, the skip-with-note attribute from V80-1 Task 6a). The build path
mirrors the shipped `SoftCardBoardTests.Cpm_boots_to_the_A_prompt_on_the_interpreter` (lines 325-372) exactly,
swapping the disk loader (`Apl2Cpm3.LoadBootDisk`), the slot (`controlPortBase: ControlPortBaseSlot4`), and
the sign-on substring (CP/M-3, not 2.2):

```csharp
using CpuEmulator.Core;
using CpuEmulator.Machines;
using CpuEmulator.Peripherals;
using Xunit;

namespace CpuEmulator.Tests.Apple2;

public class Apl2Cpm3BootTests
{
    private const long CpmBootCycles = 20_000_000;   // CP/M-3's loader chain is longer than 2.2's; generous
                                                     // budget (the slot-4 Z80 activates ~2.4M; tune on first green)

    // ADR 0018 PR-2 (V80-2) -- THE 40-col milestone. With V80-1's slot fix (the Z80 activates at $C400 + the
    // CPMLDR loads to $1100+) and V80-2's entry-handoff bring-up (Task 1/2), the real apl2cpm3 Disk 1 boots to
    // CP/M 3.1 A> on the 40-col Apple console. This is the un-fakeable A> oracle (Decision 4): the decoded
    // console text MUST carry "A>" (the CCP prompt) + a CP/M-3 sign-on substring, and the Z80 MUST be the
    // active bus master. Un-fakeable because A> at the $0400 text page can only come from a real CP/M-3 CONOUT
    // through the slot-4 $C400 handshake (CP/M's RAM maps via Z80 branch-1 to physical $1000+, never the
    // $0400 text page -- the same argument the CPM-4 reviewer confirmed for 2.2).
    [Apl2Cpm3Fact]
    public void Cpm3_boots_to_the_A_prompt_on_the_interpreter_40col()
    {
        var (systemRomPath, disk1Path) = Apl2Cpm3Vectors.TryGetAssets()!.Value;
        byte[] systemRom = Apple2Rom.Load(systemRomPath);
        byte[] diskBootRom = Apple2Rom.TryLoadDiskRom()
            ?? throw new InvalidOperationException("the slot-6 disk2.rom is required for the apl2cpm3 boot gate");
        byte[]? charRom = Apple2Rom.TryLoadCharRom();   // null -> Apple2Font.Fallback (still renders A>)
        IBlockDevice disk1 = Apl2Cpm3.LoadBootDisk(disk1Path);

        var state = new Apple2VideoState();
        var lc = new Apple2LanguageCard(systemRom);
        var drive1 = new DskFluxImage(disk1, SectorOrderKind.Cpm);   // the existing CP/M skew (Decision 2)
        var disk = new Apple2DiskII(drive1);
        var iou = new Apple2Iou(state, lc, disk);
        // THE SLOT FIX (V80-1): apl2cpm3 hard-codes STA $C400 -> the control port decodes at slot 4.
        BoardSpec spec = SoftCardBoard.Spec(systemRom, iou, disk, diskBootRom,
            controlPortBase: SoftCardBoard.ControlPortBaseSlot4);
        Machine machine = BoardMachineFactory.Build(spec);   // interpreter tier (the coprocessor is interpreter)

        machine.Reset();
        machine.Run(CpmBootCycles);                          // the real $C600 -> tracks -> $C400 -> CP/M-3 boot

        // --- (1) The un-fakeable content oracle: decode the 40-col text page and assert the CP/M-3 prompt.
        string[] screen = DecodeTextScreen(machine);
        string joined = string.Join("\n", screen);
        Assert.Contains("A>", joined);   // the CCP prompt -- the headline target

        // --- (2) A CP/M-3 sign-on substring (the disk's own ASCII pins these -- live-verified on the staged
        //         disk: "CP/M V3.0 Loader" / "Copyright (C) 1982, Digital Research" / "CP/M Version 3.0").
        //         The exact line that survives to the settled console is confirmed on the first green run
        //         (ADR 0018 OQ2: the BIOS may paint 40-col then switch, or go straight to 80-col -- the gate
        //         asserts whichever the disk actually paints to the 40-col page).
        Assert.True(
            joined.Contains("CP/M V3", StringComparison.OrdinalIgnoreCase)
            || joined.Contains("DIGITAL RESEARCH", StringComparison.OrdinalIgnoreCase)
            || joined.Contains("CP/M", StringComparison.OrdinalIgnoreCase),
            $"expected a CP/M-3 sign-on line on the console; decoded screen was:\n{joined}");

        // --- (3) The Z80 ran: it became the bus master during the boot (the $C400 handoff fired).
        Assert.True(machine.CoprocessorActive,
            "expected the Z80 to be the active bus master after the apl2cpm3 boot handoff");
    }

    /// <summary>Decode the live 24x40 Apple text page ($0400, page 1) to ASCII -- the same TextRowBase walk
    /// the 2.2 SoftCard gate uses, stripping the normal-video high bit; non-printable cells become spaces.</summary>
    private static string[] DecodeTextScreen(Machine machine)
    {
        IAddressSpace bus = machine.Space(AddressSpaceKind.Program);
        var rows = new string[24];
        for (int r = 0; r < 24; r++)
        {
            uint rowBase = Apple2HiResAddress.TextRowBase(r, page2: false);
            var sb = new System.Text.StringBuilder(40);
            for (int c = 0; c < 40; c++)
            {
                int g = bus.Read8(rowBase + (uint)c) & 0x7F;   // strip the normal-video high bit
                sb.Append(g is >= 0x20 and <= 0x7E ? (char)g : ' ');
            }
            rows[r] = sb.ToString();
        }
        return rows;
    }
}
```

> **Why this is honest, not a cover:** `A>` at the `$0400` text page can only appear after a real CP/M-3
> CONOUT, which requires the Z80 to have entered the loaded BIOS through the slot-4 handshake (the CP/M-3 RAM
> maps to physical `$1000+` via translation branch 1, never the `$0400` text page — the exact argument the
> CPM-4 reviewer confirmed for the 2.2 gate). The Z80 NOP-sliding from `$0000` (the pre-bring-up state) never
> paints `A>`, so the gate FAILS until the entry handoff is closed and PASSES only on a real boot.

## Drift / risk from ADR 0018 (flag in the PR body)

1. **The bring-up content is determined live (Task 2), not pre-designed.** ADR 0018 Decision 3 mandates this.
   The plan specifies the triage method + the ordered hypotheses + the seam each touches + the escalation
   trigger — but the exact change (likely none beyond the slot, per the CPM-4 precedent) is the Builder's live
   finding.
2. **⚠ FLAGGED RISK (ADR 0018 Decision 6 / OQ1):** if the bring-up shows apl2cpm3 needs the SoftCard to latch
   a **non-`$0000` Z80 start PC** (rather than the loader writing a `JP` stub), that touches the Z80-core reset
   path — **the Builder PAUSES and reports** (do not change Z80-core reset semantics without owner sign-off).
   Judged unlikely; flagged so it is not a silent surprise.
3. **`CpmBootCycles` raised to 20 M** (from the 2.2 gate's 10 M) because CP/M-3's loader chain is longer
   (ADR 0018 OQ4). Tune on the first green run — if the boot settles earlier, lower it; if it needs more,
   confirm the boot completes within a reasonable budget (OQ4: no new timing risk expected, CP/M-3 is still a
   coarse-timed workload at clock ratio 2.0).
4. **40-col vs 80-col staging (OQ2):** the gate asserts the CP/M-3 console on the **40-col** page. If apl2cpm3's
   BIOS goes *straight* to 80-col (the Videx) without ever painting the 40-col page, this gate's `A>` assertion
   would not find it on `$0400` — in that case the 40-col milestone collapses into the 80-col headline (V80-3)
   and this gate is re-scoped to assert the early sign-on (pre-`icrt`) the disk paints to 40-col, OR deferred
   into V80-3 with a note. The live boot decides; the gate asserts whichever the disk actually does (no
   pre-assumption — ADR 0018 Decision 4). Record the finding in the PR body.
