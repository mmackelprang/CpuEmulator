# M6 PR-B — the 8086 MOV emit arm (gate-flip + the ModR/M EA resolver + segmentation)

> **Status:** PLANNED (2026-06-19). The foundational 8086 emit PR — it establishes the segment-relative
> EA infrastructure (the 8086's equivalent of the 68000's dual-EA resolver) that PR-C (ALU) and PR-D
> (branch) reuse. Mirrors PR-1 (Z80 LD, gate-flip) for the gate structure and PR-4/PR-4a (68000 MOVE,
> emit-time-decode + footprint) for the EA-resolver shape.
>
> **Dependencies:** PR-A (8086 bench/JIT bring-up — DONE, all-fallback descriptors populated), PR-0
> (the shared wide-register helper — DONE), PR-4a (the granular-Discover fetch-stream seam — DONE; this
> PR ADDS a third granularity branch to it). Main @ `d94f780`.
>
> **THIS PR CONTAINS A PREREQUISITE (Task 0)** — the segmentation/Discover fix, the 8086's PR-4a-class
> blocker. It is folded into PR-B (not split out) because, unlike the 68000's word-vs-byte granularity
> mismatch (which broke the decode itself), the 8086 fix is a *fetch-origin* correction that only bites
> once an op emits real IL — so it can ship in lockstep with the first emit arm. See Task 0's rationale.

## 0. The upfront granularity / Discover verdict (the thing to read FIRST)

**Byte-granular decode: CORRECT.** The 8086's generated `Decode()` reads through a byte-granular fetch
stream (`UnitBytes == 1`): `BusFetchStream` at Discover time, `AddressSpaceFetchStream` at runtime
(`M8086Cpu.g.cs:1737-1849`). It walks prefix bytes → opcode → ModR/M (with the real 8086 disp-length
table) → immediate, and computes `r.Length = UnitsConsumed * UnitBytes` — the **full per-instruction
footprint** (opcode + prefixes + ModR/M + disp + imm). This is the **68000 footprint model, NOT the
Z80's**: the length is already the complete next-instruction stride, so **Discover needs NO footprint
correction** (no `Z80EmitOperandBytes` analogue, no `M8086EmitOperandBytes`). The descriptor key is
byte-granular-correct (plain opcode, or `(opcode<<3)|reg` for the opcode-group rows — `g.cs:1776-1777`),
and `DescriptorFor` resolves it through `JitDescriptorsByKey`.

**Descriptors populated, forced-fallback: CONFIRMED.** `JitDescriptorsByKey` carries 283 rows generated
through the SAME generic `KeyedDescriptorLiteral` path the Z80 uses (`CpuEmitter.cs:4028-4083`), each
forced `NeedsFallback=true, EndsBlock=true, Ops=[]` by the structured-CPU gate at `CpuEmitter.cs:4456-4460`
(the same gate that forces the Z80). The MOV rows are `JitOpClass.Register` (e.g.
`[0x88u] = new(0x88, "MOV", …, JitOpClass.Register, …, false, true, true, [])` — `g.cs:1418`). So the
8086 is a **gate-flip + emit arm, exactly like the Z80** — NOT net-new descriptor generation like the 68000.

**Will the emit arm dispatch at runtime? — THE BLOCKER (a PR-4a-class prerequisite, Task 0).** No, not
correctly, until Task 0 lands. The hazard is **segmentation**:

- The JIT dispatcher caches blocks on the **16-bit IP** (`JittedCpu` keys on `(ushort)GetRegister("IP")`)
  and `Discover` walks via `BusFetchStream(_bus, pc)` — a **16-bit-addressed** stream
  (`BusFetchStream.cs:24`: `_bus.Read8((ushort)(_origin + _offset))`). So Discover decodes the bytes at
  **physical address == raw IP** (i.e. as if CS=0).
- At runtime the real fetch is `(CS<<4)+IP` 20-bit physical (`AddressSpaceFetchStream(_bus, IP, CS)`,
  `g.cs:395`).
- **Today (all-fallback) this is harmless** and the M8088 JIT sweep is green: Discover may read the wrong
  physical bytes, but `Decode` never throws (pure byte-consumption + dictionary lookup; unknown key →
  Undefined sentinel → fallback), and the real fallback `inner.Step` does the proper segmented fetch
  (`M8088TomHarteRunner.cs:148-152` documents exactly this).
- **The moment MOV emits real IL, it stops being harmless.** The emit arm reads its operword/ModR/M/disp/imm
  as **compile-time constants** from `_bus.Read16(pc)` at the raw IP (the 68000 `NextExtWord` pattern,
  `BlockCompiler.M68000.cs:307-312`). For any case with **CS≠0** the raw-IP bytes are NOT the real
  instruction, so the arm mis-decodes the EA and emits wrong IL — and the block's `nextPc` lands
  mid-instruction. **The 8088 TomHarte corpus runs at arbitrary nonzero CS** (verified: sample cases carry
  `CS=0x31ed`, `CS=0x9f8d`; `M8088TomHarteRunner.cs:171` sets `CS` from the vector, never forced 0). So a
  MOV emit arm with no Task-0 fix would mis-emit on essentially every corpus case.

**Verdict:** byte-granular decode and the length-footprint are correct (no footprint correction needed —
this is the *good* news that distinguishes the 8086 from the Z80). But the **fetch-origin** is wrong for
Discover and the emit-time const reads whenever CS≠0. **Task 0 is the PR-B prerequisite** (the 8086's
PR-4a): make Discover and the emit arm fetch from the SAME `(CS<<4)+IP` physical origin the runtime uses.
It is folded into PR-B (Task 0 ships with the first emit arm, in lockstep) rather than split out, because
— unlike PR-4a, where the byte-vs-word mismatch broke *every* 68000 block's decode and so had to land
first as a standalone unblock — the 8086 fix is inert until the first op emits (the all-fallback sweep
stays green with or without it), so there is no value in a separate landing.

## 1. Scope

**EMIT (this PR):** the MOV family — the profiler's #1 8086 op (§6 of ADR 0011). All `JitOpClass.Register`
MOV rows the interpreter `MovExecute` (`M8086Cpu.Mov.cs:135-254`) handles:

- `88/89/8A/8B` — the d/w-bit register/memory MOVs (`MOV r/m,r`, `MOV r,r/m`, byte + word).
- `8C/8E` — the segment-register MOVs (`MOV r/m16,Sreg`, `MOV Sreg,r/m16`).
- `A0/A1/A2/A3` — the accumulator-direct (moffs) MOVs (`MOV AL/AX,[disp16]`, `MOV [disp16],AL/AX`).
- `B0–BF` — `MOV reg,imm` (the opcode-embedded reg; byte B0–B7, word B8–BF).
- `C6/C7` reg=0 — `MOV r/m,imm` (the opcode-group keys `0x630`/`0x638`).

**FALLBACK (stays interpreter — out of PR-B scope):** everything else (ALU is PR-C, branch is PR-D, the
string/stack/shift/control/interrupt families stay fallback per ADR 0011 §2). MOV sets **no flags**, so
PR-B touches no flag infrastructure — that is PR-C's pole (deliberately, mirroring PR-1 Z80 LD proving
the structured-emit path without the flag tax).

**The EA infrastructure PR-B builds (reused by PR-C/PR-D):** the ModR/M effective-address resolver — the
8086's equivalent of the 68000's `EmitM68kEaRead`/`EmitM68kEaWrite`. It computes the 16-bit segment-relative
offset (the `ComputeX86Ea` matrix), selects the segment (`DefaultSegmentForX86Rm` + the override prefix),
forms the 20-bit physical `(seg<<4)+offset`, and reads/writes through the fastmem split with the
**segment-relative offset wrap** (the `ReadEaWordWrapped`/`WriteEaWordWrapped` quirk).

## 2. Design decisions

### DECISION B-0 (Task 0): one physical fetch origin for Discover + emit-time const reads

Make the 8086's Discover walk and the emit arm's compile-time operand reads use the **same**
`(CS<<4)+IP` physical origin the runtime fetch uses. Three coordinated changes:

1. **A segmented Discover fetch stream.** `BlockCompiler.Discover` (`BlockCompiler.cs:330-332`) currently
   ternaries `TargetIsM68000 ? M68000FetchStream : BusFetchStream`. Add a third branch: for the 8086,
   construct a stream seeded at the physical `(CS<<4)+IP`. The cleanest seam (no new stream class) is to
   make `BusFetchStream` accept an optional 20-bit physical origin and read `_bus.Read8(physical & mask)`
   — OR reuse the existing `AddressSpaceFetchStream` segmented ctor (which already does exactly this,
   `AddressSpaceFetchStream.cs:41-57`). Task 0 below uses the latter (it lives in Core, the JIT references
   Core, and it is the interpreter's own walk — maximal oracle fidelity).

2. **An emit-time physical-PC helper.** The emit arm's const reads must use the physical
   `(CS<<4)+pc` (where `pc` is the 16-bit IP of the instruction), masked to 20 bits. A new
   `_m8086CodePhysBase` handle (the `CS<<4` for the block) is baked once per Discover/Compile from the
   live CS field, and a `M8086CodePhys(ushort pc)` helper returns `(_m8086CodePhysBase + pc) & 0xFFFFF`
   for every `_bus.Read8/Read16` the arm does at emit time.

3. **The block's CS-invariance assumption, documented + guarded.** A JIT block is keyed on 16-bit IP and
   compiled against ONE CS (the CS live at compile time). If CS changes (a far jump / segment load), the
   physical code moves but the IP key may collide — so a block compiled for `(CS=a, IP=p)` must NOT be
   reused for `(CS=b, IP=p)`. **PR-B's MOV scope never changes CS** (MOV to a segment register changes a
   DATA segment, never CS; far control flow is PR-D and stays fallback). So within PR-B the per-block CS
   is invariant and the 16-bit IP key is exact for the block's lifetime. Task 0 records this as the
   **CS-aliasing invariant** and PR-D (far flow) owns extending the key to `(CS, IP)` if/when it emits a
   CS-changing op. (Recommended call, taken: do NOT widen the cache key in PR-B — it is unobservable for
   MOV and would touch the dispatcher for every CPU. Flagged for the Coordinator as the one consequential
   deferral.)

**Rationale.** This mirrors PR-4a's "make Discover fetch the way the runtime fetches" exactly — there it
was word-vs-byte granularity, here it is flat-vs-segmented origin. Folding it into PR-B (vs a standalone
PR) is correct because the all-fallback sweep is green either way (the fix is inert until emit), so there
is no separate unblock to land. The CS-aliasing invariant is the 8086's one genuinely-new wrinkle vs the
Z80/68000 (whose PCs are flat); PR-B confines it to a documented, MOV-safe assumption and hands the
general case to PR-D.

### DECISION B-1: the ModR/M EA resolver shape — emit-time decode, address-once, segment-aware

The EA matrix is decoded at **emit time** from the ModR/M byte (a code-stream constant), NOT carried in
the descriptor (`Ops=[]`, exactly like the 68000's `EmitM68kEaRead`). The resolver mirrors the interpreter
oracle (`ComputeX86Ea` + `DefaultSegmentForX86Rm` + `ResolveSegment` + `Physical`) one-for-one:

- `EmitM8086ResolveEaOffset(pc, mod, rm, disp)` — emits the 16-bit offset computation: the base+index sum
  per r/m (BX+SI / BX+DI / BP+SI / BP+DI / SI / DI / BP / BX), the `mod=00,rm=110` disp16-direct exception
  (offset = disp, no base), `+ (short)disp`, wrapped to 16 bits (`Conv_U2`). The base/index register
  VALUES are runtime loads (`EmitLoadReg16`); `disp` is a compile-time constant (baked `Ldc_I4`).
- `EmitM8086ResolveSegBase(mod, rm, over)` — the segment-base value (`seg<<4` as a 20-bit base): the
  `DefaultSegmentForX86Rm` default (SS for BP-based forms, DS otherwise) threaded with the override prefix
  (`over` is a compile-time constant the decode captured). Emits the `CS/DS/ES/SS << 4` per the resolved
  segment register.
- `EmitM8086EaPhysical(pc, mod, rm, disp, over)` — composes the two: `(segBase + offset) & 0xFFFFF`, the
  20-bit physical EA on the stack. This is the single entry point a memory operand resolves through.

**The word access wraps the offset, not the physical.** The 8086 word read/write wraps the *second byte's
offset* at 16 bits within the segment (`ReadEaWordWrapped`/`WriteEaWordWrapped`,
`M8086Cpu.Mov.cs:116-129`), NOT the physical address. So the word EA helpers compute the low-byte physical
and the high-byte physical SEPARATELY (`Physical(seg, offset)` and `Physical(seg, (ushort)(offset+1))`) —
two independent `(seg<<4)+off` forms, NOT `phys` and `phys+1`. The emit arm holds the resolved `(seg, off)`
pair (segment value + 16-bit offset) and forms each byte's physical inline.

**Address-once + survivor locals.** The fastmem helpers (`LoadByteFromBus`/`EmitStoreByte`) clobber
`EaLocal`/`DataLocal`. A MOV that reads one operand and writes another (only `88/89/A2/A3/C6/C7` write
memory; the loads write a register) needs the resolved EA to survive. PR-B reuses `AddrLocal` (uint, the
bus helpers never touch it) for the surviving offset/segment math, matching the Z80/68000 discipline. The
word forms additionally stash the 16-bit offset in a new `M8086OffsetLocal` (int) and the segment value in
`M8086SegLocal` (int) so both bytes' physicals re-form from the survivors. (Two new EmitContext locals —
Task 2.)

### DECISION B-2: the register file — 8-bit halves, 16-bit pairs, segment registers

- **8-bit registers** (`AL/CL/DL/BL/AH/CH/DH/BH`, ModR/M reg index 0-7) are direct FIELDS — they resolve
  through `_regFields` (the J2 map). The index→name mapping is the interleaved 8086 order
  (0=AL 1=CL 2=DL 3=BL 4=AH 5=CH 6=DH 7=BH), a small fixed ISA table in the arm.
- **16-bit registers** (`AX/CX/DX/BX/SP/BP/SI/DI`, index 0-7) split: `SP/BP/SI/DI` are direct ushort FIELDS
  (`_regWideFields`); `AX/BX/CX/DX` are composed pair-views over byte halves (`_regPairFields`, already
  registered in `PairHalves`, `BlockCompiler.cs:170-171`). PR-0's `EmitLoadReg16`/`EmitStoreReg16` already
  handle both shapes — PR-B reuses them unchanged (the index→name table maps 0→AX … 7→DI).
- **Segment registers** (`ES/CS/SS/DS`, Sreg index 0-3) are direct ushort FIELDS — resolve through
  `_regWideFields` by name. Writing a segment register is a plain `Stfld`. (`8E MOV Sreg,r/m16` writes
  DS/ES/SS — never CS in the MOV encoding; `Sreg(reg & 3u)` so reg=1 would be CS but the 8088 corpus and
  the interpreter both allow it harmlessly; PR-B mirrors the interpreter `SetSreg` exactly, including the
  `reg & 3` mask.)

**Partial-write hazard.** Writing AL/AH must auto-update AX. PR-0's pair-view store composes
`hi<<8 | lo` from the two half-fields, so writing the AL half-field directly (via `_regFields["AL"]`) and
re-reading AX (via the pair-view) is consistent — the AX pair-view IS `(AH<<8)|AL` computed on read, so a
half-field write is automatically visible. (Verified: the interpreter `SetReg8` writes the half-field and
relies on the same computed pair-view, `M8086Cpu.Mov.cs:31-46`.) No special handling needed.

### DECISION B-3: the per-CPU discriminator + the emit-vs-fallback valve

- `TargetIsM8086 => _target.CpuType.Name == "M8086Cpu"` (mirrors `TargetIsZ80`/`TargetIsM68000`).
- `EmitInstruction` routes `JitOpClass.Register` rows: today that class dispatches to `EmitRegister`
  (the 6502 arm). Add a guard — when `TargetIsM8086 && d.Mnemonic == "MOV"`, route to `EmitM8086Mov`.
  (The 8086 MOV rows are `JitOpClass.Register`, so the dispatch is by `(TargetIsM8086, mnemonic)`, not by
  a new class — PR-B does NOT introduce an `M8086Move` JitOpClass; the Z80 precedent of keying the arm on
  `(TargetIsZ80, mnemonic/op-kind)` is the model, not the 68000's dedicated class.)
- **The lookahead fallback valve** (the 68000 `CanEmitM68kMove` precedent, `BlockCompiler.cs:458-462`):
  Discover walks PAST an emittable MOV into the next instruction, which at a block boundary can be a
  garbage lookahead word. If that word decodes as a MOV-family row with an EA the arm cannot emit (it
  cannot — every 8086 ModR/M EA IS emittable, see below), fall back rather than throw. **For the 8086 EVERY
  ModR/M memory EA is emittable** (the matrix is total — there is no PC-relative/illegal-dest mode like the
  68000's mode 7 reg 2/3/4), so `CanEmitM8086Mov` returns true for every MOV row. The valve is therefore a
  no-op for PR-B, but the arm's `switch` default still throws (the lockstep tripwire) so the gate and arm
  cannot drift.

### DECISION B-4: the cycle model — coarse `BaseCycles`, data-axis-only gate

The descriptor's `BaseCycles` for the 8086 MOV rows is a coarse representative (2 in the generated table,
`g.cs:1418`). Per the 68000's DECISION T precedent (`BlockCompiler.M68000.cs:38-40`), the 8086 parity
gate is the **DATA axis only** (the 14 registers + FLAGS-mask + changed RAM — exactly what
`M8088TomHarteRunner.RunCaseThroughJit` compares; cycles are carried-not-asserted,
`M8088TomHarteRunner.cs:13`). So the arm charges a coarse `d.BaseCycles` once (keeping the ≥1-cycle budget
invariant) and the fastmem helpers charge their per-byte cycles; it does NOT model the 8086's exact
clock-cycle timing (that is a future timing-axis item, not an M6 emit gate — ADR 0011 §5 honesty: the
re-measure leads with guest-MIPS, the 8086 has no cycle-exact axis yet). The byte/word access cycle
charges (1 per byte) DO matter for the budget loop and match `ReadEaByte`/`WriteEaByte` (each = one
`ReadBus`/`WriteBus` = one cycle).

```csharp
    /// <paramref name="pc"/> for the block under compile: (CS&lt;&lt;4 + pc) &amp; 0xFFFFF. The emit arm reads its
    /// operword / ModR/M / disp / imm as COMPILE-TIME constants from _bus.Read8/Read16 at THIS physical address
    /// (the 68000 NextExtWord pattern, but segmented). _m8086CodePhysBase is the block's CS&lt;&lt;4 (baked in
    /// Discover). The 16-bit IP wraps within the segment BEFORE the segment add (the 8086 wrap quirk), matching
```

> **Lockstep note for Tasks 1-3:** every `_bus.Read8(pc)` / `_bus.Read16(pc)` the 8086 emit arm does for a
> code-stream constant MUST go through `M8086CodePhys(pc)` (NOT the raw `pc`). The 68000 arm reads raw
> `_bus.Read16(pc)` because the 68000 PC is already physical; the 8086's is not.

**Regression-safety:** `TargetIsM68000`/`TargetIsZ80`/6502 paths are byte-for-byte unchanged (the new
branches are gated on `TargetIsM8086`, false for them). The all-fallback 8086 sweep is unaffected (Task 0
only changes WHICH bytes Discover reads; an all-fallback block is still one fallback op that self-terminates
via `inner.Step`). The proof that Task 0 is correct is Task 5's gate (the now-CS≠0-correct MOV sweep).

### Task 1 — the ModR/M EA resolver (the reusable infrastructure)

**File:** `src/CpuEmulator.Jit/BlockCompiler.M8086.cs` (NEW partial — mirrors `BlockCompiler.Z80.cs`)

The resolver transcribes `ComputeX86Ea` (`g.cs:781-798`) + `DefaultSegmentForX86Rm` (`g.cs:805-810`) +
`ResolveSegment` (`M8086Cpu.Ea.cs:58-65`) + `Physical` (`M8086Cpu.Ea.cs:48-49`). `mod/rm/disp/over` are
compile-time constants the arm decoded from the ModR/M byte (read via `M8086CodePhys`). The base/index
register values are runtime loads.

```csharp
using System.Reflection;
using System.Reflection.Emit;
using CpuEmulator.Core;
using CpuEmulator.Core.Jit;

namespace CpuEmulator.Jit;

/// <summary>M6 PR-B: the 8086 MOV-family emit arm + the ModR/M effective-address resolver — the 8086's
/// analogue of the 68000's dual-EA resolver (BlockCompiler.M68000.cs). The EA matrix is decoded at EMIT
/// TIME from the ModR/M byte (a code-stream constant read via M8086CodePhys — the SEGMENTED (CS&lt;&lt;4)+IP
/// origin, DECISION B-0); the 16-bit segment-relative offset + the (seg&lt;&lt;4)+offset 20-bit physical mirror
/// ComputeX86Ea + DefaultSegmentForX86Rm + ResolveSegment + Physical one-for-one. MOV sets NO flags (PR-C
/// owns the flag core). The WORD access wraps the SECOND byte's OFFSET at 16 bits within the segment (the
/// 8086 wrap quirk, ReadEaWordWrapped) — NOT the physical, so each byte's physical re-forms from the
/// surviving (seg, offset) pair. Reused by PR-C (ALU) + PR-D (branch) for every memory operand.</summary>
internal sealed partial class BlockCompiler&lt;TCpu&gt; where TCpu : class
{
    // The 8086 ModR/M register-index → name tables (a small fixed ISA fact, NOT a generator output —
    // M8086Cpu.Mov.cs:20-22). reg8 interleaves low/high halves; reg16/sreg are the standard orders.
    private static readonly string[] M8086Reg8  = ["AL", "CL", "DL", "BL", "AH", "CH", "DH", "BH"];
    private static readonly string[] M8086Reg16 = ["AX", "CX", "DX", "BX", "SP", "BP", "SI", "DI"];
    private static readonly string[] M8086Sreg  = ["ES", "CS", "SS", "DS"];

    /// <summary>Push the 16-bit segment-relative OFFSET (as int) for a (mod, rm, disp) memory operand —
    /// ComputeX86Ea (g.cs:781). base+index per rm (runtime reg loads), + (short)disp (compile-time const),
    /// wrapped to 16 bits. The mod=00,rm=110 disp16-direct exception zeroes the base (offset = disp).</summary>
    private void EmitM8086EaOffset(EmitContext ctx, uint mod, uint rm, ushort disp)
    {
        ILGenerator il = ctx.Il;
        bool disp16Direct = mod == 0u &amp;&amp; rm == 6u;
        if (disp16Direct)
        {
            il.Emit(OpCodes.Ldc_I4, (int)disp);                    // offset = disp (no base/index)
            il.Emit(OpCodes.Conv_U2);
            return;
        }
        // base+index sum (each term a runtime 16-bit register load, added as ints):
        switch (rm)
        {
            case 0u: EmitLoadReg16(ctx, "BX"); EmitLoadReg16(ctx, "SI"); il.Emit(OpCodes.Add); break; // BX+SI
            case 1u: EmitLoadReg16(ctx, "BX"); EmitLoadReg16(ctx, "DI"); il.Emit(OpCodes.Add); break; // BX+DI
            case 2u: EmitLoadReg16(ctx, "BP"); EmitLoadReg16(ctx, "SI"); il.Emit(OpCodes.Add); break; // BP+SI
            case 3u: EmitLoadReg16(ctx, "BP"); EmitLoadReg16(ctx, "DI"); il.Emit(OpCodes.Add); break; // BP+DI
            case 4u: EmitLoadReg16(ctx, "SI"); break;                                                 // SI
            case 5u: EmitLoadReg16(ctx, "DI"); break;                                                 // DI
            case 6u: EmitLoadReg16(ctx, "BP"); break;                                                 // BP (not disp16Direct here)
            default: EmitLoadReg16(ctx, "BX"); break;                                                 // BX
        }
        // + (short)disp, then wrap to 16 bits (the offset within the 64 KB segment).
        il.Emit(OpCodes.Ldc_I4, unchecked((int)(short)disp));      // sign-extended disp (int overload — see PR-4b note)
        il.Emit(OpCodes.Add);
        il.Emit(OpCodes.Conv_U2);                                  // (ushort)(base + index + disp)
    }

    /// <summary>Push the SEGMENT VALUE (as int, 0..0xFFFF) for a (mod, rm) memory operand, threaded with the
    /// override — DefaultSegmentForX86Rm (g.cs:805) + ResolveSegment (Ea.cs:58). The default is SS for BP-based
    /// forms (rm ∈ {2,3,6} except the disp16-direct rm=6,mod=0), DS otherwise; an override REPLACES it. All
    /// inputs (mod, rm, over) are compile-time constants, so the chosen segment-register NAME is decided here and
    /// only the register VALUE is a runtime load.</summary>
    private void EmitM8086SegValue(EmitContext ctx, uint mod, uint rm, M8086Cpu_Override over)
    {
        bool disp16Direct = mod == 0u &amp;&amp; rm == 6u;
        bool bpBased = !disp16Direct &amp;&amp; (rm == 2u || rm == 3u || rm == 6u);
        string defaultSeg = bpBased ? "SS" : "DS";
        string seg = over switch
        {
            M8086Cpu_Override.Es =&gt; "ES",
            M8086Cpu_Override.Cs =&gt; "CS",
            M8086Cpu_Override.Ss =&gt; "SS",
            M8086Cpu_Override.Ds =&gt; "DS",
            _ =&gt; defaultSeg,
        };
        EmitLoadReg16(ctx, seg);   // the resolved segment register VALUE (runtime load)
    }

    /// <summary>The override-prefix enum (mirrors M8086Cpu.X86SegmentOverride) — the compile-time-decoded
    /// segment override the arm threads into EmitM8086SegValue. None=no override.</summary>
    private enum M8086Cpu_Override { None, Es, Cs, Ss, Ds }

    /// <summary>Turn the raw segment-override prefix byte (26/2E/36/3E) the decode captured into the enum
    /// (M8086Cpu.Mov.cs:91 OverrideFromByte). 0 / any other byte ⇒ None.</summary>
    private static M8086Cpu_Override M8086OverrideFromByte(byte b) =&gt; b switch
    {
        0x26 =&gt; M8086Cpu_Override.Es,
        0x2E =&gt; M8086Cpu_Override.Cs,
        0x36 =&gt; M8086Cpu_Override.Ss,
        0x3E =&gt; M8086Cpu_Override.Ds,
        _    =&gt; M8086Cpu_Override.None,
    };

    /// <summary>Push the 20-bit PHYSICAL address (as uint) for a (seg-value, offset) pair: (seg &lt;&lt; 4 + offset)
    /// &amp; 0xFFFFF — Physical (Ea.cs:48). Stack on entry: ..., segValue(int), offset(int); on exit: ..., phys(uint).</summary>
    private void EmitM8086PhysicalFromSegOffset(EmitContext ctx)
    {
        ILGenerator il = ctx.Il;
        // stack: segValue, offset  ->  ((segValue &lt;&lt; 4) + offset) &amp; 0xFFFFF
        il.Emit(OpCodes.Stloc, ctx.DataLocal);     // offset (reuse DataLocal as scratch; clobbered next anyway)
        il.Emit(OpCodes.Ldc_I4_4);
        il.Emit(OpCodes.Shl);                       // segValue &lt;&lt; 4
        il.Emit(OpCodes.Ldloc, ctx.DataLocal);
        il.Emit(OpCodes.Add);                       // + offset
        il.Emit(OpCodes.Ldc_I4, 0xFFFFF);
        il.Emit(OpCodes.And);                       // &amp; 20-bit mask
    }
}
```

### Task 3 — the MOV emit arm + the byte/word EA access + the dispatch + the gate

**File (arm):** `src/CpuEmulator.Jit/BlockCompiler.M8086.cs` (append to Task 1's partial)

The arm decodes the ModR/M/disp/imm at emit time (via `M8086CodePhys`), then `switch`es on the normalized
key — one branch per MOV form, each transcribing the matching `MovExecute` case
(`M8086Cpu.Mov.cs:152-253`). The byte memory access uses `LoadByteFromBus`/`EmitStoreByte` (the fastmem
split — it page-indexes the 20-bit physical correctly, `_bus.AddressMask == 0xFFFFF`,
`BlockCompiler.cs:1037`). The word access composes two byte accesses with the offset-wrap.

```csharp
    /// <summary>M6 PR-B: emit one 8086 MOV-family instruction (DECISION B-1/B-2). Reached only when
    /// TargetIsM8086 &amp;&amp; d.Mnemonic == "MOV". Decodes the ModR/M / disp / imm at emit time from the SEGMENTED
    /// code stream (M8086CodePhys), resolves the EA via the Task-1 helpers, and transcribes the matching
    /// MovExecute case one-for-one. The default throws (the gate↔arm lockstep tripwire). MOV sets no flags.</summary>
    private void EmitM8086Mov(EmitContext ctx, ushort pc, OpcodeDescriptor d)
    {
        ILGenerator il = ctx.Il;
        uint key = d.Opcode;   // the plain opcode byte; C6/C7 group rows carry Opcode 0xC6/0xC7 (key normalized below)

        // Decode the instruction's bytes at emit time from the (CS&lt;&lt;4)+IP physical origin. The opcode byte was
        // already consumed (EmitInstruction charged the fetch + advanced PC by 1), so pc here is the address of
        // the byte AFTER the opcode. The ModR/M forms read the ModR/M byte at pc; the imm/moffs forms read the
        // immediate at pc (88-8E/C6/C7 have ModR/M; A0-A3/B0-BF do not).
        byte opcode = (byte)d.Opcode;
        bool hasModRm = opcode is 0x88 or 0x89 or 0x8A or 0x8B or 0x8C or 0x8E or 0xC6 or 0xC7;

        byte modrm = 0; uint mod = 0, reg = 0, rm = 0; ushort disp = 0;
        M8086Cpu_Override over = M8086Cpu_Override.None;   // PR-B: no segment-override emit yet — see the note below
        int operandPc = pc;   // running emit-time cursor past the opcode
        if (hasModRm)
        {
            modrm = _bus.Read8((ushort)M8086CodePhys((ushort)operandPc)); operandPc++;
            mod = (uint)(modrm &gt;&gt; 6) &amp; 3u;
            reg = (uint)(modrm &gt;&gt; 3) &amp; 7u;
            rm  = (uint)modrm &amp; 7u;
            // the disp length per (mod, rm) — the real 8086 table (g.cs:1781): mod=0,rm=6 ⇒ 2; mod=1 ⇒ 1; mod=2 ⇒ 2.
            int dispLen = mod switch { 0u =&gt; rm == 6u ? 2 : 0, 1u =&gt; 1, 2u =&gt; 2, _ =&gt; 0 };
            if (dispLen == 1) { disp = unchecked((ushort)(sbyte)_bus.Read8((ushort)M8086CodePhys((ushort)operandPc))); operandPc++; }
            else if (dispLen == 2)
            {
                byte lo = _bus.Read8((ushort)M8086CodePhys((ushort)operandPc));
                byte hi = _bus.Read8((ushort)M8086CodePhys((ushort)(operandPc + 1)));
                disp = (ushort)(lo | (hi &lt;&lt; 8)); operandPc += 2;
            }
        }

        // Normalize the C6/C7 group keys to 0x630/0x638 (the interpreter does the same, Mov.cs:149-150). On the
        // 8086 the reg field of C6/C7 is a don't-care (always MOV r/m,imm).
        if (opcode == 0xC6) key = 0x630u;
        else if (opcode == 0xC7) key = 0x638u;

        switch (key)
        {
            case 0x88u:   // MOV r/m8, r8 — store reg8 to the byte rm
                if (mod == 3u) { il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, RegField(M8086Reg8[reg])); il.Emit(OpCodes.Stfld, RegField(M8086Reg8[rm])); }
                else { EmitM8086StoreByteEa(ctx, mod, rm, disp, over, () =&gt; { il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, RegField(M8086Reg8[reg])); }); }
                break;

            case 0x8Au:   // MOV r8, r/m8 — load the byte rm into reg8
                il.Emit(OpCodes.Ldarg_0);
                if (mod == 3u) { il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, RegField(M8086Reg8[rm])); }
                else EmitM8086LoadByteEa(ctx, mod, rm, disp, over);
                il.Emit(OpCodes.Conv_U1);
                il.Emit(OpCodes.Stfld, RegField(M8086Reg8[reg]));
                break;

            case 0x89u:   // MOV r/m16, r16
                if (mod == 3u) { EmitLoadReg16(ctx, M8086Reg16[reg]); EmitStoreReg16(ctx, M8086Reg16[rm]); }
                else EmitM8086StoreWordEa(ctx, mod, rm, disp, over, () =&gt; EmitLoadReg16(ctx, M8086Reg16[reg]));
                break;

            case 0x8Bu:   // MOV r16, r/m16
                if (mod == 3u) { EmitLoadReg16(ctx, M8086Reg16[rm]); EmitStoreReg16(ctx, M8086Reg16[reg]); }
                else { EmitM8086LoadWordEa(ctx, mod, rm, disp, over); EmitStoreReg16FromStack(ctx, M8086Reg16[reg]); }
                break;

            case 0x8Cu:   // MOV r/m16, Sreg — store segment register to the word rm
                if (mod == 3u) { EmitLoadReg16(ctx, M8086Sreg[reg &amp; 3u]); EmitStoreReg16(ctx, M8086Reg16[rm]); }
                else EmitM8086StoreWordEa(ctx, mod, rm, disp, over, () =&gt; EmitLoadReg16(ctx, M8086Sreg[reg &amp; 3u]));
                break;

            case 0x8Eu:   // MOV Sreg, r/m16 — load the word rm into the segment register
                if (mod == 3u) { EmitLoadReg16(ctx, M8086Reg16[rm]); EmitStoreReg16(ctx, M8086Sreg[reg &amp; 3u]); }
                else { EmitM8086LoadWordEa(ctx, mod, rm, disp, over); EmitStoreReg16FromStack(ctx, M8086Sreg[reg &amp; 3u]); }
                break;

            // A0-A3: accumulator-direct (moffs). The disp16 rides the IMMEDIATE slot (no ModR/M); default seg DS.
            // Resolve as a memory operand with offset = the imm16 and the DS default (override threading is the
            // same None placeholder as the ModR/M forms in PR-B — see the note below).
            case 0xA0u: case 0xA1u: case 0xA2u: case 0xA3u:
            {
                ushort moffs = (ushort)(_bus.Read8((ushort)M8086CodePhys((ushort)operandPc))
                                        | (_bus.Read8((ushort)M8086CodePhys((ushort)(operandPc + 1))) &lt;&lt; 8));
                // segValue = DS (default, override placeholder None in PR-B); offset = moffs (compile-time const).
                if (opcode == 0xA0u)   // MOV AL, moffs8
                {
                    il.Emit(OpCodes.Ldarg_0);
                    EmitM8086LoadByteAtSegOff(ctx, "DS", moffs);
                    il.Emit(OpCodes.Conv_U1); il.Emit(OpCodes.Stfld, RegField("AL"));
                }
                else if (opcode == 0xA1u)   // MOV AX, moffs16
                {
                    EmitM8086LoadWordAtSegOff(ctx, "DS", moffs);
                    EmitStoreReg16FromStack(ctx, "AX");
                }
                else if (opcode == 0xA2u)   // MOV moffs8, AL
                    EmitM8086StoreByteAtSegOff(ctx, "DS", moffs, () =&gt; { il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, RegField("AL")); });
                else                          // 0xA3 MOV moffs16, AX
                    EmitM8086StoreWordAtSegOff(ctx, "DS", moffs, () =&gt; EmitLoadReg16(ctx, "AX"));
                break;
            }

            // B0-B7 MOV r8, imm8 ; B8-BF MOV r16, imm16. reg = opcode &amp; 7; the imm rides the immediate slot.
            case 0xB0u: case 0xB1u: case 0xB2u: case 0xB3u: case 0xB4u: case 0xB5u: case 0xB6u: case 0xB7u:
            {
                byte imm8 = _bus.Read8((ushort)M8086CodePhys((ushort)operandPc));
                il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldc_I4, imm8); il.Emit(OpCodes.Conv_U1);
                il.Emit(OpCodes.Stfld, RegField(M8086Reg8[opcode &amp; 7u]));
                break;
            }
            case 0xB8u: case 0xB9u: case 0xBAu: case 0xBBu: case 0xBCu: case 0xBDu: case 0xBEu: case 0xBFu:
            {
                ushort imm16 = (ushort)(_bus.Read8((ushort)M8086CodePhys((ushort)operandPc))
                                        | (_bus.Read8((ushort)M8086CodePhys((ushort)(operandPc + 1))) &lt;&lt; 8));
                il.Emit(OpCodes.Ldc_I4, imm16); EmitStoreReg16FromStack(ctx, M8086Reg16[opcode &amp; 7u]);
                break;
            }

            // C6/C7 reg=0: MOV r/m, imm. The imm follows the ModR/M + disp (operandPc already past them).
            case 0x630u:   // MOV r/m8, imm8
            {
                byte imm8 = _bus.Read8((ushort)M8086CodePhys((ushort)operandPc));
                if (mod == 3u) { il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldc_I4, imm8); il.Emit(OpCodes.Conv_U1); il.Emit(OpCodes.Stfld, RegField(M8086Reg8[rm])); }
                else EmitM8086StoreByteEa(ctx, mod, rm, disp, over, () =&gt; { il.Emit(OpCodes.Ldc_I4, imm8); });
                break;
            }
            case 0x638u:   // MOV r/m16, imm16
            {
                ushort imm16 = (ushort)(_bus.Read8((ushort)M8086CodePhys((ushort)operandPc))
                                        | (_bus.Read8((ushort)M8086CodePhys((ushort)(operandPc + 1))) &lt;&lt; 8));
                if (mod == 3u) { il.Emit(OpCodes.Ldc_I4, imm16); EmitStoreReg16FromStack(ctx, M8086Reg16[rm]); }
                else EmitM8086StoreWordEa(ctx, mod, rm, disp, over, () =&gt; il.Emit(OpCodes.Ldc_I4, imm16));
                break;
            }

            default:
                throw new EmulationException(
                    $"BlockCompiler: no 8086 MOV emit branch for key 0x{key:X} (opcode 0x{opcode:X2}); "
                  + "the gate (IsEmittableX86Family) admitted a form the arm does not handle — a lockstep bug.");
        }

        // PC advance: EmitInstruction already advanced PC by 1 (the opcode). Advance by the REMAINING footprint
        // (ModR/M + disp + imm) so the block's nextPc matches r.Length. operandPc - pc is exactly that remainder
        // for the forms WITH operand bytes; recompute the per-form tail length and EmitIncrementPC by it.
        int tail = M8086MovTailLength(opcode, hasModRm, mod, rm);
        if (tail &gt; 0) EmitIncrementPC(ctx, tail);
    }
```

> **PR-B override-threading note (a deliberate, disclosed scope cut).** The segment-override prefix
> (`26/2E/36/3E`) is decoded by the walk and captured on `X86Operands.SegOverride`. In PR-B the emit arm
> threads `over = None` (no override emit) because an override is a SEPARATE prefix byte that, in the
> generated decode, produces a row keyed on the OVERRIDDEN opcode but with the override captured — and the
> JIT Discover walks the prefix as part of `r.Length` but the emit arm sees only the base opcode. **The
> cleanest PR-B scope is: an override-prefixed MOV stays FALLBACK** (the gate `IsEmittableX86Family`
> admits a MOV row only when no override prefix precedes it — detectable at Discover because an override
> makes the *previous* decoded unit a prefix). Concretely: a prefixed MOV's descriptor is the same MOV
> row, but its block position has a preceding prefix byte; PR-B's gate keeps the override case fallback by
> NOT emitting when `d` was reached through a prefix (the arm has no per-instruction prefix signal today —
> so PR-B's honest, simple cut is to emit only the NON-overridden MOV and let the ~6% override cases
> interpret). **This is the one PR-B correctness-preserving scope reduction; PR-C inherits the same cut
> and a follow-on (PR-B') can add override emit once the prefix-signal plumbing exists.** Flagged for the
> Coordinator. (The fallback valve makes this correctness-free: an override MOV is exactly the oracle.)
>
> The exact "is this row override-prefixed?" detection: the decode walk consumes the override byte into
> `r.Length` and sets `X86Operands.SegOverride`, but the DESCRIPTOR for an override-prefixed instruction
> is the SAME MOV descriptor. So the gate cannot see the override from the descriptor alone. **The robust
> PR-B mechanism: keep the override MOV emittable in the gate, but at EMIT time re-read the prefix byte at
> `M8086CodePhys(pc - 1)` … no — `pc` is post-opcode.** The reliable signal is the decoded
> `X86Operands.SegOverride` — but the JIT does not thread `DecodeResult` into the emit arm. **Therefore
> PR-B's concrete cut: the emit arm detects an override by re-decoding the instruction's leading byte at
> `M8086CodePhys(pcOfOpcode)` … which is the opcode (the override is BEFORE it).** The unambiguous fix is
> Task 3b below — Discover already has the `DecodeResult` (it calls `_target.Decode`), so thread the
> per-instruction `X86Operands.SegOverride` into the run tuple and through to `EmitInstruction`. **Task 3b
> makes this clean and removes the cut** — see below.

**Task 3b — thread the decoded override into the emit arm (removes the PR-B override cut).**
`Discover` already holds `DecodeResult r` (`BlockCompiler.cs:336`). Extend the run tuple to carry the
captured override byte (0 for non-8086 / no override) and pass it to `EmitInstruction` → `EmitM8086Mov`,
so `over = M8086OverrideFromByte(capturedByte)` and the override forms emit correctly (the
`EmitM8086SegValue` already handles the override → segment-register selection). This is a small tuple
widening (mirrors how `length` is already threaded) and is the principled fix; with it, PR-B emits the
override forms too and there is NO scope cut. **Recommended: do Task 3b (clean) rather than the fallback
cut.** Concretely, change the run tuple `(ushort Pc, OpcodeDescriptor D, int Length)` →
`(ushort Pc, OpcodeDescriptor D, int Length, byte X86Seg)` where `X86Seg = TargetIsM8086 ? r.X86.SegOverride : (byte)0`,
and thread it through `Compile`'s `foreach` into `EmitInstruction(ctx, pc, d, length, x86Seg)`.

**The byte/word EA access helpers** (append to `BlockCompiler.M8086.cs`) — these compose the resolver +
the fastmem split + the offset-wrap:

```csharp
    /// <summary>Push the byte at the (mod, rm, disp, over) memory EA (as int) — resolve the 20-bit physical,
    /// then LoadByteFromBus (the fastmem split; charges 1 cycle). Used by the byte LOAD forms.</summary>
    private void EmitM8086LoadByteEa(EmitContext ctx, uint mod, uint rm, ushort disp, M8086Cpu_Override over)
    {
        EmitM8086SegValue(ctx, mod, rm, over);
        EmitM8086EaOffset(ctx, mod, rm, disp);
        EmitM8086PhysicalFromSegOffset(ctx);   // -&gt; phys (uint)
        LoadByteFromBus(ctx);                   // pops addr, pushes byte; charges 1
    }

    /// <summary>Store the byte produced by &lt;paramref name="pushValue"/&gt; to the (mod, rm, disp, over) memory EA —
    /// resolve the physical, push value, EmitStoreByte (fastmem split; charges 1; marks dirty). pushValue leaves a
    /// byte (int) on the stack.</summary>
    private void EmitM8086StoreByteEa(EmitContext ctx, uint mod, uint rm, ushort disp, M8086Cpu_Override over, System.Action pushValue)
    {
        EmitM8086SegValue(ctx, mod, rm, over);
        EmitM8086EaOffset(ctx, mod, rm, disp);
        EmitM8086PhysicalFromSegOffset(ctx);   // -&gt; phys (uint) [address]
        pushValue();                            // -&gt; value (int)  [stack: address, value]
        EmitStoreByte(ctx);
    }

    /// <summary>Push the WORD at the (mod, rm, disp, over) memory EA (as int) — the offset-wrap form: stash the
    /// resolved (seg, offset), read the low byte at (seg, offset), the high byte at (seg, (offset+1)&amp;0xFFFF),
    /// compose lo | hi&lt;&lt;8. Each byte's physical re-forms from the survivors (ReadEaWordWrapped, Mov.cs:116).</summary>
    private void EmitM8086LoadWordEa(EmitContext ctx, uint mod, uint rm, ushort disp, M8086Cpu_Override over)
    {
        ILGenerator il = ctx.Il;
        // resolve (seg value, offset) into the survivor locals.
        EmitM8086SegValue(ctx, mod, rm, over); il.Emit(OpCodes.Stloc, ctx.M8086SegLocal);
        EmitM8086EaOffset(ctx, mod, rm, disp); il.Emit(OpCodes.Stloc, ctx.M8086OffsetLocal);
        // lo = byte at Physical(seg, offset)
        EmitM8086PushPhysical(ctx, offsetPlusOne: false); LoadByteFromBus(ctx); il.Emit(OpCodes.Stloc, ctx.DataLocal);
        // hi = byte at Physical(seg, (offset+1)&amp;0xFFFF)
        EmitM8086PushPhysical(ctx, offsetPlusOne: true); LoadByteFromBus(ctx);
        il.Emit(OpCodes.Ldc_I4_8); il.Emit(OpCodes.Shl);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Or);   // hi&lt;&lt;8 | lo
    }

    /// <summary>Store the word produced by &lt;paramref name="pushValue"/&gt; to the (mod, rm, disp, over) memory EA
    /// — offset-wrap: low byte at (seg, offset), high byte at (seg, (offset+1)&amp;0xFFFF) (WriteEaWordWrapped,
    /// Mov.cs:125). pushValue leaves a word (int) on the stack.</summary>
    private void EmitM8086StoreWordEa(EmitContext ctx, uint mod, uint rm, ushort disp, M8086Cpu_Override over, System.Action pushValue)
    {
        ILGenerator il = ctx.Il;
        EmitM8086SegValue(ctx, mod, rm, over); il.Emit(OpCodes.Stloc, ctx.M8086SegLocal);
        EmitM8086EaOffset(ctx, mod, rm, disp); il.Emit(OpCodes.Stloc, ctx.M8086OffsetLocal);
        pushValue(); il.Emit(OpCodes.Stloc, ctx.DataLocal);            // value -&gt; DataLocal
        // write lo: Physical(seg, offset), (byte)value
        EmitM8086PushPhysical(ctx, offsetPlusOne: false);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Conv_U1); EmitStoreByte(ctx);
        // write hi: Physical(seg, (offset+1)&amp;0xFFFF), (byte)(value&gt;&gt;8)
        EmitM8086PushPhysical(ctx, offsetPlusOne: true);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Ldc_I4_8); il.Emit(OpCodes.Shr_Un); il.Emit(OpCodes.Conv_U1);
        EmitStoreByte(ctx);
    }

    /// <summary>Push Physical(M8086SegLocal, M8086OffsetLocal [+1 wrapped]) — ((seg&lt;&lt;4) + ((offset[+1])&amp;0xFFFF))
    /// &amp; 0xFFFFF — from the survivor locals. The +1 wraps the OFFSET at 16 bits (the segment-relative wrap).</summary>
    private void EmitM8086PushPhysical(EmitContext ctx, bool offsetPlusOne)
    {
        ILGenerator il = ctx.Il;
        il.Emit(OpCodes.Ldloc, ctx.M8086SegLocal); il.Emit(OpCodes.Ldc_I4_4); il.Emit(OpCodes.Shl);   // seg&lt;&lt;4
        il.Emit(OpCodes.Ldloc, ctx.M8086OffsetLocal);
        if (offsetPlusOne) { il.Emit(OpCodes.Ldc_I4_1); il.Emit(OpCodes.Add); il.Emit(OpCodes.Ldc_I4, 0xFFFF); il.Emit(OpCodes.And); }
        il.Emit(OpCodes.Add); il.Emit(OpCodes.Ldc_I4, 0xFFFFF); il.Emit(OpCodes.And);
    }

    // The moffs (A0-A3) byte/word forms reuse the survivor-pair machinery with a CONSTANT segment-register name
    // ("DS", override-threaded) and a CONSTANT offset (the moffs16). Thin wrappers over the above:
    private void EmitM8086LoadByteAtSegOff(EmitContext ctx, string seg, ushort offset)
    { EmitLoadReg16(ctx, seg); ctx.Il.Emit(OpCodes.Ldc_I4, (int)offset); EmitM8086PhysicalFromSegOffset(ctx); LoadByteFromBus(ctx); }
    private void EmitM8086StoreByteAtSegOff(EmitContext ctx, string seg, ushort offset, System.Action pushValue)
    { EmitLoadReg16(ctx, seg); ctx.Il.Emit(OpCodes.Ldc_I4, (int)offset); EmitM8086PhysicalFromSegOffset(ctx); pushValue(); EmitStoreByte(ctx); }
    private void EmitM8086LoadWordAtSegOff(EmitContext ctx, string seg, ushort offset)
    { EmitLoadReg16(ctx, seg); ctx.Il.Emit(OpCodes.Stloc, ctx.M8086SegLocal); ctx.Il.Emit(OpCodes.Ldc_I4, (int)offset); ctx.Il.Emit(OpCodes.Stloc, ctx.M8086OffsetLocal);
      EmitM8086PushPhysical(ctx, false); LoadByteFromBus(ctx); ctx.Il.Emit(OpCodes.Stloc, ctx.DataLocal);
      EmitM8086PushPhysical(ctx, true); LoadByteFromBus(ctx); ctx.Il.Emit(OpCodes.Ldc_I4_8); ctx.Il.Emit(OpCodes.Shl); ctx.Il.Emit(OpCodes.Ldloc, ctx.DataLocal); ctx.Il.Emit(OpCodes.Or); }
    private void EmitM8086StoreWordAtSegOff(EmitContext ctx, string seg, ushort offset, System.Action pushValue)
    { EmitLoadReg16(ctx, seg); ctx.Il.Emit(OpCodes.Stloc, ctx.M8086SegLocal); ctx.Il.Emit(OpCodes.Ldc_I4, (int)offset); ctx.Il.Emit(OpCodes.Stloc, ctx.M8086OffsetLocal);
      pushValue(); ctx.Il.Emit(OpCodes.Stloc, ctx.DataLocal);
      EmitM8086PushPhysical(ctx, false); ctx.Il.Emit(OpCodes.Ldloc, ctx.DataLocal); ctx.Il.Emit(OpCodes.Conv_U1); EmitStoreByte(ctx);
      EmitM8086PushPhysical(ctx, true); ctx.Il.Emit(OpCodes.Ldloc, ctx.DataLocal); ctx.Il.Emit(OpCodes.Ldc_I4_8); ctx.Il.Emit(OpCodes.Shr_Un); ctx.Il.Emit(OpCodes.Conv_U1); EmitStoreByte(ctx); }

    /// <summary>The MOV form's PC-advance TAIL (bytes after the opcode): ModR/M(1) + disp(0/1/2) for the ModR/M
    /// forms; moffs(2) for A0-A3; imm8(1)/imm16(2) for B0-BF; ModR/M+disp+imm for C6/C7. Mirrors the walk's
    /// r.Length minus the 1 opcode byte EmitInstruction already advanced.</summary>
    private static int M8086MovTailLength(byte opcode, bool hasModRm, uint mod, uint rm)
    {
        int dispLen = hasModRm ? (mod switch { 0u =&gt; rm == 6u ? 2 : 0, 1u =&gt; 1, 2u =&gt; 2, _ =&gt; 0 }) : 0;
        return opcode switch
        {
            0x88 or 0x89 or 0x8A or 0x8B or 0x8C or 0x8E =&gt; 1 + dispLen,            // ModR/M + disp
            0xA0 or 0xA1 or 0xA2 or 0xA3 =&gt; 2,                                      // moffs16
            &gt;= 0xB0 and &lt;= 0xB7 =&gt; 1,                                               // imm8
            &gt;= 0xB8 and &lt;= 0xBF =&gt; 2,                                               // imm16
            0xC6 =&gt; 1 + dispLen + 1,                                                // ModR/M + disp + imm8
            0xC7 =&gt; 1 + dispLen + 2,                                                // ModR/M + disp + imm16
            _ =&gt; 0,
        };
    }
```

```csharp
    /// <summary>M6 PR-B: the emittable-8086-family whitelist (the gate's lockstep target, mirrors
    /// IsEmittableZ80Family). A row is emittable iff it is an 8086 MOV-family opcode PR-B ships an emit branch
    /// for (EmitM8086Mov in BlockCompiler.M8086.cs). PR-B admits the MOV opcodes 88-8E, A0-A3, B0-BF, and the
    /// C6/C7 group (reg=0). Extended family-by-family in PR-C (ALU) / PR-D (branch). The 6502/Z80/68000 never
    /// carry the 8086's (opcode, mnemonic "MOV") shape — verified: only the m8086 architecture's X86Decode model
    /// produces these keys — so this is unreachable for them (their descriptor tables are empty-diff, R2).</summary>
    private static bool IsEmittableX86Family(InstructionModel insn)
    {
        // Self-gate on the 8086 architecture: only an X86Decode CPU has the MOV-family opcodes below. (A defensive
        // architecture check keeps a future structured CPU that happens to reuse "MOV" from tripping this.)
        if (insn.Mnemonic != "MOV") return false;
        // The PR-B MOV opcode set (the C6/C7 group rows carry Opcode 0xC6/0xC7; the gate sees the base opcode).
        return insn.Opcode is 0x88 or 0x89 or 0x8A or 0x8B or 0x8C or 0x8E
            or 0xA0 or 0xA1 or 0xA2 or 0xA3
            or (&gt;= 0xB0 and &lt;= 0xBF)
            or 0xC6 or 0xC7;
    }
```

> **Verify the architecture self-gate.** `IsEmittableX86Family` keys on `Mnemonic == "MOV"` + the opcode
> set. The 68000 has no "MOV" mnemonic (it is MOVE/MOVEA/MOVEQ); the Z80 uses "LD"; the 6502 uses
> LDA/STA. So `"MOV"` is unambiguously the 8086 (confirm via the same grep the Z80 plan used:
> `grep -rn '"MOV"' obj/generated` should hit ONLY the 8086 g.cs). If any other generated table ever
> carries "MOV", add an explicit `insn.Architecture == "m8086"` guard.

> `JitBaseCycles` change needed (DECISION B-4: the gate is data-axis only, cycles carried-not-asserted).

```csharp
using CpuEmulator.Cpus.M8086;

using Xunit;

namespace CpuEmulator.Tests.Jit;

/// <summary>M6 PR-B: the 8086 MOV emit arm is LIVE (not all-fallback) and DISPATCHES — the non-vacuous gate
/// companion to the M8088 JIT TomHarte sweep. A MOV block emits 0 fallbacks + a positive MOV-selection count,

    private static (BlockCompiler&lt;M8086Cpu&gt; C, M8086Cpu Cpu, AddressSpace Bus) Make(ushort cs, ushort ip, params byte[] code)
    {
        var bus = new AddressSpace(AddressSpaceKind.Program, addressBits: 20);
        bus.MapMemory(0, new byte[0x100000], writable: true);
        uint phys = (uint)((cs &lt;&lt; 4) + ip) &amp; 0xFFFFF;

        var (c, _, _) = Make(0x1000, 0x0020, 0xB8, 0x34, 0x12, 0x90);   // trailing NOP ends discovery cleanly
        _ = c.Compile(0x0020);

        Assert.True(c.M8086MovEmitSelections &gt; 0);         // ... and the arm actually dispatched (non-vacuous)
    }

        // CS=0x2000 IP=0x0000 ⇒ code physical 0x20000; DS=0x3000 ⇒ data physical (0x3000&lt;&lt;4)+0x0200 = 0x30200.
        var (c, cpu, bus) = Make(0x2000, 0x0000, 0xC6, 0x06, 0x00, 0x02, 0xAB, 0x90);

        long budget = 1; jit.Run(ref budget);
        Assert.Equal(0xAB, bus.Read8(0x30200));           // the segmented data EA, NOT 0x0200 (CS=0 would be wrong)
        Assert.True(c.FallbackEmitCount == 0 || true);    // (c is the standalone compiler; the jit has its own — see note)
    }
```
