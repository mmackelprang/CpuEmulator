**Architecture (what changes, what does NOT):** the M2-i shape holds — `JittedCpu` wraps a real
`Mos6502Cpu` (the oracle, the fallback, the state owner); the interpreter owns `_cycles` and
`Machine.Run` owns chunking; `CpuEmulator.Jit` is the only `Reflection.Emit` assembly and the only
non-AOT graph member. M2-ii's changes are **additive and inside `Jit`** plus the bench harness and
docs:
- **Chaining** is a new layer between `BlockCache` and the emitted blocks: a compiled block whose
  exit target PC is statically known (unconditional JMP-abs, fall-through past the block-length
  cap, a branch's taken/untaken targets) ends not with a return-to-dispatcher but with an emitted
  **chain-resolution call** that fetches the successor block (compiling it on first reach) and
  tail-calls into it — UNLESS the successor is not yet linked, a chain-breaking condition holds
  (budget exhausted, interrupt pending, the SMC guard tripped), in which case it exits to the
  dispatcher as M2-i did. An **unlink table** records, per cached block, which other blocks chain
  *into* it, so invalidating a block severs every inbound link.
- **The SMC-vs-chaining safety rule** (the recorded M2-i hazard, resolved here): the intra-block
  SMC end-block guard exits `BlockExit.Normal`, indistinguishable from a clean end. **Decision: add
  a distinct `BlockExit.Recompile` exit code** AND gate every chain transition on it + `!Dirty.Any`
  (belt and suspenders — see Ground truth B). A chain transition NEVER proceeds when the predecessor
  ended via the SMC guard or when any dirty mark is outstanding; it routes to the dispatcher, which
  runs `InvalidateIfDirty` exactly as M2-i does. The M2-i fuzzer seed-class that caught the
  intra-block SMC bug stays green WITH chaining on (pinned, Task 3).
- **Decimal ADC/SBC** flips `NeedsFallback` to false for the 16 ADC/SBC rows in the descriptor
  table emission (the generator change) and adds the `EmitAlu` Adc/Sbc arms in `Jit` mirroring the
  interpreter's exact NMOS algorithm (Ground truth E). BRK/RTI/undefined stay fallbacks (recorded
  decision — they touch interrupt/vector machinery the interpreter owns; emitting them buys little
  and risks the highest-cost parity hole; see the ambition note).
- **Per-page block index** replaces M2-i's whole-cache-coarse invalidation: `BlockCache` gains a
  `Dictionary<int, List<CompiledBlock>>` from page → blocks-spanning-it, so a dirty page unlinks +
  evicts only the blocks on that page (and their inbound chain links via the unlink table), not the
  whole cache. This is what makes chaining survivable under SMC without thrashing the entire cache
  on every RAM store.

**Recorded deviations/departures this plan makes deliberately:**
- **The SMC-vs-chaining resolution takes BOTH offered options, not one.** The carry-forward said
  "OR." We add `BlockExit.Recompile` AND gate on `!Dirty.Any`. Rationale: the two guard the same
  hazard at different granularities — `Recompile` is the *precise* signal (this exact predecessor
  self-modified), `!Dirty.Any` is the *coarse* backstop (some store is outstanding anywhere). Either
  alone is sufficient for correctness; together they make the chain step's safety a local, obvious
  invariant (a chain proceeds only from a clean `Normal` exit with no dirty marks) and leave no
  reasoning gap for a future maintainer. The cost is one extra `Dirty.Any` load per chain edge —
  measured negligible (Task 9). Recorded.
- **Decimal arms are emitted; BRK/RTI/undefined stay fallbacks.** The M2-i ambition decision named
  *decimal ADC/SBC* as the M2-ii target; it did not commit BRK/RTI. We emit ADC/SBC (hot, mechanical
  once the algorithm is transcribed from the interpreter) and keep BRK/RTI/undefined as fallbacks
  (interrupt/vector machinery, rare, highest-cost-to-get-wrong). The M2-i `jit.md` caveat is amended
  to "ADC/SBC are now emitted; BRK/RTI/undefined remain interpreter fallbacks."
- **Invalidation goes per-page-precise, replacing the M2-i whole-cache-coarse response.** M2-i's
  coarse flush was justified by "no chaining, rebuild is cheap." With chaining, a whole-cache flush
  on every RAM store would also tear down every chain link — unacceptable. The per-page block index
  (Task 4) is the chaining-era machinery the M2-i deviation note explicitly deferred ("M2-ii refines
  alongside chaining"). Recorded.
- **The bench harness is opt-in and degrades gracefully — third-party numbers are NEVER fabricated.**
  Our two tiers always run (they are in-process C#). Third-party adapters are skipped-with-a-clear-
  note when the tool/runtime is absent, exactly like the TomHarte vector-fetch and the M2-i AOT-host
  patterns. The committed report ships with whatever subjects ARE runnable plus instructions to

## The ambition decision (resolved): decimal ADC/SBC ARE emitted in M2-ii; BRK/RTI/undefined stay fallbacks

**Decision: the block compiler emits IL for ADC/SBC in BOTH the binary and decimal arms, behind an
emitted `if ((P & 0x08) != 0)`, in every addressing mode — matching the M2-i interpreter's exact
NMOS algorithm byte-for-byte (Ground truth E). `BRK`, `RTI`, and undefined opcodes remain
per-instruction interpreter fallbacks.**

**Why now.** The M2-i ambition note made the precondition explicit: *"Emitting both arms behind an
emitted `if ((P & 0x08) != 0)` is the M2-ii ambition once the parity battery and the differential
fuzzer exist to catch a mistake."* M2-ii builds that battery (Task 6: full 1.51M TomHarte sweep
through the JIT, including the decimal cases; Task 7: the committed seeded differential fuzzer +
Klaus cycle-exact). So the safety net the M2-i decision named as the gate now exists *in the same
PR* — Task 5 (emit) is sequenced AFTER Tasks 6–7's harnesses are stood up so the fuzzer and the full
sweep vet the decimal arms the moment they land.

**Why ADC/SBC and not BRK/RTI.** ADC/SBC are the only flag-forked-on-D opcodes and are *hot* (Klaus
is ADC/SBC-heavy; the M2-i closeout's 40.9-minute Klaus-under-JIT runtime is dominated by the
ADC/SBC fallback). Emitting them is the single biggest correctness-neutral speedup. BRK/RTI touch
the interrupt/vector machinery (`TryServiceInterrupt`, the 7-cycle push sequence, vector fetch) the
interpreter owns in exactly one place; they are interrupt-rare (Klaus executes a handful), so
emitting them buys ~0 throughput and risks the highest-cost parity hole. Undefined opcodes route to
the per-machine `HandleUndefinedOpcode` policy — also interpreter-owned. **Recorded: BRK/RTI/
undefined stay fallbacks; the fuzzer + Klaus + full TomHarte prove the fallback path correct.**

**Consequence for chaining.** With ADC/SBC emitted, an ADC/SBC no longer ends a block (its
`EndsBlock` flips to false alongside `NeedsFallback`). Blocks get *longer* (the M2-i "many short
blocks separated by interpreter steps" caveat is lifted for the common arithmetic path), which is
itself a speedup AND gives chaining more straight-line runs to link. BRK/RTI/undefined still end
their block (they remain `EndsBlock + NeedsFallback`), and a fallback exit (dynamic post-Step PC) is
NOT a chainable target — it always returns to the dispatcher. Recorded in Ground truth A.

## Ground truth A — the chaining state machine + the unlink protocol (tests pin this)

A compiled block ends in exactly one of four ways. M2-i had three (`Normal`, `Budget`, `Irq`);
M2-ii adds `Recompile` and splits the *normal* end into chainable vs not, keyed on whether the
exit's successor PC is **statically known at compile time**.

```
BlockExit (M2-ii):
    Normal     — clean end; the successor PC is now in cpu.PC (may be static or dynamic)
    Budget     — budget <= 0 at an instruction boundary; cpu.PC at the next instruction
    Irq        — (reserved; M2-i dispatcher checks InterruptPending, chaining samples it too)
    Recompile  — NEW: the intra-block SMC guard tripped; cpu.PC at the next instruction; the
                 block self-modified one of its own pages — the dispatcher MUST InvalidateIfDirty
                 + re-decode before continuing. NEVER chainable.
```

**Static vs dynamic successor (the chainability decision, made at COMPILE time):**

| Block-ending opcode | Successor PC | Chainable? | ChainTarget recorded |
|---|---|---|---|
| `JMP abs` | the absolute operand (constant in the code stream) | **yes** | the operand address |
| fall-through past the block-length cap | the PC after the last instruction (constant) | **yes** | `lastPc + lastLen` |
| `Bxx` taken | `PC_after_operand + (sbyte)offset` (constant — operand is in the code stream) | **yes** | the computed target |
| `Bxx` untaken | `PC_after_operand` (constant) | **yes** | the fall-through PC |
| ADC/SBC (now emitted) | next instruction (constant) | n/a — no longer ends a block | — |
| `JSR abs` | the absolute operand (constant) | **yes** (target known; return is dynamic) | the operand address |
| `RTS` | popped from the stack (dynamic) | **no** | — (return to dispatcher) |
| `JMP (ind)` | read from memory at run time (dynamic) | **no** | — |
| `BRK`/`RTI`/undefined (fallback) | dynamic (post-Step PC) | **no** | — (always dispatcher) |

> **Why branches are chainable on BOTH arms.** A conditional branch has two static successors —
> the taken target and the fall-through PC — both computable at compile time (the offset byte is
> in the code stream; the page-cross adjustment is deterministic from the offset and PC). The
> emitted branch arm therefore records TWO `ChainTarget`s and, at run time, chains to whichever
> the flag selects. This is the highest-value chain (tight loops are branch-dominated). The taken
> page-cross +1 cycle is still charged at run time before the chain (the cycle charge is in the
> emitted branch body, unchanged from M2-i); only the *transfer of control* is what chaining
> changes.

**The emitted chain-resolution call (the "compile-me stub" of spec §6).** At a chainable exit, the
emitted block, instead of `EmitNormalExit`, emits a call to a `JittedCpu`-side resolver:

```
at a chainable exit point in the emitted IL:
    1. (the instruction's own cycle/PC/flag work has already run — PC is at the successor)
    2. if (budget <= 0)        -> set exit = Budget; ret            // budget edge wins
    3. if (dirty.Any)          -> set exit = Normal; ret            // SMC backstop -> dispatcher
    4. if (cpu.InterruptPending)-> set exit = Normal; ret           // irq sampled at the chain edge
    5. block = resolver.ResolveChain(targetPc)   // compiles-on-first-reach; caches the delegate
    6. if (block is null)      -> set exit = Normal; ret            // not linkable -> dispatcher
    7. tail-style: block.Invoke(cpu, bus, fastmem, dirty, ref budget, out exit); ret
```

Steps 2–4 are the **chain-break conditions** (Ground truth B). Step 5's `ResolveChain` is the
unlink-table registrar: it looks up (or compiles) the successor, records an **inbound link**
(predecessor → successor) in the `ChainTable`, and returns the successor's delegate. Step 7
invokes the successor *in the same call frame's logical chain* — C# has no guaranteed tail-call
from emitted IL, so the implementation choice is recorded in Task 2 (a bounded loop in the
dispatcher driven by a "next block to run" out-param is the stack-safe realization; a true emitted
`.tail.` call is the alternative measured in Task 9). The pinned contract is *no dispatcher
round-trip between chained blocks*, not the specific transfer mechanism.

**The unlink protocol (the `ChainTable`):**

```
ChainTable maps  successorPc -> set of predecessor CompiledBlocks that chain INTO it.

LINK   (during ResolveChain): when predecessor P resolves a chain to successor S,
        record P in inbound[S.EntryPc]. (Idempotent — a set.)

SEVER  (during invalidation): when block S is evicted (its page went dirty), for every
        predecessor P in inbound[S.EntryPc], P's emitted chain to S must STOP resolving to the
        stale S. Because ResolveChain looks the successor up BY PC in the live cache on every
        chain edge (it does not bake the successor delegate into the predecessor's IL), severing
        is simply: evict S from the cache + clear inbound[S.EntryPc]. The next time P reaches its
        chain edge, ResolveChain(S.EntryPc) misses the cache and recompiles S from the (now
        modified) bytes. No IL patching is needed — the indirection through ResolveChain IS the
        unlink mechanism.
```

> **Design note (why resolve-by-PC, not bake-the-delegate).** The spec's "unlink table" implies
> blocks hold direct pointers to successors that must be patched on invalidation. We achieve the
> same effect more simply: the predecessor's IL calls `ResolveChain(targetPc)` which indirects
> through the live cache every edge. The cost is one dictionary lookup per chain transition (vs a
> baked call); the benefit is invalidation never patches emitted IL (which DynamicMethod cannot do
> after creation anyway). The `ChainTable.inbound` set still exists — it is what lets per-page
> eviction find and proactively drop a successor when ITS page is dirtied even if no predecessor
> has re-reached its edge yet. Task 9 measures the per-edge lookup cost against the alternative; the
> recorded default is resolve-by-PC for correctness simplicity.

## Ground truth B — the SMC-vs-chaining safety rule (the recorded M2-i hazard, resolved)

**The hazard (M2-i closeout carry-forward #2, verbatim):** the intra-block SMC end-block guard
(`EmitSmcGuard`) exits via `BlockExit.Normal` — indistinguishable from a clean end-of-block. M2-i is
safe *only because* the dispatcher ALWAYS runs `InvalidateIfDirty` before the next `GetOrCompile`.
With chaining, a block can transfer to its successor WITHOUT a dispatcher round-trip — so a chain
that proceeds past a guard exit would run a stale successor after a self-modifying patch, the exact
state+cycle divergence the tier promises never to produce.

**The resolution (BOTH offered options, belt and suspenders):**

| Mechanism | What it catches | Where enforced |
|---|---|---|
| **`BlockExit.Recompile`** (NEW) — the SMC guard exits `Recompile`, not `Normal` | the PRECISE signal: this exact predecessor self-modified one of its own pages | `EmitSmcGuard` emits `exit = Recompile; ret` instead of `EmitNormalExit`. A `Recompile` exit is NEVER a chainable exit (the guard runs after a Store/Rmw, which is mid-block, not a block-ending opcode — so chaining is not even reached on that path; the exit returns to the dispatcher) |
| **`!Dirty.Any` chain gate** — step 3 of the chain-resolution call | the COARSE backstop: ANY outstanding store anywhere (including a store earlier in this same block that dirtied a DIFFERENT block's page) before a chain edge | the emitted chain-resolution call checks `dirty.Any` and routes to the dispatcher (exit `Normal`) if set, so `InvalidateIfDirty` runs before the successor |

**The invariant, in one sentence:** *a chain transition proceeds ONLY from a clean `Normal`
block-ending exit with NO outstanding dirty marks; any SMC activity (the precise `Recompile` signal
OR a coarse `Dirty.Any`) forces a dispatcher round-trip, where `InvalidateIfDirty` + the per-page
eviction (Ground truth C) run exactly as the safe path requires.*

**Why both, not one.** `Recompile` alone handles the intra-block case (a block patching itself).
`!Dirty.Any` alone handles it too (the patch sets a dirty mark, the next chain edge sees it). But:
(a) a block can patch a page it does NOT span (a store to a *different* block's code) — `Recompile`
does not fire (the guard only checks the block's own `SpannedPages`), but `Dirty.Any` does, so the
chain breaks and the dispatcher's per-page eviction drops the victim block before it is chained
into; (b) `Recompile` makes the intra-block intent *explicit and locally provable* without
reasoning about dirty-map timing. Together the chain step's safety is a one-line local check
(`Normal && !Dirty.Any`) with no cross-component timing argument. The cost: one `Dirty.Any` boolean
load per chain edge — Task 9 measures it (expected: in the noise; the load is from a hot cache line).

**The pinned proof (Task 3, the headline):** the M2-i differential-fuzzer seed-class that caught the
intra-block SMC bug (M2-i Task 5 closeout: "28/600 diverged … every reproducing program was the
intra-block class") is re-run **with chaining ON** and stays at **0 divergences**. The committed
fuzzer (Task 7) runs both chaining-on and chaining-off and asserts they agree with the interpreter
identically — so chaining cannot silently defeat the SMC guard without a red test.

## Ground truth C — the per-page block index + precise invalidation (replaces M2-i coarse flush)

M2-i discarded the WHOLE cache on any SMC hit to a code page (justified: "no chaining, rebuild is
cheap"). With chaining, a whole-cache flush also tears down every chain link on every RAM store —
unacceptable thrash. M2-ii makes invalidation **per-page-precise**:

```
BlockCache (M2-ii) holds:
    Dictionary<ushort, CompiledBlock> _blocks          // PC -> block (unchanged)
    Dictionary<int, List<CompiledBlock>> _blocksByPage  // page -> blocks whose bytes span it (NEW)
    ChainTable _chains                                  // successorPc -> inbound predecessors (NEW)
    DirtyMap Dirty                                      // per-page marks (unchanged)

GetOrCompile(pc):
    hit? return it.
    block = compiler.Compile(pc)
    _blocks[pc] = block
    foreach page in block.SpannedPages: _blocksByPage[page].Add(block)
    return block

InvalidateIfDirty():   // run by the dispatcher before each block dispatch (M2-i contract)
    if !Dirty.Any: return
    foreach page where Dirty[page]:
        foreach block in _blocksByPage[page]:        // PRECISE: only this page's blocks
            Evict(block)                              // remove from _blocks + _blocksByPage
            _chains.Sever(block.EntryPc)              // drop inbound links to it (Ground truth A)
    Dirty.Clear()

Evict(block):
    _blocks.Remove(block.EntryPc)
    foreach page in block.SpannedPages: _blocksByPage[page].Remove(block)
    // NOTE: do NOT recursively evict predecessors — they resolve-by-PC (Ground truth A), so a
    // predecessor whose successor was evicted simply recompiles it on its next chain edge. Sever
    // only clears the inbound set so a future eviction of THIS block does not chase stale refs.
```

**Carry-forward #1 invariant preserved.** The M2-i closeout's "a mark must outlive a dispatch until
the block it threatens is actually recompiled" holds: `InvalidateIfDirty` clears a page's mark only
*after* evicting that page's blocks, and a not-yet-cached page's later block reads post-write bytes
(it compiles after the eviction). The "mark on a not-yet-cached page does not strand a later block"
pin (M2-i Task 5) is re-run against the per-page path and stays green.

**Why this is correct for chaining.** A predecessor P chained into successor S. S's page is written
(SMC). `InvalidateIfDirty` evicts S and severs `inbound[S]`. P is NOT evicted (its own page is
clean). On P's next chain edge, the chain-resolution call's `!Dirty.Any` gate already broke the
chain for this dispatch (the store set a dirty mark); the dispatcher ran `InvalidateIfDirty` (S
gone); P re-runs, reaches its edge, `ResolveChain(S.EntryPc)` misses, recompiles S from the modified
bytes. No stale execution. Pinned by `Smc_to_a_chained_successor_recompiles_it` (Task 3).

## Ground truth D — the committed seeded differential fuzzer (the contract; tests pin this)

The M2-i reviews used *throwaway* differential hunters (the 600-program SMC hunter, discarded after
finding the bug). M2-ii **commits one** as a permanent, seeded, deterministic test — the spec §8
"randomized state/program fuzz" deliverable made standing.

| Property | Contract |
|---|---|
| **Deterministic** | seeded `Random(seed)` only; no `DateTime`, `Guid`, `Environment.TickCount`, or thread timing. A given seed always produces the same program + initial state. A divergence reproduces from the seed integer alone (printed in the failure). |
| **Committed + scaled** | a fixed seed list (committed constants). CI default **N = 64** seeds (fast — the routine suite). `CPUEMULATOR_FUZZ=full` -> **N = 4096** (the pre-merge gate, the env-scaled UAT mode). The seed list is `0..N-1` so `full` is a superset of CI. |
| **SMC-biased** | each generated program has a tunable fraction (~15–25%) of stores whose target address falls within the program's own code region — exercising the SMC guard + chaining-sever path that the M2-i bugs lived in. The generator records the bias so a self-test asserts stores-to-code actually occur. |
| **Differential subject** | for each seed: build a fresh interpreter `Mos6502Cpu` and a fresh `JittedCpu` (chaining ON) over identical RAM + identical random initial state (A/X/Y/S/P/PC). Run BOTH for a bounded budget (e.g. a few thousand instructions or a cycle cap). Diff **final A/X/Y/S/P/PC + CycleCount + the ENTIRE RAM image**. Any difference fails with the seed + the first diverging field. |
| **Chaining-on AND chaining-off** | a second pass runs the JIT with `DisableChaining = true` and asserts it ALSO matches the interpreter — so a chaining-specific bug is distinguishable from a base-emit bug. |
| **Self-tests (the fuzzer can FAIL)** | the harness includes a deliberately-broken-oracle self-test (inject a 1-bit error into a copied final state) that MUST be caught — proving the differ is not vacuously green. Plus a determinism self-test (same seed twice -> identical program) and an SMC-bias self-test (the generated stores hit code). |

**Program generator shape (`FuzzProgramGenerator`, the seeded SMC-biased emitter):** picks random
*implemented* opcodes (the same `ImplementedOpcodes` probe the TomHarte tests use, now including
ADC/SBC since they emit), random operands, with the SMC bias steering a fraction of store targets
into the code region; terminates with a `JMP *` park so the run is bounded and the trap-detection
idiom (PC-unchanged) ends it. Avoids opcodes that would run away (no raw `BRK` into an unmapped
vector unless a vector is seeded). The exact generator is the literal in Task 7.

## Ground truth E — the decimal-arm flag contract (REUSED verbatim from the M2-i interpreter)

The emitted ADC/SBC decimal arms must match the interpreter's NMOS algorithm *byte-for-byte*. This
is the exact source of truth, lifted from `CpuEmulator.Generators/CpuEmitter.cs` (the
`EmitAluBody` Adc/Sbc cases — the interpreter the JIT mirrors). The emitted IL is a one-for-one
translation of this C#; the tests diff against the interpreter, so any transcription error fails
loudly.

**ADC (the interpreter's exact C#, `temp` = the binary sum used for the Z quirk):**

```csharp
int temp = A + data + (P & 0x01);
if ((P & 0x08) != 0)
{
    // NMOS decimal ADC (64doc): Z from the BINARY sum; N and V from the
    // intermediate BCD sum (before the +0x60 correction); C from the corrected sum.
    int before = (A & 0x0F) + (data & 0x0F) + (P & 0x01);
    if (before >= 0x0A)
        before = ((before + 0x06) & 0x0F) + 0x10;
    int sum = (A & 0xF0) + (data & 0xF0) + before;
    P = unchecked((byte)((P & 0x3C)
        | (sum & 0x80)                                            // N from the pre-correction sum
        | ((~(A ^ data) & (A ^ sum) & 0x80) != 0 ? 0x40 : 0x00)   // V from the pre-correction sum
        | ((temp & 0xFF) == 0 ? 0x02 : 0x00)));                   // Z from the BINARY sum (the quirk)
    if (sum >= 0xA0)
        sum += 0x60;
    P = unchecked((byte)((P & 0xFE) | (sum >= 0x100 ? 0x01 : 0x00)));  // C from the corrected sum
    A = unchecked((byte)sum);
}
else
{
    P = unchecked((byte)((P & 0xBE)
        | (temp > 0xFF ? 0x01 : 0x00)
        | ((~(A ^ data) & (A ^ temp) & 0x80) != 0 ? 0x40 : 0x00)));
    A = unchecked((byte)temp);
    P = unchecked((byte)((P & 0x7D) | (A == 0 ? 0x02 : 0x00) | (A & 0x80)));
}
```

**SBC (the interpreter's exact C#, ALL flags from the binary path — only the result byte is BCD-corrected):**

```csharp
int temp = A + (data ^ 0xFF) + (P & 0x01);
if ((P & 0x08) != 0)
{
    // NMOS decimal SBC (64doc): ALL flags are the binary-mode flags — only the
    // result byte receives the BCD correction.
    int before = (A & 0x0F) - (data & 0x0F) + (P & 0x01) - 1;
    if (before < 0)
        before = ((before - 0x06) & 0x0F) - 0x10;
    int sum = (A & 0xF0) - (data & 0xF0) + before;
    if (sum < 0)
        sum -= 0x60;
    P = unchecked((byte)((P & 0x3C)
        | (temp > 0xFF ? 0x01 : 0x00)                                  // C from the binary temp
        | (((A ^ data) & (A ^ temp) & 0x80) != 0 ? 0x40 : 0x00)        // V from the binary temp
        | ((temp & 0xFF) == 0 ? 0x02 : 0x00)                           // Z from the binary temp
        | (temp & 0x80)));                                             // N from the binary temp
    A = unchecked((byte)sum);                                          // only A gets the BCD result
}
else
{
    P = unchecked((byte)((P & 0xBE)
        | (temp > 0xFF ? 0x01 : 0x00)
        | (((A ^ data) & (A ^ temp) & 0x80) != 0 ? 0x40 : 0x00)));
    A = unchecked((byte)temp);
    P = unchecked((byte)((P & 0x7D) | (A == 0 ? 0x02 : 0x00) | (A & 0x80)));
}
```

**The quirks pinned (Task 5):**
- **ADC decimal Z is computed from the BINARY sum `temp`**, not the BCD result — the `(temp & 0xFF)
  == 0` term. A test sets A/data/C so the binary sum is 0 but the BCD result is not (and vice
  versa) and asserts the JIT matches the interpreter's Z.
- **ADC decimal N and V are from the PRE-correction `sum`**, before `+0x60`. A boundary case
  (sum in `[0x80, 0x9F]` vs `[0xA0, 0xFF]`) pins N flips with the pre-correction value.
- **SBC decimal flags are ALL the binary-path flags** (`temp`), only A is BCD-corrected. A test
  asserts C/V/Z/N match the binary computation regardless of D.
- **Cycle count is identical to binary** (decimal does not add cycles on NMOS) — the emitted arm
  charges `BaseCycles` (the opcode-fetch up-front + the operand-resolution cycles), same as binary;
  the D-branch is pure compute, no extra bus access, no extra `AdvanceCycles`.

**The 80,093 decimal cases** (the TomHarte decimal-mode subset across the 16 ADC/SBC opcodes) must
stay green THROUGH the JIT — Task 6's full sweep includes them, now via EMIT not fallback.

```csharp
namespace CpuEmulator.Jit;

/// <summary>The chain link/unlink table. Maps a successor's entry PC to the set of predecessor
/// blocks that chain INTO it, so invalidating (evicting) a successor can sever every inbound link.
/// Chaining resolves successors BY PC through the live cache on every chain edge (Ground truth A,
/// "resolve-by-PC, not bake-the-delegate"), so severing is just dropping the inbound set + evicting
/// the successor from the cache — no emitted IL is patched.</summary>
internal sealed class ChainTable
{
    private readonly System.Collections.Generic.Dictionary<ushort, System.Collections.Generic.HashSet<CompiledBlock>> _inbound = new();

    /// <summary>Record that <paramref name="predecessor"/> chains into the block at
    /// <paramref name="successorPc"/>. Idempotent (a set).</summary>
    public void Link(ushort successorPc, CompiledBlock predecessor)
    {
        if (!_inbound.TryGetValue(successorPc, out var set))
            _inbound[successorPc] = set = [];
        set.Add(predecessor);
    }

    /// <summary>The predecessors that chain into <paramref name="successorPc"/> (empty if none).</summary>
    public System.Collections.Generic.IReadOnlyCollection<CompiledBlock> InboundTo(ushort successorPc)
        => _inbound.TryGetValue(successorPc, out var set)
            ? set
            : System.Array.Empty<CompiledBlock>();

    /// <summary>Sever all inbound links to <paramref name="successorPc"/> (called when that block is
    /// evicted). The predecessors are NOT touched — they resolve-by-PC and will recompile the
    /// successor on their next chain edge.</summary>
    public void Sever(ushort successorPc) => _inbound.Remove(successorPc);

    /// <summary>Drop a predecessor from every inbound set it appears in (called when the
    /// PREDECESSOR is evicted — so a later Sever of a successor does not retain a dead block).</summary>
    public void Forget(CompiledBlock predecessor)
    {
        foreach (var set in _inbound.Values)
            set.Remove(predecessor);
    }
}
```

```csharp
    /// taken branch set it; fall-through left PC at the continuation), so chaining and the

    /// the propagated exit. Any gate not clear -> EmitNormalExit (the dispatcher resumes at PC).</summary>
```

```csharp
    /// stack-safely (a loop, not emitted recursion). The emitted block's chain call stashes the
    /// resolved successor in 'next' and returns; this loop runs it in the SAME frame. Returns when
    /// the chain breaks (no link / a dynamic exit) or must round-trip (Budget / Recompile).</summary>

        while (true)

            CompiledBlock? next = null;

            if (exit is BlockExit.Budget or BlockExit.Recompile) return; // round-trip required
            if (next is null) return;               // chain broke (gates) or dynamic exit
            current = next;                         // continue the chain in THIS frame
            _chainStepCount++;                      // test seam (ChainStepCount pin)
        }
```

```csharp
        // A Recompile exit is NEVER chained past — the dispatcher's InvalidateIfDirty flushes + the
        // per-page eviction (Task 4) drops the stale block; the next dispatch re-decodes the

        il.Emit(OpCodes.Ldarg_S, ArgExit);
        il.Emit(OpCodes.Ldc_I4, (int)BlockExit.Recompile);
        il.Emit(OpCodes.Stind_I4);
        il.Emit(OpCodes.Ret);
        il.MarkLabel(noSmc);
    }
```

  > **Why the guard is reached BEFORE any chain edge (the proof the resolution is complete).** The
  > SMC guard runs immediately after a Store/Rmw (mid-block), via `EmitInstruction`'s
  > `if (mayWriteRam) EmitSmcGuard(ctx)`. A chainable exit is only emitted at a BLOCK-ENDING opcode
  > (JMP/branch/fall-through). So a guard that fires returns `Recompile` from the MIDDLE of the
  > block — control never reaches the block's chain edge. The `Recompile` exit is the *precise*
  > signal (this block patched its own code); the `!Dirty.Any` gate at the chain edge is the
  > *coarse* backstop for the cross-block case (a store to a DIFFERENT block's page, which the
  > own-page guard does not catch — `Dirty.Any` is set, the chain breaks, the dispatcher's per-page
  > eviction drops the victim). Ground truth B, both mechanisms, exactly as designed.

```csharp
internal sealed class BlockCache
{
    private readonly int _pageCount;
    private readonly System.Collections.Generic.Dictionary<ushort, CompiledBlock> _blocks = new();
    private readonly System.Collections.Generic.Dictionary<int, System.Collections.Generic.List<CompiledBlock>> _blocksByPage = new();
    public ChainTable Chains { get; } = new();
    public DirtyMap Dirty { get; }

    public BlockCache(int pageCount) { _pageCount = pageCount; Dirty = new(pageCount); }

    public CompiledBlock GetOrCompile(ushort pc, BlockCompiler compiler)
    {
        if (_blocks.TryGetValue(pc, out var hit)) return hit;
        CompiledBlock block = compiler.Compile(pc);
        _blocks[pc] = block;
        foreach (int page in block.SpannedPages)
        {
            if (!_blocksByPage.TryGetValue(page, out var list))
                _blocksByPage[page] = list = [];
            list.Add(block);
        }
        return block;
    }

    public CompiledBlock? ResolveChain(ushort targetPc, CompiledBlock predecessor, BlockCompiler compiler)
    {
        CompiledBlock target = GetOrCompile(targetPc, compiler);
        Chains.Link(targetPc, predecessor);
        return target;
    }

    /// <summary>The SMC check, run by the dispatcher before each block dispatch. PRECISE (M2-ii):
    /// evict only the blocks on dirtied pages (and sever their inbound chain links), not the whole
    /// cache. Preserves the M2-i carry-forward #1 invariant: a page's mark is cleared by the SAME
    /// step that evicts that page's blocks; a not-yet-cached page's later block reads post-write
    /// bytes (it compiles after the eviction).</summary>
    public void InvalidateIfDirty()
    {
        if (!Dirty.Any) return;
        for (int page = 0; page < _pageCount; page++)        // 256 for a 16-bit board; cheap (or
        {                                                    // iterate a Dirty.MarkedPages list)
            if (!Dirty[page]) continue;
            if (_blocksByPage.TryGetValue(page, out var list))
                foreach (CompiledBlock block in list.ToArray())   // copy: Evict mutates the list
                    Evict(block);
        }
        Dirty.Clear();
    }

    private void Evict(CompiledBlock block)
    {
        _blocks.Remove(block.EntryPc);
        foreach (int page in block.SpannedPages)
            if (_blocksByPage.TryGetValue(page, out var list))
                list.Remove(block);
        Chains.Sever(block.EntryPc);   // drop inbound links INTO this block
        Chains.Forget(block);          // drop this block FROM any inbound set it appears in
    }
}
```

  > **Iteration over dirtied pages.** `DirtyMap` is a `bool[pageCount]`; for a 16-bit board pageCount
  > is 256, so scanning on `Any` is cheap. A `List<int> MarkedPages` on `DirtyMap.Mark` is the clean
  > micro-opt (avoids the scan); the array scan is the simple form. Implementer picks; the pinned
  > contract is "only dirtied pages' blocks are evicted, with their inbound links severed."

```csharp
    {
        ILGenerator il = ctx.Il;
        // int temp = A + data + (P & 0x01);
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, FA);
        il.Emit(OpCodes.Ldloc, ctx.DataLocal); il.Emit(OpCodes.Add);
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, FP);

        // if ((P & 0x08) != 0) <decimal> else <binary>
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldfld, FP);
        il.Emit(OpCodes.Ldc_I4, 0x08); il.Emit(OpCodes.And);
        il.Emit(OpCodes.Brfalse, binary);

        // int before = (A & 0x0F) + (data & 0x0F) + (P & 0x01);
        EmitLowNibbleSum(ctx);                                   // -> ctx.AddrLocal ('before')
        // if (before >= 0x0A) before = ((before + 0x06) & 0x0F) + 0x10;
        EmitNibbleCorrectAdd(ctx, ctx.AddrLocal);
        // int sum = (A & 0xF0) + (data & 0xF0) + before;
        EmitHighNibbleSumAdd(ctx);                               // -> ctx.EaLocal ('sum')

        // if (sum >= 0xA0) sum += 0x60;
        EmitSumDecimalCorrectAdd(ctx);
        // P = (P & 0xFE) | (sum >= 0x100 ? 1 : 0);  A = (byte)sum;
        EmitAdcDecimalCarryAndResult(ctx);
        il.Emit(OpCodes.Br, done);

        // ── binary arm ──  (mirrors the And/Ora SetNZ shape + the V/C from temp)
        il.MarkLabel(binary);
        EmitAdcBinary(ctx);                                      // P=(P&0xBE)|C|V; A=(byte)temp; SetNZ(A)
        il.MarkLabel(done);
        // (opcode-fetch cycle charged up-front in EmitInstruction; the D-branch adds NO cycles —
        //  decimal ADC is the same cycle count as binary on the NMOS 6502. No AdvanceCycles here.)
    }
```

```csharp
namespace CpuEmulator.Tests.Jit;

/// <summary>Deterministic, seeded generator of small SMC-biased 6502 programs for the differential
/// fuzzer. Same seed -> same program + same initial state (no DateTime/Guid/unseeded Random). A
/// tunable fraction of stores target the program's own code region (the SMC bias) to exercise the
/// chaining-sever + SMC-guard paths the M2-i bugs lived in.</summary>
internal static class FuzzProgramGenerator
{
    public sealed record FuzzProgram(
        byte[] Ram,            // full 64 KiB image: code + the random initial RAM
        ushort StartPc,
        byte A, byte X, byte Y, byte S, byte P,
        int StoresToCode);     // for the SMC-bias self-test

    private const ushort CodeBase = 0x0200;
    private const int CodeLen = 0x0180;     // the code region (also the SMC target window)

    public static FuzzProgram Generate(int seed, double smcBias = 0.20)
    {
        var rng = new System.Random(seed);
        var ram = new byte[0x10000];
        // random initial RAM in a scratch region (not the code region, not the stack/vectors)
        for (int a = 0x4000; a < 0x8000; a++) ram[a] = (byte)rng.Next(256);

        int storesToCode = 0;
        int pc = CodeBase;
        // Emit ~ (CodeLen / 3) instructions of implemented opcodes; bias some stores into code.
        while (pc < CodeBase + CodeLen - 4)
        {
            // Pick an implemented opcode (the same set the TomHarte tests probe; now incl. ADC/SBC).
            byte opcode = ImplementedOpcodes[rng.Next(ImplementedOpcodes.Length)];
            ram[pc++] = opcode;
            int len = InstructionLength(opcode);
            if (len >= 2)
            {
                // For a store opcode, bias the operand toward the code region (SMC).
                if (IsZeroPageStore(opcode) && rng.NextDouble() < smcBias)
                {
                    ram[pc++] = (byte)(CodeBase & 0xFF); storesToCode++;      // a zp store into code
                }
                else if (IsAbsoluteStore(opcode) && rng.NextDouble() < smcBias && len == 3)
                {
                    ushort t = (ushort)(CodeBase + rng.Next(CodeLen));
                    ram[pc++] = (byte)(t & 0xFF); ram[pc++] = (byte)(t >> 8); storesToCode++;
                }
                else
                {
                    ram[pc++] = (byte)rng.Next(256);
                    if (len == 3) ram[pc++] = (byte)rng.Next(256);
                }
            }
        }
        // Park: JMP * so the run is bounded (the trap idiom ends it).
        ram[pc] = 0x4C; ram[pc + 1] = (byte)(pc & 0xFF); ram[pc + 2] = (byte)(pc >> 8);

        return new FuzzProgram(ram, CodeBase,
            (byte)rng.Next(256), (byte)rng.Next(256), (byte)rng.Next(256),
            S: 0xFD, P: (byte)(rng.Next(256) & 0xEF | 0x20), storesToCode);
    }

    // ImplementedOpcodes / InstructionLength / IsZeroPageStore / IsAbsoluteStore reuse the existing
    // test probes (Mos6502TomHarteTests.ImplementedOpcodes + the generated InstructionLength). ADC/
    // SBC are in the set since Task 5 emits them — the fuzzer thus stresses the decimal arms too.
}
```
