**Goal:** stand up **Tier 1 — the IL-JIT** (spec §6, decision #2/#3) as a working, gated,
*provably-equivalent* execution path for the 6502 — without spending the full parity battery
(that is M2-ii). This PR delivers the four artifacts that make the tier exist and be trusted:
(1) a generated, AOT-clean **opcode descriptor table** on the CPU class (the realization of
spec §5 artifact ③ — "per-opcode IL-emission methods" re-imagined as *data, not code*, with
recorded rationale); (2) a **new `CpuEmulator.Jit` assembly** — the ONLY assembly allowed
`Reflection.Emit` — holding a CPU-agnostic block compiler that walks descriptors into one
`DynamicMethod` per block, a PC-keyed block cache, the **fastmem split** (RAM/ROM → baked
`byte[]` access; MMIO/unknown → bus callout), a per-block **cycle-budget decrement + exit
stub**, **block-entry interrupt checks**, and **dirty-page invalidation**; (3) the
**`RuntimeFeature.IsDynamicCodeSupported` gate** at the construction seam, keeping
Core/Cpus/Peripherals/Monitor/Host AOT-clean by construction; (4) **sampled validation** —
TomHarte parity through a JIT-wrapped CPU (200/opcode), Klaus to the success trap under JIT,
the 8 `Category=UAT` sessions re-run JIT-wrapped, and trace-equivalence spot tests under the
fastmem-disabled accuracy mode. **PR #12** (branch `feat/m2-jit-i`, base `main`, head
`497a014` is the baseline; **994 tests green**).

**Architecture (the realization of spec artifact ③, recorded with rationale):** the spec
(§5) named the third generated artifact "per-opcode IL-emission methods that the M2 block
compiler composes." We deliberately **change its shape from code to data**: the generator
emits a compact **`public static readonly OpcodeDescriptor[] JitDescriptors`** on the CPU
class — a per-opcode row of (mode, class, register operands, op-kinds, cycle template id) —
and `CpuEmulator.Jit` contains a **single CPU-agnostic block compiler** that walks those
descriptors and emits IL. **Why data-not-code:** (a) **the AOT packaging law stays intact** —
emitting IL-emission *methods* into `Cpus.Mos6502` would either drag `Reflection.Emit` types
into an `IsAotCompatible` assembly or force a partial-trust dance; a descriptor table is pure
data, trivially AOT-clean, and the one assembly that emits IL (`Jit`) is the only non-AOT
member of the graph, exactly as spec §3's "load-bearing packaging rule" demands; (b)
**one-spec-drives-everything is preserved** — the table is generated from the same
`InstructionDef[]` that drives the interpreter, disassembler, and assembler, so it cannot
drift; (c) **CPU-agnostic for M3** — a Z80 spec that emits the same descriptor schema gets a
JIT for free, where per-CPU IL-emission methods would have to be regenerated and re-reviewed
per architecture. The cost we accept: the block compiler is a *descriptor interpreter that
emits IL* rather than a straight-line composition of generated snippets — more logic in
`Jit`, but written once. (This is the Pydgin "walk the IR → emit" arm, research §2/§4.)

**The interpreter is the oracle, the fallback, and the state owner.** `JittedCpu` *wraps* a
real `Mos6502Cpu` instance. The wrapped interpreter owns all architectural state (its public
`A/X/Y/S/P/PC` fields, its private `_cycles`); emitted IL reads and writes those public fields
directly via reflection-resolved `FieldInfo` baked into the `DynamicMethod` at compile time.
Any instruction the compiler cannot emit (decimal-mode ADC/SBC in M2-i — see the ambition
decision) compiles a **fallback callout to the inner interpreter's `Step()`**, so correctness
never depends on the JIT. Block-entry interrupt servicing also routes through the inner
interpreter's existing `Step()` (which calls `TryServiceInterrupt`), keeping the authentic
7-cycle sequence in exactly one place.

**Recorded deviations/departures this plan makes deliberately:**
- **Artifact ③ becomes data, not code** (the descriptor table) — the headline architecture
  decision, rationale above. The spec sentence "per-opcode IL-emission methods" is amended at
  closeout to "a generated per-opcode descriptor table consumed by a CPU-agnostic block
  compiler in `CpuEmulator.Jit`."
- **`Step()` always delegates to the inner interpreter; only `Run` uses blocks.** Decision
  recorded in Ground truth D. Rationale: `Step` is the monitor's single-instruction primitive
  and the TomHarte harness's primitive — both demand exact per-instruction cycle/trace
  fidelity, which is the interpreter's job. Compiling a one-instruction block to satisfy `Step`
  would buy nothing and risk a parity gap. `Run` is where blocks earn their keep.
- **The JIT binds to a concrete `AddressSpace`, not `IAddressSpace`.** Fastmem requires the
  page table's backing `byte[]` and writability, exposed via the internal
  `TryGetDirectAccess`. A `JittedCpu` over a non-`AddressSpace` bus is a construction error
  (host-world, thrown loudly) — recorded; M3 generalizes if a second `IAddressSpace` impl ever
  ships.
- **Dirty-page invalidation is whole-cache-coarse in M2-i** — any RAM store to a page that owns
  ≥1 cached block discards the *entire* block cache, not just that page's blocks. Rationale:
  M2-i has no chaining, so cache rebuild is cheap (re-decode on next entry), and a per-page
  block index is chaining-era machinery (the unlink table). The dirty *map* is per-page (Ground
  truth F); the *response* is coarse. Recorded; M2-ii refines alongside chaining.
- **Fastmem reads of RAM/ROM bypass `TracingAddressSpace`** — the design tension the brief
  names. Resolved per spec §3 decision #3: **parity is state+cycles equivalence, NOT bus-trace
  equivalence, for fastmem'd RAM/ROM**. A `JitOptions.DisableFastmem` flag routes every access
  through the bus, restoring trace-equivalence for the trace spot tests. Ground truth E states
  this as the tier's accuracy contract.

## The ambition decision: decimal-mode ADC/SBC are unsupported-in-IL in M2-i

**Decision: the block compiler does NOT emit IL for ADC/SBC; it emits a fallback callout to
the inner interpreter's `Step()` for both opcodes, in every addressing mode.** It DOES emit IL
for every other documented opcode class (Load, Store, Register, Transfer, Jump, Branch, the
non-ADC/SBC ALU ops — AND/ORA/EOR/CMP/CPX/CPY/BIT — RMW, Stack, Flow).

**Why.** The 6502's ADC/SBC are the only opcodes whose semantics fork on a runtime flag (the D
bit), and the decimal arm (see `CpuEmitter.EmitAluBody`, the `Adc`/`Sbc` cases — ~25 lines of
nibble-correction branching each, with the NMOS flag quirks) is precisely the kind of
densely-branchy, flag-cross-coupled logic where an IL-emission bug is most likely and a parity
failure most expensive. The binary arm is simple, but emitting *only* the binary arm would be a
silent correctness hole the day a guest sets D (Klaus exercises D; the demo does not). Emitting
*both* arms behind an emitted `if ((P & 0x08) != 0)` is the M2-ii ambition once the parity
battery and the differential fuzzer exist to catch a mistake. **In M2-i, ADC/SBC fall back per
instruction** — the safety valve doing exactly its job. This keeps the M2-i IL surface to the
mechanically-regular opcode classes, where descriptor-driven emission is provably faithful, and
defers the one genuinely tricky opcode pair to the PR that has the fuzz harness to vet it.

**Consequence for parity.** A block containing an ADC/SBC compiles up to that opcode, emits the
fallback callout (which runs one interpreter `Step`, advancing PC and cycles authentically),
then **ends the block** (the post-fallback PC is dynamic, so the block cannot statically
continue). The next `Run` iteration re-enters the dispatcher at the new PC. Klaus (which is
ADC/SBC-heavy, decimal included) therefore runs as many short blocks separated by interpreter
steps — slower than a full JIT, but **provably correct**, and still exercising the block
machinery on every non-ADC/SBC run. This is recorded as the M2-i performance caveat in
`jit.md`; M2-ii's benchmark numbers will quantify it and motivate emitting the decimal arms.

**Also fallback-per-instruction in M2-i (recorded, not ambition-gated):** `BRK` and `RTI` (they
touch the interrupt/vector machinery the interpreter owns), and any opcode not in the dispatch
table (undefined opcodes — the descriptor row is absent, so the compiler emits the
undefined-opcode fallback, which is itself an interpreter `Step`). Branch, Jump, JSR, RTS *are*
emitted (they are control flow that ends a block, not interrupt machinery).

## Ground truth A — the descriptor schema (tests pin this verbatim)

The generated table is `public static readonly OpcodeDescriptor[] JitDescriptors` indexed by
opcode (256 entries; absent opcodes are a sentinel `OpcodeDescriptor.Undefined`). One row
carries everything the block compiler needs to (a) decode the instruction length and operand
shape, (b) emit its bus pattern + semantics, (c) charge its cycles, and (d) decide whether it
ends a block — **without re-reading the spec or the interpreter source**. The records live in
`Core` (AOT-clean data; no behavior).

```csharp
namespace CpuEmulator.Core.Jit;

/// <summary>How an opcode affects block flow — the compiler decision to continue, end,
/// or bail the block. Mirrors the generator InstructionClass plus the JIT-only
/// distinction the interpreter does not need (whether the op ends a block).</summary>
public enum JitOpClass
{
    Load, Store, Register, Transfer,    // straight-line; block continues
    Alu, Rmw,                           // straight-line (Alu rows for ADC/SBC carry NeedsFallback)
    Branch,                             // conditional control flow; ends a block
    Jump, Jsr, Rts,                     // unconditional control flow; ends a block
    Flow,                               // BRK/RTI — interrupt/vector machinery; fallback + ends block
    Undefined,                          // not in the dispatch table; fallback + ends block
}

/// <summary>Addressing mode — the same closed set as Core.Specification.AddrMode, copied into
/// the JIT data layer so the descriptor table has no dependency on the spec-authoring types
/// (which are generator-facing). One-to-one with AddrMode; the generator maps across.</summary>
public enum JitMode
{
    Implied, Accumulator, Immediate,
    ZeroPage, ZeroPageX, ZeroPageY,
    Absolute, AbsoluteX, AbsoluteY,
    IndirectX, IndirectY, Indirect, Relative,
}

/// <summary>One micro-op the compiler emits, in spec order. Kind is the interpreter OpModel
/// kind string ("Ora", "ShiftLeft", "Compare", "BranchIf", "SetFlag", ...) — the SAME closed
/// vocabulary the CpuEmitter switches on; RegA/RegB carry register operands (e.g. Compare
/// carries the compared register; Transfer carries source+target; BranchIf carries the flag
/// bit in FlagBit + the When sense in BoolArg). The descriptorized form of OpModel.</summary>
public readonly record struct JitOp(string Kind, byte RegA, byte RegB, byte FlagBit, bool BoolArg);

/// <summary>One opcode row. Immutable value data; the whole table is a static readonly array.</summary>
public sealed record OpcodeDescriptor(
    byte Opcode,
    string Mnemonic,            // for diagnostics + the disassembler cross-check
    JitMode Mode,
    JitOpClass Class,
    int Length,                 // 1-3, the InstructionLength value (discovery advances PC by this)
    int BaseCycles,             // the ComputeCycles value for (mode, class) — the cycle template
    bool PageCrossPenalty,      // true => +1 cycle when the indexed read crosses a page (GT F)
    bool NeedsFallback,         // true => the compiler emits an interpreter-Step callout, not IL
    bool EndsBlock,             // true => discovery stops AFTER this opcode (control flow / fallback)
    System.Collections.Immutable.ImmutableArray<JitOp> Ops)
{
    /// <summary>The sentinel for an opcode absent from the dispatch table. NeedsFallback +
    /// EndsBlock so an undefined opcode in a run is serviced by the interpreter (whose
    /// HandleUndefinedOpcode owns the policy) and ends the block.</summary>
    public static OpcodeDescriptor Undefined(byte opcode) => new(
        opcode, "???", JitMode.Implied, JitOpClass.Undefined,
        Length: 1, BaseCycles: 0, PageCrossPenalty: false,
        NeedsFallback: true, EndsBlock: true, Ops: []);
}
```

| Field | Source in the generator | Pinned by |
|---|---|---|
| `Opcode` / `Mnemonic` / `Mode` | `InstructionModel.Opcode/Mnemonic/Mode` (mapped to `JitMode`) | "row N is opcode 0xNN, mnemonic agrees with `Disassemble`" |
| `Class` | `InstructionModel.Class` mapped to `JitOpClass`; `Jump`+`Jsr`+`Rts`+`Flow`(Brk/Rti) split out of the interpreter `Jump`/`Flow` by op-kind | per-class spot theory |
| `Length` | `CpuEmitter.ModeLength(mode)` (the existing function, reused) | "Length == InstructionLength(opcode) for all 151" |
| `BaseCycles` | `CpuEmitter.ComputeCycles(mode, class)` (the existing function, reused) | cycle-template pin |
| `PageCrossPenalty` | the existing `isPageCross` predicate (AbsX/AbsY/IndY + Load/Alu) | "the page-cross opcodes carry the flag, the rest don't" |
| `NeedsFallback` | true for `ADC`/`SBC` (the ambition decision), `BRK`/`RTI`, undefined | "ADC/SBC/BRK/RTI rows carry NeedsFallback; LDA/STA/etc. don't" |
| `EndsBlock` | true for Branch/Jump/Jsr/Rts/Flow/Undefined + any `NeedsFallback` row | "the control-flow + fallback opcodes end a block" |
| `Ops` | `InstructionModel.Ops` descriptorized (kind string + register/flag bytes) | per-class spot theory |

**Critical invariant (pinned):** `Length` and `BaseCycles` are emitted by reusing the
generator's existing `ModeLength` and `ComputeCycles` functions — the *same* code the
interpreter's cycle behavior derives from — so the descriptor table can never disagree with the
interpreter on instruction length or base cycle count. Task 1 lifts those two functions to be
callable from the descriptor-emission path (they are already `static` in `CpuEmitter`).

## Ground truth B — block lifecycle: discover -> compile -> execute -> invalidate

```
                   Run(ref budget) enters the dispatcher loop
                                   |
                 +-----------------v------------------+
                 | block = cache.Get(inner.PC)?       |
                 |   miss -> DISCOVER + COMPILE + cache|
                 +-----------------+------------------+
                                   |
            +----------------------v-----------------------+
            | at block entry, in emitted IL:               |
            |  1. if (inner.InterruptPending) -> EXIT(irq) |  <- interrupt check at block entry
            |  2. run emitted body, charging cycles into a |
            |     local; on each instruction boundary check|
            |     the budget local -> if <= 0 EXIT(budget) |  <- cc_interrupt-style budget exit
            |  3. straight-line until an EndsBlock opcode   |
            |     -> set inner.PC, EXIT(normal)            |
            +----------------------+-----------------------+
                                   | control returns to the dispatcher
            +----------------------v-----------------------+
            | EXIT(irq)    -> inner.Step() services it     |  (the 7-cycle sequence, one place)
            | EXIT(budget) -> return to Machine.Run; budget|
            |                 decremented == CycleCount d  |
            | EXIT(normal) -> loop: dispatch at the new PC |
            +----------------------------------------------+

   A RAM store anywhere in an emitted body also marks its page dirty. AT EMIT TIME the
   compiler records which pages the block bytes occupy; AT RUN TIME an emitted store to a
   RAM page calls dirty.Mark(page). INVALIDATE: when a marked page owns >=1 cached block,
   the WHOLE cache is discarded (coarse, M2-i) — the next dispatch re-discovers.
```

**Discovery** (`BlockCompiler.Discover`): starting at `pc`, read the opcode byte *through the
bus* (a peek-equivalent read; discovery is a debugger-view decode, not execution — it must not
perturb), look up `JitDescriptors[opcode]`, append it, advance `pc += descriptor.Length`. Stop
when (a) `descriptor.EndsBlock`, or (b) the block reaches the **64-instruction cap**, or (c)
the next opcode bytes would cross out of the discovered page's fastmem-readable region into
MMIO (a defensive stop — code in MMIO is undefined). The discovered run is a list of
`(pc, descriptor)` pairs.

**Compile** (`BlockCompiler.Compile`): create a `DynamicMethod` with the Ground-truth-D
signature. Emit the entry interrupt check, then each instruction's IL per its descriptor, then
the normal-exit epilogue. Bake the inner CPU's `FieldInfo` handles (`A`,`X`,`Y`,`S`,`P`,`PC`,
`_cycles`) and the fastmem page array into the emitted code. Wrap the delegate in a
`CompiledBlock` recording the entry PC and the set of pages the block's *instruction bytes*
span (for invalidation).

**Execute**: the dispatcher (in `JittedCpu.Run`) calls the block delegate; on `BlockExit.Irq`
it runs `inner.Step()` (which services the interrupt); on `BlockExit.Budget` it returns; on
`BlockExit.Normal` it loops.

**Invalidate**: see Task 5. The dirty map is a per-page `bool[]`; a fastmem RAM store sets
`dirty[page]`; the dispatcher checks, before each block dispatch, whether any dirty page owns a
cached block and if so clears the cache.

## Ground truth C — `AddressSpace.TryGetDirectAccess` (the fastmem seam)

The JIT needs each page's backing array, its offset, and whether it is writable — the page-table
internals `AddressSpace.PageEntry` already holds. Exposed via an internal method (the 2a-era
fastmem intent note: "JIT binds to a concrete `AddressSpace` via an internal view"):

```csharp
// in AddressSpace, with [assembly: InternalsVisibleTo("CpuEmulator.Jit")] on Core:

/// <summary>JIT fastmem view (internal — CpuEmulator.Jit only). For a page-aligned address,
/// reports the backing array + the index of this page's first byte + writability when the page
/// is RAM/ROM (the fastmem fast path). Returns false for peripheral and unmapped pages (the
/// MMIO/open-bus slow path — the JIT emits a bus callout for those). A peek-equivalent view:
/// it never reads or writes, never throws, has no strict-mode behavior — it describes the page.</summary>
internal bool TryGetDirectAccess(uint pageStart, out byte[] backing, out int pageOffset, out bool writable)
{
    ref readonly PageEntry page = ref _pages[(pageStart & AddressMask) >> PageShift];
    if (page.Backing is not null)
    {
        backing = page.Backing;
        pageOffset = page.BackingOffset;   // index of this page's first byte within Backing
        writable = page.Writable;
        return true;
    }
    backing = System.Array.Empty<byte>();
    pageOffset = 0;
    writable = false;
    return false;                          // peripheral or unmapped -> MMIO slow path
}

/// <summary>Page count (= 1 << (AddressBits - 8)); the JIT sizes its fastmem + dirty arrays.</summary>
internal int PageCount => _pages.Length;
```

`Fastmem` (in `Jit`) builds, at `JittedCpu` construction, a `byte[]?[] _pageBacking`, an
`int[] _pageOffset`, and a `bool[] _pageWritable`, one slot per 256-byte page, by calling
`TryGetDirectAccess` for each page. A null `_pageBacking[p]` means "page p is MMIO/unmapped —
emit a bus callout." This array is baked into emitted blocks as a constant reference.

## Ground truth D — the compiled-block signature + exit protocol

```csharp
namespace CpuEmulator.Jit;

/// <summary>How a compiled block returned control.</summary>
public enum BlockExit { Normal, Budget, Irq }

/// <summary>The emitted delegate shape. The DynamicMethod is created with this exact
/// signature; the dispatcher in JittedCpu.Run invokes it. 'cpu' is the wrapped interpreter
/// (emitted IL reads/writes its public fields via baked FieldInfo and calls its bus/Step on
/// the slow paths); 'bus' is the concrete AddressSpace (MMIO callouts go here); 'fastmem' is
/// the page-backing array (direct RAM/ROM access); 'dirty' carries the page-dirty marks for
/// RAM stores; 'budget' is decremented per instruction and drives the budget exit; 'exit'
/// reports why the block returned.</summary>
public delegate void BlockDelegate(
    Mos6502Cpu cpu, AddressSpace bus, byte[]?[] fastmem, DirtyMap dirty,
    ref long budget, out BlockExit exit);
```

> **CPU-agnosticism note:** the signature names `Mos6502Cpu` concretely for M2-i (the only CPU).
> M3 generalizes the wrapped-CPU parameter to the spec's state-bearing type; the *block compiler*
> is already CPU-agnostic (it walks descriptors), so M3's work is the wrapper + field-resolution,
> not the emit loop. Recorded; not built here.

**Cycle charging.** Each emitted instruction adds its `BaseCycles` (plus a runtime +1 when
`PageCrossPenalty` and the emitted page-cross test fires) to a cycle local, and ALSO does the
authentic per-byte work the interpreter does (PC increments, bus reads/writes in order on the
slow path). At every instruction boundary the emitted code subtracts the just-charged cycles
from `budget` and, if `budget <= 0`, sets `inner.PC` to the *next* instruction's PC and exits
`Budget`. **The inner interpreter's `_cycles` is advanced by the emitted block too** — via the
same bus callouts on the slow path (each `ReadBus`/`WriteBus` increments `_cycles`), and on the
fastmem fast path via an emitted `cpu.AdvanceCycles(n)` call (a new `internal` method on the
hand-written `Mos6502Cpu` partial, reached via `InternalsVisibleTo` + `skipVisibility: true` —
see Task 2 for the full seam; chosen over baking a `FieldInfo` for the private `_cycles` so the
generator stays untouched and the interpreter's cycle invariant is honored in one place). This keeps
`CycleCount` == the interpreter's notion at every block exit, which is what `Machine.Run` and
the budget contract read.

## Ground truth E — the accuracy contract (the tier's promise, stated in `jit.md`)

| Dimension | Interpreter (Tier 0) | JIT (Tier 1), fastmem ON (default) | JIT, fastmem OFF (`DisableFastmem`) |
|---|---|---|---|
| Final register/flag state | cycle-exact | **identical** | identical |
| `CycleCount` total | cycle-exact (per bus transaction) | **identical** (same cycle templates + page-cross + interpreter fallbacks) | identical |
| Per-cycle bus trace order | exact (every read/write, dummy reads) | **NOT preserved for fastmem RAM/ROM** — direct array access emits no bus transaction; MMIO accesses DO hit the bus in order | **preserved** — every access routes through the bus |
| Interrupt latency | instruction-boundary | **block-boundary** (checked at block entry; documented) | block-boundary |

**The contract, in one sentence:** *JIT parity is state + cycle-count equivalence; it is NOT
bus-trace equivalence while fastmem is on, because fastmem RAM/ROM access deliberately bypasses
the bus for speed (spec §3 decision #3: the JIT is block-accurate, not cycle-bus-accurate).*
Trace-equivalence is available on demand by constructing the `JittedCpu` with
`JitOptions { DisableFastmem = true }`, which routes every access through the bus and restores
an identical `TracingAddressSpace` trace — this is the mode the trace spot tests (Task 7) use.
This resolves the brief's design tension honestly: the trace tension is real, and the resolution
is to make trace-fidelity a *mode*, not a tier promise.

**Why MMIO stores can't contain code (the invalidation corollary, documented):** the
dirty-page map only tracks *RAM* stores. A store to an MMIO page goes to a device, not to
memory the CPU fetches opcodes from — by the fastmem split's own definition, MMIO pages are
never fastmem-read and never hold cached blocks. So MMIO stores are correctly *not*
dirty-tracked. (A pathological machine that maps RAM-behind-a-device-that-also-decodes-writes
is out of scope; no current machine does this — recorded.)

## Ground truth F — the JIT × device-honest-time × chunked-`Run` interplay (the recorded G2 hazard)

The devices-intake closeout flagged three pinned contracts that assume interpreter granularity.
M2-i resolves each:

| G2 contract | The tension | M2-i resolution |
|---|---|---|
| (a) write-cycle-exact enable timestamp — `Scheduler.CurrentCycle` reads `Cpu.CycleCount`, which must be current at the bus transaction that writes a device-enable register | a JIT that batches cycle updates at block exit would make `CurrentCycle` stale at a mid-block `STA $D100` | **Emitted MMIO stores charge their cycles and advance `inner._cycles` BEFORE the bus callout** (the bus callout is where the device sees the write). So `Cpu.CycleCount` is exact at the device write, identical to the interpreter `WriteBus` ordering (which increments `_cycles` then calls `Write8`). Pinned by a JIT version of the timer-enable-timestamp test. |
| (b) chunked `Machine.Run` hands budgets as small as the gap to the next event; "IRQ at the very next instruction boundary" | a block longer than the budget would overshoot the event, delaying its IRQ past one instruction | **The budget exit fires at the instruction boundary where `budget <= 0`**, so a budget-1 slice (the monitor's per-instruction stepping) executes exactly one instruction then exits — identical to `ICpuCore.Run`'s contract. The block-length cap bounds the worst case; the budget local is the authority. A pending event's IRQ is seen at the *next block entry's* interrupt check, which after a budget exit is the next instruction — block-boundary == instruction-boundary when budgets are tight. |
| (c) a short-period repeating timer fragments every `Run` into period-sized slices | per-64-cycle JIT enter/exit would dominate | **Acknowledged, not optimized in M2-i.** Block *compilation* is cached, so a fragmented `Run` re-*executes* cached blocks (cheap) and only pays dispatch overhead per slice, not recompilation. The compile-once-execute-many property holds even under fragmentation. M2-ii's in-block event-horizon check (decrementing toward the next event, not just the budget) is the optimization; recorded out of scope. The timer-counting UAT session (Ground truth I in devices-intake) re-runs JIT-wrapped and still passes — correctness is unaffected by fragmentation. |

**The unifying principle:** the JIT does not own time or scheduling — the *inner interpreter*
owns `_cycles`, and `Machine.Run` owns chunking. The JIT's emitted blocks advance the inner
`_cycles` exactly as the interpreter would, and exit on budget exactly where `ICpuCore.Run`
would. So `Machine.Run`, `CycleScheduler`, the wired-OR lines, and the device-honest time source
all keep working **unchanged** — they read `Cpu.CycleCount` and call `Cpu.Run(ref budget)`, and
`JittedCpu` honors both contracts. This is why no Core/Machine/scheduler code changes in M2-i.

## Ground truth G — the fastmem rules table (what the compiler emits per access)

For every memory access an emitted instruction performs, the compiler decides at EMIT TIME
(when the page is statically known — true for all current fixed-map boards) or RUN TIME (a
guarded check, when the page index is computed from a register). The address class governs the
emitted code:

| Page class (from `TryGetDirectAccess`) | Emitted READ | Emitted WRITE | Cycle charge | Trace? |
|---|---|---|---|---|
| RAM (backing, writable) | `fastmem[page][offset + (addr & 0xFF)]` — direct array load | direct array store **+ `dirty.Mark(page)`** | charged to the cycle local; `cpu._cycles += 1` | no (fastmem bypasses bus) |
| ROM (backing, not writable) | direct array load | **dropped** (ROM write is a no-op; the interpreter drops it silently too) — no dirty mark | as RAM | no |
| MMIO (no backing; peripheral) | `bus.Read8(addr)` callout — `cpu._cycles` already advanced | `cpu._cycles` advanced **then** `bus.Write8(addr, v)` callout (GT F contract (a)) | the callout's `Read8`/`Write8` do NOT touch `_cycles` (the bus does not); the emitted code charges it | yes (bus sees it) |
| Unmapped (no backing; no peripheral) | `bus.Read8(addr)` → open-bus value (or strict throw — honored, it is a real bus read) | `bus.Write8(addr, v)` → dropped (or strict throw) | as MMIO | yes |
| `DisableFastmem` (any page) | `bus.Read8(addr)` for ALL pages | `bus.Write8(addr, v)` for ALL pages (+ `dirty.Mark` for writable pages, so SMC still works) | as MMIO | yes (every access) |

**Address-classification timing:** for a statically-known effective address (Immediate has no
memory access; ZeroPage/Absolute have a fixed page once the operand bytes are read — but the
operand bytes are themselves *runtime* data, so even ZeroPage's page is runtime in general),
the compiler emits a **runtime page-class branch** keyed on the computed page index against the
baked `fastmem` array: `fastmem[page] is null ? <bus callout> : <direct access>`. The branch is
cheap (one array load + null test) and is what makes fastmem correct for indexed modes that may
cross from RAM into MMIO. For the common case (a fixed-map board where a whole instruction's
access stays in RAM) RyuJIT collapses the branch's hot path. M2-i does NOT attempt emit-time
page specialization (a known-RAM-only optimization) — that is an M2-ii speed refinement; M2-i
emits the safe runtime branch everywhere. Recorded.

**The `_cycles += 1` per fastmem access** mirrors the interpreter's `ReadBus`/`WriteBus`, which
each do `_cycles++` then the bus op. The emitted fastmem path skips the bus op but keeps the
`_cycles++`, so cycle counts match the interpreter byte-for-byte; the MMIO path keeps both. This
is the mechanism behind Ground truth E's "CycleCount identical" row.

```csharp
    private static void EmitJitDescriptors(StringBuilder sb, SpecModel model)
    {
        // Build a 256-slot lookup so absent opcodes get the Undefined sentinel.
        var byOpcode = model.Instructions.ToDictionary(i => i.Opcode);

        sb.AppendLine();
        sb.AppendLine("    /// <summary>Per-opcode JIT descriptor table (generated artifact ③, data form).");
        sb.AppendLine("    /// Indexed by opcode; absent opcodes are the Undefined sentinel. Consumed by");
        sb.AppendLine("    /// CpuEmulator.Jit's CPU-agnostic block compiler. AOT-clean data — no Reflection.Emit");
        sb.AppendLine("    /// here; the JIT assembly is the only place that emits IL.</summary>");
        sb.AppendLine("    public static readonly CpuEmulator.Core.Jit.OpcodeDescriptor[] JitDescriptors =");
        sb.AppendLine("    [");
        for (int op = 0; op <= 0xFF; op++)
        {
            if (byOpcode.TryGetValue((byte)op, out var insn))
                sb.AppendLine($"        {DescriptorLiteral(insn)},");
            else
                sb.AppendLine($"        CpuEmulator.Core.Jit.OpcodeDescriptor.Undefined(0x{op:X2}),");
        }
        sb.AppendLine("    ];");
    }

    /// <summary>One descriptor row as a C# object-creation expression. Reuses ModeLength,
    /// ComputeCycles, and the isPageCross predicate — the SAME functions the interpreter
    /// body emission uses, so the table cannot drift from the interpreter.</summary>
    private static string DescriptorLiteral(InstructionModel insn)
    {
        InstructionClass cls = insn.Class;
        int length = ModeLength(insn.Mode);
        int baseCycles = (cls == InstructionClass.Branch) ? 2 : ComputeCycles(insn.Mode, cls);
        bool pageCross = insn.Mode is "AbsoluteX" or "AbsoluteY" or "IndirectY"
            && cls is InstructionClass.Load or InstructionClass.Alu;
        (string jitClass, bool endsBlock, bool fallback) = ClassifyForJit(insn, cls);
        string ops = string.Join(", ", insn.Ops.Select(JitOpLiteral));
        return $"new(0x{insn.Opcode:X2}, \"{insn.Mnemonic}\", "
             + $"CpuEmulator.Core.Jit.JitMode.{insn.Mode}, "
             + $"CpuEmulator.Core.Jit.JitOpClass.{jitClass}, "
             + $"{length}, {baseCycles}, {(pageCross ? "true" : "false")}, "
             + $"{(fallback ? "true" : "false")}, {(endsBlock ? "true" : "false")}, "
             + $"[{ops}])";
    }
```

  `ClassifyForJit` maps the interpreter's `InstructionClass` to `JitOpClass`, splitting the
  interpreter's coarse `Jump`/`Flow` by op-kind (JMP→`Jump`; JSR→`Jsr`; RTS→`Rts`; BRK/RTI→
  `Flow`+fallback) and setting `NeedsFallback` for ADC/SBC (by `insn.Ops[0].Kind` ∈ {`Adc`,
  `Sbc`}), BRK, RTI; `EndsBlock` = control-flow class OR fallback. `JitOpLiteral` renders an
  `OpModel` as a `new CpuEmulator.Core.Jit.JitOp("Kind", regA, regB, flagBit, boolArg)` (mapping
  `Reg`→byte index, `Flag`→bit). Branch base cycles is pinned to 2 (the minimum; the +1/+1 for
  taken/page-cross are emitted at run time, matching the interpreter's variable branch).

```csharp
namespace CpuEmulator.Jit;

/// <summary>Tier-1 IL-JIT CPU: wraps an interpreter Mos6502Cpu (the oracle + fallback +
/// state owner) and runs cached, compiled blocks for Run. Step always delegates to the inner
/// interpreter (per-instruction fidelity for the monitor + harness). Implements the same
/// ICpuCore + IMonitorSupport surface, so a Machine, a MonitorEngine, and the TomHarte runner
/// drive it identically to the interpreter.</summary>
public sealed class JittedCpu : CpuEmulator.Core.ICpuCore, CpuEmulator.Core.IMonitorSupport
{
    private readonly Mos6502Cpu _inner;
    private readonly AddressSpace _bus;
    private readonly Fastmem _fastmem;
    private readonly BlockCache _cache;
    private readonly BlockCompiler _compiler;

    public JittedCpu(Mos6502Cpu inner, AddressSpace bus, JitOptions? options = null)
    {
        if (!System.Runtime.CompilerServices.RuntimeFeature.IsDynamicCodeSupported)
            throw new System.PlatformNotSupportedException(
                "The IL-JIT tier requires a runtime JIT. This process is NativeAOT or otherwise "
              + "dynamic-code-disabled; use the interpreter (Mos6502Cpu) directly. See docs/user-guide/jit.md.");
        System.ArgumentNullException.ThrowIfNull(inner);
        System.ArgumentNullException.ThrowIfNull(bus);
        _inner = inner;
        _bus = bus;
        var opts = options ?? new JitOptions();
        _fastmem = new Fastmem(bus, opts);
        _cache = new BlockCache(bus.PageCount);
        _compiler = new BlockCompiler(_inner, _bus, _fastmem, opts);
    }

    public string Architecture => _inner.Architecture;
    public long CycleCount => _inner.CycleCount;
    public void Reset() => _inner.Reset();

    /// <summary>One instruction — ALWAYS the interpreter (recorded: Step is the monitor +
    /// harness primitive; per-instruction fidelity is the interpreter's job).</summary>
    public void Step() => _inner.Step();

    /// <summary>Run a cycle budget through cached, compiled blocks. The budget decrement equals
    /// the CycleCount delta; overshoot is bounded by one instruction (the block exits at the
    /// boundary where budget <= 0). On a pending interrupt at a block boundary, the inner
    /// interpreter services it (the 7-cycle sequence, one place).</summary>
    public void Run(ref long cycleBudget)
    {
        while (cycleBudget > 0)
        {
            if (_inner.InterruptPending)         // block-entry interrupt check (dispatcher side)
            {
                long before = _inner.CycleCount;
                _inner.Step();                   // services it authentically
                cycleBudget -= _inner.CycleCount - before;
                continue;
            }
            _cache.InvalidateIfDirty();          // SMC: discard cache if a code page was written
            CompiledBlock block = _cache.GetOrCompile((ushort)_inner.PC, _compiler);
            block.Run(_inner, _bus, _fastmem.PageBacking, _cache.Dirty, ref cycleBudget, out _);
            // Normal/Budget: loop or fall out (cycleBudget drives the while). Irq cannot occur
            // mid-block in M2-i (checked only at entry); the enum carries it for M2-ii chaining.
        }
    }

    // ICpuCore introspection + IMonitorSupport: ALL delegate to the inner interpreter, so the
    // monitor's disassembler/assembler/InterruptPending/register views are byte-identical.
    public void SetIrqLine(bool a) => _inner.SetIrqLine(a);
    public void SetNmiLine(bool a) => _inner.SetNmiLine(a);
    public System.Collections.Generic.IReadOnlyList<string> RegisterNames => _inner.RegisterNames;
    public ulong GetRegister(string n) => _inner.GetRegister(n);
    public void SetRegister(string n, ulong v) => _inner.SetRegister(n, v);
    string CpuEmulator.Core.IMonitorSupport.Disassemble(byte o, byte lo, byte hi)
        => ((CpuEmulator.Core.IMonitorSupport)_inner).Disassemble(o, lo, hi);
    int CpuEmulator.Core.IMonitorSupport.InstructionLength(byte o)
        => ((CpuEmulator.Core.IMonitorSupport)_inner).InstructionLength(o);
    bool CpuEmulator.Core.IMonitorSupport.TryAssemble(string m, string t, out byte[] b, out string? e)
        => ((CpuEmulator.Core.IMonitorSupport)_inner).TryAssemble(m, t, out b, out e);
    public bool InterruptPending => ((CpuEmulator.Core.IMonitorSupport)_inner).InterruptPending;
    public string ProgramCounterName => ((CpuEmulator.Core.IMonitorSupport)_inner).ProgramCounterName;
    public int RegisterBits(string n) => ((CpuEmulator.Core.IMonitorSupport)_inner).RegisterBits(n);
```

```csharp
namespace CpuEmulator.Jit;

internal sealed class BlockCompiler
{
    private readonly Mos6502Cpu _cpu;
    private readonly AddressSpace _bus;
    private readonly Fastmem _fastmem;
    private readonly JitOptions _opts;
    internal int CompileCount { get; private set; }   // test seam (Block_cache_hits pin)

    // Baked field/method handles — resolved once, reused across every block.
    private static readonly FieldInfo FA  = typeof(Mos6502Cpu).GetField("A")!;
    private static readonly FieldInfo FP  = typeof(Mos6502Cpu).GetField("P")!;
    private static readonly FieldInfo FPC = typeof(Mos6502Cpu).GetField("PC")!;
    private static readonly MethodInfo MRead  = typeof(AddressSpace).GetMethod("Read8")!;
    private static readonly MethodInfo MWrite = typeof(AddressSpace).GetMethod("Write8")!;
    private static readonly MethodInfo MAdvance =
        typeof(Mos6502Cpu).GetMethod("AdvanceCycles", BindingFlags.NonPublic | BindingFlags.Instance)!;

    public BlockCompiler(Mos6502Cpu cpu, AddressSpace bus, Fastmem fastmem, JitOptions opts)
        => (_cpu, _bus, _fastmem, _opts) = (cpu, bus, fastmem, opts);

    /// <summary>Decode from pc until an EndsBlock opcode, the length cap, or an MMIO boundary.
    /// Reads opcode bytes through the bus (a debugger-view decode; never executes; stops before
    /// entering MMIO so it never perturbs a device — see the discovery-read note).</summary>
    public System.Collections.Generic.List<(ushort Pc, OpcodeDescriptor D)> Discover(ushort pc)
    {
        var run = new System.Collections.Generic.List<(ushort, OpcodeDescriptor)>();
        for (int i = 0; i < _opts.BlockLengthCap; i++)
        {
            byte opcode = _bus.Read8(pc);
            OpcodeDescriptor d = Mos6502Cpu.JitDescriptors[opcode];
            run.Add((pc, d));
            if (d.EndsBlock) break;
            pc = unchecked((ushort)(pc + d.Length));
        }
        return run;
    }

    public CompiledBlock Compile(ushort entryPc)
    {
        CompileCount++;
        var run = Discover(entryPc);
        var dm = new DynamicMethod(
            $"block_{entryPc:X4}", typeof(void),
            [typeof(Mos6502Cpu), typeof(AddressSpace), typeof(byte[]?[]),
             typeof(DirtyMap), typeof(long).MakeByRefType(), typeof(BlockExit).MakeByRefType()],
            typeof(BlockCompiler).Module, skipVisibility: true);   // reach the AdvanceCycles seam
        ILGenerator il = dm.GetILGenerator();
        var ctx = new EmitContext(il);

        EmitEntryInterruptCheck(ctx);     // Task 4 lands the full check; Task 2 emits a stub
        foreach (var (pc, d) in run)
        {
            EmitInstruction(ctx, pc, d);
            EmitBudgetCheck(ctx, (ushort)(pc + d.Length));  // the budget exit stub (below)
        }
        EmitNormalExit(ctx);
        var del = (BlockDelegate)dm.CreateDelegate(typeof(BlockDelegate));
        return new CompiledBlock(entryPc, del, PagesSpanned(run));
    }

    /// <summary>Emit one instruction. NeedsFallback rows emit a callout to inner.Step() (the
    /// safety valve). The ZeroPage-load arm is shown in full; the rest mirror CpuEmitter.</summary>
    private void EmitInstruction(EmitContext ctx, ushort pc, OpcodeDescriptor d)
    {
        if (d.NeedsFallback) { EmitFallbackStep(ctx); return; }
        switch (d.Class)
        {
            case JitOpClass.Load: EmitLoad(ctx, d); break;
            case JitOpClass.Store: EmitStore(ctx, d); break;
            // ... Register, Transfer, Alu (non-ADC/SBC), Rmw, Branch, Jump, Jsr, Rts ...
            default: throw new EmulationException(
                $"BlockCompiler has no emit arm for class '{d.Class}' (opcode 0x{d.Opcode:X2}); "
              + "a JIT bug — the descriptor said it was emittable but no arm exists.");
        }
    }

    // ── The worked example: LDA $zp (Load class, ZeroPage mode) ──────────────────────────
    // Interpreter reference (Op05/OpA5 in Mos6502Cpu.g.cs):
    //   uint addr = ReadBus(PC); PC = (ushort)(PC + 1);   // operand fetch — 1 cycle
    //   byte data = ReadBus(addr);                          // zp data read  — 1 cycle
    //   A = data; P = (P & 0x7D) | (A==0?2:0) | (A&0x80);   // load + SetNZ (+ opcode fetch 1 = 3 total)
    private void EmitLoad(EmitContext ctx, OpcodeDescriptor d)
    {
        ILGenerator il = ctx.Il;
        switch (d.Mode)
        {
            case JitMode.ZeroPage:
                EmitReadAtPC(ctx);                            // pushes (byte)bus[PC]; charges 1 cycle
                il.Emit(OpCodes.Stloc, ctx.AddrLocal);        // addr = operand byte (0..255)
                EmitIncrementPC(ctx, 1);
                il.Emit(OpCodes.Ldloc, ctx.AddrLocal);        // push addr
                LoadByteFromBus(ctx);                          // pushes data byte; charges 1 cycle
                il.Emit(OpCodes.Stloc, ctx.DataLocal);
                il.Emit(OpCodes.Ldarg_0);                      // cpu
                il.Emit(OpCodes.Ldloc, ctx.DataLocal);
                il.Emit(OpCodes.Stfld, FA);                    // A = data
                EmitSetNZ(ctx, FA);                            // P = (P & 0x7D) | (A==0?2:0) | (A&0x80)
                EmitChargeOneCycle(ctx);                       // opcode-fetch cycle (total 3 == BaseCycles)
                break;
            case JitMode.Immediate: /* operand IS the data; one code read; A=data; SetNZ; +fetch */ break;
            case JitMode.Absolute:  /* lo=read PC++, hi=read PC++, ea=lo|hi<<8, data=read ea; +fetch */ break;
            // AbsoluteX/Y, IndirectX/Y: indexed forms with the emitted page-cross +1 test
            // (PageCrossPenalty); mirror CpuEmitter.EmitOperandResolution exactly.
            default: throw new EmulationException($"Load: no arm for mode {d.Mode}");
        }
    }
}
```

  **`LoadByteFromBus` — the fastmem/bus branch (Ground truth G), shared by every memory read:**

```csharp
    /// <summary>Emit a byte read of the address on the IL stack. Emits the runtime page-class
    /// branch: fastmem[page] null -> bus.Read8 (MMIO/unmapped); else direct array load. Either
    /// way charges 1 cycle (matching the interpreter ReadBus). When DisableFastmem, always
    /// emits bus.Read8.</summary>
    private void LoadByteFromBus(EmitContext ctx)
    {
        ILGenerator il = ctx.Il;
        il.Emit(OpCodes.Stloc, ctx.EaLocal);                 // ea = address
        EmitChargeOneCycle(ctx);                              // AdvanceCycles(1) + budget-=1 BEFORE access
        if (_opts.DisableFastmem)
        {
            il.Emit(OpCodes.Ldarg_1);                         // bus
            il.Emit(OpCodes.Ldloc, ctx.EaLocal);
            il.Emit(OpCodes.Callvirt, MRead);                 // bus.Read8(ea) -> byte
            return;
        }
        Label mmio = il.DefineLabel(), done = il.DefineLabel();
        il.Emit(OpCodes.Ldarg_2);                             // fastmem (byte[]?[])
        il.Emit(OpCodes.Ldloc, ctx.EaLocal); il.Emit(OpCodes.Ldc_I4_8); il.Emit(OpCodes.Shr_Un);
        il.Emit(OpCodes.Ldelem_Ref);                          // fastmem[page] (byte[] or null)
        il.Emit(OpCodes.Dup); il.Emit(OpCodes.Brfalse, mmio); // null -> MMIO
        EmitFastmemIndex(ctx);                                 // backing[offset(page) + (ea & 0xFF)] -> byte
        il.Emit(OpCodes.Br, done);
        il.MarkLabel(mmio);
        il.Emit(OpCodes.Pop);                                  // drop the null backing
        il.Emit(OpCodes.Ldarg_1); il.Emit(OpCodes.Ldloc, ctx.EaLocal); il.Emit(OpCodes.Callvirt, MRead);
        il.MarkLabel(done);
    }
```

  **The budget exit stub (the cc_interrupt pattern, Ground truth B step 2):**

```csharp
    /// <summary>After each instruction, check the budget. The instruction has already charged
    /// its cycles into the budget via EmitChargeOneCycle (which does cpu.AdvanceCycles(1) AND
    /// budget-=1 together). If budget <= 0, set PC to the NEXT instruction (nextPc) and exit
    /// Budget. This is the only overshoot source: a block runs one instruction past the zero
    /// crossing, bounded to one instruction.</summary>
    private void EmitBudgetCheck(EmitContext ctx, ushort nextPc)
    {
        ILGenerator il = ctx.Il;
        Label keepGoing = il.DefineLabel();
        il.Emit(OpCodes.Ldarg_S, (byte)4);                   // ref long budget
        il.Emit(OpCodes.Ldind_I8);
        il.Emit(OpCodes.Ldc_I4_0); il.Emit(OpCodes.Conv_I8);
        il.Emit(OpCodes.Bgt, keepGoing);                     // budget > 0 -> continue the block
        // budget exhausted: PC = nextPc; exit = Budget; ret
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Ldc_I4, (int)nextPc); il.Emit(OpCodes.Conv_U2);
        il.Emit(OpCodes.Stfld, FPC);
        il.Emit(OpCodes.Ldarg_S, (byte)5);                   // out BlockExit exit
        il.Emit(OpCodes.Ldc_I4, (int)BlockExit.Budget); il.Emit(OpCodes.Stind_I4);
        il.Emit(OpCodes.Ret);
        il.MarkLabel(keepGoing);
    }
```

  > **EmitChargeOneCycle** does both halves of cycle bookkeeping in one place: `cpu.AdvanceCycles(1)`
  > (so `CycleCount` tracks) AND `budget -= 1` (so the budget exit fires). This keeps the
  > "decrement == CycleCount delta" contract true by construction — every charged cycle moves
  > both counters together.

```csharp
    /// the interpreter's ReadBus/WriteBus), subtracts the consumed cycles from budget, then
    /// exits the block (the post-Step PC is dynamic — the block cannot statically continue).</summary>

        // long before = cpu.CycleCount; cpu.Step(); budget -= cpu.CycleCount - before;
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Callvirt, MCycleCount); il.Emit(OpCodes.Stloc, ctx.TmpLong);
        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Callvirt, MStep);

        il.Emit(OpCodes.Ldarg_0); il.Emit(OpCodes.Callvirt, MCycleCount);
        il.Emit(OpCodes.Ldloc, ctx.TmpLong); il.Emit(OpCodes.Sub);    // consumed
        il.Emit(OpCodes.Sub); il.Emit(OpCodes.Stind_I8);              // budget -= consumed
        EmitNormalExit(ctx);                                          // PC already set by Step
    }
```

```csharp
namespace CpuEmulator.Jit;

/// <summary>Per-page dirty marks. An emitted RAM store calls Mark(page); the dispatcher
/// consults the marks before each block dispatch (the cc-cheap SMC check).</summary>
public sealed class DirtyMap(int pageCount)
{
    private readonly bool[] _dirty = new bool[pageCount];
    public bool Any { get; private set; }
    public void Mark(int page) { _dirty[page] = true; Any = true; }
    public bool this[int page] => _dirty[page];
    public void Clear() { System.Array.Clear(_dirty); Any = false; }
}

internal sealed class BlockCache(int pageCount)
{
    private readonly System.Collections.Generic.Dictionary<ushort, CompiledBlock> _blocks = new();
    private readonly System.Collections.Generic.HashSet<int> _pagesWithBlocks = [];
    public DirtyMap Dirty { get; } = new(pageCount);

    public CompiledBlock GetOrCompile(ushort pc, BlockCompiler compiler)
    {
        if (_blocks.TryGetValue(pc, out var hit)) return hit;
        CompiledBlock block = compiler.Compile(pc);
        _blocks[pc] = block;
        foreach (int page in block.SpannedPages) _pagesWithBlocks.Add(page);
        return block;
    }

    /// <summary>The SMC check, run before each dispatch. If any dirty page owns a cached block,
    /// discard the WHOLE cache (coarse, M2-i — cheap because there is no chaining to unlink) and
    /// clear the marks. A write to a page with no cached block clears its mark without a flush.</summary>
    public void InvalidateIfDirty()
    {
        if (!Dirty.Any) return;
        bool hitCode = false;
        foreach (int page in _pagesWithBlocks)
            if (Dirty[page]) { hitCode = true; break; }
        if (hitCode)
        {
            _blocks.Clear();
            _pagesWithBlocks.Clear();
        }
        Dirty.Clear();   // marks are consumed each dispatch cycle
    }
}
```

  The compiler emits `dirty.Mark(page)` only on **writable-RAM** stores (ROM stores are dropped;
  MMIO stores route to the bus, never marking). `CompiledBlock.SpannedPages` is the set of pages
  the block's instruction *bytes* occupy (computed in `Discover`/`Compile` from the
  `(pc, length)` span). Under `DisableFastmem`, stores still `dirty.Mark` writable pages (so SMC
  works in trace mode too — Ground truth G last row).
