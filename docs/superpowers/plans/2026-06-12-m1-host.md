**Goal:** spec §9 item 7 — **a runnable live machine**. `dotnet run --project
src/CpuEmulator.Host` boots a `Breadboard6502` (RAM + demo ROM window + `SimpleUart`) and
drops into the monitor REPL on stdio; the user loads/assembles/runs programs and talks to the
UART. The user's hands-on milestone — UX matters: clear banner, `?` help, a documented (not
over-engineered) Ctrl/EOF story. Five fronts: (1) **`CpuEmulator.Peripherals`** with
`SimpleUart : IPeripheral` — a polled 4-register MMIO window, byte-queue in / byte-sink out;
(2) the **`Breadboard6502`** composition with a demo ROM **assembled at startup by the
generated assembler** (artifact ⑤ eating its own dogfood); (3) the recorded-intake Monitor
additions — the **scheduler-aware run delegate** (`g`/`s` route through `Machine.Run` so
peripherals tick) and the **`i` input-inject command**; (4) the **Host program** with
default-REPL, `--demo`, and `--load` modes; (5) **headless end-to-end UAT sessions** plus a
README "Try it" quickstart with a real transcript. PR #8 of Milestone 1 (branch
`feat/m1-host`, base `main`, branched after PR #7 merges — head `37374fb` is the baseline).

**Architecture:** nothing in Core, the generator, or the spec table changes. `SimpleUart` is
CPU-agnostic and Core-only; sub-page decode (`offset & 0x03`) lives in the device per the
`AddressSpace` contract, so one page-mapped UART mirrors through its page like real
partially-decoded hardware. `Breadboard6502` lives in the Host project (it names
`Mos6502Cpu`). The monitor seam is one optional ctor delegate `Func<long, long>` (budget in,
cycles out): `Run/Step/RunUntil` route every slice through it; the host passes `Machine.Run`;
null preserves today's bare-CPU behavior byte-for-byte. `Step`/`RunUntil` slice at budget 1 —
safe because both `Machine.Run` and the generated `ICpuCore.Run` are while-loops over
`Step()` with a ≥1-cycle floor, so budget 1 executes exactly one instruction (verified:
`Mos6502Cpu.g.cs` `Run` = `while (cycleBudget > 0) Step()`; `Machine.Run` exits the moment
`CycleCount >= target`).

**Tech stack:** unchanged (net10.0, Roslyn 4.12.0, xUnit 2.9.3) + two new projects:
`src/CpuEmulator.Peripherals` (net10.0, `IsAotCompatible`, Core-only — the spec §3 AOT-clean

- **Demo message:** `"Hello from Breadboard6502!\r\n"` — 26 chars + CR LF = **28 bytes** at

- **Hello-phase cycles:** reset 7 + `LDX` 2 + 28 × (`LDA abs,X` 4 + `BEQ` not-taken 2 +

  **436 cycles** from power-on to the echo loop, message fully transmitted.
- **Echo-loop costs:** idle poll = 4+2+3 = **9**; one echoed byte = 4+2+2+4+4+3 = **19**.
  UAT budgets: `g 1000` covers hello (436) with margin; `g 200` covers two echoed bytes (38)
  plus idle polls; `--demo`'s 10,000 is ~20× the hello cost.
- **Run-delegate one-instruction property (the seam's load-bearing fact):** generated
  `Run(ref long)` is `while (cycleBudget > 0) { Step(); … }` (Mos6502Cpu.g.cs:227–235) and
  `Machine.Run(1)` exits after one inner `Cpu.Run` because every instruction advances
  `CycleCount` ≥ 1 ≥ target−start (Machine.cs:64–81; `ICpuCore.Step` "always advances … by
  at least one"). Budget 1 ⇒ exactly one instruction, both drivers.
- **Klaus smoke geometry (unchanged from PR #7):** success trap $3469; a passing run needs
  ~96M cycles (actual 96,241,367); the 1M-cycle slice cannot legitimately trap. Through the
  host, image bytes ≥ $D000 do not land (ROM ignore + UART tee + open-bus ignore) — and the
  slice never reads them; execution stays below $4000.

## Ground truth A — `SimpleUart` register map (tests assert these verbatim)

Mapped over one 256-byte page; the device decodes `offset & 0x03`, so the four registers
mirror 64 times through the page (authentic partial decode — `$D004` is DATA again).

| Offset (&0x03) | Name | Read | Write |
|---|---|---|---|
| 0 | DATA | dequeue next rx byte; **0x00 when the queue is empty** (documented — no error, open-line idle) | transmit: invoke `OnTransmit` with the low byte (null sink ⇒ byte dropped) |
| 1 | STATUS | bit0 = rx-ready (queue non-empty), bit1 = tx-ready (**always 1** — transmit is instantaneous in M1), bits 2–7 = 0 | ignored |
| 2 | — | reserved: 0x00 | ignored |
| 3 | — | reserved: 0x00 | ignored |

**Behavior contracts:** STATUS reads NEVER dequeue (peek semantics — poll loops spin on it);
DATA reads are destructive by hardware nature, so a monitor `m` dump over DATA dequeues —
**documented known monitor-over-MMIO behavior** (recorded intake; Peek API = monitor-v2
backlog). `AccessWidth` ignored (8-bit device; values mask to a byte). Sinks: ctor takes
nothing; `FeedInput(byte)` enqueues rx (`ConcurrentQueue<byte>`, the recorded choice);
`Action<byte>? OnTransmit` fires per tx byte. `Realize` claims nothing (polled I/O; rx-IRQ
recorded for the timer milestone).

## Ground truth B — `Breadboard6502` memory map

| Range | Mapping | Notes |
|---|---|---|
| $0000–$CFFF | RAM (52 KiB) | `WithRam`; zero page, stack, user program space ($0200 is the house origin) |
| $D000–$D0FF | `SimpleUart` (1 page) | DATA $D000, STATUS $D001; mirrors every 4 bytes through the page |
| $D100–$DFFF | unmapped | open-bus reads 0xFF, writes ignored (default non-strict options) |
| $E000–$FFFF | ROM (8 KiB) | `DemoRom.Build()` image: demo program + message + all three vectors |

Vectors (in ROM): NMI/RESET/IRQ all = $E000 — restart the demo (no handlers; nothing asserts
lines in M1). CPU: default `UndefinedOpcodePolicy.Throw` — jumping into garbage surfaces as
an `EmulationException`-derived throw, which the REPL already catches into a `? ` line and
survives (PR #7's strict-bus-survival posture).

```csharp
using System.Collections.Concurrent;
using CpuEmulator.Core;

namespace CpuEmulator.Peripherals;

/// <summary>
/// Minimal polled UART: a 4-register window, partially decoded (offset &amp; 0x03), so the
/// device mirrors through whatever page span it is mapped over — authentic partial decode
/// (sub-page decode is the peripheral's job per the AddressSpace contract).
///
///   offset 0  DATA    read: dequeue next rx byte (0x00 when empty)    write: transmit
///   offset 1  STATUS  read: bit0 rx-ready, bit1 tx-ready (always 1)   write: ignored
///   offset 2/3        reserved: read 0x00                             write: ignored
///
/// STATUS reads never dequeue (peek semantics). DATA reads are destructive by hardware
/// nature: a monitor 'm' dump over DATA dequeues rx — documented known monitor-over-MMIO
/// behavior (the Peek API is monitor-v2 backlog). Byte sinks: FeedInput(byte) enqueues rx;
/// OnTransmit fires per transmitted byte. Polled I/O only in M1 — rx-IRQ joins the timer
/// milestone (recorded), so Realize claims nothing. AccessWidth is ignored (8-bit device).
/// </summary>
public sealed class SimpleUart : IPeripheral
{
    private readonly ConcurrentQueue<byte> _rx = new();

    public string Name => "uart";

    /// <summary>Per-byte transmit sink. Null is allowed — transmitted bytes are dropped.</summary>
    public Action<byte>? OnTransmit { get; set; }

    /// <summary>Queue one byte for the guest to read from DATA.</summary>
    public void FeedInput(byte value) => _rx.Enqueue(value);

    /// <summary>Polled I/O: no IRQ claims, no scheduled events (rx-IRQ is recorded for the
    /// timer milestone — it will claim context.IrqLine here when it lands).</summary>
    public void Realize(IMachineContext context) { }

    public uint Read(uint offset, AccessWidth width) => (offset & 0x03) switch
    {
        0 => _rx.TryDequeue(out byte value) ? value : 0x00u,  // DATA: destructive read
        1 => (uint)((_rx.IsEmpty ? 0x00 : 0x01) | 0x02),      // STATUS: peek only
        _ => 0x00u,                                            // reserved
    };

    public void Write(uint offset, AccessWidth width, uint value)
    {
        if ((offset & 0x03) == 0)
            OnTransmit?.Invoke(unchecked((byte)value));        // DATA: transmit
        // STATUS/reserved writes ignored
    }
}
```

```csharp
using CpuEmulator.Core;
using CpuEmulator.Cpus.Mos6502;
using CpuEmulator.Monitor;

namespace CpuEmulator.Host;

/// <summary>
/// The breadboard's 8 KiB ROM image ($E000–$FFFF), assembled AT STARTUP by the generated
/// single-instruction assembler (artifact 5 eating its own dogfood): a hello-print loop,
/// then a polled echo loop. Only data is poked — message bytes, NUL, vectors.
/// Assembly happens in a SCRATCH space mapping the SAME byte[] writable at the SAME
/// addresses: the live breadboard maps this image read-only, and TryAssembleAt over
/// non-strict ROM is a silent no-op (the recorded a-over-ROM behavior).
/// </summary>
public static class DemoRom
{
    public const ushort Entry = 0xE000;
    public const ushort MessageAddress = 0xE01E;
    public const string Message = "Hello from Breadboard6502!\r\n";

    public static byte[] Build()
    {
        var image = new byte[0x2000];
        var scratch = new AddressSpace(AddressSpaceKind.Program, addressBits: 16);
        scratch.MapMemory(0xE000, image, writable: true);
        var cpu = new Mos6502Cpu(scratch);
        var assembler = new MonitorEngine(cpu, scratch, cpu);

        uint pc = Entry;
        foreach (string line in new[]
        {
            "LDX #$00",      // E000  entry: reset vector lands here
            "LDA $E01E,X",   // E002  next message byte
            "BEQ $E00E",     // E005  NUL terminator -> echo loop
            "STA $D000",     // E007  UART DATA: transmit
            "INX",           // E00A
            "JMP $E002",     // E00B  print loop
            "LDA $D001",     // E00E  echo: poll STATUS
            "AND #$01",      // E011  rx-ready?
            "BEQ $E00E",     // E013  not ready -> poll
            "LDA $D000",     // E015  DATA: dequeue rx
            "STA $D000",     // E018  DATA: echo it back
            "JMP $E00E",     // E01B  echo forever
        })
        {
            if (!assembler.TryAssembleAt(pc, line, out byte[] bytes, out string? error))
                throw new EmulationException(
                    $"demo ROM assembly failed at ${pc:X4} '{line}': {error}");
            pc += (uint)bytes.Length;
        }
        if (pc != MessageAddress)
            throw new EmulationException(
                $"demo ROM layout drifted: cursor ${pc:X4}, expected ${MessageAddress:X4}.");

        foreach (char c in Message)
            scratch.Write8(pc++, (byte)c);
        scratch.Write8(pc, 0x00);                              // terminator
        scratch.Write8(0xFFFA, 0x00); scratch.Write8(0xFFFB, 0xE0); // NMI    -> entry
        scratch.Write8(0xFFFC, 0x00); scratch.Write8(0xFFFD, 0xE0); // RESET  -> entry
        scratch.Write8(0xFFFE, 0x00); scratch.Write8(0xFFFF, 0xE0); // IRQ/BRK -> entry
        return image;
    }
}
```
