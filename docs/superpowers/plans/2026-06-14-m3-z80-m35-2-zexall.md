gate (the Klaus analog for the Z80). Build a minimal in-test CP/M host: a BDOS stub (functions 2 + 9 for

complete (M3.4e green; the whole base→FDCB sweep is TomHarte-green), so ZEXALL is a black-box confirmation of

## Scope

**IN scope (the integration harness):**

1. **A minimal CP/M BDOS stub.** Intercept a `CALL 0x0005` (the BDOS entry). Implement the two console
   functions ZEX uses:
   - **Function 2 — console out:** print the character in register `E`. Append it to the transcript.
   - **Function 9 — print string:** print the `$`-terminated string starting at the address in `DE`. Append
     each char to the transcript; stop at the `$` (0x24) terminator.
   - For any other function code (in `C`), the stub does nothing (returns). ZEX uses only 2 + 9.
   - The stub does NOT execute a real BDOS; it reads the CPU registers (`C`, `E`, `DE`), performs the host-side
     effect, then forces a `RET` (pop the return address the `CALL 5` pushed, set PC to it). It is driven from
     the run loop, OUTSIDE the CPU, so no Z80 code for the BDOS is needed.
2. **The CP/M low-memory image.** A `.com` program expects the standard CP/M Page Zero:
   - **0x0000 — WBOOT (warm boot):** a `JP 0x0000`-style termination sentinel. ZEX finishes by `RET`ing to
     0x0000 (its initial stack holds 0x0000, the CP/M return-to-CCP convention), or by an explicit `JP 0x0000`.
     The harness treats PC reaching 0x0000 as the termination condition.
   - **0x0005 — BDOS entry:** the byte the program `CALL`s for OS services. The harness intercepts a `CALL`
     whose target is 0x0005 (it does NOT need real code at 0x0005 — the intercept fires on the call target).
   - **0x0100 — TPA:** the `.com` image is loaded here; execution starts here.
3. **The `.com` loader.** Read the `.com` bytes, copy them into RAM starting at 0x0100, set PC := 0x0100,
   SP := a sane high value (the standard CP/M top-of-TPA; ZEX sets up its own stack early, but seed 0xFFFE /
   the documented CP/M value so the initial `RET`-to-0x0000 termination works). Seed Page Zero (0x0000 holds
   the warm-boot sentinel; 0x0005 is the BDOS hook target).
4. **The bounded run loop + termination.** Loop `cpu.Step()`. BEFORE each step, check whether PC == 0x0005
   (about to enter BDOS) — if so, service the BDOS call (read `C`/`E`/`DE`, do the console effect, pop the
   return address, set PC) and continue WITHOUT stepping the (absent) BDOS code. Terminate when PC == 0x0000
   (warm boot). Bound the whole run by a generous cycle budget; if the budget is exhausted before termination,
   FAIL with a diagnostic (PC + a transcript tail).
5. **The transcript assertion.** Capture every console byte into a `StringBuilder`. After termination, assert
   the transcript contains the ZEX completion banner and contains NO `ERROR` token. ZEX prints, per sub-test,
   the test name followed by `OK` or `ERROR <crc> <expected-crc>` (and a final summary line). The gate: zero
   `ERROR` lines AND the run terminated (did not exhaust the budget).
6. **Both exercisers, staged.** ZEXDOC (documented flags) runs as the faster pre-check; ZEXALL (all flags incl.
   X/Y) is the strict gate (D8). Both are full ZEX runs (billions of T-states) — see "CI / runtime" below for
   the env-gate that keeps the default `dotnet test` fast.
7. **The fetch scripts + provenance.** `tools/get-zexall.ps1` + `tools/get-zexall.sh` fetch `zexall.com` +
   `zexdoc.com` into `<cache>/zex/`, mirroring `tools/get-klaus.{ps1,sh}`. A skip-when-absent attribute
   (`ZexFact`) skips the harness at discovery when the binaries are missing (so CI without the fetch is green,
   exactly like Klaus + the Z80 TomHarte vectors).

**OUT of scope (each is later / separate):**

- **A real `CpuEmulator.Hosts.CpmZ80` machine.** D6 — YAGNI. The harness is a throwaway test fixture; promoting
  it to a real host (with `MachineBuilder` wiring, a real BDOS peripheral, file I/O) is gated behind M3.6 being
  greenlit. If M3.6 lands, the fixture's BDOS-intercept + loader logic is the seed for the real host (noted in
  the closeout as the promotion path).
- **Interrupt-path coverage.** ZEXALL/ZEXDOC are PURE-COMPUTATION exercisers — they do NOT assert interrupt
  servicing (no IM-mode / NMI / IFF round-trip tests). Task 1 CONFIRMS this empirically (the harness runs
  without any IRQ/NMI line ever asserted; if ZEX needed an interrupt the run would hang or mis-CRC). So the
  full ZEX pass does NOT strictly depend on M3.5-1 — it depends only on the complete interpreter (M3.4e).
  M3.5-1 is nonetheless merged (#29), so this is not a blocking concern; the closeout records the confirmation.
- **A full CP/M BDOS.** Only functions 2 + 9 (console out / print string) are implemented. File I/O, the FCB,
  disk functions, and the other ~40 BDOS calls are NOT — ZEX uses only console output. Any other function code
  is a silent `RET` (recorded; if a future ZEX variant needs more, it surfaces as a hang and is added then).
- **The CCP / a CP/M command line.** The `.com` is loaded + jumped directly; no CCP, no command-tail parsing
  (the FCB/command-tail area at 0x005C/0x0080 is zeroed — ZEX needs no arguments).
- **A cycle-exact ZEX timing assertion.** The gate is the CRC PASS (`OK`, no `ERROR`), not a T-state total.
  ZEX self-validates via CRC; the harness asserts the transcript, not `CycleCount`.
- **JIT-through-ZEXALL.** Running ZEX through the JIT is M3.5-3 (the tier-parity proof). This slice is the
  interpreter gate only.

  `Z80InterruptServicingTests.BuildCpu()` (the M3.5-1 UAT) is the simplest construction template (no vector
  case): map a fresh 64 KiB program RAM, a 16-bit I/O space, `new Z80Cpu(bus, io)`. **The ZEX harness needs
  only the program bus — ZEX does no I/O — but pass a fresh I/O space anyway (the ctor's second arg) to match
  the construction shape.**
- **The Z80 register API the harness uses (CONFIRM the exact names at Task 0).** From the TomHarte runner
  (`Z80TomHarteRunner.cs:40-49`): `SetRegister`/`GetRegister` keys include `"PC"`, `"SP"`, `"A"`, `"F"`,
  `"B"`–`"L"`, `"I"`, `"R"`, `"IX"`, `"IY"`, `"WZ"`, the alt-pair views `"AF_"`/`"BC_"`/`"DE_"`/`"HL_"`, and
  `"DE"` (the pair view — used by BDOS function 9 to read the string pointer). `cpu.CycleCount` (long) is the
  budget counter; `cpu.Step()` runs one instruction. The harness reads `"C"` (the BDOS function code), `"E"`
  (function 2's char), and `"DE"` (function 9's pointer). **Confirm `"DE"` is a valid pair-view key for
  GetRegister at Task 0** (the runner sets `DE_` for the alt set; the main `DE` pair view must exist — the
  generated register file emits both halves and the pair view; verify by reading the spec's `Registers` table,
  `src/CpuEmulator.Cpus.Z80/Z80Spec.cs:30-50`, and the generated accessor — if `"DE"` is absent, read `"D"`
  and `"E"` and combine: `(D << 8) | E`).
- **`Run(ref long cycleBudget)` exists but the harness does NOT use it.** `CpuEmitter.cs:256-264` emits a
  `Run` that loops `Step()` until the budget is spent — but it does NOT expose the per-step PC so the BDOS
  intercept cannot fire inside it. **The harness loops `Step()` itself** (the Klaus pattern), checking PC ==
  0x0005 before each step. Do NOT use `Run` (it would step through the absent BDOS code and crash/hang).
- **`Step()` services interrupts first, then idles on halt, then fetches.** `CpuEmitter.cs:145-200`: `Step`
  calls `TryServiceInterrupt()` (returns false — no line asserted in the harness), then (Z80 has a HaltOp)
  idles if `Halted`, then fetches. **ZEX never HALTs and never asserts an interrupt line, so every `Step` is a
  plain fetch-execute.** (Re-confirm ZEX has no HALT in Task 1: if a ZEX run ever sets `_halted` with no
  pending interrupt, the run would idle-spin to budget exhaustion — the budget-exhaustion FAIL catches it.)

## The pinned CP/M facts (with sources)

> These are the well-established CP/M-80 Page-Zero conventions ZEX relies on. Sources: the CP/M 2.2 Interface
> Guide (Digital Research), the standard CP/M memory map, and cross-checked against how every Z80-emulator ZEX
> harness drives it (e.g. anotherlin/z80emu's `zextest.c`, floooh's z80 ms1 writeup). The harness pins these
> as the loader + intercept contract.

| Address | Role | What the harness does |
|---|---|---|
| **0x0000** | WBOOT (warm boot) | Termination sentinel. ZEX `RET`s here (initial stack top = 0x0000) when done; the loop terminates when PC reaches 0x0000. Seed: leave 0x0000 as whatever; the loop checks PC, not the byte. |
| **0x0005** | BDOS entry | The `CALL 0x0005` target. The harness intercepts a step whose PC == 0x0005 and services the call host-side (read regs, do console effect, `RET`). No real code at 0x0005 is needed. |
| **0x0100** | TPA base | The `.com` image is copied here; PC := 0x0100 at start. |
| **0x005C–0x007F** | default FCB | Zeroed (ZEX needs no file args). |
| **0x0080–0x00FF** | default DMA / command tail | Zeroed (length byte 0 at 0x0080 = empty command tail). |

**The BDOS call ABI (CONFIRM, the harness implements):**

- The program loads the **function code into `C`** and calls 0x0005.
- **Function 2 (console out):** the character is in **`E`**. Effect: emit `(char)E`.
- **Function 9 (print string):** **`DE`** points at a `$`-terminated string (terminator = `$` = 0x24).
  Effect: emit bytes from `[DE]` until `$`.
- The BDOS returns via the address the `CALL` pushed. The harness services the effect, then pops two bytes
  off the stack (`SP` → return address, little-endian: `lo = [SP]`, `hi = [SP+1]`, `SP += 2`) and sets
  `PC := (hi << 8) | lo`. This is the host-side `RET` (the same pop the real BDOS's `RET` would do).

**The termination contract (CONFIRM at Task 1 against the actual run):**

- ZEX's startup sets its return address such that the final `RET` lands at 0x0000 (warm boot). The harness
  seeds `SP` so the bottom of ZEX's stack frame holds 0x0000 — **but ZEX sets up its own stack early**, so the
  reliable termination signal is **PC reaching 0x0000** by ANY route (the `RET`-to-WBOOT). Pin PC == 0x0000 as
  the terminator; the cycle budget is the safety net. (If Task 1 finds ZEX terminates differently — e.g. a
  specific `JP 0x0000` or a tight self-loop — record the actual signal and pin THAT. The empirical run wins.)

## The `.com` provenance / fetch plan (D6 — pinned)

**What ZEXALL/ZEXDOC are:** Frank D. Cringle's Z80 instruction set exerciser (written 1994). `zexdoc.com`
exercises every Z80 instruction checking the **six documented flags**; `zexall.com` checks the documented
flags **plus the undocumented X (bit 3) + Y (bit 5)** flags. Each is a self-contained CP/M-80 `.com` program
that prints, per sub-test (~67 sub-tests), the test name + `OK` or `ERROR <crc> <expected-crc>`, via BDOS
console output, then warm-boots.

**Confirmed fetch source (primary):** the **`agn453/ZEXALL`** GitHub repository
(`https://github.com/agn453/ZEXALL`) — actively curated, carries the pre-built `zexall.com` + `zexdoc.com`

**License: GNU GPL v2.0** (the repo's stated license), original author **Frank D. Cringle**. Raw binary URLs:
- `https://raw.githubusercontent.com/agn453/ZEXALL/main/zexall.com`
- `https://raw.githubusercontent.com/agn453/ZEXALL/main/zexdoc.com`

**Confirmed fetch source (mirror / fallback):** **`begoon/z80exer`**

## CI / runtime — keeping the default `dotnet test` fast (the staged gate)

ZEXALL runs **billions of T-states** (a full pass is minutes-to-tens-of-minutes of emulated execution on a
software interpreter, depending on host speed). The default `dotnet test` must stay fast. Mirror the existing
staged-gate conventions (`CPUEMULATOR_UAT=full`, `CPUEMULATOR_Z80_REGS_ONLY`, the Z80 TomHarte 200-case
sample):

- **Default (`dotnet test`, no env):** run a **fast smoke subset** — ZEXDOC only is still very long, so the
  default does NOT run a full exerciser. Two options, decided in Task 4 (recommend option A):
  - **(A, recommended) the harness `[ZexFact]` for the full runs are `Skip`-gated to `CPUEMULATOR_ZEX=full`**
    (mirroring `CPUEMULATOR_UAT=full`), so by default they are SKIPPED with a clear reason. A SEPARATE
    fast-running `[ZexFact]` "wiring smoke test" runs by default: it loads ZEXDOC, runs only until the FIRST
    sub-test prints its first `OK` (or a small bounded cycle budget, e.g. 50–100M cycles — enough to clear
    ZEX's CRC-table init + the first sub-test), and asserts that first `OK` appeared with no `ERROR`. This
    proves the BDOS stub + loader + transcript capture WORK on every CI run, in seconds, without the
    multi-minute full sweep. The full ZEXDOC + ZEXALL run only under `CPUEMULATOR_ZEX=full`.
  - **(B) a `[Trait("Category","Slow")]`** on the full runs + a filtered default (`dotnet test
    --filter "Category!=Slow"`). Rejected as the primary because it requires the runner to pass the filter
    (the env-var gate is zero-config, matching the project's `CPUEMULATOR_UAT` precedent). Note (B) as the
    alternative if the user prefers trait-filtering.
- **`CPUEMULATOR_ZEX=full`:** run the full ZEXDOC (pre-check) then the full ZEXALL (strict gate). This is the
  composition proof; it runs in the nightly/UAT lane, not on every commit.
- **The cycle budget:** generous-but-bounded. A full ZEX pass is on the order of low-billions of T-states.
  Set the budget at **5_000_000_000** (5e9) — comfortably above a passing run, bounded so a hang (an
  infinite loop from a real interpreter bug) FAILS with a diagnostic rather than running forever. (Klaus uses
  500M for ~96M needed — the same ~5x headroom; ZEX needs ~1–2e9, so 5e9 is the analogous headroom. Tune in
  Task 4 against the ACTUAL passing cycle count, recorded.) Use a `long` (5e9 exceeds `int`).
- **The smoke budget:** ~100_000_000 (1e8) — enough to init ZEX's CRC tables + clear the first sub-test.
  Tune in Task 4 against the actual cycles-to-first-OK, recorded.

> **DECISION FOR THE COORDINATOR (D-runtime, new — confirm before the full-gate lands in CI):** should the
> FULL ZEXALL run in the project's CI nightly lane, or only locally under `CPUEMULATOR_ZEX=full` on the user's
> machine? Recommendation: gate it to `CPUEMULATOR_ZEX=full` (local/nightly), with the fast smoke subset on
> every CI run (so the harness wiring is always exercised). This keeps CI minutes bounded. Flagged, not
> assumed.

```csharp
using System.Text;
using CpuEmulator.Core;
using CpuEmulator.Cpus.Z80;

namespace CpuEmulator.Tests.Zex;

/// <summary>
/// A MINIMAL in-test CP/M-80 host for the ZEXDOC/ZEXALL exercisers (M3.5-2, decision D6 — a test
/// fixture, NOT a real CpuEmulator.Hosts.CpmZ80 machine). It loads a .com image at 0x0100, seeds the
/// CP/M Page Zero (warm-boot terminator at 0x0000, the BDOS entry the program CALLs at 0x0005),
/// runs the Z80 interpreter one Step at a time, and intercepts a CALL to the BDOS (PC == 0x0005)
/// to service console output (function 2 = char in E; function 9 = $-terminated string at DE),
/// capturing the console transcript. It terminates when the program warm-boots (PC reaches 0x0000)
/// or the cycle budget is exhausted (a hang guard). ZEX is pure-computation: it asserts no interrupt
/// line and never HALTs, so every Step is a plain fetch-execute.
/// </summary>
public sealed class CpmBdosHost
{
    private const ushort Tpa = 0x0100;       // .com load + entry
    private const ushort BdosEntry = 0x0005; // the CALL target the intercept fires on
    private const ushort WarmBoot = 0x0000;  // termination sentinel
    private const byte StringTerminator = (byte)'$';

    private readonly Z80Cpu _cpu;
    private readonly AddressSpace _mem;
    private readonly StringBuilder _console = new();

    public bool Terminated { get; private set; }

    public CpmBdosHost(byte[] com)
    {
        ArgumentNullException.ThrowIfNull(com);
        _mem = new AddressSpace(AddressSpaceKind.Program, addressBits: 16);
        _mem.MapMemory(0x0000, new byte[0x10000], writable: true);
        // Load the .com into the TPA.
        for (int i = 0; i < com.Length; i++)
            _mem.Write8((uint)(Tpa + i), com[i]);
        // Seed Page Zero: a warm-boot sentinel byte at 0x0000 (PC reaching here terminates) and a RET
        // at 0x0005 as a harmless real target (the intercept fires BEFORE executing it, so this is just
        // belt-and-suspenders for any path that does not hit the intercept).
        _mem.Write8(0x0000, 0x76);  // HALT byte at 0 is never executed (we terminate on PC==0 first)
        _mem.Write8(BdosEntry, 0xC9); // RET

        var io = new AddressSpace(AddressSpaceKind.Io, addressBits: 16);
        _cpu = new Z80Cpu(_mem, io);
        _cpu.SetRegister("PC", Tpa);
        _cpu.SetRegister("SP", 0xFFFE); // a sane CP/M-ish stack; ZEX sets up its own early
    }

    /// <summary>Run to warm boot or budget exhaustion. Returns the captured console transcript.</summary>
    public string Run(long cycleBudget)
    {
        while (_cpu.CycleCount < cycleBudget)
        {
            ushort pc = (ushort)_cpu.GetRegister("PC");
            if (pc == WarmBoot) { Terminated = true; break; }
            if (pc == BdosEntry) { ServiceBdos(); continue; }
            _cpu.Step();
        }
        return _console.ToString();
    }

    /// <summary>Service a BDOS call host-side: do the console effect, then RET (pop the return
    /// address the CALL pushed). Only functions 2 (console out) + 9 (print $-string) are implemented;
    /// any other function code is a silent RET (ZEX uses only 2 + 9).</summary>
    private void ServiceBdos()
    {
        byte fn = (byte)_cpu.GetRegister("C");
        switch (fn)
        {
            case 2: // console out: char in E
                _console.Append((char)(byte)_cpu.GetRegister("E"));
                break;
            case 9: // print $-terminated string at DE
            {
                ushort addr = (ushort)_cpu.GetRegister("DE");
                for (int guard = 0; guard < 0x10000; guard++)
                {
                    byte b = _mem.Read8(addr);
                    if (b == StringTerminator) break;
                    _console.Append((char)b);
                    addr = (ushort)(addr + 1);
                }
                break;
            }
            default:
                break; // unimplemented BDOS function — silent RET (ZEX never hits this)
        }
        ReturnFromBdos();
    }

    /// <summary>Host-side RET: pop the 16-bit return address off the Z80 stack and set PC.</summary>
    private void ReturnFromBdos()
    {
        ushort sp = (ushort)_cpu.GetRegister("SP");
        byte lo = _mem.Read8(sp);
        byte hi = _mem.Read8((ushort)(sp + 1));
        _cpu.SetRegister("SP", (ushort)(sp + 2));
        _cpu.SetRegister("PC", (ushort)((hi << 8) | lo));
    }
}
```

```powershell
# Fetches Frank D. Cringle's Z80 instruction-set exercisers (zexdoc.com + zexall.com) into the vector
# cache (same root as the TomHarte vectors + the Klaus binary; never vendored).
#
# Provenance: ZEXDOC/ZEXALL — Frank D. Cringle's Z80 instruction set exerciser (1994), GPL-2.0.
# Primary source: agn453/ZEXALL (curated from YAZE-AG v2.51.3 by Andreas Gerlich).

                             else { Join-Path $HOME ".cache/cpuemulator/vectors" })
)
$ErrorActionPreference = "Stop"
$zexDir = Join-Path $Destination "zex"
New-Item -ItemType Directory -Force $zexDir | Out-Null

$files = @(
    @{ Name = "zexdoc.com";
       Urls = @("https://raw.githubusercontent.com/agn453/ZEXALL/main/zexdoc.com",
                "https://raw.githubusercontent.com/begoon/z80exer/master/zexdoc.com") },
    @{ Name = "zexall.com";
       Urls = @("https://raw.githubusercontent.com/agn453/ZEXALL/main/zexall.com",
                "https://raw.githubusercontent.com/begoon/z80exer/master/zexall.com") }
)

foreach ($f in $files) {
    $binPath = Join-Path $zexDir $f.Name
    if (Test-Path $binPath) { Write-Host "$($f.Name) already present at $binPath"; continue }
    $ok = $false
    foreach ($url in $f.Urls) {
        try {
            Invoke-WebRequest -Uri $url -OutFile $binPath -ErrorAction Stop
            $len = (Get-Item $binPath).Length
            $firstByte = [System.IO.File]::ReadAllBytes($binPath)[0]
            # Sanity: non-empty, under 16 KiB, not an HTML error page (first byte '<' = 0x3C).
            if ($len -gt 0 -and $len -lt 0x4000 -and $firstByte -ne 0x3C) {
                Write-Host "$($f.Name) fetched to $binPath ($len bytes) from $url"
                $ok = $true
                break
            }
            Remove-Item $binPath -ErrorAction SilentlyContinue
            Write-Warning "fetched $url but it failed the sanity check (len=$len) — trying the mirror"
        } catch {
            Remove-Item $binPath -ErrorAction SilentlyContinue
            Write-Warning "fetch of $url failed ($_) — trying the mirror"
        }
    }
    if (-not $ok) { Write-Error "could not fetch $($f.Name) from any source"; exit 1 }
```

```csharp
/// mirroring CPUEMULATOR_UAT=full. Binaries are fetched (tools/get-zexall.*); absent → skip (ZexFact).
/// </summary>
public class ZexallTests(ITestOutputHelper output)
{
    private const long SmokeBudget = 100_000_000;   // ~enough to clear ZEX init + the first sub-test
    private const long FullBudget  = 5_000_000_000; // generous-but-bounded; a passing run needs ~1-2e9

    private static bool FullEnabled =>
        Environment.GetEnvironmentVariable("CPUEMULATOR_ZEX") == "full";

    /// <summary>Wiring smoke (DEFAULT, every CI run): load ZEXDOC, run a bounded budget, assert the first
    /// 'ok' sub-test appeared and NO 'error' did. Proves the BDOS stub + loader + transcript capture work
    /// on the REAL binary without the multi-minute full sweep.</summary>
    [ZexFact("zexdoc.com")]
    public void Smoke_zexdoc_first_subtest_passes()
    {
        string path = ZexVectors.TryGetBinaryPath("zexdoc.com")!;
        byte[] com = File.ReadAllBytes(path);
        var host = new CpmBdosHost(com);
        string transcript = host.Run(SmokeBudget);
        output.WriteLine(transcript);

        AssertNoError(transcript);
        Assert.Contains("ok", transcript, StringComparison.OrdinalIgnoreCase);
    }

    [ZexFact("zexdoc.com")]
    public void Zexdoc_all_subtests_pass()
    {
        Skip.IfNot(FullEnabled, "full ZEX run — set CPUEMULATOR_ZEX=full to enable (it runs for minutes).");
        RunFull("zexdoc.com");
    }

    [ZexFact("zexall.com")]
    public void Zexall_all_subtests_pass()
    {
        Skip.IfNot(FullEnabled, "full ZEX run — set CPUEMULATOR_ZEX=full to enable (it runs for minutes).");
        RunFull("zexall.com");
    }

    private void RunFull(string binary)
    {
        string path = ZexVectors.TryGetBinaryPath(binary)!;
        byte[] com = File.ReadAllBytes(path);
        var host = new CpmBdosHost(com);
        string transcript = host.Run(FullBudget);
        output.WriteLine(transcript);

        Assert.True(host.Terminated,
            $"{binary} did not terminate within {FullBudget} cycles — PC stuck or an infinite loop:\n{Tail(transcript)}");
        AssertNoError(transcript);
        // ZEX prints a completion banner when all sub-tests finish (e.g. "Tests complete").
        Assert.Contains("complete", transcript, StringComparison.OrdinalIgnoreCase);
    }

    /// <summary>Fail if ANY sub-test reported ERROR. ZEX prints "&lt;name&gt; ERROR &lt;crc&gt; &lt;expected&gt;"
    /// for a failure; "&lt;name&gt; OK" for a pass. The gate is zero ERROR lines.</summary>
    private static void AssertNoError(string transcript)
    {
        if (transcript.Contains("ERROR", StringComparison.OrdinalIgnoreCase))
            Assert.Fail("ZEX reported a failing sub-test (composition bug):\n" + transcript);
    }

    private static string Tail(string s) =>
        s.Length <= 400 ? s : "..." + s[^400..];
}
```

## Risks

- **The ZEX binary cannot be fetched in the Builder's environment.** THE primary risk (intermittent socket
  errors are a known tonight-issue). MITIGATED by design: the harness is built + tested with hand-assembled
  `.com` fixtures (Tasks 1–2), so the host MECHANISM is proven without the network; `ZexFact` skips the real
  runs when the binaries are absent; the fetch script tries a primary + a mirror. The honest close-state if the
  fetch fails: "harness landed + smoke/host-fixture-gated; run `tools/get-zexall` on a working connection to
  enable the full ZEX gate." Escalate to the Coordinator only if BOTH sources are unreachable AND the user
  needs the gate green this session. **Fallback options enumerated in the provenance section** (mirror /
  assemble-from-source / user-caches-once).
- **A ZEX sub-test reports `ERROR` (a real composition bug).** The HIGH-VALUE risk — this is exactly what ZEX
  catches that TomHarte cannot (a flag-after-flag or sequencing interaction). Per the invariant, this triggers
  `superpowers:systematic-debugging`: name the failing sub-test, minimize to an instruction sequence,
  reproduce as a focused case, fix the interpreter, pin a regression test. Do NOT weaken the gate. Given the
  full ISA is TomHarte-green, a failure would be surprising — but finding one would be the slice's most
  valuable outcome.
- **The ZEX transcript tokens differ from the documented strings.** The exact `OK`/`ERROR` casing + the
  completion-banner wording must be confirmed against the ACTUAL transcript (the smoke run prints it). Mitigated
  by the Task-4 note to read `output` and pin the real tokens; the `ERROR` check is case-insensitive.
- **The `"DE"` pair-view GetRegister key may not exist.** Confirmed-or-refuted at Task 0 Step 4; the host has a
  documented fallback (`(D<<8)|E`). Low risk (the register file emits pair views).
- **The cycle budget is mis-sized.** Too low → a passing run FAILS on budget exhaustion (raise + re-measure);
  too high → a hung run wastes minutes before failing (acceptable — it still fails). Tuned in Task 4 against
  the ACTUAL passing count, recorded.
- **The full ZEX run is slow in CI.** MITIGATED by the env-gate (`CPUEMULATOR_ZEX=full`) — the default CI run
  does the seconds-long smoke, not the minutes-long full sweep. The D-runtime decision (full-in-nightly vs.
  local-only) is flagged for the Coordinator.
- **`Skip.IfNot` vs. early-return.** The dynamic-skip API depends on whether the project references
  `Xunit.SkippableFact`. Confirmed at Task 0 (grep how `CPUEMULATOR_UAT` tests skip); the early-return form is
  the documented fallback.
